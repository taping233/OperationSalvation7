# 首领实机卡牌疑点审查与修复

两项确认问题均已按父任务授权作最小修复，完成未提交。详细复现、覆盖与源码指纹见 [verification.json](verification.json)。

## 寻宝图

原主动技能在装备域合法，但合成为 `onPlay` 后，`acquire` 与 `draw.amountField` 的混排违反既有 schema。旧实现先标记“已使用”，再在结算入口抛错，导致没有洗入宝箱、没有抽牌，却损失本场次数。两个隔离内存场景均复现该错误。

`battle.equipment.js` 在共同技能合成边界把当前卡面引用转为合法字面量，不修改原卡数据或 schema；原卡与合成卡先校验，分段结算成功后才消耗次数。异常保留次数并显示提示。

修复后的固定随机种子 2 场景确认：原手牌“初始攻击/银河之旅”抽到另一张初始攻击，总张数 2→3，视图分组仍为 2，初始攻击叠数为 2，宝箱留在牌库。因此同名叠牌确实可能造成“没有新卡面”的观感，但本轮原故障已由独立实验确认。

全部 4 张正式结构化主动装备已检查：原合成契约失败的只有寻宝图；修复后四张全部合法，原字段与规则未改变。

## 不变应万变-改

现行实现只响应“本牌已在手中时，新打出的武术”，没有抽入时追溯上一回合的规则。按父授权保留此机制，在现有 `unplayableReasonFor` 阻止未变形原卡空打出，并给短因“先打出一张武术牌，使本牌变形”。预览和手牌禁用继续复用同一判定，完整卡面说明保留。

普通与 BOSS 战均验证：拒绝时能量及手牌/弃牌不变；在手后打出武术即正常变形并按 1 费产生伤害；后续武术仍可持续重变形；BOSS 晚抽原卡不追加追溯规则。
