# 归档室独立子页实施

2026-10-11。状态：依据老板否定本轮视觉后的反馈，已将归档室统一到主代理重定的基地视觉系统；定向代码验证完成，等待主代理复核完整样板。

## 视觉统一修订

上一版独立绿灰底、金色阶段框与额外展柜卡片已弃用。当前归档只消费共同的 `--camp-bg/ink/muted/line/accent/dark` 变量；纸灰底、墨色文字、细线、直角、少量红色选中标记与共同按钮规则。原奖章绘图本体继续保留，不给每枚奖章新增多层框。

顶部导航明确为成就、角色档案、卡背、故事。成就与卡背陈列保留旁侧阅读区；角色阶段奖励改成连续细线序列，人物目录与通用双排卡牌浏览分开；故事采用目录与正文。删除档位双语眉题、奖章无用途编号、重复“阶段奖励”标题与重复状态文字。

本轮只改归档专属模块、CSS、专属测试与本记录；原动作契约和存档仍不变。视觉状态以老板和主代理的样板复核为准，代码测试不证明新美术已获认可。

老板已授权整体基地迭代。本切片只新增归档室模块、专属样式与测试；未修改数值、存档、奖励命令、原归档模块或仓库放大区。

## 具体变化

- 成就采用奖章陈列与旁侧详情。默认优先显示可领取成就；未达成/可领取/已领取分别显示，目标条件与奖励在详情集中阅读。原成就筛选与搜索继续使用。
- 全员归档顶部展示首次归档进度和阶段奖励；下方人物目录用已有手绘头像，切换人物展示该人物的归档卡牌。未归档卡仍可预览，状态明确。
- “前往归档培养”携带实际人物 ID，直接沿父模块现有 `focusWarehouseForCharacter` 定位仓库可培养卡。
- 卡背区以实物卡背陈列和预览展示选择；锁定卡背仍显示真实解锁条件；“查看解锁目标”既定位成就也展示其详情；只有已解锁且未使用的卡背可应用。
- 见闻采用篇章目录与纸页阅读，已记录内容默认打开最近段落，未记录段落禁用。记录损坏时保留原数据并提供重新读取。
- 移除原全员归档规则长段、重复总计、点击说明和未改变操作选择的解释。保留达成条件、奖励、进度与未记录内容的来源等必要信息。

## 接入契约

新增文件：

- `game/src/hub/hub.archive-v3.js`
- `game/css/base-archive-v3.css`
- `tests/hub-archive-v3.test.js`

`archiveV3HTML({ base, meta, cards, view, art })` 返回 `.hub-archive-v3` 整页；`view` 为 `achievements/classes/backs/stories`，默认成就。`art` 可省略，默认当前 `SDT.Art`，只调用 `classAvatarArt`。

父模块在 `bindArchive(UI, renderHub)` **之后**调用 `bindArchiveV3({ ui: UI, base: B, meta: M, cards: SDT.Cards, refresh: renderHub })`。前者仍负责成就筛选、目标定位和见闻异步载入；后者负责奖章选择、人物目录、卡背预览和通用卡牌翻页。全页更新继续由父模块完成。

`claimAch/claimColl/selBack/hubCollectionView/collZoom` 沿用父动作，培养跳转使用 `hubTab=stash/view=cards/character=<实际人物ID>`。通用归档卡牌的每个 button 同时保留 `collZoom` 与 `data-browser-key`，因此 `bindCardBrowser` 只处理翻页，不重复打开卡牌。

CSS 放在旧基地样式后加载，限定 `#overlay #hubMain.pg.hub.base-camp .hub-archive-v3`，不影响原游戏成就页、战斗卡牌、仓库或人物个人页。
