# 首次页面等待与入场掉帧处理

老板反馈交付EXE任意页面首次进入既有等待，也有页面已出现后的动画/操作掉帧，并要求尽快修复重包。本轮只处理已定位的公共开页开销，保留全部玩法、资源品质和动效时长；不把构建体积预算当作帧率结论。

## 修改

- `target-motion.js`：首次且有明确起始姿态时，传递完整双关键帧，避免Motion mini为单关键帧逐区域同步读取计算样式。默认Motion句柄直接提供原生动画归属，不再调用两次`getAnimations()`。中途改目标保留原来的当前位置采样及取消语义。
- `core/motion.js`及`interface-motion.js`：传统开窗动效持有并释放自己的句柄，新动效控制器按句柄取消旧动效，不再为每次开页枚举卡片全部动画，也不取消其他组件的动画。
- `game.menu.js`及`game.boot.js`：标题空闲时加载菜单模块和CSS，保留同一Promise去重及失败重试；不实例化页面或执行存档动作。真实点击时仍由原页面控制器挂载，冷入口取消与上下文隔离保持。

菜单冷入口测试的一处旧断言改为核对当前加载层的`aria-label`及未隐藏状态，匹配现行画稿加载层；其他取消、合并、重试及保存断言保留。

## 验证

7个定向测试文件58项通过，覆盖目标动效、原生关键帧与归属、页面控制器/取消、公共动效、标题动效及轻量启动。ESLint定向通过。类型检查前9组通过，runtime组发现本轮句柄类型声明不足，补充已安装Motion实际返回结构后单独复跑runtime组通过，真实实现覆盖557/557。生产构建、数据校验及体积预算通过。

内置浏览器当前窗口使用本轮交付包的同一生产目录，地址`http://127.0.0.1:8139/`。真实点击设置并切换“画面与反馈”成功，控制台无error；标题空闲时约940ms开始、44ms完成菜单模块请求，在点击前已准备。没有变更画质或FPS设置，也没有构造游戏状态。

基线采样见[baseline-trace.json](baseline-trace.json)。设置首次模块等待59.4ms；重复打开仍有74/88ms长任务。CPU样本显示默认目标动效的动画枚举约4.9ms，传统动效清理枚举约9.6ms；这些是单次采样开销。浏览器自动化自身也读取布局，后续对照总耗时受其及系统负载影响，不能据此报告FPS提升百分比或所有页面卡顿已消除。桌面资源协议的`no-store`仅为排查候选，本轮没有修改缓存策略。
