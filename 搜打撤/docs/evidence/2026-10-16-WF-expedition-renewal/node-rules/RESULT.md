# 节点生命周期与战斗背包规则验收

2026-10-16，本分工实现已冻结，未提交、未构建、未使用浏览器。根会话负责当前窗口实页、阶段全量与现行文档同步。

## 实际行为

- 战斗背包按钮禁用；通用背包入口（含快捷键来源）、引擎 openBag、Agent 可行动作面均拒绝打开。旧背包详情、拖拽、丢弃、跨安全格和排序动作在 battleActive 时不能改卡。独立药水快捷栏及手牌规则保持原行为。
- 普通宝箱与战利品增加“返回地图 · 保留奖励”；永久放弃使用独立文字与确认。奖励的候选、当前宝箱阶段、多箱队列/索引、领取和放弃索引、金币领取状态归原坐标保存，可与其他节点待领并存。
- 原节点重进先恢复待领奖，再判断节点完成。木材、口粮、钥匙旧节点入口改为逐张领取；满包不再静默丢奖励并消费节点。
- 战斗胜利即消费节点，未领奖重进进入战利品；未结束战斗的读档不提前消费节点。战后暂离地图前沿现有 Base+Run 节点幂等事务提交击杀、XP、宠物蛋进度，领奖进度仍留原节点，后续领取不会重复结算胜利。失败保留重试页，重试成功同步活动及节点快照的 progressCommitted 标记。
- 事件选择一级选项即完成，未领取候选仍可重进；退出、整理和读档沿原候选与付款记录，不重新抽取。
- 商店关闭可重进且购买记录不刷新；移动或跨门离开后旧店停止成交，门本身仍可通行。旧商店回调另核验坐标身份。
- 祭坛卡牌待领与复原待完成均可从地图重进；复原状态模块和界面由 expedition_ui 分工实现，本分工接入 flow、校验和地图完成投影。

## 存档合同

- 新增 `nodeChestRewards`：对象，键为非负整数坐标 `li,idx`；值是原 `chestReward` v1 完整快照。每份值的 seed 必须等于当前对局，坐标必须为非负整数并与键一致，其余队列/领取/战后续流结构沿原恢复校验。
- 原 `chestReward` 保留为当前活动领奖页，旧档读取时归档到相应坐标。两者同时描述当前坐标时须内容/进度一致；不一致则拒绝读取并保留原档。
- `context.battleSettlement.progressCommitted` 可缺省（旧档等于 false），存在时必须为布尔值；true 表示该胜利进度已提交，剩余奖励继续逐张领取。
- 新 `nodeRewards[type=restore]` 合同见 expedition_ui 分工证据；本分工只接入 `validNodeRestore` / `nodeRestoreAt` / `resumeNodeRestore`。
