## 实施

- `game.bag.js`：地图背包与安全格大卡浏览从当前可见顺序和代表UID实时定位，翻卡及说明引用返回重新打开当前详情并注册原动作；导航沿已有道具pending、输入隔离和详情busy，动作开始/完成刷新公共导航。使用成功关闭、容器、存取、丢弃和合成继续原事务。
- `game.bag.view2.js`：正式tile渲染输出可选`data-pocket-index`；消耗区首次打开按明确索引，后续按entry身份重找索引，解决同名记录与显示顺序错位。切片继续只渲染，不持有流程或动作。
- `game.hub.depart.js`：只读携带详情接公共连续浏览，固定初始牌单列，额外选中堆按正式格名顺序及稳定stackKey展开。同名variant沿实际堆查看，返回对应汇总格；不改变现有同名格汇总、拖回移除或起局规则。Base、档位、选择代际和当前整备选择共同约束旧引用返回。
- `hub.warehouse.js`：待复原详情接当前堆引用返回重建及原restore按钮busy导航守卫，`bindWarehouse`返回当前视图刷新函数供来源结果使用。
- `game.hub.runtime.js`：复原保存中同步公共导航；关闭详情后，若基地仍有效，成功结果原位刷新当前仓库与资源，失败继续现有操作反馈。保留详情未关闭时原有成功演出及所有前期runtime增量。

复用第十四批已有`getItems/getIndex/canNavigate/onReopen`与导航刷新入口，未新增详情、库存或事务框架；公共展示缓存与原有动作恢复接线按现行调用保留。

## 老板统一验收入口

- 地图背包/安全格筛选后连续翻卡，核对各卡详情和操作对应当前堆，返回原浏览位置。
- 消耗区同名不同卡记录逐个查看，翻页或说明引用返回后数量/规则对应原记录。
- 使用、合成、存取等待期间暂停导航；失败后恢复，成功按原流程关闭或转入下一页。
- 整备查看初始牌与多个已选堆、同名variant，再返回对应携带格；换页/换档/选择变化后旧引用不重开旧整备。
- 待复原说明引用返回后继续复原；复原中主动关闭详情，完成后当前列表和资源同步，失败原因可见。
