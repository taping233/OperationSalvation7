## 设计原则

开阔战场作为主体，意图贴近敌人，生命状态贴近角色；手牌集中在底部，能量在手牌左侧、结束回合在右侧。只在文字需要承托的位置使用安静底色。危险红、格挡灰白、能量冷青与主动作暖琥珀各有固定职责。

### 当前方案：手牌与职业技能返修

老板本轮指定：职业技能更明显，手牌不倾斜；常态下沉只露部分卡面，悬停完整展开，离开回落，并接入现有卡牌样式接口。随后追加手牌放大、标题露出，可以横向遮挡叠放。

- 职业技能固定在人物左侧，按钮挂在 `#btSelf` 内，随人物定位；独立显示大图标、实际名称“刺击”、费用、效果与每回合次数。内容读取 `slamSkillFor('侠客')`，已用/能量不足/敌方回合有禁用状态。
- 手牌统一直立，现行卡盒260×390布局像素，比前版280×420略缩约7%；横向间距190像素，相邻牌重叠70像素。常态纵向下沉140像素，费用与原生标题完整露出；悬停或键盘聚焦时置顶并上浮140像素。选中仅保留描边，不固定展开；鼠标离开后回落。
- 卡面直接调用 `cards.view.js` 的 `cardHTML`，使用原有插画映射、`card-frame-presentation.js` 与 `card-layout-selected.css`。预览只控制卡片宿主的尺寸、位置和交互，没有复制或覆盖卡面内部设计。
- 预览以现有数据切片、规范卡库和共用渲染上下文组成内存只读数据口，未调用玩家卡库的存储初始化。五张展示牌为初始攻击、格挡、冰刺、火球和鬼魅之刃，名称、费用与完整规则来自共用数据/描述接口。

当前证据：[紧凑牌堆与人物旁技能](controls-layout.png)、[布局和交互读数](controls-layout-verification.json)。280px叠放版证据为 `hand-size-rest.png`、`hand-size-hover.png` 与 `hand-size-verification.json`；前次接口接入证据为 `hand-rest.png`、`hand-hover.png` 与 `hand-verification.json`；旧 `preview.png` 为首版布局，各自只代表记录时点。

### 当前场景衔接

老板指出后景与地板衔接有问题。原地板全画幅铺放时，素材约42%处的远沿截断了后景建筑下部，透明边缘亮线进一步强化了断层。

地板现改为底部对齐、覆盖画面高度82%；远沿降至画面约53%，在地板自身43%至52%的区间完成透明过渡，画面约61%前达到不透明。建筑基座能完整显露，地板在角色站脚线之前接实。此轮仅调整独立地板图层的映射与局部alpha遮罩，三层源图、后景、前景、角色动画及手牌布局未改。
