# 背包容量共用口径

本批统一整备、收卡、换卡、容器取出、安全格转移与容量说明：普通占用不再用总占用代替，资源卡可使用专用扩展格，全部内容受总容量约束。

依据：现行整备以普通占格不超过基础、总占格不超过基础加扩容判断；`docs/rules.md`明确珍珠盒扩格只收资源卡。散装`inventory`没有卡牌类型，新增占格归通用格，修正原`addItem`只看总容量的旧分支。旧档内容保留，按存档规则保留同名未满叠的合并。

状态：本批修改完成，编辑释放，保留未提交，持续目标进行中。集中修改，由老板统一验收。

分工：6.1-sol/high分别维护纯容量模型/整备、库存与领奖消费者、派生与实时说明；主会话统一接口、文档和集成。

## 实施结果

- `bagSlotUsage`按既有叠放与位置查询普通/资源占格，`bagCapacityState`统一有效布局与可用空间。收卡、奖励预估与整备沿该入口，不再以总占用代替普通占用；新增珍珠盒同时计算其新占格和扩容。
- 典型差距：基础16格、珍珠盒扩容9格，普通15格与资源2格总共17格，再收一格普通牌后普通16、总18，整备和局内现在沿相同规则允许。
- 单张/批量更换、合成、锦囊/珍珠盒整组取出、安全格移回与交换统一预估，再修改卡牌位置或材料；取回已有容器不重复增加扩容。普通占用超基础或总占用超容量时拒绝新格，同名未满合并继续可用。
- 派生状态与实时容量文本共用查询，显示实际普通/资源可用空间；商店与奖励整理同步描述当前卡牌空间，保留背包格网和总量徽标。散装物资新增格沿通用容量检查，旧内容保留。
- 现行规则、存档派生和二级界面说明同步；没有新存档字段或容量副本。搜刮点预估直接使用公共函数新增的默认推导，无追加无效接线。

源代码与相关差异用于集成核对；本批未运行测试、lint、构建、检查脚本或实页验收。没有新增服务、删除文件、暂存、提交或推送。

## 老板统一验收

带珍珠盒且资源已占扩展时继续收普通牌；普通格满时资源仍可收、总格满时拒绝新增；容器自身扩容；全部领奖预估与逐张实际领取；换卡/合成、锦囊与珍珠盒取回、安全格移回与交换；散装物资新增格与同名合并；旧档超容内容和容量文字。
