## 第二版：折叠牌一次点击与名称条

父任务真实浏览器已查看第一版常态和悬停（截图位于 `../2026-10-16-WF-cloud-play-eight-hours/screenshots/27-battle-default-after-r1.png`、`28-battle-hover-after-r1.png`），确认手牌下沉、HUD可读与完整悬停没有裁切。父任务报告一次Playwright鼠标点击“长剑”未选中，随后Enter可以选择自己；当次浏览器没有事件监听证据，未确证稳定复现频率。

静态与定向构造输入发现一个明确缺口：底缘 `bt-slot::after` 的真实事件目标是槽位，而第一版pointerdown只绑定在子卡牌。槽位本身也没有btPlay/UID，因此该桥上的手势会漏接。第二版将原有唯一pointerdown监听迁至槽位，让卡面冒泡和槽位桥共用；槽位同步卡牌的btPlay与UID，注能连续轮转UID时同步更新。原aim轻点、拖动、目标确认与300ms残留click抑制保持，未新增第二次提交动作。移除冗余的内层透明命中延伸，拖动时关闭稳定槽位桥。

名称条保持21px逻辑字（当前显示约13px）和原卡名同步，左竖条改为柔和上沿，底色改为低对比渐变；末张牌名称条上限174px，不再铺满整卡形成过长黑块。没有改变共享卡框/卡名字体或原卡面排版。

- 最终定向测试：8文件128项通过，见 `target-tests-r2.log`
- 新增/扩展构造输入覆盖：卡面和桥各自一次tap选目标、长剑一次桥tap选自己且不耗费、残留click不反转、注能同叠连续选择不同UID、代表UID切换；原拖动、取消、敌方/自己/无目标落点回归均通过
- ESLint、JS节点语法、PostCSS 159节点解析、自有diff空白检查通过，见 `eslint-r2.log`、`validation-r2.json`
- 待父任务安全刷新后的真实鼠标复验：从下沉区第一次点击即选中、直接拖动、左/中/右扫牌与底缘命中。构造DOM输入和静态CSS不是浏览器hit-test证据，未将父任务单次失选的唯一原因当作已证实
- 本版没有使用浏览器、启动/操作服务、构建、提交、推送或删除文件


## 第三版：常驻信息减重与动作可读性

保留第二版260×390卡面、284px/85%下沉、1.05倍悬停、稳定槽位pointer链。父任务已补充实机结果：两场鼠标选卡后点目标通过；随后同一场真实拖动偷袭至敌人、法杖至自己、元素爆裂多段击杀通过，翻第二栏、能量/消耗与胜利闭环正常。上述为父任务报告，不记成本worker亲自操作。

### 实现

1. 敌人常驻HUD保留姓名、生命和当前意图，基础攻击移到现有完整意图详情；点击/Enter/空格都可展开，aria-expanded与持久展开同步。姓名行不截断，灼烧、诅咒、蓄力和庇幕等复合/阶段条件保留在摘要。一般名牌padding从12×14减为10×12，行间略收紧，姓名/血量字号不缩小
