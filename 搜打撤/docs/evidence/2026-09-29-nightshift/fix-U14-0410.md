## U14-a（G-1，P2）：useItem 入口复检 itemUsability，BOSS 战禁逃引擎侧同闸

**改动**：`game/src/battle/bag/battle.bag.js`（useItem 内，getHostedExecutionCard 之后、分流之前，+4 行）

```js
const usability = itemUsability(card);
if (!usability.usable) { G.log(`[[icon:lock]] 【${esc(card.name)}】${usability.why}，道具未消耗`, 'dim'); return; }
```

- 复检挂在取得执行卡之后，对 hosted 卡同样成立：`getHostedExecutionCard` 对含 `rules.bag` 的卡原样返回，对 hosted 文本卡只规范化 desc——itemUsability 所读的 id/desc/rules 与视图层（battle.engine.js:273 对原始卡算快照 .off）完全同源，口径不会分叉。
- 拒绝 log 用 `usability.why`（'BOSS 战中无法逃跑' / '合成材料：…' / '场上没有敌人可用'），`G.log` 在该作用域可用（同函数既有调用），`esc` 顶部已导入；级别按派单取 'dim'，措辞对齐既有「目标已失效，道具未消耗」风格。
- 三条使用通道同闸：战斗背包 btBag、拖拽（battle.aim.js useItemCmd）、agent 命令通道（agent.state.js:200 push('useItem')）都收敛到本函数。

**非目标场景零影响论证**：
1. 本来可用的道具：itemUsability 返回 usable:true，控制流与原路径逐字节相同（药水栏快照同函数判定，二者不会出现"视图可用、引擎拒绝"的新增分叉）。
2. `!card` 分支不可达：battleBagItems 已滤 `o.card &&`。
3. tt-token-color（合成材料）：人类路径本就被视图 .off 拦住；原引擎路径反而会被 agent 通道白白消耗——现在拒绝，是修复方向内的收口，非回归。
4. 敌方指向道具 + 场上无敌人：原先进 useBattleEffectItem 后 log+return（不消耗）；现在更早 return（不消耗），仅 log 文案/时机变化，结果等价。
5. usePotion → useItem 路径复检幂等（同函数同结果），拒绝发生在任何 splice 之前，无双重消耗。

**测试**（`tests/m3-contract.test.js`，startGame 增加可选 startOpts 参数透传 isBoss/nest，+33 行含改签名）：

- `G-1 regression anchor: same flee item still ends battle outside boss`——非 BOSS 战同道具照常 `finish(null)` 终局且道具消耗。
- 红绿验证：临时摘除修复重跑，BOSS 用例红、回归锚绿（用例确实抓得住该缺陷），已恢复修复。
