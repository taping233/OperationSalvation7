## U12-b（F2，P2）意图伤害快照 vs 实伤实时——选型诊断与实施

**三方案诊断**（诊断在先，选型标准=改动面最小+不破坏 intent 数据结构既有消费契约）：

| 方案 | 评估 |
| --- | --- |
| ① 渲染层现算 | **选定**。玩家可见的意图显示只有一处：`battle.layers.js updateFoes`（`intentViewModel` 的唯一 UI 调用点，`intentSummary` 无 UI 消费方）。渲染每帧重建快照后执行，天然覆盖**所有** foe.atk 变更路径（atkDown 卡、偷攻归还、未来新增路径都无需逐点登记刷新）——即 STS2 `RefreshIntents` 语义的渲染层等价物。改动=1 处 import + ctx 加 2 字段 + 1 处表达式。 |
| ② atk 变化点同步刷新 | 否。需枚举并侵入 resolution.js（atkDown 落点）、effect-steps、偷攻、bag 等多个模块并给各模块接 `intentFor`/turn 端口，漏一处即复发；改动面与回归风险都更大。 |
| ③ intent.damage 改惰性 getter | 否。改变 intent 数据形状：快照侧 `freezeObject({ ...intent })` 会把 getter 物化成数字、读档 `clone(f.intent)` 后惰性失效（加载前后行为不一致）、AI 顾问消费语义被动变化；契约风险最高。 |

**消费契约枚举**（全部核实，方案①下 `foe.intent` 数据零变化，仅显示层改读现算值）：
- `battle.layers.js:689`（UI 渲染，唯一玩家可见）→ 本次改动点。
- `battle.snapshot.js:151` `freezeObject(foe.intent)` → 快照契约不变（仍有用例断言其保持回合末快照值）。
- `battle.runtime.session.js:79-82`（读档回填）→ 不变。
- `agent.state.js:84` / `agent.policy.js:96`（AI 顾问）→ 不变（已知残留，见「残留与边界」）。
- `intentFor` 赋值点共 4 处（lifecycle:234、enemy-phase:69/326、session:82），全部以**当回合值**计算且紧跟 `set$turn` 之后——渲染层用 `snapshot.turn` 现算与存量 intent 的回合语义恒等；另经 rg 核实 `affix/behavior/evenAttack/noFirstAttack` 战斗中无 mid-battle 变异，现算的 kind/label/hits 与存量恒等。

**实施**（battle.layers.js）：
1. import `calculateEnemyIntent`（纯模块，无门面依赖；ESM 循环依赖检查通过）。
2. `updateUnits` 的 ctx 增带 `turn: snapshot.turn || 1, playerStatus: snapshot.pstat?.status || null`（快照每帧现成数据，无新端口）。
3. 非冰冻分支：`intentViewModel(f.intent)` → `intentViewModel(calculateEnemyIntent(f, ctx.turn || 1, ctx.playerStatus))`。

**验收用例**（tests/m2-contract.test.js 新 describe，经公共入口 `BattleSession.start/playCard/getSnapshot` + 引擎公共出口 `playerTakeHit`）：玩家回合内对 atk 5 的敌人打出割蚀（atkDown 2）后，渲染口径显示值=3、`playerTakeHit` 实伤=3、二者相等；同时断言快照 `foes[0].intent.damage` 仍为 5（快照契约保持）。
