## 一、断言设计思路（对齐模块真实契约）

### 1. tests/cov-target-session.test.js — 瞄准会话状态机

源码契约（`game/src/battle/core/battle.target-session.js`）：会话以 `settled` 一次性结算，`isCurrent()` 是所有入口的公共门。

| 测试组 | 契约依据（源码原文） | 断言设计 |
|---|---|---|
| 会话开启与一次性结果 | `const promise = new Promise(done => { resolve = done; })` | 新会话 `settled=false`、`hover=null`、promise 挂起（微任务后仍未结算）；`select` 合法目标返回 true 且 promise 以 `{status:'selected', target}` 结算；结算后再 select/cancel 返回 false 且结果恒定 |
| 目标校验 | `const foe = targets?.[target.idx]; if (!foe || foe.dead) return false;` | 越界 idx 与死亡 foe 拒绝，且拒绝**不终结会话**（`settled` 仍 false，可继续选择）；`getTargets ? getTargets() : snapshot?.foes`——用可变 getTargets 证明其优先于 snapshot |
| selectDirect 的 side 门 | `if (!isCurrent() \|\| kind !== side && !(side == null && kind === 'any')) return false;` | side='enemy' 只放行 enemy；side=null 只放行 'any'；side='self' 只放行 self；拒绝后会话存活 |
| hover 转换 | `if (hover?.el === next?.el) return hover; … onHover?.(hover, previous)` | 切换按序回调 `(next, prev)`；同 el 引用判重不重复回调；select/cancel 前清空 hover 并回调清除 |
| cancel 与战局失效 | `if (isBattleCurrent?.()) return true; … resolve({ status: 'cancelled', target: null })` | cancel 返回 true 并结算 cancelled；重复 cancel 拒绝；isBattleCurrent 变假后**下一次触碰自取消**（清 hover + 结算），且自取消不重复结算 |
| hitAt 无 DOM 守卫 | `if (!isCurrent() \|\| !side) return null;` | 仅测不碰 `document.elementFromPoint` 的前置短路分支（settled 后、side=null 时返回 null）。**取舍**：elementFromPoint 拾取半边依赖真实布局，jsdom 无布局不可测，如实跳过（要求 4 口径） |

### 2. tests/cov-battle-clock.test.js — 演出时序（isTestRuntime 旁路的取舍）

源码契约（`game/src/battle/runtime/battle.clock.js:10-15`）：

```js
function isTestRuntime() {
  return typeof process !== 'undefined' && process.env?.VITEST === 'true';
}
function waitPresentationMs(ms, signal) {
  if (isTestRuntime() || isTurbo() || !(ms > 0)) return Promise.resolve();
```

旁路是**调用时**读取环境变量，因此测试在 `beforeEach` 临时 `delete process.env.VITEST` 驱动真实调度路径（零生产改动），`afterEach` 恢复；并把「VITEST=true 时长等待必须短路（否则全套件挂起）」本身作为一条契约断言（测试旁路回归守卫）。前置统一复位：`setPace(1)`（demoMs 恒等、80ms 下限可见）、`setTurbo(false)`。模块级 `pauseDepth`/`waits` 跨用例共享——每个用例把新建的等待全部推进到结算再结束。

| 测试组 | 契约依据 | 断言设计 |
|---|---|---|
| waitPresentationMs 真实调度 | `setTimeout(finish, waiter.remaining)` | fake timers 下 299ms 不结算、到点结算且无残留定时器；`!(ms > 0)` 非正时长立即结算；abort 以 `signal.reason` 原据拒绝（事前已中止同样拒绝） |
| schedule / …Ms | `schedulePresentation = waitPresentationMs(demoMs(ms))` | 回调到点恰好执行一次；`demoMs` 80ms 下限可见（10ms 实等 80）；`schedulePresentationMs` 原始毫秒直排不经下限；取消函数使回调不再执行 |
| pause 挂起/恢复 | `waiter.pause()` 清定时器、`resume()` 重排剩余时长；`pauseDepth++` | 暂停期间推进时钟不结算、恢复后续跑；release 幂等；先行暂停时新建等待不启动、恢复后才全额计时；嵌套暂停外层释放前不恢复 |
| waitHitStop 顿帧 | `const release = pausePresentation(); const timer = setTimeout(done, demoMs(ms));` | 顿帧窗口内并发等待被冻结、到点只恢复不代结算、恢复后续跑；嵌套顿帧共享生命周期（两窗都结束才恢复）；abort 立即打断并解除暂停 |

**排障记录（仅测试侧问题）**：首轮 hitstop 用例 3 处失败，根因是我在 `await hit` 前未推进 fake 时钟（时钟冻结→该 await 永不结算→5s 超时），超时中断又把模块级 `pauseDepth` 泄漏为 1，级联污染同文件后续两用例（depth≥1 下新建等待不启动 timer）。改为「先推进时钟再 await」并补窗口内冻结断言后全绿；生产代码零改动。

### 3. tests/cov-motion-primitives.test.js — 动画数学底座（数值三原则：端点/值域/收敛）

源码契约（`game/src/core/motion-primitives.js`）：「纯时间函数、无 DOM、无状态、无随机，同参数恒同结果」。

| 测试组 | 契约依据 | 断言设计 |
|---|---|---|
| ease 曲线族 | 注释「t80 注记…对称 S」「入场/落点用 out 系（快起缓收）」 | 全 6 曲线 f(0)=0、f(1)=1 精确；[0,1] 101 点采样输出有界 [0,1] 且单调不减；smooth/smoother/cubicInOut 对称性 f(u)+f(1-u)=1（「对称 S」）；cubicOut/quintOut 中点 >0.5（out 系快起缓收）；linear 恒等 |
| spring | 「欠阻尼二阶系统…带一次过冲后回稳」「omega=18、zeta=.62 时约 0.35s 收敛、过冲 ~8%」；`Math.min(0.99, Math.max(0.05, zeta))` | t≤0 返回 0；默认参数 1s 采样有界 [0,1.2]、峰值 >1.03（过冲存在）、1s 处收敛到 1（<1e-3）；与 settleMs 联动：2× settle 后 \|1-f\| < eps；极端 zeta 钳制后不产生 NaN；同参恒同果 |
| settleMs | 「\|1-f(t)\| 首次小于 eps 的时刻——不手拍秒数」 | 回归锚：`{zeta:.62, omega:18}` → 351ms（对齐源码注释「约 0.35s 收敛」）；正整数毫秒；eps 放松变短、omega/zeta 增大变短 |
| hopPoint | 「from→to 按曲线插值 + 抛物拱抬升（height*4h(1-h)，中点最高、两端落地）」 | u=0/1 精确落地两端；越界 u 兜到两端；默认 smoother 下中点 x 过半、y 抬升一个 height；height=0 退化为直线插值；x 沿曲线单调前进 |
| decayOsc | 「静置期（t<t0）恒 0」「幅度 amp 指数衰减 + 频率 freq 正弦」 | t≤t0 恒 0；受力后采样 \|v\| ≤ amp·e^(-decay·dt) 包络且正负半周均出现；远期衰减 <1e-6；amp 线性缩放、确定性 |
