## 〇、行为变化声明（顶部，老板已拍板）

**变了什么**：玩家受伤不再即时钳 0（hp 数据层可为负）；伤害致 `hp<=0` 即时走 `finish(false)` 战败流程——其中「自己回合自伤致死同样触发」与「恰好打到 0 血也判死」是硬变化。**旧语义「自己回合永远死不了、0 血可被同回合治疗拉回」自本单元起不复存在**（死了即死，STS2 的 Revived 治疗复活按拍板不实施）。免死钩 deathSave（黑暗吊坠）语义逐字保留：致死伤害先被拦一次（hp 不动、保险 -1、本回合无敌），拦不住才死。敌方回合 7 处既有 `finish(false)` 路径（enemy-phase.js:90/130/156/253/388/400/441）全部保留不动。

**读档/存档兼容核实（拍板第 5 点）**：
- 战斗内存档点=存档 payload 的 `battle:` 字段（game.session.js createRunSavePayload:172），**只在 `game.battleActive` 为真时经 `SDT.Battle.serialize()` 写入**；本单元后 hp<=0 在伤害结算当拍同步 `finish(false)` → `G.battleActive=false` → serialize 不会再被调用 → **战斗检查点不可能捕获负血**，恒正成立。
- 战斗中节流落盘（battle.action-runner.js:42）守卫 `battleActive && phase===PLAYER`：死亡后 battleActive=false 不落盘；回合开始落盘（enemy-phase:416）位于既有 `hp<=0` 检查（:388/:400）之后，到不了负血。beforeunload 全量保存同走 saveGame 门（state='done'/终局待结算阻断）。
- **顺带发现（只报告不动手，hub/ 属并行工匠属地）**：`finish(false)` 之后、死亡结算置 `terminalPending` 之前的窗口内，run 级顶层 `hp: game.hp` 若被 saveGame 写入会带负血（旧语义该窗口写 0）。读档侧 `numOr(s.hp,…)` 不拦负值。属死亡结算域的防御缺口，与旧语义同类（0 血窗口本就存在），建议 hub 存档域会话或在结算处置时钳 0；本单元未动 hub。

## 二、修法（diff 摘要）

1. **engine.js `damagePlayer`**：`G.hp = Math.max(0, G.hp - n)` → `G.hp = G.hp - n`；函数体末新增 `if (n > 0 && G.hp <= 0) finish(false);`（`finish` 为模块内 hoisted 转发，lifecycle 的 phase 守卫天然防重复收尾）；日志 hp 补钳。deathSave 拦截分支逐字未动。`finish` 内 `session.abort()` 会中止当前动作信号，出牌管线经既有 BattleActionCancelledError 取消链安静收场（action-runner catch 静默吞取消，finally 的落盘守卫 `battleActive` 拦死局），无 Unhandled。
2. **engine.js `playerTakeHit`**：`G.hp = Math.max(0, playerRef.hp)` → `G.hp = playerRef.hp - (r.overkill || 0)`。**关键发现：combat.js `dealDamage`（:166-168）内部本就把 target.hp 钳 0 并把超出量记入 `r.overkill`**——combat.js 非本单元属地不动，消费侧按 overkill 还原真实负血；死亡判定不在此处加（敌方回合既有 `G.hp<=0` 检查收口，路径保留不动，命中后 on-hit 附加（狂乱诅咒/消耗手牌/龙尊阶段）时序维持原样）；日志补钳。
3. **enemy-phase.js 毒/灼结算**：三处 `G.hp = Math.max(0, pref.hp)` → 按 `p1/b1.overkill` 累计还原（`playerOverkill` 累加，末尾 `G.hp = pref.hp - playerOverkill`，覆盖时光符文双结算的多次 tick 叠加超杀）；两处日志补钳；行 130 既有死亡检查不动。tickPoison/tickBurn 与 dealDamage 同款内部钳（combat.js:130/175），同样消费侧还原。
4. **ui/hud.js**：`dispHp = Math.max(0, game.hp)` 用于血条文本（hpKey 缓存键保留真实值，负血→结算回正后能触发一次重绘，无害）。
5. **未实施**（拍板明确不做）：STS2 Revived 治疗复活；battle.resolution.js/exec-play.js 的终局短路（U16 属地，与本单元 damagePlayer 内 finish 天然衔接：U16 短路挡同卡余下 op，U18 负血负责判死）。
