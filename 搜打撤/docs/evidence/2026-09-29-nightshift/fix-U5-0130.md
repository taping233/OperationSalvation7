### U5-a：battle-loader ensure 路径裸 window（game/src/battle/battle-loader.js，+8 行）

`ensureBattleReady` 内两处 `window.SDT?.Battle` 裸引（函数开头 + 动态 import 的 then 回调），
宿主环境拆除（如测试 teardown）后经 `SDT.BattleLoader.ensure` 直接导出路径调用会同步抛
`ReferenceError: window is not defined`（unhandled）。

修法对齐 9d7b871（captureBattleContext 谓词守卫）定式，两处各加一行守卫：

```js
if (typeof window === "undefined") throw new Error('战斗模块加载失败：宿主环境已拆除（window 不存在）');
```

- 选 **throw（async 函数内即 rejection）** 而非同步裸抛的依据——调用方错误处理姿势盘点（rg 全量）：
  - `startBattle`（同文件 58 行）：`try { await ensureBattleReady() } catch` ✓
  - `game.run.altar.js:75`：`ensureBattleReady().catch(error => console.warn(...))` ✓
  - `game.menu.js:760`：外层 `try { ... await ensureBattleReady(); ... }` ✓
  - 三方均有捕获姿势，reject 更安全（任务指示：不确定就 reject）。
- then 回调内守卫覆盖「import 期间环境被拆」时序：守卫 throw 走既有 `.catch`（battlePromise 置 null，
  允许重试语义不变），调用方收到可读 Error 而非 ReferenceError。

### U5-b：对局档 prev 备份键（game/src/hub/game.storage.js，+6 行）

`RunStorage.write()` 原先在 `localStorage.setItem(RUN_KEY(index), nextRaw)` 直接覆盖唯一好档——
写基线（writeBaseline）只防并发不防逻辑坏档。修法（最小侵入）：

1. 新常量，命名对齐 CORRUPT_KEY 形态：
   ```js
   const PREV_KEY = index => `sdt-run-${index}-prev`;
   ```
2. 主写执行**之前**，若 currentRaw 非空，尽力转存上一版原串：
   ```js
   if (currentRaw) { try { localStorage.setItem(PREV_KEY(index), currentRaw); } catch { /* 尽力而为 */ } }
   ```
3. `remove()` 同步清理 prev，避免悬挂（独立 try/catch，不影响 remove 返回值路径）：
   ```js
   try { localStorage.removeItem(PREV_KEY(index)); } catch { /* 尽力而为，不悬挂 */ }
   ```
4. 主写路径其余逻辑（写基线推进/事务门 txPending/身份递增/CORRUPT 清理/STALE_SLOT 判定）**逐字未动**——
   diff 0 删除可证；备份语句置于 `JSON.stringify(nextRaw)` 之后，stringify 失败时与原行为一致（不触备份、不主写）。
