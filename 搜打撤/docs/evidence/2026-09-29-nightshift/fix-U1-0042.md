## ③ 自查结论：浏览器语义不变性

对照修改前后原文：

- 修改前谓词为箭头表达式：`(contextVersions.get(game) || 0) === version && (!registeredGame || registeredGame === game) && window.SDT?.game === registeredGame && getSlot() === slot && keys.every(...)`。
- 修改后谓词为箭头块体：先 `if (typeof window === "undefined") return false;`，随后 `return <原表达式逐字相同>`（三个 && 子句、短路顺序、操作符、空格均未动）。
- 浏览器内 `window` 恒存在，两个 `typeof window === "undefined"` 守卫恒为 false，不可达；可达路径上的快照逻辑（version/registeredGame/slot/values 采集）与谓词表达式逐字未动，求值顺序与返回值完全一致。
- 唯一行为变化仅发生在 `window` 缺失/被拆除场景：原为抛 `ReferenceError: window is not defined`（未定义行为），现为安全返回 `false`（语义：环境不在 = 上下文必然失效），即本次修复目标。该场景在浏览器中不存在，线上行为零变化。
- 调用方盘点：`game.menu.js:713/741`、`game.run.altar.js:379`（自定义 getSlot）、`game.run.scenes.js:117`、`game.run.dev.js:16`、`battle-loader.js:47`（默认 getSlot）。签名未变，window 缺失时 guard 先于任何 `getSlot()`（含自定义）执行，全部调用方透明受益。
