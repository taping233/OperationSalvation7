## 背包来源返回

`bag-return-hook.js` 在打开背包时认领当前来源页与现有对局上下文，拒绝过期来源；关闭时复用在途返回，等待同步或异步来源回调，并以实际替换背包的新页确认原有 void 回调成功。失败不消费来源，新登记的钩子也不会被旧返回完成清除。

`game.bag.js` 在来源恢复成功后才清理背包、搜刮覆盖和滚动返回标记；失败保持原背包并提示再次返回。搜刮仅从当前奖励/总览页认领，已有事件、物资或商店来源优先。背包刷新、说明返回与分区入口透传结果，B 键先收特写及可见背包切换语义保留。

源码修改完成；等待返源期间复用公共输入隔离并在完成后释放，前四批物品使用、丢弃、容器及持久化接线沿用。

## 临时页与帮助返回

`overlay-return-state.js` 在同步/异步返回期间防重入；返回失败、抛错/拒绝或仍在原临时页时保留返回操作，并由帮助页公共操作反馈提示重试。同步单次重建认领本次目标版本；异步准备通过 `commit(render)` 执行目标重建，其他页面接管后停止旧呈现恢复。恢复前后核对目标，`applyContext`重绘后再次核对，焦点使用正式控件可用性。

`overlay.js` 帮助入口传递 `back(state, commit)` 并接收失败反馈；商店、收购台、撤离整理及背包帮助返回均传递实际结果，失效明确返回false。公共 `dialog-surface.js` 的Tab循环、初始焦点及返回焦点同用控件可用性；`confirm-dialog.js` 在失败后把因禁用失去的确认焦点交回当前按钮，保留用户已移向其他控件的选择。

## 正式来源接线

商店与收购台渲染成功后才提交页面版本、当前页和清理返回标记；`onReturn`透传真实重建结果并恢复原浏览状态。渲染前失败保留原返回身份，背包可重试。

事件来源共6处登记后置：主事件页、异常改装台、暗巷赌约、事件选牌、分支候选与原卡选择页。来源页实际渲染后再登记，满包后同一调用栈打开背包可立即认领；效果和保存沿原所有者处理。原本已在渲染后登记的资源页及保存重试页沿用。
