# 照相馆：具体案例与可实施建议（2026-10-10）

老板要求从宽泛原则进一步找到实例和明确改法。本轮优先推荐“紧凑检索 + 全宽照片墙 + 按需详情”，以赏图和浏览为核心。相片墙与选片桌两种交互原型仅用于评估布局和动作，未改正式游戏。

## 实例一：收藏页的工具栏与状态位置

[Brainrot Horrors的Card Album作者案例](https://byandresfe.com/case/roblox-game-ui-system)提供了收藏页、状态局部图和按钮状态表。实际图中，类别、稀有度和搜索放在一条紧凑工具栏；数量贴在卡片右上，等级标签在下方；装备状态用独立绿勾与标签。作者将筛选、搜索、稀有度、拥有数量、锁定、装备、详情和操作逐项标注，能直接检查信息位置。

![Card Album](https://byandresfe.com/cases/roblox-game-ui-system/album.webp)

照相馆建议：把当前约184px高的检索面板压成56px左右的工具带。保留搜索、常用类别与一个筛选入口；稀有度、人物与排序在入口下展开，已应用的条件以短标签显示。照片名和类型固定在底签，稀有度维持框式/标签身份，选中只添加一种常驻标记。

## 实例二：Destiny的贴物品详情

[Destiny UI负责人David Candland的案例](https://www.cand.land/destiny/)明确解释：游标提供物品上下文信息，使界面无需为详情永久划出一块分离区域。实图里，带等级标题、关键数值、特性和动作提示的浮层贴着当前装备出现。这是其历史界面案例，本轮未实际游玩Destiny。

![Destiny物品详情](https://images.squarespace-cdn.com/content/v1/5aa416faf8370ab26ce4c7dc/1521323045716-P5YX2RQZ5S3KFIKGJYW6/tooltip1.PNG)

照相馆建议：默认收掉右侧常驻同图预览，照片墙占全宽。悬停220ms后，只出现名称、类型/稀有度和一行关键内容，宽230–260px；键盘焦点也能读，点击仍直接放大。完整规则与背签随大图出现。这样可以避免重复展示同一张图，并给照片增加约四成横向空间。

## 实例三：把选中拆成有先后的动作

[Náthaly Moyano的The Mother个人项目](https://nathalymoyano.com/work-themother)提供了四幅卡片选中分镜：默认状态，烟雾过渡改变卡底，稍后出现扫光，稳定在选中状态。图里还明确处理查看后通知标记消失的行为。它是个人项目的设计分镜，未把它当作已发售游戏或实测时长。

![卡片选中分镜](https://framerusercontent.com/images/t99P0DX3YQ4yYmYOYbkLvBqVigs.webp?height=1080&width=1920)

照相馆建议：同样分段，但用相纸的语言。选中瞬间标记先明确；相纸抬起3px，用120ms落稳；40ms后底签的一小段边缘高光移动一次，160ms结束。扫光局限于底签或夹子，不穿照片和规则文字。静止后保留选中标记，不维持持续闪烁。

## 实例四：按钮状态不是一套默认样式

[同一收藏页作者的按钮状态表](https://byandresfe.com/cases/roblox-game-ui-system/sys-button-states.webp)展示默认、悬停、按下、加载、不可用与成功。可见按下态比悬停态更暗，厚度/投影收紧；不可用态改变整个按钮面，成功态有明确差别。

![按钮状态表](https://byandresfe.com/cases/roblox-game-ui-system/sys-button-states.webp)

照相馆建议：主按钮高度40px，普通面板按钮底边留2px实体厚度。悬停用100ms提亮并露出边缘；按下用80ms下移2px、收掉底边阴影；释放用100ms恢复。加载需有文字或进度，禁用保留可读标签且取消抬升。返回按钮保持既有图标与透明盒。

## 推荐的实际布局参数

下面是给本项目的原型建议，不是从外部截图测出的参数。以此前1523×956当前窗口的最终显示像素为起点，源码需按项目UiScale换算；尚未在正式游戏验收。

| 部分 | 建议值/行为 | 对应问题 |
| --- | --- | --- |
| 顶部馆名带 | 高56px，标题24px，说明12–13px | 页面身份清楚，装饰不扩大工具区 |
| 检索工具带 | 高56px，搜索宽320px，筛选按钮约80×40px | 替换现页184px高的大面板 |
| 条件展开 | 高级条件按需展开；多条件时增加一行28px标签 | 保留检索能力，减少默认密度 |
| 照片墙 | 全宽4列，左右36px，列/行间距24px | 单张纸宽约345px；原图区域约317px，比现页约226px宽更大 |
| 相纸 | 留边12–14px，侧面厚度2–3px，接触阴影短且一致 | 用纸层结构表达厚度；保持原等级框/夹子 |
| 底签文字 | 名称16px、类型12px；底签高48–56px | 读字稳定，长名称先给两行空间 |
| 悬停详情 | 220ms后出现，宽230–260px；进入110ms | 把右侧常驻详情变成对象附近的短信息 |
| 大图与背签 | 照片约占可用宽度60%，背签约28%，中间留24px | 主对象与信息面分工，照片按原比例完整显示 |

全宽四列估算：`(1523 - 36×2 - 24×3) / 4 ≈ 345px`。只是几何预算；边框、滚动条、最长名字和真实控件还需在原型和正式页核对。

## 推荐的动作时序

| 动作 | 具体顺序 | 总时长起点 |
| --- | --- | --- |
| 悬停照片 | 等待220ms → 相纸抬起3px/120ms → 简要信息110ms出现 | 快速掠过不触发详情 |
| 点击取片 | 当帧反馈 → 来源照片向大图位置移动/缩放260ms；背签延后80ms、用180ms展开 | 260ms |
| 收回照片 | 背签先淡去；照片沿来源回落，200ms结束 | 200ms |
| 切筛选 | 控件稳定；仅照片内容交接180ms，最多首屏8张做20ms错峰 | 最迟320ms |
| 翻看背签 | 照片绕竖轴转到侧面110ms，再以背面展开110ms；文字在转完后可读 | 220ms；候选，原型尚未实现 |

移动和光效要有相同的主方向；同一次过渡只让照片承担主要运动。选中、翻片、放大分别表达不同意义。快速重复输入应取消或接续上次动作，不能让旧回调改新状态；减少动态模式保持静态结果。

## 原型覆盖

- **相片墙（推荐）**：六张既有缩略图，搜索、按需类别筛选、悬停短信息、点击取片与背签展开、按钮/Esc收回；用260ms与200ms观察动作衔接。
- **选片桌**：左侧缩略片条、中央单张大图、右侧背签，点片条或上一/下一片切换；适合连续赏图，与相片墙有不同布局用途。
- 原型未复制268张目录、稀有度全部框式、存档/备注写入或完整游戏键盘逻辑，不能据此宣称正式页美术完成。
- 外部例子已读作者说明并通过内置浏览器查看上述原图；动作时长为本项目建议，没有声称测到原游戏帧时长。
- 参考图片仅引用原网址；六张本地现行卡图嵌入线程原型，未上传素材到外部服务，未生成新卡面。
