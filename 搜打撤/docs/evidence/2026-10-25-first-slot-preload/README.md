# 存档首进预加载修复

基地逻辑在选档页显示后的空闲时段提前加载，当前首页背景改走已有受限解码池预热；将首次准备工作提前，实际改善幅度尚未做运行计时。

## 实现范围

- `game.hub.js` 导出 `preloadBaseHub()`，复用原先的模块请求缓存和失败清理，不挂载页面或写存档。
- `game.boot.js` 经既有会话端口注入预加载函数，`game.menu.pages.js` 传入选档页。保留层级边界，菜单不直接导入基地页面。
- `menu-slots.js` 在选档DOM挂载后安排空闲准备，离页、页面被替换或后台时跳过；不支持空闲回调的平台用80ms定时回退。真实点击与预载共享请求，预载失败不阻塞档位操作。
- 启动背景预热从旧 `hub-wallpaper.webp` 改为首页实际使用的 `base-operations-v5.webp`，使用已有图片池的并发、去重、解码和内存预算。
- 原有档案读取、迁移、写入锁、切档保护、页面取消与入场流程保留。

## 验证

最终9份定向测试117项通过，包含城市快照/空闲调度、基地预载与真实进入并发、失败恢复、启动就绪、全局输入生命周期，以及contracts和architecture-boundaries哨兵。完整结果见[最终测试报告](final-tests.json)。四份修改的JavaScript执行ESLint，退出0。

最初实现让菜单动态导入基地门面，contracts检测出依赖环；已改为启动层经现有runtime注入，最终哨兵通过。基地旧测试的照相馆替身缺少现有 `finishPhotoStudioEntry` 导出，已补齐替身。

最初额外运行 `menu-pages-lazy-entry.test.js` 有两项失败：热指南仍被假定同步返回、诊断最后一条仍被假定为stage记录；该文件将 `game.menu.pages.js` 整体替换为模拟工厂，不执行本轮改动的选档与基地预载链。未修改这两项无关菜单约定，失败原始结果见[target-tests.json](target-tests.json)。最终117项通过不包含这两项。
