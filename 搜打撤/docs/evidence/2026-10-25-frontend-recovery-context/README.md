# 图片恢复与浏览上下文续轮

2026-10-25，Friday，WF-frontend-recovery-context-1025。状态：已实现、完成未提交，待老板实页验收。沿用老板“不需要测试，直接做”，本轮只读源码、修改与登记，未测试、lint、类型检查、构建或游戏实页；无新服务、文件删除、提交或推送。

## 本轮落实

1. **图片失败可就地重试**：新增 `game/src/ui/visual-resource-recovery.js` 与 `game/css/visual-resource-recovery.css`，用同一6000毫秒截止、请求互斥、来源校验及关闭清理处理加载。正常状态不增加提示，失败/超时后提供“重新加载”，恢复后撤去提示并处理按钮移除后的焦点。不可取消的解码回调只持有可清空记录。
2. **庭院背景与照相馆原图接入**：`game/src/hub/hub.courtyard-runtime.js` 替换无error处理的背景探针；`game/src/ui/card-zoom-photo-source.js` 替换旧原图探针，保留当前预览并提供原图重试。`card-zoom-controller.js` 同步释放接口，旧私有完成函数已从文件中清除。
3. **关键插图的晚失败仍能处理**：`page-visual-readiness-sharing.js` 在关键图准备时登记持续恢复。页面揭幕截止/取消不等于图失败，也不撤销当前挂载图的load/error与独立截止；原等待结束后才发生的错误仍有局部反馈。新来源不能被旧完成写入失败态。接入指南位图及信箱空态，未把普通长卡牌列表全部转为恢复按钮。
4. **公共返回快照扩展适配口**：`overlay-return-state.js` 增加可选 `readContext` / `applyContext`，允许页面提供稳定键下的分类、筛选、选择等普通值；应用顺序为上下文、展开、滚动、焦点，不保存旧DOM或写存档。
5. **设置返回保留位置**：`settings-navigation.js` 捕获分类与按分类键保存的阅读位置；`menu-settings.js` 在进入信箱/数据页时捕获当前快照，返回时重建对应分类并恢复展开/滚动，同时保留首次进入设置的退出状态，避免标题页进入设置后绕经子页就丢失原退出状态。返回检查同局/档位、当前页面与一次性消费；数据页刷新仍可返回。
6. **数据页返回减少一次冲突过渡**：源码发现 `menu-data.js` 先hideOverlay再同步openSettings，两套开合争用同一浮层；改为从设置进入时直接接回设置，仅独立打开的数据页执行关闭，旧页按钮加当前挂载守卫。
