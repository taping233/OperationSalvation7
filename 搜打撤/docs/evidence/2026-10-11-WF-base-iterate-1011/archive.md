# 归档室信息结构减法

2026-10-11。状态：信息结构与专属测试已调整，等待主代理实页复核。

归档室只负责成就、收藏进度、卡背和故事。当前人物的招式阅读与培养只在队员页处理，避免同一角色出现两套卡牌库和不同培养入口。

## 本轮修改

- 原“角色档案”改为“收藏进度”：只展示不同卡牌收集总量、阶段条件、奖励与领取状态。
- 移除归档室人物目录、角色卡牌墙、卡牌翻阅/放大绑定和逐人物仓库跳转。
- 收藏概览保留唯一“前往队员培养”入口，传递 `hubTab=classes/group=people/section=profile`。主代理还需在父导航消费 section，保证之前查看外观或招式后仍抵达培养。页面不复制队员招式与培养布局。
- 旧 `view=classes` 保持可用，内容映射为收藏进度，父模块既有路由白名单无需改变。
- `claimColl/claimAch/selBack` 仍由父模块绑定；成就筛选、卡背解锁目标定位和故事异步加载契约保持。
- 删除专属 CSS 中已无对应内容的角色目录和卡牌墙规则。只调整归档作用域，按钮新规范由主代理后续统一。

## 验证边界

专属测试覆盖四分类切换、旧 classes 路由兼容、总收藏进度与阶段领取条件、已领取状态、唯一队员入口、无重复卡牌库、当前档成就、锁定卡背与解锁目标、切档浏览复位、未记录故事禁用。读取和导航不写存档。

7/7 专属测试、专属模块与测试 ESLint、CSS 解析通过；父导航培养 section 的真实回流仍待主代理接入与实页验证。
