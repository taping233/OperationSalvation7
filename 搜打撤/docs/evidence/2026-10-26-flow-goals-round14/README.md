## 实施

- `hub.warehouse.js`：完整同步新增、耗尽、数量与保护状态，按稳定堆键复用旧卡格及卡图，仅为新增堆构造单个正式卡格。类型/品质筛选沿同一生成逻辑原位补选项，保留选值、输入焦点、查询与滚动。普通仓库与待复原提供当前筛选下的`getItems/getIndex/index/onBrowse`，翻卡每次重读唯一库存堆。
- `game.hub.pages.js`：普通仓库详情接入既有大卡浏览，翻卡按当前堆重建说明和动作。保护、转化、材料、孵化与拆包统一使用现有writeDetail等待及完整refreshInventory；成功有余量继续详情，耗尽后回邻近卡格。保护/转化/孵化保存结果与成就检查独立反馈。来源和详情归属分别维护，关闭详情后提交完成仍同步有效仓库。退出这些正常路径的强制renderHub重建，未提供刷新回调的既有调用保留fallback。
- `card-zoom-controller.js`与`ui.dom.types.d.ts`：增补可选实时索引、导航可用性、引用返回重建及`_refreshCardZoomBrowse`。库存变化后计数/上下边界/键盘沿实时列表，保存中暂停跨卡；说明引用返回时由原呈现者按当前库存重建操作，不复用旧详情闭包。新引用页维护自己的导航范围。
- `collection-view-art.js`：原卡图窗口在refresh时观察新加入的未构造卡格，远处新卡滚入视口仍沿同一绘图与图片恢复入口。

沿现有collection view、单卡格生成、大卡控制器、返回状态与懒构图接线，未新建库存/详情框架或样式系统。原有材料/待复原/交易等未提交增量保留。

## 老板统一验收入口

- 仓库筛选后打开大卡，点击上/下一张或左右键连续浏览；每张操作和数量对应当前卡。
- 多包连续拆开，新卡堆与类型/品质选项原位出现，列表滚动、筛选及详情保留；新增远处卡格滚入时正常补图。
- 连续保护、转化、单张/整堆使用，核对实际数量、经验、保护状态和资源；耗尽转向邻近可用卡格。
- 保存中尝试翻卡/说明引用，完成后恢复；主动关闭详情后，当前仓库同步本次结果。
- 打开卡牌说明引用，再返回来源卡，继续翻卡、保护或使用；当前堆已消失时沿现行有效库存处理。
