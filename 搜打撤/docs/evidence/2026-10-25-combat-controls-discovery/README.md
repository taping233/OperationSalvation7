## 技能输入与手牌交叠

`battle.aim.js`原先将技能按钮的`data-ui-tip`祖先同时视为说明阅读区；指针捕获后，松手事件仍以技能自身为目标，阅读判断会提前返回，留下未收尾的指向。现在仅对当前非跟手技能/药水的源控件排除该误判，实际指针落在状态或说明层时仍保留隔离；轻点沿原`btSlam`，拖动沿原选敌和结算入口。

`battle-equipment.css`将脚下的技能/装备横排改为人物左侧48px独立纵列，与立绘留18px间距，底部在生命条上方，限制最大高度并内部滚动，生命条不再被控件行撑高。人物头顶状态展示保留。此为实现交付，未实页确认遮挡已消失或技能可用。

## 发现卡池

`battle.discover-candidates.js`统一职业卡门：普通生成池直接剔除职业卡，不再允许宽松目录回调重新放行；明确职业池保留。`effect-steps.ctx.js`在共享池名词谓词内同样排除非职业池中的职业卡，覆盖注能、类型、费用、系列等入口；「灵能召唤」沿现有注能池获得统一修正，不改它的免注能效果。

`battle.discover-flow.js`将同一职业卡门应用于已缓存的生成候选，并在候选过滤后按原对象重新映射确认下标；已确认的非法候选不改发另一张。牌库底/储存卡选择保留已有实例。`battle.acquire-operation.domain.js`在叠加筛选时透传显式职业池标记，保留卡面明确声明的职业发现。
