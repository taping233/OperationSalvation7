# 奖励、商店与事件结算修复

本轮对照本地《杀戮尖塔2》反编译源码的奖励选择、商店购买和事件完成边界，修复项目既有流程的结算与恢复问题。实现完成后集中验收，结果在下方记录；未记录的检查不视为通过。

## 实现范围

| 模块 | 改动 |
| --- | --- |
| 共享保存边界 | `core/run-checkpoint.js` 统一同步保存的 false/异常处理；保留旧端口无返回值兼容。保存失败不会自动回滚已经完成的局内领取或成交 |
| 奖励 | 发卡动作防同步重入；保存失败可原位重试。普通节点完成时先准备幂等节点消耗，再保存无待领奖的稳定状态，成功后才释放页面与回调；失败保留原奖励、已领事实及重试入口。战斗奖励继续由原胜利事务处理 |
| 资源二选一 | 领取调用防重入，页面同时核对当前对局与奖励记录身份；保存失败明确提示且退出留页，重试只保存、不重发卡 |
| 商店 | 购买/出售核对原商品、报价、owned/UID 和当前页面；核心交易防重入。保存失败保留同次完整内存成交并显示未保存，离店失败留页；委托优惠应用失败回退未提交草稿，保留已掷定结果 |
| 事件 | 发卡预留、防重入、完成事实及保存重试；骰子结果在失败后保留，过期回调失效。重编确认再次核对源卡身份、牌区及候选条件；最终奖励承接失败保留原选择及原付费次数 |
| 验收入口 | 复用 `feedback-1018-review`，追加内存奖励完成、商店、军需和救护场景按钮。构造初始数据后使用真实控制器与 UI 输入；默认不占用或写入玩家档位 |

引用的源码为 `D:/素材/杀戮尖塔2源码/sts2-decompiled/` 中 `Reward.cs`、`MerchantEntry.cs` 和 `EventModel.cs`；采用其成功/失败与单次收尾的划分，不复制游戏内容、数值或完整架构。
