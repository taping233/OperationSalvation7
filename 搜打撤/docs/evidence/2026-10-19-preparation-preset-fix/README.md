# 2026-10-19 整备预设容量与选择应用修复

老板授权修复首局/整备审查的前两项：预设容量计算，以及人物、宠物与实际应用流程不一致。首次目标显示条件不在本轮范围。

## 当前行为

- 预设与主整备共用 `departureSummary` 和 `core/card-capacity.js` 的叠放规则：装备每张一格，其余每三张一格；实际初始牌数量、同名合堆、宠物增加或转换起始牌均参与计算。推荐装配预览透传同一批输入。
- 容量摘要显示已用/可用格数，超容时禁用应用并说明原因；错误提示独立换行。
- 应用预设同时传递选定人物、宠物和卡牌。先预选人物供确认，再进入整备；宠物走已有 `Base.setPet` 保存入口。保存失败保留原携带选择和预设页，允许重试。
- 未指定人物/宠物的旧预设继续使用原有默认选择；换档不会沿用上一档预设。文案已改为先确认人物、再整备出发。

1. 构造白塔、机器人、3张草甲的预设。机器人使初始攻击为7张，占3格，加3件装备共6格；基地5格时显示6/5、容量不足，应用按钮禁用。
