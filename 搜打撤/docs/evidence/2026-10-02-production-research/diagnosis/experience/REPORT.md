视觉上优先处理一项本轮已确认的问题：物资搜刮窗顶部口袋条挡住“选一件，继续前行。”标题中后段。整备小卡效果的阅读压力仍是历史画面线索。保留现有地图“下一步路线＋闸门方向＋资源前景”组合、战斗实算意图、跨页金色主按钮；这些已经解决了真实决策问题，不需要整体推翻。

## E01 — 专属动作音效接线缺口：应首先收敛

**S＋P 已证。** `game/src/main.js:16` 导入 sound.js。现行 `sound.js:183/272/336` 定义三个可播放注册来源，`:417-419` 查 SFX，未知项直接返回；`sound.bank.js:14` 的 SampleSfxBank 有现成完整库，但已有全 src 审计的 `bankIntegrationReferences` 为空。注册表探针真实求值得到 prepReady、deployStart、extractionSuccess、searchReveal、storyComplete、attackArrow 均未注册，而 card、victory、phase 已注册。

具体调用包括 `game.hub.depart.js:333/349` 整备/出发、`game.run.scenes.js:190/196` 搜寻、`game.run.shop.js:379/407/424` 买卖、`game.run.altar.js:735/796` 撤离确认/成功。动态分支另见 `battle.lifecycle.js:135` bossVictory（普通 victory 已接）、`:240` bossReveal/battleEnter，`game.run.flow.js:402` storyComplete/eventClue，`battle.vfx.js:315-324` 元素伤害 cue 优先于通用 hit；其中 attackArrow 已由探针证实未注册。故不能只用 23 个字面调用点描述全部缺口，也不能将其误写成“20 种按钮没有声音”。

**反证/边界：** `sound.js:563-565` 全局按钮 pointerdown 播 click；hit/hurt/kill/victory/phase 等也在当前注册表，战斗进入和结束仍调用 music（`battle.lifecycle.js:152/239`）。可以有通用点击、通用战斗反馈、背景乐。不能判游戏完全无声，也不能从此断定某次实战总伤害声全丢：同次反馈可能另有其他 cue，未本轮操作或录音。

**最小后续验法：** 先用纯模块测试核关键状态事件到唯一运行时注册表的解析，不依赖素材库名称；再在获准的当前内置浏览器中正常操作一段整备→出发→搜寻/第一战，记录具体 cue、注册命中和可听结果。撤离/首脑/剧情分支单独验，不通过改存档伪造覆盖。本轮未授权实施。

## E02 — 场景声景钩子与当前公开 API 脱节

**S＋P 已证。** `ui/overlay.js:141/192` 调 `SDT.Sound.scene?.(...)`，`game.run.altar.js:46` 火堆也调此方法；`sound.js:584-595` 导出 Sound API 没有 scene，探针 `sceneExported:false`。optional chaining 会跳过，不能将“调用没报错”视为场景环境音接通。不要与 `sfx('scene')` 混淆：后者是 `sound.js:303` 的另一种单次音效。

**反证/边界：** `sound.js:437` 仍把标题、地图、战斗模式交给 WinterSoundscape，`battle.lifecycle.js:219` 有 setBoss，敌方阶段有压力调节。已存在模式/压力声景机制，缺的是 overlay 这条场景化钩子，不是全部环境声音。未试听，不能评价是否空、刺耳、重复或混音失衡。

**最小后续验法：** 先约定 overlay 场景 cue 与 board/battle 模式是否需要分层，再做公开 API 契约测试及火堆进入/退出的当前浏览器录音对照。此项可与 E01 共用一次音频入口收敛，不先新增第二套系统。
