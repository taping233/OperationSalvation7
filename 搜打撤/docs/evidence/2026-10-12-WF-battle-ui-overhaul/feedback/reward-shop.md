# 奖励与商店界面定向记录

2026-10-12。依 [参考板](../../2026-10-12-WF-ark-ui-reference-1012/reference-board.md) 第 5、6、8、9 节与图版 05、10、11 改造。来源的卡牌/价格/容量/金币规则仍由现有运行态判定。

- 宝箱奖励：卡牌列表点击只选择，右侧显示卡名、类别、稀有度、完整规则、估值和实际去向；详情动作确认收取。三选一只收一张，其他候选标为散落；满包提供整理背包入口，返回保留选中项和已收标记。批量逐张调用原 `grantCard`，失败按原规则散落，并以已入包/已散落原位结果展示。剩余卡牌离开前列出对象和数量，返回继续领取不结算；金币在原收取/离开动作支付一次。
- 商店：保留商人身份与货架，将同位名称/图像/价格放在中间列表；点击商品只刷新右侧单层详情，显示完整规则、价格、余额、容量去向和购买动作。现有购买校验、扣币、入包、存档接口不变；成交后货位与余额立即反映，原飞行只说明去向。
- 交互守卫：隐藏动作直接调用也不能以普通批量收取三选一，或绕过剩余离开确认；失败不标已收、售出。

定向验证：`npx vitest run tests/chest-click-flow.test.js tests/sys03-loot-shop-txn.test.js tests/pet-egg-chest.test.js tests/shop-sell-stored-guard.test.js tests/node-retrigger.test.js --reporter=dot`，5 文件 31 测试通过；目标 JS 的 ESLint、语法检查及目标 `git diff --check` 通过。测试覆盖满包时详情按钮通过全局背包入口触发、挂起/恢复后保留选中项，且入口按钮本身未被禁用。实际 `game.boot.js` 将该按钮接到 `showBackpack()`；后者在已选角色的远征 `modal` 状态允许打开，并用 `Chests.suspend/resume` 返回奖励。主会话仍需在当前内置窗口实页核对奖励详情/滚动/整理返回，以及商店三列与购买后静态状态。

节点回归脚本的自动点击顺序已加入新查看和继续动作；主会话将原页面正文提示断言改为旧节点不再出现领取输入，同时保留收益数量、visited 和 idle 断言。
