## 实施

现役恢复药水`tt3-blue-potion`为heal+energy，地图执行器只接治疗。旧可用性按完整操作数组判纯治疗，导致地图满血时仍显示可用；混合治疗/复原全部无效时也缺少统一拒绝。

- `bag-item-effects.js`收拢`bagRecoveryStatus`与`isRestorableBagEntry`，供预览和逐步执行共同读取治疗数值/缺血、有效复原记录/count及容量；实际步骤在前序效果完成后再检查。前序已经消费时，后续失败提示保持实际消费事实。
- `game.bag.rules.js`按地图生效操作聚合资格，治疗/复原任一有效即可使用，全部无效返回相应原因；复原沿既有`restorationCapacityReason`和`canReplaceBagCard`，考虑消耗源牌后是否真正释放格子。随机获得、发现与未知旧规则继续由原执行者判断。
- `bag-legacy-use.js`实际`useOwnedCard`入口实时重算同一状态，原详情保留，阻止无效使用；纯复原失败继续原Promise返回形态。既有事务、随机计划、兼容用途与资源逻辑保留。
- `game.bag.js`在已有详情hint接`mapBagUseHint(card)`，仅混合地图/战斗操作显示当前地图生效部分，如“地图使用：回复生命。”；纯效果提示、完整规则正文、角标与按钮既有映射保持。`game.bag.view2.js`无需修改。

未调整卡牌定义、平衡或效果顺序，未引入新使用框架；原完整数组的纯效果判断改由实际地图部分和共同恢复状态维护。

- 满血/缺血时查看恢复药水，核对角标、按钮、当前用途与实际使用结果。
