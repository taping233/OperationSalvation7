- `game.reward-organizer.js`：库存端口检查当前会话并透传同步/异步结果；由整理页在 owner 完成保存后更新展示。

## 丢弃与合成的完整流程

`bag-inventory-actions.js` 连接现有纯库存命令、保存、失败恢复与成功收据，替代 `game.bag.js` 中分散的先反馈再保存实现。丢弃保存失败放回原条目；合成保存失败撤回本次产物、恢复同一材料条目与碎片，保留其他背包变更。等待期间阻止本入口重复操作。同步保存继续同步返回，异步保存返回Promise。

安全格、容器、丢弃/合成及背包发现复用现有 `core/run-checkpoint.js` 的统一保存结果解释，退出各自重复的同步/异步保存判定。新增 `completeRunCheckpoint` 承接保存结果并保留同步完成；既有 `saveRunCheckpoint` 继续提供Promise形式。原业务所有者继续负责本次修改恢复或结算后的保存重试。

丢弃确认改用现有 `confirmAction`；取消保留原背包/详情，确认失败可在公共确认框重试，成功后再关详情和刷新。合成成功后再退出详情；失败提示使用公共操作反馈，原操作可重试。旧私有丢弃确认页、`confirmDragDiscard`/`cancelDragDiscard`接线及独立先报成功分支已退出。

老板统一验收入口：详情丢弃的取消/确认/保存失败，拖出背包后的丢弃确认，奖励满包整理的安全格移入/丢弃/领取/返回，通行证两种合成的保存失败与重试；再看发现确认、事件确认、容器存取及焦点样式。
