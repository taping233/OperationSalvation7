## 集成审查补修：覆盖保全与清槽交错

保全 Base/Run 原串及顺序删除两主键现共用一次同槽 Web Lock 租约，不再在保全后释放锁并重新排队删除。Base 新增仅接受当前有效租约的 `_wipeLocked` 窄口；Run 复用 `_removeLocked`。仍分别报告 Run 删除失败和 Base 删除失败，不把顺序删除写成跨键原子提交。

清槽成功后记录基地空槽观察。覆盖流程随后初始化时，如果另一标签已创建任何 Base 或 Run 主串，`Base.reset` 会拒绝；不会把刚创建的 Run 与新默认基地混配。

新增 `tests/save-slot-lock-interleaving.test.js` 四项：保全期间排队的新写入在清槽后保留；先排队的新档保全最新原串；任一保全失败不删除主档；清槽后仅新建 Run 也会阻断后续初始化。连同整档删除反馈、基地锁、存储读失败和存档整改组，`npm run test:target` 共 5 文件、48 项通过。Runtime 全域类型检查与此次源码/新测试定向 ESLint 均通过。没有修改公共 UI 或读取真实玩家存档。
