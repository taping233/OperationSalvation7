# 卡库搜索与稀有度分配优化

2026-10-25，老板要求继续优化性能；沿本会话要求，不运行测试、lint、类型检查、实页或构建。

本轮有两项源码依据明确的修改：

- `createCollectionModel.replace` 原对所有保留卡牌立即执行 `searchOf`，照相馆回调会拼接名称、原描述及 `displayCardDescription` 生成的展示说明。现替换数据时只重置搜索WeakMap；`project` 有非空查询时，先按现有分类、人物、稀有度条件过滤，再按需生成候选的搜索文本。同一数据代的文本继续复用；替换数据同时清掉搜索索引与投影结果。不搜索时避免整库搜索说明生成，但首次实际搜索仍承担尚未生成的候选文本成本，未将此描述为后台预建或零耗时。
- `rarityOf` 原每次调用都创建防循环Set，即使普通卡直接返回稀有度。现只有进入衍生来源循环时才创建；能力卡棱彩优先、来源缺失和循环来源回退沿原判定。调用方包括卡面渲染、照相馆排序和筛选，不缓存可变卡牌稀有度。

源码属地：`game/src/ui/collection-view.js`、`game/src/cards/card-rarity.js`；同步 `docs/performance.md`，保留其他既有增量。现行 `createCollectionModel` 游戏调用方为照相馆，已回读其替换、筛选与分类计数入口。
