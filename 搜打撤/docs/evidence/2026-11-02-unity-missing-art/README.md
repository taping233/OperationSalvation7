# Unity 编辑器缺图与图片交付

2026-11-02，老板说明问题来自他人打开工程后发来的视频，并提供标题页截图：中央背景缺失，左上标题标志为白色矩形。老板明确图片应包含在工程本身，因此本轮修正工程的图片交付规则，不生成单独补齐包，不加入运行时下载或替代图片流程。

## 原因与证据边界

本机正式图片文件齐全。此前源码快照把所有超过1,000,000字节的文件排除，导致GitHub的`e40115e9`与`b512cf4`未包含189张现役PNG，共278,386,947字节，只有相应`.meta`。这些图包括卡面、人物、节点、标题页和部分界面图片；不同页面按需加载时缺失，看起来像随机缺图。

截图对应的两个正式入口为：`CurrentHomeAssets.DefaultWallpaper`加载`Assets/Resources/Art/CurrentHome/wu-bass.png`（2,414,222字节），`TitleScreen`的品牌区加载`Assets/Resources/Art/CurrentHome/wordmark.png`（1,559,243字节）。它们在本机存在，在上述两个Git提交中缺失，且均列于旧恢复清单。无Sprite的Unity Image会绘制白色矩形，表现与截图一致。尚未取得对方工程文件或Console日志，因此不声称已在对方机器复现；已确认旧源码直接下载后确实缺这些图片。

静态排查同时确认：当前759个图片映射指向695张有效PNG，最近六张新卡的12个大小图齐全；无资源名大小写、同名键或meta/GUID缺口。5角色264张独立帧的文件尺寸、NPOT和纹理上限与manifest相符。未发现普通卡面或场景图片被错误卸载的正式调用路径。本轮没有据此改动缓存、画质、图像像素、尺寸或GUID。

## 修改

`SoudacheUnity/_planning/github-sync-1101/export_manifest.py`与`audit_inventory.py`允许正式`Assets/`图片直接进入交付，不受通用1MB上限排除。`filter_plan.py`沿同一候选规则。旧清单里的67项退役媒体及对应meta继续一起排除，本机文件保留；不会把其中17张旧图片重新纳入。

新交付清单必须包含原189张现役大图，正式图片必须带原`.meta`，缺项时报告具体路径。清单检查也拒绝继续使用遗漏图片的旧列表。大文件证据、临时构建、Library、日志、音频与字体仍沿原边界，不扩大到所有二进制。

现行入口为`export_manifest.py --output <本批清单>`；历史发布收据、旧恢复清单和固定批次的临时复制脚本保持历史身份，不能用它们的旧1MB过滤器复制新版工程。当前说明已同步`SoudacheUnity/GITHUB-SOURCE.md`、`MIGRATION.md`和`_planning/github-sync-1101/README.md`。

## 状态

本轮只生成新的交付候选清单并核对图片覆盖，不运行Unity、编译、游戏测试或实际窗口验收；不生成zip，不复制或重新打包游戏，不暂存、提交或推送。图片本身已经在本机Unity工程原路径中，修改的是导致对外交付遗漏图片的规则。

本轮实际执行`export_manifest.py --output <本目录>/export-manifest.json`成功退出0：4000个交付候选文件，共524,261,884字节；其中1389张正式Assets图片及原meta全部收录。原遗漏189张现役PNG及其meta未纳入项为0，截图中的`wordmark.png`与`wu-bass.png`均已列入。新清单为724,997字节，保存在本目录；未覆盖任何历史发布收据。这是交付清单结果，不是运行测试或Git上传结果。

远端仍是原先的已发布版本，189张图片尚未上传；本轮交付清单不能当作已同步GitHub的证明。前两轮新卡及战斗源码仍保留本地未提交状态，运行验收边界不变。
