# 当前页面与取证范围

本页只说明本轮实际看到与操作的现状。尚未实施的新方案不能引用这些截图作为“新效果通过”。

## 来源与输入

- 平台：Codex 内置浏览器；全程未使用外部浏览器、CDP或headless。
- 第一阶段：`http://127.0.0.1:5200/` 共享工作区。Vite日志确认其他源码更新造成整页重载，之后停止本会话创建的5200服务，改用冻结副本。
- 第二阶段：`http://127.0.0.1:5318/`；源码/CSS/数据冻结，素材只读复用。输入文件清单见 [runtime-snapshot.json](runtime-snapshot.json)。
- 未设置viewport覆盖。截图对应当时窗口，主线与独立测试页的自然尺寸不同；不将这些截图当作主动多尺寸验收。完整尺寸/原始字节指纹见 [截图清单](screens/manifest.json)。
- 使用真实控件点击、Tab、ArrowRight；开发者节点按钮构造不占档位、不写正式存档的测试局。没有通过页面求值写入战斗状态。
- 页面求值仅用于读取DOM、计算样式和布局。一次尝试用rAF读取飞行中间帧因只读环境未暴露该函数失败，未重复领取；因此不以本轮记录证明飞行轨迹/帧率。

## 由现状直接决定的协调项

1. 奖励页的“其他可领卡”与“已领卡”不能采用同一种压暗。当前已领卡确实会变暗并留位，新的焦点效果不得把它提亮成可领取。
2. 牌库中的卡名、价值、正文已经存在，再加P3式名称条会重复，且可能占用卡底信息区；此参考在本项目应舍弃。
3. 拾牌层已经逐帧接管`.bt-card`。公共卡片动画不能扩成所有`.bt-card`，否则跟手与回位会争transform。
4. 设置与背包已经有移动选中底板。改造应整理现行实现，不能再铺第二个背景层。
5. 常驻状态栏的多状态画面本轮未出现，B组实施前需要补0/1/4/5/8状态及两位数层数的真实展示，不能据空栏宣布布局合格。

## 参考包的证据边界

两份DLL均通过本机ILSpy静态反编译，未加载执行模组。反编译逻辑足以核对函数、时长、公式、节点关系和事件条件；不能证明实际帧率、所有游戏版本兼容性或每段动画的真实观感。部分P3牌堆动画按固定逐帧步长变化，方案明确没有把它们当成帧率无关的底座。
