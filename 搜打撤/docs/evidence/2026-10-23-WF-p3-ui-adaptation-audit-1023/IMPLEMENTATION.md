本轮交付为执行方案、代码摘录与现状证据。文中的参数是实施起点，尚未作为新效果实装通过。实施后的画面与交互必须按末尾场景验收。2026-10-23 复审后的取舍、当前源码变化与核验结果见 [复审记录](REVIEW.md)。

## 现状决定了哪些参考不能照搬

| 对象 | 已核实的当前行为 | 转译结论 |
| --- | --- | --- |
| 设置分类、背包区域与筛选 | `.selection-state-plate` 已跟随选择移动；不是缺一套动画 | 整理既有底板和控件颜色职责；不再额外铺第二块选中底色 |
| 奖励卡 | 卡面按钮负责“放大查看”，下方按钮负责“收下”；当前三张可以全领；领取后原卡留位并变为“已收下” | 浏览焦点不等于领取选择；不能用 P3 的大幅压暗把其他可领卡表现成禁用 |

| 卡片边框 | 卡面图已经承担纸边和稀有度；全局样式又清除宿主 outline/border/shadow；发现页另叠独立选中框和标签 | 这组责任本身值得整理：卡面身份、键盘焦点、选择标记分开，减少互相覆盖 |
| 状态栏 | 玩家显示全名；敌方/随从超过 4 个状态才统一切紧凑；现有词条说明支持多种输入与避边 | 先稳定常驻栏，再改说明表面与更新方式；参考的完整状态列表只用于新增明确入口 |
| 大图、背包、战斗二级层 | 已有输入所有权、inert、返回焦点、来源有效性与各自关闭语义 | 不能照抄参考中的独立全屏点击层，否则会抢已有 Esc、目标选择或返回链 |

## 第一组：按钮、设置行与分类选择

### A01 设置行高亮：在既有行上改，不另挂逐帧控制器

- **项目入口**：`game/css/settings-navigation.css` 的 `.chk:hover`、`:has(input:focus-visible)`、`:has(input:checked)`，见 [P04](project-code.md#p04)；页面结构在 `game/src/ui/menu-settings.js`。
- **参考**：`SettingsSkin` 的整行鼠标/键盘高亮，100ms、文字反色、装饰偏移8，见 [R08](reference-code.md#r08)。
- **改法**：将“正在阅读此行”与“开关已开启”分开。hover/focus-within 用同一浅色底板与较亮标题；开启状态保留在开关本体。先沿现有冬日色板做 120–160ms 颜色过渡。
- **协调**：旧 `page-settings.css` 与 `settings-navigation.css` 若同时命中，在当前 `.settings-tabbed` 范围内合并责任。移除该范围内重复阴影/重复轨道；不再在后面新增一层更高优先级覆盖。范围外页面另行核对，不能整文件删除。
- **验收**：Tab 到开关、拖动音量、鼠标移出开启行，仍能分别辨认焦点、悬停与开启；行高和控件位置保持稳定。

### A02 分类底板：整理已选与悬停的层级

- **项目入口**：`installSelectionStateMotion`、`selection-state-motion.css`、设置 `.settings-tab` 与背包 `.bag-rz/.bag-pill`，见 [P02](project-code.md#p02)。
- **参考**：当前曲目实底反色、其他项目仅悬停加底色，见 [R10](reference-code.md#r10)。
- **改法**：选中填充由一块移动底板承担，字重、文字和小标记可配合表达选择；未选中 hover 用较弱的短反馈。可调底板材质、边线和颜色，但保留一个可见选中来源。快速 A→B→C 切换从当前位置继续。控制器未挂载、挂载前和减少动态时，仍由同一业务状态显示完整静态选择。
- **协调**：现有 CSS 已使被底板接管的选项背景透明，新增设计要改这一套规则；不要再让 `.on`、`aria-selected`、伪元素各画一块底板。若现有效果显得迟滞，先比较接续时长，P01 只保证位置续接，不证明速度连续。
- **验收**：快速连续切换、重选当前分类、从空分类返回、横向尺寸变化后底板不闪回原点、不滞留双选中。

### A03 小图标的视觉层与点击盒分离

- **项目入口**：局内顶栏 `configureRunTopBar/installRunTopBar` 见 [P27](project-code.md#p27)，菜单图标在现行菜单组件；公共目标层见 [P01](project-code.md#p01)。
- **参考**：音乐盒52×52点击盒不变，内部图形向1.08平滑靠近，见 [R09](reference-code.md#r09)。
- **改法**：仅在设置/返回/整理等明确的小图标按钮上，操作内部 `.ic` 或自有图形层。hover 可从1→1.04起步，按下短暂回落；保持按钮布局盒不动。
- **协调**：返回箭头已有专用画法与页面动作；已完成的专用图形按I01保留，重复占位图按I01替换，不额外添加按钮声。滑块、复选开关、结束回合长按按钮、卡面宿主不进入此选择器。
- **验收**：指针停在按钮边缘不会反复进出；按住移出再松开不触发；禁用和 reduced-motion 下保留静态可读状态。

### A04 按压、开启、禁用、忙碌采用同一组件的状态规则

- **项目入口**：设置 `.mini-btn/.ov-btn:active`、`menu-settings.js` 的原生按钮与 switch，见 [P04](project-code.md#p04)、[P23](project-code.md#p23)。
- **参考**：普通/hover/pressed/hover_pressed/focus 使用同样内边距；当前项目反色且尺寸不变，见 R08、R10。
- **改法**：用背景/内阴影表达按下；稳定标签宽度和内边距。禁用保留文字对比；原因放在邻近提示或可访问说明里，不能只依靠无法聚焦的disabled按钮hover。忙碌文案变化预留足够按钮宽度。
- **协调**：设置行已有1px下移时，不再叠整行缩放；开关圆点的22px位移继续由 switch 样式负责，行高亮不写其 transform。音频“开启偏好”与“实际播放/静音状态”由 P23 的同一状态源刷新。
- **验收**：音量从0到100、音乐不可播放/重试、按钮在确认后进入忙碌时，布局不跳，标签与当前状态不矛盾。

## 第二组：卡片选择、阅读与领取

### C01 发现选择：合并多重框，只留清楚的选择语言

- **项目入口**：`bindDiscoverySelection` 的 `paint/select/confirm/cancel`；`discovery-selection.css` 的独立frame、mark、outline、shadow，见 [P05](project-code.md#p05)、[P06](project-code.md#p06)。
- **参考**：参考牌堆用当前对象前置、轻位移与背景主次表达焦点，见 [R06](reference-code.md#r06)。
- **改法**：保留独立“✓ 已选”标记；将当前多层outline、内框、外光合并为一种克制的宿主强调。卡面自身稀有度和职业框继续表达身份。业务已选靠标记/文字表达，键盘focus-visible放在实际可聚焦宿主，不能在清框时一起删掉；已选B时焦点可独立停在A。若选择框改形，在本组件内同步替换旧frame规则。
- **协调**：P11全局清框与P06局部加框当前存在责任交叉，应明确“卡面边缘”和“选择标记”两个层，不能再加 `!important` 抢回外框。逻辑仍是先选中、再确认；检查大图不能变成确认。
- **验收**：鼠标经过A→选择B→查看B→返回→取消/重新选择C；已选标记、确认按钮与 `aria-pressed` 一致，取消不支付、不领取。

### C02 浏览焦点与业务选择分开，不统一套“已选”

- **项目入口**：非战斗卡的 `active` 当前合并 pointer/focus/aria-selected，见 [P03](project-code.md#p03)；奖励结构见 [P25](project-code.md#p25)。
- **参考**：StatusButton 的hover与展开是独立进度，见 [R01](reference-code.md#r01)。
- **改法**：在各现有调用方明确状态语义：奖励=查看焦点/待领/已领；发现=未选/已选/提交中；背包=阅读焦点/拖动；牌库=只读焦点；手牌=阅读/拾起/目标待选。共享动作可以相同，业务标记不混用。
- **协调**：不要新增全局“所有 `.bt-card` 都可选”规则。P03继续限定真实消费者，战斗和发现通过自己的责任入口接入；`aria-pressed` 与 `aria-selected` 按控件原语义维护。
- **验收**：奖励页移到下一张仅改变阅读焦点，不出现已领取/已选；发现页切焦点不偷偷换业务选择；卡牌大图中的按钮不被外层选项捕获。

### C03 战斗手牌动效重整：拾牌控制器是唯一姿态所有者

- **项目入口**：`battle.aim.js` 的 `startAim/applyPose/stepMotionFrame/returning/cancelAim`；`battle-stage.css`阅读/已选规则，见 [P07](project-code.md#p07)、[P10](project-code.md#p10)。
- **参考**：R06的同一progress驱动位移、缩放、角度，以及中途反向返回。
- **改法**：如要调整选牌手感，直接整理现有静止→阅读→拾起→跟手→回位的目标与优先级；不要给同一 `.bt-card` 再套一次 target-motion。统一从当前姿态接续，选中标记不另写transform。
- **协调**：当前`.aim-lift`关闭CSS transition，JS逐帧写transform；公共卡片控制器也明确排除手牌。若认为旧阅读/已选规则不合理，在这一条链内改写并移除被替代规则，保留提交时取牌位置的接口。
- **验收**：快速跨牌、取消后立即再拿起、无效目标回位、拖拽中窗口失焦、费用变化重绘、连点不能双出；全程只出现一张拿起副本。

### C04 固定命中与文字阅读：不复制参考卡的26%放大

- **项目入口**：`createHandHitController/resolveHandHit/readingAccessBands`，见 [P08](project-code.md#p08)。
- **参考**：P3牌堆的26%放大会同时缩放其Hitbox；音乐盒则分离点击盒与内部视觉，见 R07、R09。
- **改法**：普通网格轻抬/放大先从已有1.02附近调；战斗静态点击区域继续跟布局槽位，不能跟抬起后的形状重新吸附。正文和词条保留原生阅读行为。
- **协调**：P08把真实按钮和 `.hsc-desc` 从出牌路径排除，不能为了整卡点击顺滑而吞掉它们。首次拿起、点击确认、拖出取消分别沿原输入状态机处理。
- **验收**：卡片重叠边界停住不颤动；选中文本、点击词条/详情不会出牌；触屏不依赖hover；同一pointer最多提交一次。

### C05 奖励页：强调当前卡，不把其余可领取卡变成禁用

### I01 同图多义与缺省回退必须拆开登记

- **项目入口**：`icons-bitmap.js` 的NAMES、ALIAS、MAP、TYPE_ART，见 [P24](project-code.md#p24)；具体引用见 [图标记录](ICON-REPLACEMENT.md)。
- **老板新增要求**：剩余牌库样本及同类重复占位图标后续全部重设计。不得只替换一处或只改一个全局键。
- **改法**：先区分“同一语义合理共用”“不同功能误共用”“未知键回退”“字符映射丢失原义”。查同图多键，也查同键多义；以用途表确定新语义键。未知拼写修调用，不为每个错误键画图；字符有原义则在明确的业务调用处改成显式键，避免全局字符替换再次压成一图。
- **协调**：已知chart→archive、info→scroll是显式临时语义别名；cards还被人物卡池、收购台、锦囊、卡背奖励等共用。控件、地图节点、卡类型图标承担不同尺寸和语义，不能一张新图再次包办。
- **验收**：每个被替代引用都有新键和实页；字符标记、函数、数据动态键、Canvas路径与失败回退均核对；未知键不能静默冒充另一个正常功能。
