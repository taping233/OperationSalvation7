# 重复占位图标重设计清单

老板已授权后续替换全游戏同类重复占位图标，按实际用途重设计。2026-10-23 复审后，清单同时覆盖“多个键同图”和“一个键多义”；本轮只修订清单，尚未绘制或替换。主方案见 [I01与实施分级](IMPLEMENTATION.md)。

## 范围与盘点口径

资源盘点为61张位图文件（60 PNG＋1 WebP）；`NAMES`注册61个键，altar另走现有手绘WebP。资源数、注册键数、页面用途数是三种口径。PNG中30个键形成11组组内RGBA像素完全相同的图；本次重算仍一致。

11组不是全部问题的边界。crystal既表示冰冻又表示注能，question还被用于警告、搜索、无穷和固定标记，单靠图片去重查不出这些语义冲突。反过来，同一“背包”在标题、按钮和日志出现可以合理共用，不必为每行日志另画一张。

本项完成标准是：可达的不同含义不再使用重复占位表达；同一含义形成稳定图形，按显示尺寸简化细节。未使用的资源只记录，无运行入口时不为凑数量绘图；不删除资产。

## 11组相同图片的处理方向

以下是用途方向，键名以实际调用为准；不是见英文文件名就立即各出一张图。

| 同图键 | 必须分开的含义与图形方向 |
| --- | --- |
| book / cards / notes / save / scroll | 卡牌叠片、装订书册、笔记页、存档、卷轴各有主轮廓；cards内部继续按下表分用途 |
| archive / folder / trash | 仓储箱、文件目录、丢弃容器；chart另设计统计图形，不再借仓储图 |
| arrow / exit / upload | 方向箭头、离开入口、托盘上行箭头；保留已完成的专用返回箭头 |
| bag / pocket / pouch | 随身背包、安全格、法师锦囊用不同闭合结构；安全格不能只有颜色差异 |
| broom / pen / tools | 清理、编辑、制作/工具分别用可辨认轮廓；同一工具类可在同义入口复用 |
| crystal / gem | 资源宝石与战斗机制拆开；注能、冰冻、免伤、宠物蛋、通行证碎片不再都画水晶 |
| door / home | 通道/离开与基地分开；地图已完成手绘通道不替换为控件小图 |
| helmet / plate / shield | 角色/能力、护甲值、装备分类/防护按真实含义拆分；先核对shield是否同时承担格挡与分类 |
| hourglass / mouse | 时间/持续回合与鼠标操作分开 |
| lantern / sparkles | 照明、一般提示、法术类别、觉醒/符文等用途拆开；提示不强行画成灯笼 |
| play / skip | 播放三角与跳过端线分开；无可达入口的键暂不制作 |

## 状态图标必须按机制核对

现行状态元数据是9个增益＋7个诅咒，见 [D12](review-current-code.md#d12)。同图问题之外，还存在runner同时表示潜行/闪避、sparkles同时表示免疫/宇宙形态等问题。下表为设计方向；已有图形若已清楚表达该机制，可保留并记同义复用，不为数量重画。

| 状态 | 当前键 | 新设计的辨识要点 |
| --- | --- | --- |
| 攻击强化 | swords | 武器＋强化标记，与普通攻击图同源但有明确增益语义 |
| 法术强化 | crystal | 法术核心＋强化标记，区别注能和冰冻 |
| 潜行 | runner | 遮蔽/隐匿轮廓，区别位移闪避 |
| 免疫伤害 | sparkles | 完整防护边界，区别数值减伤 |
| 减伤 | plate | 防护承受/削减标记，保留当前数值解释 |
| 闪避 | runner | 偏移轮廓/避让方向，次数与潜行回合分开 |
| 剑仙形态 | sword | 剑与形态标记，区别普通武器 |
| 满月形态 | wood | 满月，不能把内部natureForm历史键误画成树叶 |
| 宇宙形态 | sparkles | 轨道/天体，区别普通法术和免疫 |
| 流血 | blood | 血滴可沿用合格原型，不能仅以红色区分中毒 |
| 中毒 | skull | 毒性记号，区别死亡与消耗牌堆 |
| 冰冻 | crystal | 冰晶/雪花，区别宝石资源与法伤 |
| 沉默 | cross | 被阻断的声波/施法，区别一般关闭按钮 |
| 破甲 | tools | 破裂防护，区别制作工具与维修 |
| 禁疗 | heart | 心形＋阻断，区别可恢复生命 |
| 攻击降低 | arrow | 武器＋降低标记，区别导航箭头 |

状态图形、卡牌词条、单位说明和对应日志中的同义机制保持一致。元数据目前归 `combat.factory.js`，共享工作区有其他任务编辑该文件；本轮只读。后续实装按登记协调该入口，不能为图标整改覆盖其玩法变更。玩家的 `playerEffects`及敌方额外标记不在这16项内，继续沿动态来源盘点，不能漏掉或强塞入该枚举。

## 保留边界与实现入口

- `core/icons-bitmap.js` 的 `NAMES / ALIAS / MAP / TYPE_ART / url / img / rich / hydrate` 是主要接线入口。已明确用途的控件改用显式语义键；纯文本emoji的全局映射只保留通用含义。⚠、🔍、∞、📌不能继续全部压到question，雪花也不能默认等于通用水晶。
- 未知键当前回退question且写控制台诊断。拼写或遗漏注册应修调用/注册，不为错误键绘制新图，也不把它悄悄映射成另一个业务图标。
- coin当前走 `assets/ui/map-hud-1015/gold-is7-v2.webp`，altar走现有地图手绘；地图 `core/map-node-art.js` 优先现有原画/`drawMapNativeSymbol()`，才走 `renderer.icons.js`。资源路径复用、同一原画的不同尺寸、故障后备分别记录。已完成原画不因“重复出现”被重画。
- `renderCombatPiles()`目前用玩家所选卡背显示牌堆。这是有含义的复用；标题小图重设计不能覆盖玩家卡背，也不能新增当前玩法没有的弃牌区。
- 法伤HUD也使用crystal，见 `ui/battle-hud-info.js`及 [D13](review-current-code.md#d13)；法术强化、基础法伤、注能、冰冻需明确同族与不同义。
- `TYPE_ART`同时驱动卡类别：装备/能力/法术等不能只换某个页面标题，而让卡面与筛选仍保留旧占位。状态图标元数据的入口也要沿调用追踪。
- 保留现有图片URL与透明底接入能力；需要扩展格式时再改注册结构。已有代码原生箭头、音量双态、CSS图形分别核对，不把所有控件改成生成式位图。

## 视觉与接入约束

1. 先取一组牌堆、背包、安全格、冰冻、注能试样，在真实控件尺寸并排比较。采用本项目现行冷色/金属/玻璃界面相容的视觉重量，P3只借鉴反馈与层级，不整批套P3配色。
2. 必须靠轮廓区分关键含义；颜色只辅助。所有图统一光学中心与留白，做小尺寸简化。现有显示尺寸包含13–14px分类/词条、18–22px标题、以及60–76px空态/设施装饰；不能让一张细节密集大图机械缩小承担全部用途。
3. 颜色与状态由宿主控制。检查hover/focus/已选/禁用，以及现有opacity、saturate和filter；不能把光晕或已选颜色烘进每个图，再与按钮反馈叠两次。换图不改按钮尺寸、命中盒或卡片transform所有权。
4. 有文字标签的装饰图避免重复读出英文键；纯图标按钮保留明确中文可访问名称。加载失败时动作名称和可操作性仍存在，不能只剩空白图。
5. 新旧资源分批接入，相关标题、按钮、卡面和说明同批统一。注册、调用、动态数据键与字符映射一起核对；旧文件不删除。生成的art-manifest和发布资源去重别名按现行工具重建，不能手改生成文件或沿用旧构建的别名结果。
6. 普通/选中/禁用与暗浅背景在当前窗口实际页面核对。多个显示尺寸来自各控件本身，不要求额外改变浏览器窗口；不以源图放大预览代替实装验收。
