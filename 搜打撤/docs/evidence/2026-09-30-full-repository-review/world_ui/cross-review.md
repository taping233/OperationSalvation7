## R-HUB-01：预设应用后被清空

- 生产可达入口：`game.hub.depart.js:31` 的“下一局目标与两套预设”按钮 → `game.hub.js:219` 的 openPreparation → preparation feature。`preparation.view.js:19` 有“应用到整备”按钮，点击委托 `:61` 发出 `preset-apply` 与 presetId，未被隐藏/开发标记限制。
- 真实生产接线 `game.hub.js:55-56` 使用 `setDeployPick` 和 `openDepartPrep`，与根夹具注入一致。`game.hub.preparation.js:114-116` 先 applyPicks 后 openDeparture；`game.hub.depart.js:91` 无条件 `deployPick={}`，覆盖刚应用的选择。
- 合法初态：仓库 2 张普通稀有武术；预设请求该牌 2 张，人物/宠物均未选。previewDeployment 明确空人物/宠物可通过，普通牌不触职业禁带，1 种牌加初始攻击 2 格在16格以内。没有请求超库存、坏卡或禁止职业牌。
- 根证据实际 feature onIntent + 实际 depart setter/open 函数，虽 mount/buildModel 为夹具，但 UI 的相同 intent 路由和生产 navigation 源码确认一致。`actualPicks={}`、selectedBagCount=1 对应卡牌选择丢失；没有扣仓库牌的证据，不应夸成仓库损失。
- P2：整个预设应用功能稳定无效，玩家如未注意可空载出征；仍可手动整备，非存储不可恢复错误。

## R-BAG-01：整卡名移动超过安全格容量

- 公开输入不只 bridge：背包卡面 `inspectStack` → 卡牌特写“移入安全格”按钮，`game.bag.js:692-695` 直接调用 moveStackSafe。拖拽 `.card-slot` → `.safe-grid .bag-slot`，`game.bag.drag.js:58-69` 捕获 pointerdown，`:149-151` drop 调用同函数。
- `game.session.bag.js:26-50` 现行同名普通牌每3张分1格；9张普通武术占3个背包格，在默认16格内，安全格初始空、默认2格，故根夹具开始没有超容量。真实牌库任一可持有的普通武术可替代测试卡，故不是依赖任意非法容量字段。
- `game.bag.js:186` 按名字筛全部9张；`:188-193` 只在没有同名安全牌且当前已满时拒绝，不计算本次新增格数；`:200` 全部置safe。即使鼠标拖的是一个显示为×3的槽，动作仅传name，仍把同名全部9张移入。
- 根日志 safeUsed=3 > safeCap=2。安全格显示 `game.bag.js:589-606` 只循环到sCap，额外第三堆不显示但实例仍有safe标记；终局保护可能因此超过付费安全格上限，应沿终局命令确认具体保护后果。
- P2：合法公开输入突破保护容量并隐藏多余堆。根测试直接调 bagSlots 而未模拟pointer链，报告可写“调用实际移动函数，UI入口静态确认”，不宜称真实拖拽已验收。

## R-BAG-02：珍珠盒取出一次释放多格

- 生产入口 `game.bag.js:670-675` 珍珠盒卡面特写的“打开珍珠盒”按钮 → `:700` openPearlStore；存储页 `:427-432` 每个同名聚合行可点击 `pearlTake`。根测试实际 showBackpack、inspectStack、pearlStoreZoom、pearlTake 与该路径一致。
- 合法初态：1个珍珠盒（装备占1格，额外9资源格）、69张同名普通资源（3张/格占23格）、盒内9张另一个同名资源（不占格）。used=24、cap=16+9=25；盒内9张=1盒合法上限。资源可占扩容格，因此并未用非资源挤入珍珠盒限制区。测试的资源牌名称/ID是夹具，但类型与叠放规则不依赖该自定义ID。
- 69张单资源为合成容量夹具，未证明在特定正常种子一局就能收齐；同类缺陷也适用于任意已合法占24格的资源组合加盒内9张，不依赖这69张特定牌或RNG结果。没有把“合成合法状态”称为真实跑局获得状态。
- `storedStacks` 按name聚合整个盒内容，`:463-469` 只要求现有1空格，`:471` 解除全部同名stored标记；9张释放为3格，24→27，超25。root日志与源码一致。
- P2：存储操作突破背包格容量，重绘只显示cap个槽，可能有额外卡无法通过普通背包槽查看。不是牌删除；没有证据断言丢档。

## R-BAG-03：锦囊整叠存入越过3张

- 公开入口 `game.bag.js:671-675` 锦囊特写“打开锦囊” → `:701` openPouchStore；存放页 `:371-375` 非职业法术堆点击pouchPut。root调用真实showBackpack/inspectStack/pouchStoreZoom/pouchPut，源码支持玩家点击可达。
- 合法初态：锦囊1张、已存同名法术甲2张、未存法术乙3张；stored两张不占背包，锦囊+乙共2格，2≤3张锦囊限额。法术卡无cls，不触禁止职业筛选；UID各自唯一，未把同一实例复制到两个容器。
- `:386` 仅测当前stored().length>=3；`:387-389` 找到乙的3张堆后将3张全存，不加本次stack.count。2+3=5明确超过自身UI/注释的3张规则。
- P2：锦囊存储/隐藏牌量超过规则；是否进一步改变锦囊战斗释放策略属战斗分片，不需靠这类推断才能成立。
