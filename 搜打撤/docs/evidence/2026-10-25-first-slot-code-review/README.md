# 首次进入存档：代码层诊断

结论：进入基地路径把基地页面逻辑的首次装载、实际背景图片首次准备、部分存档迁移集中在点击档位之后。基地模块会缓存，因此首次进入与再次进入具有不同成本；尚无运行耗时数据，不能给出各环节占比或认定某一项耗时毫秒数。

## 已核实的首进成本

1. `game/src/hub/game.hub.js:36` 的 `loadHubModule()` 在第一次 `enterHub` 时才动态导入 `game.hub.runtime.js`；进入前只有菜单模块空闲预载，没有同等基地逻辑预载。Acorn静态依赖图以main启动入口和菜单页静态闭包为已加载基线，基地首次仍新增43个JS源码模块，共332736字节（约325KiB）。其中包含仓库、配置、交易、收藏和整备代码；进入基地首页也会解析/求值这些静态依赖。该数字是源码静态闭包，不是生产包体积、请求数或实测阻塞时长。CSS已由基地门面静态导入，不属于这43个JS的新增样式成本。
2. `game/src/game.boot.js:153` 的基地图片预热仍指向 `hub-wallpaper.webp`，实际首页 `game/src/hub/hub.home-v3.js:28` 使用 `base-operations-v5.webp`。现有预热不能覆盖当前首页图片准备；`game/src/ui/page-visual-ready.js:21` 在页面挂载后等待代表图片与全局字体就绪，默认最长1500ms。上限不是固定等待时间，实际影响待计时。
3. `game/src/ui/menu-slots.js:119` 起在页面加载前同步 `Base.use()`，继而等待仓库/口袋改名迁移与待写入完成。正常未改动存档已有缓存及跳过无变化写入逻辑，不应直接认定每次都会重写整档。`game/src/hub/meta.js:197` 对未结算收藏逐项调用 `collectPool().find()`，重复扫描全卡库；存在待迁移收藏时还会触发持久化。其影响受档案大小及迁移状态影响，不能解释所有正常档位的首进差异。

## 优先处理方向

优先把基地模块装载提前到选档页空闲阶段，并把图片预热改为当前实际背景；之后再按需要拆分非首页模块、复用收藏池查询。保留现有读写锁、迁移持久化和过场取消契约。
