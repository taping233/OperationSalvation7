## 统一样式规则草案

以下为可逆的实施起点，不是已经验证通过的数值。

1. 页面外壳保持现有场景、顶栏、七格底栏；不增加新的全屏蒙层，不动全局等比缩放
2. 房间主标题34、对象名32–42、主操作24–30、正文24、辅助标签22逻辑px；细微编号可更小，但不能承担必要操作说明
3. 区分三种表面：场景可完全展示；导航／分组可用 `.72–.82` 深玻璃；说明／数据／错误使用 `.90–.94` 深阅读底。不要为可读性继续叠加整页blur
4. 主文 `#f2f5f0`，次文 `#bccbd0`，青 `#9edce7` 表示可互动／当前选择，金 `#e2c891` 表示执行／确认，暖色表示缺额／危险；卡牌稀有度语义保留
5. 普通按钮圆角8–12px；同组开关用容器统一圆角，不同页面不要混入胶囊、斜切、直角三套同权控件；资源胶囊是资源类特例
6. 当前选择至少有边／底和文字两项反馈，hover只微亮；焦点用明确2–3px outline；disabled不只透明，应同时保留原因文字
7. 主要文字面板内边距24／32，组间距16／24，文字与分割线至少12；避免用缩小文字解决长文案
8. 空态正文不超过两行，只有一个首要下一步；保留新档、筛选、上限、失败的原因差异
9. 同一页不重复当前余额；详情图应比列表更利于查看；不为了视觉更改交易、安全格、背包格、材料结算或存档逻辑

## 素材风险：人物浅底不是单纯 CSS 主题问题

已用 Pillow 只读检查现有原图：五张 `portraits/full/{wu,heixiang,xingyue,baita,changwuyu}.webp` 均为1024×1536 RGB，无alpha，边角接近白色。原画本身必须有新的透明版本或明确保留展板形式。

现有 `portraits/battle/*.webp` 虽为RGBA，但 `wu` 是不同服装／不同画法的战斗形象；`changwuyu` 为768×512宽幅带暗色场景。已看图确认，不建议拿战斗图简单替换人物档案原画，更不能靠 multiply 将服装、肤色一起染暗。素材处理不得覆盖既有full源文件，新的同原画派生资产应单独命名并逐人检查头发／武器边缘。

另外 `hub.personnel.js:12–18` 的 `portraitBounds` 对四人仍记2560×1440，而实际full图是1024×1536，属于旧元数据：不宜把当前取景数值视为已经正确。人物素材路线确定后才校准，避免一边换图一边叠偏移补丁。
