## 实施

- 出征保存成功后先保留候选，地图发布维护已完成阶段；异常或拒绝时返回`{status:'departure-pending',committed:true,retry,isCurrent}`。并发重试复用同一Promise，仅从未完成阶段继续；候选/RNG恢复、计数器初始化等已完成部分继续保留，原始发牌、扣仓和保存命令不再重放。默认选角阶段发现本局已有人物时继续已完成确认。
- 操作归属使用Game/Base对象、档位/选择代次、出征代次、候选seed/discoveredPairs及运行/撤离/终局状态。原入口归属与合法转交后的发布归属分开；成功后对象继续提供同局只读身份判断，失效后结束旧候选继续入口。
- 人物确认在建立自己的保存阶段前接收本次发布对象，按原页面、档位和选择代次接管；提供“继续出征／重试打开地图”，等待显示“正在打开地图…”并复用公共控件忙碌状态。发布成功后进入原prepared/saved/transitioned流程，保留职业牌、补给、熟练度加血与后续保存的一次性标记。
- 基地入口将地图发布与教学提示收尾接到同一继续对象；返回重试页后不再依赖旧整备DOM。开发节点入口识别待发布结果，下次操作继续原测试远征。
- 重试页先挂载内容、记录归属并注册动作，再独立尝试地图刷新；同一刷新异常保留已挂载的继续按钮。
