# 注能材料存在性查询验收

材料组只需要知道是否还有可选副本，不需要完整可选数组。`infusionMaterialState` 改用 `some`，首个成功后停止；完整已选列表、原因文案与加减决策不变。内部返回形状明确移除未消费的 `available`，两个生产调用点只读取其余五个字段，无调用方修改。没有保留缓存。

## 操作计数

真实 `BattleSession.restore → beginInfusion → renderInfusionSelection`，使用当前目录卡 `tt3sp-bloodstorm` 和初始攻击；mixed9 另有 `tt3-fireball`、`tt3-reshot`、`tt2-shoot`。计数仅覆盖一个实际注能面板 render，输入快照取得在计数之前。

| 场景 | 燃料检查：原版 → 优化 | 查牌：原版 → 优化 | owned UID 读取：原版 → 优化 |
| --- | ---: | ---: | ---: |
| 正常 mixed9：主卡 + 5 初始攻击 + 3 不同招式 | 8 → 4 | 17 → 13 | 108 → 90 |
| 正常 stacked9：主卡 + 8 初始攻击 | 8 → 1 | 17 → 10 | 108 → 66 |
| 合成放大 30 张，不代表常态手牌 | 29 → 1 | 59 → 31 | 990 → 528 |
| 合成放大 60 张，不代表常态手牌 | 59 → 1 | 119 → 61 | 3780 → 1953 |

UID 读取包含分组和 owned 查找，不只 `.find` 比较。单副本组与全禁燃组不减少检查；全禁燃仍保留首副本原因回退。每组还省去一个完整 available 临时数组，未测量堆内存、浏览器延迟或 FPS。完整 HTML SHA256、文本和按钮属性在四组原版/优化版比较中一致，连续五次操作后的呈现也一致。具体值见 [counts.json](counts.json)。

## 正确性边界

- renderer 的全量 `snapshot.hand.map(findCard)` 没有缩短，owned/granted/override 的后部旧卡仍在分组前修复；新增回归逐一检查修复结果，不能用短路省略这一投影。
- 输入重新读取手牌、已选、需求数量、实时禁燃规则、变换及 override。同对象规则编辑、已离手副本、选中后失效仍可移除、自燃拒绝均覆盖。
- 跳过的后部 eligibility 查询不再提前写入 effective-card provenance；没有消费者依赖这些未使用卡面的 provenance。实际选择、后续查牌和最终确认仍实时解析/修复，确认检查每张已选材料，未把存在性结果传到支付边界。
- 只保证使用中的五个返回字段语义相等，不宣称原内部对象完全同形或任意副作用 callback 的调用次数相等。5,120 个三副本组合比较保留字段完全相等。
