## 实施

现码领取命令已改为异步，但旧收据仍通过同一点击事件的前后快照与日志节点判断，无法等到真实领取完成。本批将反馈接回命令生命周期，沿原事务保存。

- `hub.reward-feedback.js`新增`runRewardClaim`，等待一次真实命令，结合本次领取标记与库存记录已保存结果；保存中暂停领取按钮，失败原位显示实际msg/why。持久化后日志异常仍按已提交记录显示成功；收据绘制失败保留结果供重绘。`bindRewardFeedback`仅负责重绘，旧事件快照、点击捕获与日志扫描已移除。
- `game.hub.runtime.js`成就/里程碑领取统一接入该owner，保留`hubWrite`锁与所有既有仓库、预设、整备和结算增量。新收据提供对应仓库/卡背入口；容量不足可直接打开仓库或扩建。卡背通过现有`hubCollectionView/backs/id`导航定位。
- `hub.archive-v3.js`奖励与里程碑记录采用稳定ID，领取后原待领项消失时选相邻项；每个目录保留内部滚动与展开，不覆盖收据焦点。`selectArchiveBack(id,base,cards)`验证现有且已解锁卡背后定位预览，应用继续走原操作。

原成就分类、搜索、奖章与卡背预览已有保留机制，`hub.archive.js`无需修改；`meta.js`与Base发奖事务保持原实现。未新增奖励框架或样式系统。

## 老板统一验收入口

- 连续领取成就与收藏里程碑：保存中状态、实际资源/卡牌/卡背数量与所得目的地一致。
- 仓库不足或保存失败时，原项保留可重试；查看仓库/扩建后可回原目录继续领取。
- 新卡背领取后“查看卡背”定位新预览，应用仍由玩家操作。
- 领取后继续浏览奖励、里程碑和成就，核对稳定选择、相邻项、搜索与内部滚动。
- 保存后显示异常、领取中换页/换档，已完成奖励保持一次，旧收据不打断新页面。
