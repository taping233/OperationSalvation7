# 内置历史规则查询复用与旧自定义ID兼容

按不可变规则声明复用一次历史查询表，避免迁移入口反复展开；同时修复既有自定义卡牌ID为 `constructor`、`toString`、`__proto__` 时误读继承属性而中断目录启动/普通战斗。基底为 `da9adae8afaadadbc7ac245698c8a2f4646719ad`，不改变当前内置规则或开启卡牌设计/导入UI。

## 当前行为与边界

- 三个历史表原有深冻结、合并顺序及普通对象原型不变；70键浅表在模块初始化时合并并冻结。只共享声明引用，不缓存卡牌、规则指纹或返回结果；实时规则与ID仍每次读取，迁移规则树独立克隆。
- 自定义ID只有修订表自身存在同名键才进入迁移。旧性能候选曾断言继承ID抛错，本次明确改成同对象返回和深相等不修改断言，而非跳过该控制；null/undefined卡牌原有错误契约保留。
- 自定义兼容回归从公开Cards存储入口保存卡牌，再冷载目录并使用普通BattleSession开始/出牌。旧式卡牌伤害2/费用1，显式规则卡伤害3/费用2；校验出手、空闲、卡牌所有权和内容。完整库字符串相等仅覆盖启动后的出牌过程，启动只校验自定义卡内容。
- 当前创建/导入UI关闭；这是已保存/已拥有卡牌的兼容修复。测试是jsdom代码模拟，没有读取或修改玩家数据，不代表浏览器实玩。
