# 选人 → 出征 → 地图与节点体验审查

日期：2026-10-11。对象：v0.60.0 当前工作树。状态：体验与诊断完成，以下改进均为建议，未实施。

核心判断：这条流程已能完成一次真实探索，但人物展示、出征信息、地图、节点与战斗的视觉和反馈尚未连成同一段冒险。最先影响体验的是奖励窗主按钮被挤出可视区、开局信息不一致、消耗规则教学滞后；美术提升应同时处理角色构图、场景连续性与信息层级。

后续参考研究与总体框架见[修改计划](../2026-10-11-selection-map-plan/MODIFICATION-PLAN.md)，该计划尚未实施。

## 实际体验范围

- Codex 内置浏览器，真实控件点击和滚动；没有构造游戏状态、强制战斗或合成事件。
- 当前窗口截图均为 1523×956，DPR 1.25；没有设置 viewport，也没有开展多尺寸验收。
- 从 `http://localhost:5200/` 的档位 04 基地出发，未覆盖重开任何档位。此次体验创建的对局保留在该档位第二层入口。
- 路径：五名人物切换 → 无的角色卡池 → 整备 → 启程补给 → 第一层地图 → 物资点收取 → 火堆 → 遭遇战胜利 → 战后搜刮 → 首次消耗教学 → 商店购买一张初始攻击 → 层间闸门 → 第二层入口。
- 实战使用偷袭一次、初始攻击两次，击败三名拾荒者；生命保持 35/35。未从仓库额外带入卡牌。
- 本轮只新增本目录的报告、截图及浏览器证据，未修改游戏源码、资产或共享台账，未 build、提交或启停服务。

未覆盖：随机叙事事件、祭坛、首脑、终层撤离、不同角色实战与皮肤切换。没有音频试听、连续录像或帧率采样；对动态的判断来自本轮真实操作及相关动效源码，截图只证明所截状态。

## 对照依据

以《明日方舟》集成战略的招募、队伍、路线与节点组织为主要流程参照；官方 [模式介绍及界面图](https://ak.hypergryph.com/news/2020087413.html) 是 2020 年版本，作为界面组织的历史样例。共通节点、奖励与暂离规则参考 [PRTS 集成战略说明](https://prts.wiki/w/%E8%82%89%E9%B8%A1)。不将早期截图当成当前版本逐像素标准。

《崩坏：星穹铁道》采用 [差分宇宙 V2.7 官方更新说明](https://www.hoyolab.com/article/35257106) 作为准备与试错成本的机制参照：预设阵容、战斗重开及调整阵容体现了减少重复准备的方向。本轮没有登录两款商业游戏进行实机体验，也未完成其最新版本 UI 的逐项核验。

由这些参照形成的设计建议是：角色页帮助选人，准备页交代本次投入和风险，地图帮助比较下一步，节点展示选择或实际结果，战斗与奖励保持身份和上下文连续。具体改法为本项目的设计判断。

## 可以保留的部分

角色立绘与雪境场景已有可用的气氛基础；选人条的选中态、明确的下一步按钮、章节当前位置、已探索提示、商店余量与购买后的金币反馈均能工作。

战斗的选牌抬起、目标高亮、敌方意图及单一目标自动确认也有效。本轮使用这些操作完成首战，不能笼统评价为“没有动效或反馈”。建议集中解决整页重播、反馈位置和对象身份连续性，不增加持续粒子作为默认改法。

## 建议处理顺序

1. 先使奖励主按钮始终可见，统一开局数量与背包摘要，将损耗说明放到首次消耗前。
2. 做一条“无 → 整备 → 首层物资 → 火堆 → 战斗 → 奖励”的完整样板，统一角色尺度、场景受光、字体、按钮与进退节奏。
3. 再改地图的主次、节点剪影、回程/深入分组及资源说明。
4. 扩展其他人物与节点，最后补细节和声音。此顺序为审查建议，没有形成实施授权。
