# 游玩操作链的代码效率优化

老板明确要求优化影响实际游玩体验的代码。本轮保留现行玩法、视觉和操作规则，针对角色图片切换、群攻悬停和背包刷新的重复工作实施四个源码文件的最小修复，另更新一条经完整差分复核的素材消费者指纹。未实施只减少安装包体积而没有当前游玩收益证据的方案。

## 修改与受控证据

| 实际操作链 | 代码变化 | 同条件受控结果 |
| --- | --- | --- |
| 配置页快速切换角色、切换后离页 | 图片加载完成时先核对连接状态和最新请求，过期请求不再主动调用 decode | 连切4人：decode调用4→1；随后离页：4→0 |
| 群攻牌拖至合法空地预览敌人 | 同一次同步悬停共用一份新快照，下次输入重新读取 | 4活敌8→1；死敌/能量原地变化后重入7→1，全部预览HTML相同 |
| 局内背包打开、切分区及筛选 | 同一次渲染共用普通区/安全格的卡堆结果，操作仍实时检查容量 | 13张混合数据：普通9→5、安全8→4、消耗7→4次分组；54组模型/HTML/顺序等价 |

这些是实际函数调用计数、生命周期和输出等价证据，不是整机FPS、RSS或交互毫秒的实测提升。图片下载以及已经进行中的解码不由本次补丁取消；背包不跨刷新缓存，群攻不跨帧缓存。

定向结果：角色2文件14项、战斗3文件36项、背包5文件110项均通过。详细依据见[角色图片生命周期](assets/personnel-preview-lifecycle.md)、[群攻快照](css/runtime/README.md)、[背包渲染](entry/bag-render-report.md)。完整冻结检查609文件、5968项通过、16跳过，代码已提交，详见[收官摘要](completion.md)。

## 检查与交付边界

当前平台内置浏览器已做的有限观察见[输入范围](browser/README.md)。老板随后明确要求停止实玩，主会话即停止浏览器操作；背包的后续实页流程未执行，保持自动化等价和生命周期验证的证据范围。没有继续进行自然跑局、长时游玩或原生EXE交互。

新版独立Windows EXE在新交付目录生成，旧版保留，见[EXE交付记录](desktop-exe/README.md)。标准构建生成资源成功，末端仍保留五项资源预算失败；没有改变阈值。包体与CSS归因分别留在[资源报告](assets/README.md)、[CSS报告](css/README.md)，它们不作为本轮游玩流畅度收益。

另一会话的事件投骰、商店与数据在途增量未纳入本次冻结输入。构建与验证分别使用HEAD对象导出的副本和冻结index，未在混合源码工作区build。代码与最终证据、完整验收凭据及本地大文件指针见[收官摘要](completion.md)。
