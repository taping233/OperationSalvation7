## 实现边界

`secondary-ui-tokens.css` 显式增加 `.ui-scale-system` 消费者；`ui-design-system.css` 增加仅负责几何的 `.ui-control`、`.ui-control-compact`、`.ui-control-icon`，不套全局 button。各页在原生效规则中消费变量，不在文件末尾追加覆盖层。

实际 CSS 仅7个：上述两公共来源及 `bag-design-system.css`、`expedition-shop.css`、`base-logistics-trade-v12.css`、`settings-navigation.css`、`departure-selected.css`。设置旧 `settings-cover.css`、选人英雄展示、卡面/战斗布局未改。仓库重复的同名类别规则在原位置合并为一个，避免同控件两处声明高度。

老板随后指出当前领奖背景过于显眼，主会话单点转交 `chest-reward-overview.css`：三类奖励背景根使用独立 `::before` 场景层，14px 模糊、亮度 .68、饱和度 .58，青灰遮罩 .62→.55；卡面与文字不套滤镜，根尺寸不变。此为额外背景单点，按主会话要求不新增测试/截图，集中实页时一并判断层次；未混入此前7个尺度CSS的静态通过结论。

主界面只加显式作用域/控件角色，不改 data-act 或数据规则。文字清理详见 [相邻记录](../copy-cleanup/README.md)。最终改动规则清单见 [changed-rules.json](changed-rules.json)；当前输入 SHA256 与一次集中静态检查见 [static-check.json](static-check.json)。

## 集中验证建议

1. 背包：当前窗口的主标题、44px工具、筛选与详情往返；保原卡宽和容量事实。
2. 领奖：复用领奖负责人的 v3 常规/满包场景；其 CSS 未由本线改写。
3. 整备：推荐/筛选工具44px、出发60px，卡区仍可滚动且底栏可达；保卡面和数据。
4. 设置：主标题/分类标题/正文关系，以及工具按钮在当前窗口可读、不被旧高特异性规则压回小字。
5. 仓库或商店：仓库筛选/分页44px与类别60px；商店详情规则加大后仍能滚动，购买/整理动作常驻可达。

本轮只验当前窗口与代表差异。主要风险是长文本换行和旧 CSS 高特异性覆盖，需要真实计算样式/画面判断；没有新增素材、存档或玩法变更，也未新增多尺寸任务。
