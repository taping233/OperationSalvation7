同步准备下降约54%。来源为 [前](photo-render-before.json) / [后](photo-render-after.json)，脚本 [photo-benchmark.js](photo-benchmark.js)。Codex 内置浏览器当前窗口1280×720、DPR1.25；直接调用页面入口、强制一次布局并等待首屏，排除公共过场动画时间，不写存档。馆藏268张，每轮首屏挂载16图；壳节点异步补齐，有一轮在采样时为259。修改后仍有一次冷开78ms长任务，未证明所有设备首次打开零卡顿，也未作全场120FPS结论。

城市切幕统一等待场景图与目标页视觉准备。照相馆先绘制不透明等待姿态，再并行加载切幕场景和准备馆藏，完成后启动原980ms揭幕。首屏卡图等待上限由220ms调整为2200ms，切幕装饰图最多等待3000ms；失败保留底色、标题兜底，取消时释放。基地、设置、成就及出发共用场景图准备逻辑。

其他落实项：仓库图片事件同帧合并布局；战斗瞄准/回位同帧复用卡片基础几何，角色帧推进只读一次尺寸；标题提示观察器改用祖先集合合并新增子树；界面确认音排在战斗音效前加载，两路解码限制保留。对应定向测试验证100次图片事件合并、离页停止、角色单帧一次尺寸读取、音效队列顺序及缓存失效。

审计复用已有行为：地图遮挡停绘及后台预取让步沿[上一轮证据](../2026-10-16-WF-game-performance-1016/README.md)；标题指针效果已有单帧合并，庭院在隐藏/离页时暂停并清理，音频已有生命周期管理。本轮未额外改这些调度策略。
