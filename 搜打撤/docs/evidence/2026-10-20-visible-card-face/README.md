# 收藏与人物招式：避免离屏完整卡面的同步构造

## 已定位的成本

原分页只控制已创建DOM的hidden：页面生成器先为全部条目调用cards.cardHTML，整页写入时解析全部卡面（图片、装饰、词条、描述等），随后bindCardBrowser读取轨道样式/宽度才隐藏非当前页。收藏和人物招式都走这条路径。空收藏室原本没有大列表卡面，本补丁不声称显著改善初始空态；主要收益对象是积累较多收藏后的浏览和人物卡池。卡面字符串即使命中缓存，后续HTML解析与大DOM上的查询/绑定仍需支付。

本批将共同分页组件接入按需卡面接口，两页仅预建轻量身份与筛选字段。只有可见页渲染完整卡面，已浏览页复用；先筛选后首次渲染。没有调整动效时长、遮罩等待或画质。仓库使用连续滚动网格，尚未套用此接口，本批不声称改善仓库或所有界面卡顿。

## 同环境成本对照

测试通过实际Cards初始化顺序ensureStarters/ensureSha/ensureTabletop/ensureDmgTypes/ensureEffectFields装配得到281张卡，包含当前批次。早期268张仅为dataSlice静态数组去重，遗漏初始化追加，已被本最终281张对照替代。收藏用全部281条设为拥有的压力输入，不是用户真实存档或可收集资格证明；人物为实际侠客卡池17张。

真实cards.cardHTML、Icons.rich、页面生成器和绑定函数；Node/Vitest/jsdom同进程，暖卡面缓存，预热后前后交替7次取各指标中位数。轨道宽度显式设为900或1500px，min=220/gap=30源于base-rooms-v7.css，不能把这两个轨道宽度称为1180/1920窗口实测。收藏容量公式floor((trackWidth+gap)/(min+gap))，人物明确固定4列。

- 收藏，900px轨道、3张可见：卡面282→4（含1张详情），DOM元素7995→970；生成/富文本处理/解析/绑定合计中位数584.42→77.55ms。
- 收藏，1500px轨道、6张可见：卡面282→7，DOM元素7995→1025；合计552.95→73.29ms。
- 人物侠客，两种轨道宽度均4张可见：卡面17→4，DOM元素533→207；900px合计29.07→15.46ms，1500px27.13→12.59ms。
- 收藏初始HTML517821→77035字节；人物36727→8650字节。完整身份条目仍分别281/17，没有丢失筛选对象。

明细见benchmark.json。耗时是CPU/DOM模拟对照，未包含浏览器样式布局、网络、图片解码、绘制和GPU；不得换算成真实开页时间或FPS。分阶段中位数之和不一定等于总耗时中位数。真实窗口最终容量和实页耗时需集成后测量。

## 回归与未核项

最终7测试文件25项通过，含原18项及新7项；源码和新测试使用项目ESLint通过。新增覆盖首屏按需、翻页复用、尺寸变化、首次筛选、搜索全量metadata、节点替换、旧页失效、缓存不跨页泄漏、无内容重试、焦点迁移、实际原始卡对象放大与库存JSON不变。性能对照另1项通过，已针对异常安全修订后的最终源码重新测量。渲染失败回归验证：下一页第二张卡抛错时，上一页卡面、分页按钮、焦点与点击仍可用；修复渲染输入后点击下一页正确重试。该修订先完成整页待渲染HTML再提交DOM与分页状态，异常原样传播，不吞错。

未运行全量、构建、架构哨兵、实页或截图。保留既有卡面槽宽高/长宽比，但真实视觉和宽度需在新部署复验：收藏打开/搜索/翻页/缩放窗口/放大返回；人物招式四列/搜索/过滤/换人物/放大。没有本地同步、共享工作树写入、提交或发布。

## 复现

在独立候选副本中，将本目录collection-before.txt和personnel-before.txt分别复制为game/src/hub/hub.collection-v4.before.js、game/src/hub/hub.personnel.before.js；将benchmark-harness.txt复制为tests/card-browser-lazy-benchmark.test.js。使用已安装项目Vitest以jsdom环境运行该文件；不启动浏览器或复制资源树。baseline与candidate输入指纹见input-sha256.json。该性能脚本属于显式比较，不加入日常自动测试清单。
