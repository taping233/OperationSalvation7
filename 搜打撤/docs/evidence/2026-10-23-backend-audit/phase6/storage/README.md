# 纯业务冗余清理：基地升级提交骨架

本轮仅修改 `game/src/hub/base.js`，把背包、宠物、仓库、龙巢背包四个升级入口重复维护的提交骨架归为私有 `commitUpgrade`。实际差异 **+11 / -20，净减 9 行、140 字节**。四个具名方法及公开接口保留；本轮不修缺陷、不删除功能或整文件。

## 修改与调用证据

| 入口（现行行号） | 资格读取 | 保留在提交草稿内的业务动作 |
| --- | --- | --- |
| `base.js:502 upgradeBag()` | `canUpgradeBag()` | 木材扣款、`bagUp++` |
| `base.js:509 upgradePet(id)` | `canUpgradePet(id)` | 按宠物等级计算口粮、更新该宠物等级 |
| `base.js:516 upgradeStash()` | `canUpgradeStash()` | 木材扣款、达到容量门槛时扣符文、`stashUp++` |
| `base.js:529 upgradeNestBag()` | `canUpgradeNestBag()` | 扣两个符文和五币、增加龙巢背包容量 |

`base.js:776–777` 仍把四个方法加入 `api`，`base.js:794` 仍为四个方法配置失败值。`base.js:811–866` 原有槽位锁、身份复核和异步写入包装没有修改。仓库、背包有 `game.hub.runtime.js:280/302` 的现行调用，宠物有 `hub.personnel.js:40` 的现行调用。龙巢背包保留既有公开端口；不以缺少当前直接调用作为删除理由。

## 逐步顺序与静态等价证据

| 步骤 | 原实现 | 归一后 |
| --- | --- | --- |
| 资格读取 | 入口先调用对应 `canUpgrade*` 一次 | 对应表达式作为第一个实参，仍读取一次 |
| 资格失败 | 立即返回 `false`，不进入 `mutate` | helper 同样返回 `false`；业务箭头只被创建，不执行字段、getter 或业务回调 |
| 资格成功 | 调用一次 `mutate` | helper 调用同一个 `mutate` 一次 |
| 草稿修改 | 在 `mutate` 回调内按原顺序计算扣款、修改状态，最后返回 `true` | 同一回调先执行原完整业务语句，再返回 `true` |
| 落盘失败 | `mutate` 返回 `false`，不播放音效 | 同上 |
| 落盘成功 | 对 `ok` 作原有真值判断，播放音效，返回 `ok` | 同上 |
| 异常 | 不在入口捕获，交回既有上层边界 | helper 没有新增捕获或异步边界 |

`mutate` 本身（现行 `base.js:243–247`）未修改：无槽位时不调用草稿回调，其他情况仍通过 `commitBaseMutation` 完成原保存/回滚。扣款所需 `rules()`、`petUpCost()`、`petLevel()`、`stashCap()` 均保留在原草稿回调内，没有移到资格失败也会求值的位置。没有新增 `await`、Promise 或锁。

`prove-upgrades.mjs` 仅解析源码，不导入或执行游戏模块。它先逐 AST 节点确认 helper 正好等于约定骨架，再把四个现行调用点展开为原函数，核对四个**完整函数声明 AST**。最后把整个现行文件中的 helper 展开并移除其声明，与整个修改前文件 AST 核对，结果完全一致。`ast-equivalence.json` 保存四入口结果及整文件结果，因此本轮也保留了基线中已有的未提交修复。

该证明针对上述展开后的执行语句和程序结构；未进行运行时验证。编辑产生的私有调用栈帧和匿名回调分配不参与业务字段求值，也未作为需要保持的公开端口。
