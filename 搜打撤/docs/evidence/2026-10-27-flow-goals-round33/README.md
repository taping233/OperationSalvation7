# 系统菜单原页返回

本批将系统菜单的继续游玩接到已有来源拥有者，补齐研究所、领奖、背包、容器和腾位页面的返回。设置、规则帮助及设置子页返回菜单时继续使用进入菜单前的来源。

状态：修改完成、编辑释放，保留未提交，持续目标进行中，由老板统一验收。

- `bag-return-hook.js`在离开原页前捕获纯展示快照，成功返回后核对新页身份并恢复滚动、展开与焦点。原 renderer 重建页面，不复制旧 DOM 或游戏状态。
- `menu-leave.js`打开时认领来源，继续时等待实际返回，失败留在菜单重试。领奖后备路径复用`Chests.suspend/resume`；工厂注入该端口。菜单子链记录当前页来源，设置/帮助头栏再次打开菜单也沿原来源继续。
- 设置返回统一使用`createOverlayReturn`，检查当前设置页及原对局/档位；设置的资料/信箱子页沿相同归属交接。背包恢复保留原私有领奖/事件返回路径、筛选和排序；容器与腾位页保留原闭包、操作回执和待确认选择，再查实时背包渲染。
- 研究所地图、商店、祭坛、符文法阵和成本确认登记原渲染入口，继续原候选与确认内容。撤离保存与重试页沿已有内部对话框隔离；研究所菜单仅呈现已实现的继续、设置、帮助与保存退出。
- 容器取卡提示改用与实际存取相同的`previewCardRewards`和容器扩格投影，退出旧的总占格对比普通容量判断。
- 现行界面说明与路线图同步。三名6.1-sol/high按源代码审查、设置、背包/容器/腾位分工，主会话集成菜单、研究所与公共展示恢复。

依据为当前源码和相关差异。本批未运行测试、lint、构建、检查脚本或实页验收；无新服务、文件删除、暂存、提交或推送。

老板统一验收关注：来源页经过菜单/设置/帮助及资料子页后继续；背包恢复后再返回原奖励；法阵候选与献祭确认、腾位待确认选择、滚动位置；领奖继续与容器取卡提示；保存期间入口及来源恢复失败重试。
