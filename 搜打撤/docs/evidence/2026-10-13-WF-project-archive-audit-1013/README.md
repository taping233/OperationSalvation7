## 建议采用的日常流程

1. **接手一次定位。** 跨域或长任务运行 `handoff`，按路径查归属与未决；目标路径已知直接读目标。把 HEAD、工作树、index 与生成物状态记入任务证据，后续同属地复用，不重复全树盘点。
2. **按属地交付小切片。** 一次切片先明确可观察结果和文件清单；对共享文件做局部补丁并紧随登记。素材生成与运行接入分开，先定最终图，再同步映射、manifest、来源和尺寸；候选稿留在证据/源目录，不混入运行资产树。
3. **按变更选择反馈。** 工具/说明走契约测试或 `docs:check`，游戏逻辑走近邻测试及必要集成，玩家可见变化加当前窗口内置浏览器实页。验证记录同时写输入基线、命令、退出码和未核项；环境错误与产品失败分列。
4. **归档候选三证据。** 明确幸存正本或零引用、调用/加载链、覆盖顺序后，列每个待删路径请老板拍板。已批清单删除后做定向搜索、检查与差异核对；在途属地和无主物品先协调归属。
5. **收官再打包。** 更新自有任务证据和占用状态；完成未提交按归属保留。只有明确提交指示才审 index、冻结检查与 ship；CI、构建和实页只引用对应源码版本，不沿用过期的绿色结论。

这五步是本轮流程优化方案。`WORKFLOW-TOOLS.md` 当前有本轮之前的未提交差异，定向 `handoff` 未显示活跃编辑占用；应先核实该差异归属，再把新增且不重复的条款合并到唯一现行来源。其中第 2 步“候选素材不进运行树”、第 3 步“环境错误单列”可先作为本任务执行习惯。
