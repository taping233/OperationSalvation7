# 基地 V8：按单页明确参考复刻，补足操作块与颜色主次

2026-10-11。状态：参考方案已明确，实施与游戏画面待老板验收。负责人：base_design_references 子代理。本轮只写参考记录，不修改游戏源码。

V8 主页采用《重返未来：1999》右侧「亮纸票据主行动 → 两个目的地 → 一条宽入口」的空间组织。保留冬日营地壁纸，用可识别的实体操作块建立主次。V7 的「满屏室内 + 右侧薄白大字」停止作为主页实施方案；只增大字号仍会让壁纸成为唯一焦点。

角色整备页单独采用《绝区零》横向展示页的「左侧人物/场景 + 右侧固定资料 + 上方角色切换 + 底部局部页签」。商店单独照《明日方舟》顶部类别与商品网格。每个页面有一个主布局参考，冬日营地的颜色、字级与控件材料由本项目统一；Persona 只提供当前选择的高对比规则，不进入主页的构图、红色背景或品牌装饰。

下述原图坐标是读取真实像素后的目视约数，坐标使用整图左上为原点；项目尺寸与动效为实施建议，不是原游戏官方规格。原图的玩法词汇、活动、货币与等级规则不移植。

## 1. 主页唯一主参考：1999 官方 Steam 画面

[官方商店截图来源](https://store.steampowered.com/app/3092660/Reverse_1999/) · [1920×1080 真实主页图](https://shared.steamstatic.com/store_item_assets/steam/apps/3092660/ss_e70464235b008e3f2db10b9e525587e8fd3b02ef.1920x1080.jpg?t=1730383505)

实际看见的结构：人物与室内连成横向画面；右侧行动区有完整矩形轮廓和底面。主票据使用米白实体底与深色大字；下方目的地以深底、浅边与浅字承托，亮度明显低于主票据。资源放在右上黑色实体条中。该图左侧有辅助入口，右侧主行动上方有活动广告；这两部分与本项目减少入口的要求不匹配，V8 不保留其数量。

### 可以直接实施的 V8 坐标

以当前横向窗口为画幅，操作组固定在 x=68%–95%。场景不改整体颜色，只在这一区域外沿做弱暗化。操作组不是额外弹窗：所有项目都处于主页，点击后跳转完整页面。

| 项目 | 画面位置与面积 | 文案与材料 |
| --- | --- | --- |
| 资源 | x=68%–95%，y=7%–11%，宽 27%、高 4% | 一条深灰实底，资源 16–18 px；图标与数字同基线 |
| 基地名与简短状态 | x=68%–95%，y=19%–25% | 名称 22–24 px，状态 13–14 px；不增加第二张卡 |
| 主行动 | x=68%–95%，y=28%–48%，宽 27%、高 20% | 米白纸质实底；主词「出击」44–48 px 深色，目的地/状态 15–16 px；右侧明确箭头或票孔 |
| 整备 | x=68%–81%，y=51%–64%，宽 13%、高 13% | 深灰实底 + 米白文字 24–26 px；一个图形即可 |
| 仓库 | x=82%–95%，y=51%–64%，宽 13%、高 13% | 与整备同尺寸、同基线、同材料 |
| 补给 | x=68%–95%，y=67%–79%，宽 27%、高 12% | 深灰实底 + 米白文字 26 px；与主票据同宽，明度低一档 |
| 辅助功能 | x=68%–95%，y=82%–87% | 任务 / 档案 / 设置 14–16 px 共用一条基线；需要更多时跳转完整工具页 |

这组关系保留 1999 的「一大、两并排、一宽」骨架，并放大主要操作面积；资源与辅助收进同一视线区。坐标调整是本项目对功能数量和当前窗口的映射，不声称与原图一比一。主行动可见面积约为一个目的地的 3 倍；其字级约为目的地的 1.8 倍，形成明确的第一操作点。

## 2. 配色与排版：画面冷、操作暖，只有一套材料

| 角色 | V8 建议色 | 应用位置 |
| --- | --- | --- |
| 操作纸底 | `#EEE8D8` | 主行动；当前选中页签或当前选中目的地 |
| 纸面字色 | `#202522` | 所有亮纸面标题与数字 |
| 深色底 | `#20282A` | 目的地、补给、资源与固定资料区 |
| 深底文字 | `#EEE8D8` | 名称、主要数值与操作说明 |
| 次级文字 | `#B9C0BC` | 深底辅助文案；重要数字不用此色 |
| 单个强调色 | `#C9864D` | 主行动票根、短线和选择标记；呼应营地暖灯 |

颜色是本轮实施建议，取自「冬日室内冷环境 + 暖纸操作」的关系，未做原图逐像素取色。强调色只承担一次当前选择或主行动记号；不把页签、等级边、任务角标和所有数字同时染亮。人物和房间原有的青蓝色仍归美术背景，UI 不另加荧光绿、Persona 红或金色外发光。

主体 UI 用同一套中文主字体。主行动 44–48 px、目的地 24–26 px、页面标题 32 px、物品名称 20–22 px、正文 16 px、辅助 13–14 px。正文行高约 1.45–1.55；同组间距 12/16 px、组间距 24/32 px。图形与文本齐左，不居中堆叠图标、标题、英文、状态四行。菜单入口不重复显示「进入」「前往」「打开」等同义词。

## 3. 人物整备页唯一主参考：绝区零横向展示页

[安比资料页来源](https://www.sportskeeda.com/esports/zenless-zone-zero-anby-demara-guide-best-w-engines-drive-discs) · [1200×675 真实角色页](https://staticg.sportskeeda.com/editor/2024/07/16aea-17200720612258-1920.jpg?w=1200)

看见：人物立于左侧连续背景中，没有塞入竖卡。右侧资料占 x≈630–1120，即宽约 41%；资料从名字到两列数值共用一个固定面。角色切换条在上方，基础/技能/装备为资料面下方的统一横向页签。画面先是「左人物、右资料」两个大区域，局部数据再分层。

同游戏的场景姿态参考：[绝区零设置指南中的真实菜单全景](https://esports.gg/news/zenless-zone-zero-zzz/zenless-zone-zero-zzz-settings-for-best-performance-and-quality/) · [1568×882 全景图](https://media.esports.gg/uploads/2024/07/image-25-6-1568x882.jpg)。该图人物斜坐沙发，腿、沙发、砖墙共同构成宽画面，右侧有固定内容面；可借鉴横向人物与环境的关系，但「EVENTS」不是资料区。本项目将右区映射为资料，不能把该截图误记成原游戏角色属性页。

### 角色页实施坐标

| 区域 | 本项目位置 | 内容 |
| --- | --- | --- |
| 返回 | x=3%–10%，y=4%–9% | 与其他大页同盒、同字号 |
| 横向角色场景 | x=0%–62%，y=0%–100% | 角色坐在冬日营地的桌边或长椅；环境随画幅铺开，不加竖向立绘外框 |
| 角色切换 | x=64%–95%，y=5%–10% | 同高小头像或姓名，一条切换行；不挤占主展示 |
| 固定资料面 | x=64%–95%，y=18%–80% | 一张深灰面；名字 32 px、等级/类型 18 px、主要数值 24 px；次要数值两列基线对齐 |
| 局部页签 | x=64%–95%，y=83%–90% | 基础 / 技能 / 装备，当前项为米白底深色字 |
| 主操作 | 固定资料面右下角 | 更换装备/确认，操作区位置不随页签改变 |

资料面替换内容，角色展示保持连续。装备选择也留在这张完整整备页中，或跳转完整装备选择页；不回到主页开几个狭窄浮窗。横向场景资产可单独生成，但须沿用既有人设与冬日营地画风；本调研未生图或写入美术文件。

## 4. Persona 只借当前选择，动效只保留有限节奏

[Persona 5 Royal 暂停菜单截图来源](https://medium.com/design-bootcamp/ux-ui-in-video-games-the-pause-menu-6f07e113e21e) · [真实菜单图](https://miro.medium.com/v2/resize%3Afit%3A1400/1%2AY17fcN5SpijR55XfgQMbCA.jpeg)

看见：当前 Skill 与其他条目采用明显不同的文字/底色组合，并带单个指示标记；整列只有一个当前项。主菜单字块具有强轮廓，选中不会仅表现为浅色细下划线。截图不能证明该游戏的实际动画时序。

本项目只借「一个当前项高对比反转」：当前项米白实体底 + 深色字 + 一枚暖色短标；其他项深底 + 米白字。不要照搬红手、拼贴字、故意歪斜字号或满屏品牌纹样。主页主票据默认已经最亮，指针悬停时只变化边缘/票根，其他目的地只在被指向的一个块上反转，不让全组同时点亮。

| 反馈 | V8 实施建议 | 事实边界 |
| --- | --- | --- |
| 悬停/选择 | 100–140 ms 反转或亮度变化，最多位移 2 px | 项目方案；静态 Persona 图只证明状态差异 |
| 点击主行动 | 票根或箭头完成一次短反馈，140–180 ms | 项目方案 |
| 进入完整大页 | 260–300 ms，整页淡入 + 微小缩放；最多标题/内容/操作三组错开 30 ms | 沿用 Google 官方导航关系原则 |
| 返回 | 同关系反向配对，资料面先退出，再恢复基地行动组 | Google Shared axis 的进入与返回关系 |
| 切换局部页签 | 160–180 ms，仅资料内容区更换 | 项目方案；不要每行数值逐条飞入 |

背景不做永不停的扫描光；所有高对比和大位移都服务于当前操作。时长、幅度与角色场景使用方式是本项目建议，未宣称已观察到 Persona 或 ZZZ 的原版动画。

## 5. 其他页面各自照一张图，避免再次拼成主页

仓库仍可沿用 V7 已读的 [1999 六列仓库真实图](https://assets.st-note.com/production/uploads/images/220854821/picture_pc_8a9f6307dc53697cf0b2d00d6487154d.png?width=1200)：只在仓库整页使用局部类别与连续网格。将其选中项改用 V8 米白底深字，保留物品本身等级色的范围。

商店只照 V7 已读的 [明日方舟信用商店真实图](https://truth.bahamut.com.tw/s01/202007/733e80d514aa6fb40f880574f36173c7.JPG)：完整页顶部分类、大商品网格、名字在上/图在中/价格在下。原图 5 列商品，本项目按当前内容先放 4 列。页面实体底统一成 V8 深灰与米白纸面，保留已有等级/状态的业务含义；原游戏的货币、折扣与售罄规则不照搬。

本轮教学原则复用已读的 [Microsoft Fluent 2 Layout](https://fluent2.microsoft.design/layout)、[Apple UI typography](https://developer.apple.com/videos/play/wwdc2020/10175/) 与 [Google 官方 Motion](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md?plain=1)。分别支撑间距分组、固定字重/字号/行高角色、根据页面关系配对转场；它们不要求把成熟游戏外观换成系统应用控件。

本轮在内存中实际查看了 1999 官方主页、ZZZ 角色页、ZZZ 菜单全景和 Persona 菜单。V7 的方舟商店与 1999 仓库像素证据直接复用。未保存第三方二进制、未操作游戏浏览器、未做检测、测试或 build。主线接入与老板效果反馈仍为待完成项。
