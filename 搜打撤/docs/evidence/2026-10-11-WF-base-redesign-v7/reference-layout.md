# 基地 V7：真实游戏 UI 参考与可实施骨架

2026-10-11。状态：调研已完成，实施与游戏画面待老板验收。负责人：base_design_references 子代理。本文件只记录本轮参考证据，不代表游戏已经通过任何检测。

主页直接借鉴《少女前线 2》的「场景铺满、边侧开放大字菜单」；仓库借鉴《重返未来：1999》的「整页分类与疏排网格」；商店借鉴《明日方舟》的「整页顶部分页与大商品网格」。不再沿用上一轮七图标常驻侧栏、右下小整备台、设施卡片墙。菜单条目是整页入口，主页不承担编辑、兑换和详情操作。

下面的画面关系来自实际读取的截图像素；百分比为目视约数，字号及动效数字为本项目的实施建议，均不是原游戏的官方规格。截图能证明布局与可见状态，不能证明原游戏的完整交互与动画。

## 1. 可直接对应的真实截图

### R01 少女前线 2：主页，主骨架

[来源：Lutris 游戏页](https://lutris.net/games/girls-frontline-2-exilium/) · [真实截图原图](https://lutris.net/media/games/screenshots/Screenshot_20250210_221836.png)

看见：完整指挥室与人物占满画面，人物视觉中心在左侧约 35%；右侧导航右对齐，没有每条独立厚卡底。Campaign 的字高约为其他入口的 1.8 倍，其他入口垂直疏排；文字组主要位于右侧约 25% 宽度。底部是次级功能与资源，不侵入中央人物。

借鉴：新壁纸完整铺满，保留中部约 55% 为连续场景。右侧只放「出击、整备、仓库、商店」四个开放文字入口，出击最大。入口不包进圆角卡，不把整备内容搬回主页。原图的活动、招募与底部功能数量不照搬，按本游戏实际功能减项。

### R02 重返未来：1999：主页，主行动的物件化层级

[来源：APPLe 攻略页](https://www.sportskeeda.com/esports/reverse-1999-apple-build-guide) · [真实截图，840 px 版](https://staticg.sportskeeda.com/editor/2023/11/bbbcf-16989432687869-1920.jpg?w=840)

看见：房间中央保持通透；资源沿右上单行排列。右侧主行动是一张明显大于下方入口的演出门票，两个次级入口并排，其下再放一个长入口。四个左侧辅助入口没有连成厚侧栏，整体以房间为主体。

借鉴：主行动与次级入口在面积、字级和周围留白上拉开。若使用票据，仅主行动使用一个物件；本轮主骨架仍用 R01 的开放大字。保留室内自然光与手绘资产的材质统一，不把门票、科幻玻璃、金属雕花同时叠加。

边界：来源页正文抓取失败，但对应截图已通过 HTTP 200 在内存中读取并查看；未从攻略推导玩法或当前版本事实。

### R03 重返未来：1999：仓库，独立大页骨架

[来源：竹依的新手指南](https://note.com/takeyori/n/n26c937d0cfdc) · [真实仓库截图，1200 px 版](https://assets.st-note.com/production/uploads/images/220854821/picture_pc_8a9f6307dc53697cf0b2d00d6487154d.png?width=1200)

看见：截图为 1200×554；左上是返回与主页两个控件，左侧四类文字占宽约 16%。内容从 x≈292 至 x≈1037，6 列、4 行；格子约 93 px，列间空隙约 37 px。分类的选中状态是强调色文字与菱形；物品数量只出现于格底，等级颜色集中在格底与短底边。整页没有中央详情弹窗。

借鉴：仓库占满页面，顶部返回、左侧局部分类、中央连续网格。先用 6 列内容网格；详情进入完整详情页，或在整页内固定占右侧约 24%，不再新开小弹窗。选中分类用单个菱形或短线与文字明度变化；选中物品用细描边，等级颜色仍留在物品格底，避免把两种状态混淆。

来源说明：作者标注截图为 2025 年 10 月界面。该版本可作布局参考，不据此声称当前游戏版本未变化。

### R04 明日方舟：信用商店，全屏商品页

[来源：采购中心介绍](https://forum.gamer.com.tw/C.php?bsn=33651&snA=2287) · [真实截图](https://truth.bahamut.com.tw/s01/202007/733e80d514aa6fb40f880574f36173c7.JPG)

看见：1920×1080；返回/主页与资源在顶端，商店大类横向排列在其下。当前分类采用明亮页签与上沿强调色；商品区域为 5 列、2 行，每个商品的名字在顶部、物品图在中央、价格在底部。售罄是覆盖物品的大字状态，不依靠价格旁小字。商品内容占画面约 70% 高度。

借鉴：商店改整页；本游戏先用 4 列大商品，分类在同一顶部基线，数量按实际内容变化。商品图区至少占商品高度的一半；名字、数量、价格各只有一个固定位置。购买在选中商品后的右下明确位置完成。状态信息与价格保持原有业务含义，不照搬原游戏的信用点、折扣或售罄规则。

## 2. 本轮一套统一的实施规则

| 部位 | 可直接实施的规则 | 对应依据 |
| --- | --- | --- |
| 主页场景 | 壁纸铺满；主体保持在画面 25%–55% 横向区间；右侧只做局部深色渐隐，保护文字；中央不叠面板 | R01、R02 |
| 主页导航 | 四个开放大字入口，右对齐；出击 44–48 px，整备/仓库/商店 24–28 px，辅助描述 12–14 px；行间距 40–56 px | R01 的约 1.8 倍字级关系；数字是实施建议 |
| 主页信息 | 资源放右上一行；角色名/基地名只保留一处；常驻入口以文字为主，图标只为识别补充 | R01、R02 |
| 完整大页 | 返回与标题共用左上基线；局部分类占宽 12%–16%，内容占 62%–76%；必须有可见返回，主操作稳定在右下 | R03、R04 |
| 仓库排版 | 图像网格至少占内容区 2/3；名称、数量、等级固定位置；类别用局部导航，不把每类包进独立卡 | R03 |
| 商店排版 | 横向大类、一处商品网格、一处操作区；4 列大商品起步，图区占商品高度至少 1/2 | R04；列数为实施建议 |
| 整备页 | 整页左 40% 展示人物/装备，右 50% 承载装备选择与数值，余量用于间隔；模块依任务排布，不复制主页设施小卡 | 本轮功能映射，非原游戏截图事实 |
| 字体 | 中文只用一套易读主字体；装饰体只用于大页标题；标题、名称、正文、辅助信息分别固定字级，不逐块发明字体 | Apple 字体原则，见下 |
| 材质与色彩 | 房间与人物沿用本项目插画画风；UI 用中性深灰、暖白文字、一个现有强调色；框线 1 px，圆角 0–4 px；等级色只在对象相关位置 | R01、R03 的视觉观察与本轮统一约定 |
| 选中 | 类别：强调字色 + 菱形/短线；物品：细线边框；禁用：降明度 + 明确状态文字。不得让「被选中」误读为「更高等级」 | R03、R04 |
| 留白 | 同组间距 8/12/16 px，组间距 24/32/48 px；优先通过距离表达分组，减少卡底与分隔线 | Fluent 官方布局原则 |

整备/仓库/商店/任务是完整页面之间的跳转关系。点击后应替换当前主要内容，不在主页背景上浮出一个窄窗。物品详情允许完整独立页，并保留回到原分类和滚动位置的路径。

## 3. 权威教学原则与本项目动效映射

**Microsoft Fluent 2：间距与层级。** 官方布局指南说明，距离近的元素被理解为相关；较大的周围留白会提高一个元素的注意权重；间距可表达分组，无需每处添加框线。其基础间距单位为 4 px。本项目据此建立上表的间距阶梯，主行动周围留白大于次级入口。[官方 Layout](https://fluent2.microsoft.design/layout)

**Apple WWDC20：字体样式。** Apple 将字体样式定义为字重、大小与行高的组合；字号本身不足以表达细微层级，也可以改变字重；长文本需要适合阅读的行距。本项目据此建立固定文字角色，正文不用装饰字、不靠加亮边补可读性。[The details of UI typography](https://developer.apple.com/videos/play/wwdc2020/10175/)

**Google Material：根据页面关系选择转场。** 官方组件文档将 Shared axis 用于存在空间/导航关系的页面，将 Fade through 用于关系弱的目的地；Shared axis 的进入和返回应显式成对配置。文档给出的默认 Shared axis 时长为 300 ms，缓动为 cubic-bezier(0.4, 0, 0.2, 1)。本项目复用关系与时序，不需要引入 Android 组件。[Google 官方 Motion 文档](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md?plain=1)

| 本项目操作 | 实施建议 | 依据与边界 |
| --- | --- | --- |
| 主页 → 完整大页 | 原菜单 120 ms 淡出；新页 260–300 ms 从 0.985 缩放至 1 并淡入；标题、内容、操作区最多三组错开 30 ms | Material 导航关系；具体数值是本轮建议 |
| 大页 → 主页 | 反向配对，新页先退场再恢复基地菜单；返回时不重新播放整幅房间长动画 | Material 进入/返回配对 |
| 仓库 ↔ 商店 | Fade through：旧内容先淡出，新内容再淡入；总 220–260 ms；资源与返回控件保持位置 | Material 弱关系目的地 |
| 大页内部分类 | 内容区 160–180 ms 淡变；选中线/菱形一次移动完成，不让每个格子分别跳动 | 本轮建议，静态截图不证明原游戏动画 |
| 指针悬停/按下 | 100–140 ms 明度变化；开放菜单仅移动 2–4 px；按下可缩至 0.99；不增加连续光带、闪烁和漂浮 | 聚焦被操作对象的反馈 |
| 装备/购买结果 | 在被操作对象与结果位置之间做一次短过渡，结果文字即刻可读；提示 1.2–1.6 s 后退场 | 本轮建议；业务逻辑由现有实现决定 |

## 4. 本轮迭代顺序与证据边界

1. 先把主页改成 R01 骨架，将基地操作移到完整大页；不要先堆纹理、描边和粒子。
2. 仓库以 R03、商店以 R04 做同一套页面外壳；先用实际代表内容完成排版，再覆盖其余内容。
3. 最后补标题、材质、物品分级与成对转场；主页和子页沿用同一文字、间距、线宽和强调色。

本轮已读取 5 张真实游戏 UI 截图及 3 份官方设计教学来源，只将截图在内存中查看，未保存第三方二进制素材。未操作游戏浏览器，未做截图验收、测试或 build。网上静态截图不能确认原游戏具体动画、运行尺寸与所有交互状态；以上动效和尺寸均标注为实施方案，交由主线接入后由老板看效果。
