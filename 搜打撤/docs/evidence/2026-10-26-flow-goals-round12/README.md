## 实施

- `game/src/battle/bag/battle.bag.domain.js`：`useItem`、`usePotion`、`useBattleEffectItem`透传实际结果，复用既有预留marker在消费账本提交后记录consumed。同步未消费返回false、已消费返回true，进入目标选择返回`{status:'needs-input'}`，排队动作在队列完成后返回本次consumed。结构化处理的原handled信号、队列resolve及吞异常均不替代消费证据；已消费后的显示/收尾异常保持实际已消费结果。
- `game/src/battle/core/battle.engine.factory.domain.js`：回合结束期间对药水/道具的拒绝明确返回false，其他转发保持既有规则；旧点选与拖拽调用忽略返回仍兼容。
- `game/src/battle/view/battle.potion-use.js`与`battle.view.js`：本次药水来源贯穿实际命令结果，失败或取消目标后，原UID仍在同一有效战场时恢复详情、焦点及“药水已保留，可重试或取消”反馈，不可用时保留具体原因。药水栏内容刷新保留本次来源；成功消费、离页、换战斗清理。使用资格、目标与消费规则仍由原命令维护。
- `game/src/battle/view/battle.decision-shell.js`：牌堆、手牌选卡及编组同页同正文且本页详情仍有效时复用DOM，避开整页重绘的强制关闭；规则快照变化则退出旧详情。发现页继续原忙态与提交机制。公共返回状态维护焦点，详情上/下一张浏览后关闭返回当前卡。
- `game/src/battle/view/battle.decision-content.js`：同名选卡组补稳定身份，代表UID/下标改变后优先恢复同一剩余卡组，消失时沿原邻位回退。

复用既有消费账本、动作队列、详情控制器与公共返回状态；未新增事务或样式框架。`game.bag.safe-transfer.js`、`battle.overlays.js`、`battle.hand-inspector.js`保留本轮开始时实现及原有增量，本批不开放战斗背包或独立手牌详情。

## 老板统一验收入口

- 药水详情→使用：同步消费及排队消费后收回详情；拒绝/未消费时回原药水重试。
- 多敌药水→选择目标→取消，核对原药水、详情、提示与焦点；随后可重新使用。
- 排队中切页/换战斗，旧完成只结束本次来源；回合结束中发起使用按实际拒绝处理。
- 牌堆/编组/选卡查看详情后触发同内容刷新，保留详情；卡牌规则或内容变化使用新内容。
- 详情上/下一张后返回当前浏览卡，同名组选一张后焦点回剩余同组；原滚动保持。
