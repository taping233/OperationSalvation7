# 战斗提交反馈与输入收尾

2026-10-16老板对已报批三项回复「继续」，本轮按批准执行：核心出牌提交结果与失败回退、鼠标瞄准后Enter确认、手牌差分后的焦点交接。测试与实机验证留最后统一。

范围：在原出牌规则上增加权威可用性/结构化接收回执，区分拒绝、等待目标/注能/支付、入队及实际提交/取消；表现端按同一场次/UID/动作接线，不用几何命中冒充成功。保留装备上限、费用、发牌和选择规则，旧playCard调用合同保持。焦点仅在原来位于手牌内时交接，不主动抢鼠标或外部控件焦点。

分工：node_rules持有battle.engine/core/exec-play/action-runner及必要提交类型；根持有battle.aim.js反馈/Enter接线与必要手牌呈现收口；global_ui持有battle.layers.js焦点局部；expedition_ui只读复核提交呈现生命周期。无新美术或服务，不提交。

## 本轮实现

- 核心提供只读可用性查询和结构化提交接口，保留旧出牌返回语义；拒绝、目标/注能/支付接管、入队及实际提交分别表达。合同和确切核心路径见 [core-contract.md](core-contract.md)。
- 表现端先解除active aim，再提交命令；用场次、UID和动作序号接收回执。核心拒绝时给出原因，源牌仍在当前手牌时平滑归位；等待选择不按失败取消。扣费并移出源牌后的效果取消不触发假归位。
- 鼠标瞄准单目标时Enter确认当前合法落点，与鼠标提交共用目标会话；输入框、规则区、独立按钮、组合输入与长按重复不触发这个确认。
- 手牌内容差分前捕获原卡面/规则焦点及滚动位置；同组存活时恢复，原组消失时转最近存活组，空栏回退分栏钮或选项。已转到敌人/其他控件时不抢焦点，长按Enter/空格不连续触发下一张。
- 手牌常驻层已经挂载时不再自我替换，以免在差分捕获焦点前先摘挂失焦。这是当前舞台内的局部交接，不新增发现/墓地/跨场次的焦点记忆。

## 人工复核与收口

expedition_ui对核心接收、提交点、一次性结算与队列取消链作限定只读复核；据此收口了两处表现边界：指向敌人/自身的可选注能牌按实际直打意图查询，不被材料门提前拦住；姿态释放取原始play事件，不取动画抵消后的played集合，覆盖同帧打出又回手且UID不变的牌。原play+draw抵消飞行动画的规则保留。
