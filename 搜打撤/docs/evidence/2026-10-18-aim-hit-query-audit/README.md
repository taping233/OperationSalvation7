2026-10-18 UTC。只读审计发现一个小型重复 DOM 查询；本轮决定不移动公共命中边界，不改生产代码。后续有真实浏览器帧分析，再决定是否值得优化。

## 路径与计数

`battle.aim.js` 的 `aimPointerFrame` 调用 `aimHoverAt`。后者先调用 `session.hitAt`，由 `battle.target-session.js` 执行一次 `document.elementFromPoint`。如果返回 any 命中，`aimHoverAt` 又按相同坐标查询一次，以排除手牌和操作控件。两次查询间该路径没有 DOM 写入。

计数脚本加载当前真实 `createTargetSession`，从当前源码提取 `aimHoverAt`；jsdom 固定每个场景的命中节点并计数。每场景运行 1000 次：

- 合法 any 战场子节点：2000 次查询，1000 次接受。
- any 手牌、data-act 按钮、data-ui-tip 控件：各 2000 次查询，全部拒绝。
- any HUD、顶部栏、道具栏、战场外遮罩：各 1000 次查询，全部拒绝。
- enemy 敌人节点：1000 次查询，1000 次接受。

原始输出见 `counts.jsonl`。从项目根目录重跑：

```sh
node docs/evidence/2026-10-18-aim-hit-query-audit/count-hit-queries.mjs
```

只使用已有 jsdom，不安装依赖、不启动服务、不加载外部网页、不改生产文件。源码形状变化时脚本会停止，须人工检查提取范围。

## 语义边界与未核项

理论上可以把 any 排除检查合并到 `hitAt` 已取得的当次节点，避免第二次查询，保留 `{kind, el}` 返回结构且不跨帧缓存。但这会移动共享目标会话的排除边界；本轮不为一次查询节省扩大回归面，未实施这个建议。

未来若实施，必须保留场次存活检查、HUD/顶部栏/道具栏、手牌/卡槽/卡面、手牌工具、技能说明、data-act/data-ui-tip 控件及战场外遮罩的排除语义，保持 enemy/self 命中和提交时实时校验。不能用跨帧命中缓存引入陈旧目标。

本实验只是函数调用计数，不是浏览器命中测试、布局计算或帧率测量。未证明耗时瓶颈、卡顿来源或 FPS 收益；jsdom 不模拟实际布局与绘制。当前内置浏览器实页验证未完成，没有使用 headless/CDP/外部浏览器替代。本证据不构成生产优化或实页验收通过结论。
