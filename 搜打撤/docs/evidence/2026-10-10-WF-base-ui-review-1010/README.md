# 基地与二级页面：评估、外部对比和实施计划

日期：2026-10-10。状态：**评估与计划完成，游戏源码与素材尚未接入修改**。老板已授权整个基地及相关美术整改，最新要求是先完成评估与计划，再实施和对比迭代。

## 核心判断

当前最需要解决的是内容组织和点击承诺。部分页面已经能清楚说明状态，但人物培养的操作链没有接通，外观预览还有大立绘消失的问题。只统一颜色或增加装饰不能解决这两项。

仓库适合借鉴《明日方舟》的紧凑物品陈列、稳定数量位置和用途分类；人物管理借鉴角色与成长信息同屏；反馈借鉴有明确目标的详情与跳转；美术统一继承本项目认可的手绘块面语言。

## 老板定义的三个标准

| 标准 | 本轮含义 | 检查方式 |
| --- | --- | --- |
| 准确性 | 界面是否清晰地展示了该展示的内容 | 检查对象、数量、当前状态、用途、条件、收益与主动作的层级；分类名称对应实际内容 |
| 满足感 | 点击界面各部分能否得到意料之内的反馈 | 实际点击，核对选中、预览、展开、跳转、禁用原因和返回；按钮承诺须落实到具体内容 |
| 统一画风 | 相邻页面与相关美术是否采用一致的视觉语言 | 比较笔触、色块、光影、图像完成度、字体、控件、状态和动效；对象维持各自身份 |

满足感不等同于收藏豪华程度、奖励数量或动画数量。

## 已成立、应保留的操作

- 仓库选卡更新右侧详情，放大后能返回仓库。
- 待复原空态明确说明来源、钥匙成本和下次出发清空的条件。
- 建设页选择背包或仓库，会更新对应收益、费用和不足原因。
- 伙伴页能区别随行、已相遇、未相遇；“查看孵化条件”能展开实际条件。
- 未解锁卡背可预览条件，“查看解锁目标”会定位并聚焦对应成就。这是培养跳转应参照的完整反馈链。

## 拟实施的信息结构

| 主入口 | 内容 | 主任务 |
| --- | --- | --- |
| 出征 | 模式 → 人物 → 整备；准备状态与相关待处理提醒 | 清楚选择风险与回报，完成出发准备 |
| 仓库 | 战利品、基地物资、待复原；用途筛选和统一详情 | 找到物品、理解用途、完成收藏/培养/出售/使用/复原 |
| 队员 | 人物与伙伴；当前对象的培养、招式、外观 | 看清能力与成长，完成预览与培养 |
| 后勤 | 补给、扩建 | 查看补给、购买所需物品、提升容量 |
| 档案 | 成就、全员归档、卡背、见闻 | 查看长期目标、阅读记录、领取与使用奖励 |

这是拟实施结构，不是已经存在的功能；不增加新的玩法系统。原有购买、归档、出售、复原、孵化、升级和存档命令继续使用。

## 美术与交互规则

1. 底色围绕本项目已有的冬日冷灰、墨蓝与局部暖色建立；内容承托保持安静，优先让图像、数值和动作可读。
2. 同层分类采用同一组尺寸与选中标记；物品选中、品质、已拥有、不可用分别表达，不能只以同一颜色代替。
3. 网格点击选择并更新详情；详情中的查看动作打开大图；操作按钮给出对应结果、条件或确认。跨页跳转携带所需对象与筛选。
4. 当前对象预览与已装备状态独立；缺少材料仍能阅读能力和获取说明；成功结果在当前页面可感知。
5. 角色、宠物、物资采用共同笔触、色面和光影；图标保持功能识别职责，不作为大幅角色插画的替代品。
6. 宠物各有独立形体、性格、眼色和识别锚点。无的蓝眼、虎牙、发型、饰品与服饰不是其他主体的画风要求。
7. 动效服务选中、展开、换图与返回；处理中断与加载，静止画面仍能看清状态。

| 2 | 人物培养与仓库衔接；拆清个人成长和全员归档 | 与干员详情及绝区零培养入口比较；人物→可培养物品→收益/条件→返回的对象上下文连续 |
| 3 | 五个主入口与补给、扩建、伙伴、档案二级页 | 与角色、记录、阅读参考分别比较；每页主对象、主动作和次要信息清楚；分类均能到达实际内容 |
| 4 | 宠物/必要物资代表样稿及接入 | 比较现有人物、卡面与新样稿的笔触、色面和身份；先纠正第二稿错误的人设特征，一件成立后再扩展同套 |
| 5 | 清理现行样式中的重复/旧规则；跨页复核 | 对比完整出征、物品、培养与档案链；关键内容无遮挡，返回/焦点/选中一致；相关定向验证和当前窗口实页检查 |

每个阶段按三个标准记录失败项，修改后再比较；没有新变化或失败依据，不机械重复检查。文件删除另列具体路径；已授权范围内可直接清理文本中的旧样式规则。
