# 先学案例，再按实际卡面重画

2026-10-11。状态：本轮只研究、并排看图和设计brief；没有继续生图、接入新素材、修改游戏源码或统一验收。之前已做的源码保持现场。雪箱与winter-street候选已经被老板否定；商店/入城候选也不作为风格锚点。

本研究阶段完成后，根已开始后续[商店画法单样本](../art-calibration/shop/ART-GEN.md)派工：仅一张NAI候选→内置图像参考精修，不接入游戏，不批量扩展。研究阶段与制作阶段分别记录，不以原候选成功推定认可。

**画法以老板指定的实际卡面为基准，专业案例用于学习造型、舞台、构图和展示。** 卡面的大主形、宽笔触、有限明暗与局部强调需要落实到具体素材；写“块面厚涂”风格词、减少几个细节或生成成功，都不能证明画风成立。

## 新的素材方案边界

| 素材 | 先确定的设计 | 明确删除/避免 |
|---|---|---|
| 战场后景 | 建筑/自然主形、远近明度、与人物协调的卡面色块语言；可分远后景与透明中景框架资产 | 与角色竞争的中央大亮景、均匀碎砖纹理、整图写实/PBR质感 |
| 战场地板 | 横向可承重平面，匹配真实figure/imgBottom脚锚；独立地板资产及透明重叠边界 | 用全屏固定百分比冒充脚线；用CSS渐变冒充绘画地板 |
| 战场前景 | 单独透明近物层；低矮/靠边，真实遮挡顺序与点击区域独立 | 一张壁纸内的“看起来有前景”冒充可叠放层；遮脸、武器、血条或意图 |
| 普通宝箱样本 | 矮宽、完整盖身、大锁板、少量结构箍；按卡面暖红/米金/灰或相关协调主色试一种；真实透明 | 强绑雪、蓝缎带、角色徽记；地板、白底、光柱、密钉、碎磨损和UI描边烘焙 |
| 商店 | 参考方舟商人/货品分工，商人左、商品右；柜台和高亮出口不得侵商品区，木/布/金属用大色组区分 | 棚柱/柜台横穿留白；整张图同灰褐细碎切面；背景直接画价格/货位/按钮 |
| 入城 | 参考STS2完整页的主对象与奖励分层；实际已获卡是焦点，门廊为环境支撑 | 中轴尖塔/亮门洞/旗帜与真实奖励组成双焦点；提前虚构随机奖励 |

这些是来源驱动的待制作brief，不是新作品已通过。战场三层的生产规格、五种箱的推广与构图参数，仍需先用单一样本和实际显示尺寸建立关系。

## NAI与内置生图组合的真实用法

老板已允许商店/入城采用组合途径。已只读核对本地`tools/nai_gen.py`与`nai_style.py`：当前客户端有文本prompt/char_prompt，**没有图片reference参数**。过去脚本保存参考图SHA不等于图片送入NAI。现仅确认凭据文件存在，未读取/输出秘密、未验证远端凭据/额度、未发请求。

后续可按既有文本配方让NAI出一张画法候选，再由内置imagegen明确使用实际卡面和候选作视觉参照，处理构图、留白、分层或透明边缘。两步分别记录真实输入和保留项，不能声称NAI已接收卡面图片。先完成一张样本的画法与用途关系，再推广；不以必须混用两个渠道代替质量判断。
