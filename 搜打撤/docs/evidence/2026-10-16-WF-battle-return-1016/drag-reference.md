## 恢复的流程

1. 手牌鼠标按下即开始起拖，卡牌 holder 位置向鼠标位置插值。位置使用每帧 `delta * 7`，缩放使用 `delta * 8`；位置误差小于 1 个布局像素时吸附。单条 rAF 同时推进活动牌与归位牌，后台大帧的插值比例封顶为 1，避免越过目标。
2. 出牌线为视口高度的 75%，按起点采用 `max(75%线, 起点Y−100)` 或 `min(75%线, 起点Y−50)`。真正过线之前松开左键不结束起拖；仍随鼠标移动，随后跨线时选择点击确认模式。
3. 单体牌过线后停靠底部中央，缩放到 0.75，箭头从卡牌指向鼠标。仍按住左键进入的场次使用松手模式：命中合法目标才施放，松空改为点击确认并保留指向。随后点击合法目标施放，点击空白取消；最终确认再次检查出牌区。
4. 无目标/群体牌过线后继续跟手，处于出牌区时显示战场提示，退入 75%–95% 中间带只隐藏提示。按住跨线时松手确认；已松键跨线时下一次左键按下确认。本项目仍拒绝在 HUD、控件或手牌上释放。
5. 进入目标阶段后，离开过底部取消区再回到 95% 以下即取消；右键、Esc、输入失效及场次失效也取消。归位重新读取当前手牌 CSS 布局目标，使用同一位置/缩放插值时钟，撤下前轮 170ms 独立 WAAPI 回落。

## 网页接口适配与边界

- 单体范围继续使用本项目 `createTargetSession` 和 `elementFromPoint`；拖动卡及全部后代沿现行 `.aim-lift` 样式不参与命中，overlay 保持指针捕获。未修改战斗核心命中范围、伤害、发牌或费用。
- 源码的 100/50 是设计布局距离；本项目在 1920×1080 布局外统一缩放，鼠标位置则为视口视觉坐标，因此起点偏移使用 `100 * uiScale()` / `50 * uiScale()`。75%/95% 线仍按视觉高度比例计算，阈值规则未变。
- 过线前松键、松空转点击时释放指针捕获但保留全局鼠标采样；左键已松开导致的失捕获不会错误取消。真实 `pointercancel`、失焦、隐藏和窗口变化仍清理。
- 同场重绘仅在左键仍按住时重新取得捕获；松键等待和点击确认状态不重新捕获已释放的 pointer。
- 消费过的鼠标释放记录同一 pointer/坐标，只拦该次后续合成 click；键盘 click 不受此拦截，避免 window 释放处理后旧卡牌或单位委托重复提交。
- 群体点击模式在按下时提交，因此先保存该 pointer 的待松键标记，跨发现页等换页继续等待真实 pointerup，再以松开坐标启动短 click 抑制窗口。长按不会让窗口在松键前过期；pointercancel、新 pointerdown、失焦及 HMR 清除旧标记，下一次独立点击不继承该消费状态。
- 原数字键/Enter 使用 `selectCardByClick` 兼容入口，调用前取消仍存活的鼠标会话；注能和现有键盘目标选择分流保持原功能。这是本项目键盘适配，不宣称复刻 Godot 的快捷键节点结构。
- 本次 0.75 停靠尺寸由老板重新明确批准；不沿用此前不缩牌的历史偏好。
