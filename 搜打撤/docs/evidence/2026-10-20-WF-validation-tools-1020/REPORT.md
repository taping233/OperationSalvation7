# 验证工具可靠性修复

两项问题已处理，完成未提交。doctor 的失败来自夹具目录未被实际删除；按路径选验仍采用原计划入口，将预检等待上限从 15 秒调整为 60 秒，补全启动失败、超时和信号中止提示。检查选择与实际门未修改。

## 原因与改动

`tests/workflow-doctor.test.js` 原先先生成依赖目录，再用 `rmSync` 删除以构造缺失目录或链接目录。当前 Windows 环境中，调用返回后目录仍在，导致链接创建报 EEXIST，缺包场景实际仍有包。两项失败在本轮再次复现，见[修复前输出](doctor-before.log)。夹具现可直接省略依赖目录，并在建立链接前断言目录不存在。真实 doctor 实现未改；缺包、失效链接、可读链接和版本漂移仍由原诊断逻辑判断。

原无 Git 副本对背包与宝箱两个路径选验，15.332 秒时达到旧上限；相同输入随后能在约 1.6 秒生成计划，见[首次失败](snapshot-plan-before.log)、[失败计时](snapshot-plan-before-timing.json)与[后续原实现结果](snapshot-plan-warm.log)。可确认旧上限会截断较慢的首轮预检；未将底层耗时进一步归因为磁盘或机器负载，也没有证据表明无 Git 是原因。

`scripts/workflow-evidence.mjs` 保留原子进程和检查选择，将计划等待上限设为 60 秒；超时停止并说明“未执行检查”，保留原错误 code/cause；其他子进程失败和信号中止也会报错。没有自动重试、缩小范围或跳过门禁。现行使用说明已同步到[工作流入口](../../WORKFLOW-TOOLS.md)。
