# 性能方法与历史基准

## 生产资源发布规则

`vite.config.js` 动态复制与生成预取清单使用同一发布决定：旧根角色帧、被当前地图图表替代的节点稿和旧过场只按 `scripts/runtime-asset-redundancy-review.mjs` 的精确已审定清单省略；源文件保留，dev 仍可访问。每次构建检查角色 catalog、选择器指纹和动态资产消费者，缺失或未审定情况保守保留；构建期间选择变化或完整 Rollup 图恢复被省略引用时明确失败，不能输出请求缺件的预取清单。未来重新选用原稿需重新核验发布规则，不能仅刷新指纹绕过审查。动态URL消费者可通过 `opaqueConsumerDependencies` 显式列出已审的间接路径提供者（如声音采样播放器与目录）；任一依赖或消费者缺失/变更时保留全部候选。指纹仅在单次扫描内按文件缓存，不跨扫描复用；所有精确值仍须独立审查，不自动刷新。

等字节 URL 别名每次重新校验原图和正本，重绘、分歧或缺正本时恢复独立发布。口粮原图与缩略图分别别名；缩略图清单保留旧逻辑查询键，让低倍率卡库继续选择缩略图，随后 `assetUrl` 指向实际发布的正本，启动再按最终 URL 去重。现用角色/宝箱帧、皮肤、字体和许可文档不由这份冗余清单排除。


本页维护测量方法、调度行为和历史结果。当前 Vite 性能需在当前平台内置浏览器、当前窗口采样；记录代码状态、设备、操作路径和采样条件，再做同条件比较。绘制上限可在设置中选择，实际帧率与回归以对应测量报告为准。

## 构建重复资源预算

`perf-budget.cjs` 先统计所有产物字节数并按文件大小分组，仅对同大小的候选文件读取内容、计算 SHA256；大小唯一的文件不读取内容，因此这一步不检测其内容读取错误，也不是全资源可读性校验；所有文件的 stat 错误及同大小候选的内容读取错误仍会使检查失败。重复字节仍按同内容文件多出的份数累计，包体与重复资源阈值不变。检查对象必须是已完成、检查期间不变的构建输出。

## 当前 Vite 测量入口

使用开发地址的 `?perfProbe=1` 探针，并按实际任务采样地图移动、缩放、页面覆盖或战斗。分别记录绘制耗时、帧间隔、长任务和资源开销；受控动画与真实玩家操作注明各自范围。服务与浏览器约束见[质量门](quality-gates.md#内置浏览器验收)。 展开左侧“性能”后，“音乐播放（只读）”显示公开音乐快照的后端、请求/当前曲目、开关、播放进度、实际/目标音量、静音、错误与轨道；“读音乐”手动刷新，主动采样期间最多每秒刷新。未采样时不轮询，折叠会中止采样；正常无 debug query 不加载探针。进度递增与非零音量只证明播放状态，不能替代耳听验证。

### 自然入口与资源压力的测量边界

2026-10-17 自然存档路径出现 Chrome code 9，原因仍未查明；已用故障夹具确认角色帧退出释放可能被单个不完成的加载阻塞，并修复该生命周期缺口；尚无证据将其与现场崩溃关联。完整目录预取使用流式 fetch，不代表全部图片同时解码。192MiB/96张图片池只统计保留的已加载 Image，不包括在途解码、Pixi纹理、音频和浏览器内部缓存；资源预取完成计数不能当作内存占用。牧师当前50帧的宽×高×4合计33.40MiB；探索/战斗曲以48kHz双声道float32计算分别37.67/43.95MiB，交叠约81.62MiB。这些仅为资产容量估算，不是实际内存、峰值保证或崩溃归因。

回合反馈与战斗二级页隔离夹具使用声音替身、不跑完整目录预取，其持续正常不覆盖自然游戏音频与全资源路径。长BGM默认使用HTML5媒体后端，避免在游戏WebAudio上下文整曲解码；失败不回退整曲WebAudio，保留可播旧曲或显示失败状态。短音效继续WebAudio文件采样。原记录提及音乐开/关对照提示音频路径相关风险，但当前工作树未保留10-17自然入口审查原报告，不能据此复用历史验收或认定code9已消除。下一轮观测可在同一路径各阶段通过开发页 ?perfProbe=1 的“性能→测当前页面/读加载/读音乐”可见面板保存结果与截图，分别记录预取完成、首次战斗、营火、第二战及注能前；每次页面采样需六秒，应记录对时间线的影响。面板资源记录可能截断，且不显示图片池或进程内存；本轮实际观测范围见[逐页性能核查](evidence/2026-10-18-WF-page-perf-1018/README.md)。

已有时点证据：[09-29 全场景账本](PERF-LEDGER-2026-09-29.md)、[09-29 照相馆专项](PHOTOLIB-PERF-TASK-2026-09-29.md)、[09-28 Vite 记录](archive/records-2026-09-28/VITE-IAB-PERFORMANCE-2026-09-28.md)。复用前核对代码、环境和操作是否仍相同。

## 当前优化

- 仓库筛选/点卡在当前更新内建立稳定堆键索引，普通点卡只更新一次；背包仅在当前整页渲染确有散装物资时筛选一次资源目录。索引不跨操作保存，原地库存与目录变化下次操作立即生效。
- 远征路线复用已算出的节点状态投影；路径查找仅在单次 BFS 内去重阻塞判断；重编事件在当前打开内按类型/稀有度分组候选。节点壳复用本次事件模板，普通节点不解析未使用的事件正文；输出与选择规则保持。
- 选人页不再额外投机解码并强持五张默认全幅立绘；当前可见立绘、头像与皮肤仍按各自入口加载，切人/换肤保持原解码后替换机制。
- 手牌每次仍读取当前状态，只向 DOM 提交变化的属性与样式；注能无关按键不取战斗快照，有关按键每次读取一次新快照，离页解绑；发现页 350ms 入场闸门只在展开状态改变时写提示与 aria。
- 公共卡面每卡最多保留最近生成的 32 种 HTML 参数变体；标题时钟在不可见、被全页覆盖、壁纸/制作名单模式和离页时停止，恢复只运行一份。操作数对照、页面覆盖和实页边界见[逐页性能核查](evidence/2026-10-18-WF-page-perf-1018/README.md)；这些预算不表示 FPS、RSS 或崩溃根因的实测结论。
- 回合标题与获取/随机释放卡面使用共用反馈色板和节奏。节能画质或减少动态偏好下保留静态短显的标题、真实回合数与完整卡面，省略位移、飞行及落位高亮；高/均衡保持相同反馈语义。标题仅一个，1450ms清理，不加入动作等待；场次切换、关页和宿主移除取消计时及动画。
- 设置 → 画面与反馈通过“画质档位”选择节能/均衡/高画质，通过“动画帧率”选择 30/60/120 FPS 绘制上限；默认均衡、60 FPS，浏览器本地保存并即时生效，保存失败明确提示。地图背景与角色画布采样上限分别为 1/1.5/2×，庭院为 0.75/1/1.25×。采样受屏幕像素密度限制，倍率与 CSS/视频范围收在“详细说明”；卡牌文字与主地图节点仍用原始清晰度。
- 地图活动绘制及移动、镜头滑动、迷雾、辉光、换层动画按所选预算提交；普通输入、状态变更与收尾帧立即绘制。战斗角色的动作时间轴仍按原 30/60 FPS 推进，仅 GPU 绘制提交取角色原上限与用户预算较小者，不延长死亡或其他演出；庭院保持最高 30 FPS。预算不限制浏览器全部 CSS/视频，不改变游戏计时、移动进度、随机与结算等待；120 只在高刷新屏幕有额外收益。
- 地图辉光窗口进行中切换到减少动态或节能档时，下次驱动回调停止动画失效并补一帧静态辉光；不再等原呼吸窗口结束。
- 战斗角色在异步接管恢复、活跃帧推进、静止轮询与动作入口重新检查减少动态偏好；开启后复用原 hide 路径释放纹理、恢复静态立绘，过期异步接管不能复活帧层。不新增订阅或改变动作时钟；关闭偏好后沿正常接管入口恢复。
- 节能关闭指定标题雪雾、装饰呼吸与地图辉光呼吸，并暂停地图雪层、体积光与边缘光点的 CSS 动画，保留静态美术；均衡减少标题雪雾/装饰光效；高画质保留完整装饰。目标、伤害、资源提示不受抑制，「减少动态效果」仍独立生效。
- 空闲地图在显式失效或活动切换时补绘，主循环保留约 4Hz 状态巡检。调度器没有 `idleFps` 配置。
- 标题或不透明全屏页面覆盖地图时不调用 Renderer。页面隐藏时，地图雪层、体积光和边缘光点通过共享可见性状态暂停；回到前台后按当前画质和减少动态偏好恢复，不修改用户设置。
- 静态天空、棋盘、渐变和壁纸继续复用缓存；资源完成加载后使调度器失效并补绘。
- HUD 仅在对应字段变化时写入 DOM。
- 战斗瞄准箭头Canvas的位图按实际显示矩形×屏幕DPR分配，CSS仍使用逻辑布局尺寸；绘制坐标保持视口口径，清屏先恢复单位矩阵覆盖整个位图。相同坐标/颜色/位图尺寸复用绘制缓存。此项只修正缩放后的像素预算，不改变箭头几何、命中或瞄准帧循环，也不构成code9原因或已消除崩溃的证明。
- 战斗角色帧输出画布按DPR×UiScale采样，允许小于1，保留画质档位1/1.5/2×上限；逻辑坐标、源帧纹理与动画节奏不变。创建、复用、设置变化、窗口resize和恢复可见时核对逻辑容器尺寸；活跃绘制及已有静止轮询只比较采样倍率，变化才重读尺寸并resize、置脏补画。resize始终使用容器逻辑尺寸，不从Pixi舍入后的screen反推。此项减少输出backing像素预算，不代表纹理/RSS节省、FPS提升或code9已修复；小窗细边缘观感需实页核验。
- 敌方攻击弹道Canvas保持uiRect逻辑尺寸与曲线坐标，位图按逻辑尺寸×UI缩放×DPR取整分配；小窗允许低于逻辑1倍采样，绘制变换使用同一缩放×DPR。此通路不受画质档位控制，降动效仍跳过弹道；淡出与兜底移除时序保持不变。
- 图片预热强持有池按画质限额：节能 48 MiB、均衡 96 MiB、高画质 192 MiB，张数上限仍沿统一预算。切换画质时即时释放超额池引用；单张超过当前额度不强持，优先保留可容纳的小图。`Art.warmStats().maxBytes` 报告当前限额；这只是池内按原图尺寸估算的RGBA引用量，不等于浏览器总内存或立即回收的RSS。可见图片与src不受影响，升档不主动重新预热已释放图片。
- 普通 `Art.warm()` 调用共用最多两个图片加载/解码槽；排队URL立即去重，加载和解码完成或失败后再推进，失败允许后续调用重试。不限制可见DOM图片或显式启动批次，队列本身不改变画质对应的缓存预算。
- 标题启动不再投机解码全部敌人抠图；参战敌人的可见图片由 `cutoutFigures()` 按需切到现有抠图 URL，缺失仍回退原图。可见图片加载与原图URL保持；冷缓存首场显示须单独验证。
- 战斗进入与检查点恢复只预热传入卡牌的实际图片 URL，使用现有 `retain:false`，仍经两槽加载/解码但不加入 Art 强引用池，不附带全敌人图鉴与全职业立绘；可见参战者由原场景图片按需加载。此项只减少投机图片强持，不释放可见图片或保证浏览器立即回收；成功 URL 仍会话内去重，后续显示可能由浏览器重新解码，不能据此断言崩溃根因已修复。通用美术收集器仍可供显式调用，但启动不再调用完整人物清单；预热池预算与加载失败处理不变。已被预热池淘汰的图片即使迟到加载成功，也不再主动解码；批量预热仍正常结算完成进度。
- 地图每次绘制共用节点几何、路线和节点状态投影；任意节点的待复原查询直接读取坐标，不复制整个游戏运行态。投影不跨帧保存，原地编辑奖励在下一帧可见。
- 道路先按曲线控制点包围盒和纹理外缘判断是否进入视口，再裁剪与烘焙；平移回来时补齐。每条边在缩放、选择和奖励状态变化时复用原画布，按现行尺度重烘焙；短曲线按曲率减少纹理切片，中心线弦误差目标不超过缓存像素的1/8，保留原40片上限。原图、纹理宽度和缓存分辨率保持原口径。
- 可选基地静态房间（`home/home.scene.js`）不启动连续 Pixi ticker：首次显示、更新、resize、纹理就绪和恢复可见时合并请求单帧；隐藏取消待绘制帧，离开时取消帧并解绑迟到纹理事件。纹理所有权不变；主首页与庭院不属于该按需绘制范围。
- 网页与本地启动只准备六张常见场景和13张现行卡框，共19项，统一以四路HTTP预取编码资源，不主动创建场景 Image、解码或加入强持池。首页提示仅表示这批HTTP资源进度，不代表图片已解码，不阻塞开始游戏；人物、卡图、图鉴缩略图与角色帧沿既有页面入口按需加载，不再在启动时遍历完整目录。场景仍由选人页、路线目标预取与可见页面按需加载；恢复战斗继续等待三层图片decode。续局原地重开拾取/火堆由CSS自然加载，没有额外揭幕等待，冷首用时延需实页验证。后台预取在页面隐藏、地图移动或有待处理输入时暂停发起下一批。响应体流式消费至结束后才计入完成，不为每件资源额外拼接完整 ArrayBuffer；不支持流式响应时沿原路径消费。同一最终 URL 的并发请求共用进行中的 Promise；旧队列执行时再查完成缓存，成功耗尽响应后才记完成，失败释放读取器与进行中标记，允许后续重试。主启动的 DOMContentLoaded 监听只执行一次；隔离复原夹具跳过启动后台预取，真实图片/场景加载不变。
- 本轮受控热点基准与实页采样见[地图与预热优化证据](evidence/2026-10-16-WF-game-performance-1016/README.md)，指标分别说明同步绘制、受控操作与真实输入范围。
- 照相馆分类标记在同一帧合并更新；换选复用标签尺寸，尺寸观察器或窗口变化重新测量。网格入场沿用重绘前的宽度，避免替换内容后立即读宽度；无样式的旧计数 `.bump` 状态不再触发布局读取。
- 照相馆卡牌图片由美术队列加载，不进入弹层 CSS 背景就绪检测。保持现有视觉的同窗口前后对照见[照相馆布局读取优化](evidence/2026-10-14-WF-photo-perf-opt/README.md)。
- 照相馆关闭时释放页面 DOM、监听器和图片队列，保留当前馆藏的派生索引、描述与卡片模板；数据内容、顺序或美术渲染器变化时整体重建。卡片高度按窗口、分类布局与字体状态缓存，最多16项。
- 城市切幕共用场景图解码与目标页视觉就绪条件。照相馆先画出不透明等待切幕，场景图和目标页并行准备，完成后再播放980ms揭幕；首屏卡图等待上限2200ms，切幕装饰图上限3000ms，装饰图失败以底色和文字兜底，取消时清理等待。基地、设置、成就与出发沿共用切幕准备逻辑。
- 卡牌描述富文本按最终展示文本复用分词与转义结果，最多256项；超过2048字符不缓存，修改文字或同ID不同说明自然使用新结果，不缓存战斗数值或整张卡状态。公共卡片浏览器仍每次读取当前过滤与尺寸，但仅在值不同后写入显隐、列样式、空状态和分页控件，图片加载后无变化刷新不产生重复DOM变更。相同输入计数与微基准见[运行热路径优化](evidence/2026-10-17-runtime-hotpaths/README.md)，不是实机FPS结论。
- 仓库图片加载事件合并到同一帧做网格布局；页面离开后不再补排。战斗瞄准与卡牌回位在同一帧复用基础几何，角色帧推进复用一次尺寸读取；标题提示观察器按祖先集合合并新增子树；启动音效优先准备界面确认音，再处理战斗音效。
- 本轮跨域审计、照相馆同窗口基准及慢图切幕、真实战斗操作范围见[全域性能续优证据](evidence/2026-10-16-WF-game-performance-wide-1016/README.md)。
- 全局图标观察器按祖先关系合并新增子树；普通数值文本更新不扫描整页，标签属性变化只清理目标元素。无图标的字符串直接返回，避免建立两份逐字符引号索引。
- `Art.decodeIn` 按图片元素与源地址去重加载回调、解码和补绘；换源、失败与脱离文档分别清理，保留冷图的补绘并恢复原有内联可见性。
- `node scripts/css-redundancy-audit.mjs` 只读列出同文件声明覆盖候选；`--entry` 按入口样式顺序列出跨文件候选。候选须再核对浏览器支持、独立宿主与活跃占用，不能直接当作删除清单。本次清理与局部性能对照见[公共渲染优化记录](evidence/2026-10-16-runtime-perf/README.md)。

当前行为可沿[画质设置测试](../tests/performance-settings.test.js)、[预热生命周期测试](../tests/art-warmup-lifecycle.test.js)与[静态房间测试](../tests/m05-home-scene.test.js)核对。10-17画质/独立复核/预取/静态房间四份原报告未保留在当前工作树，不复用其验收结论；本轮实际覆盖见[逐页性能核查](evidence/2026-10-18-WF-page-perf-1018/README.md)。调度测试与模拟采样不能替代真实 GPU/帧率测量。

## 历史 Electron 基准（冻结）

`npm run perf` / `perf:soak` 启动 Electron 基准，属于冻结桌面线。以下方法和阈值用于解释旧报告。旧脚本按系统缩放比构造 1920×1080 物理像素内容区，采样空闲、移动、缩放与覆盖场景，再汇总多轮结果。

### 旧报告的两级判定

- 发布性能门槛 `performanceGatePassed`：物理内容区为 1920×1080；移动与缩放场景 Renderer 绘制耗时 p95 不高于 8ms；空闲 Renderer 调用数相对持续 60 FPS 至少下降 40%；`covered` 样本的 Renderer 调用数为 0。
- 体验目标 `experienceTargetMet`：移动与缩放的整体帧间隔 p95 不高于 20ms，慢帧比例低于 5%。它包含 Chromium 合成、系统调度和后台负载，不再与游戏自身 Renderer 耗时混为一个发布门槛。

数值会受机器、电源模式和后台程序影响；比较前后结果时应保持环境一致。

## 2026-09-04 实测（历史快照）

当时显示缩放比为 1.5，基准内容区为 1280×720 CSS 像素，对应 1920×1080 物理像素。接入运行时库后的三轮中位数如下：

| 场景 | Renderer 调用 | 平均绘制耗时 | 绘制耗时 p95 | 整体帧间隔 p95 | 慢帧率 |
|---|---:|---:|---:|---:|---:|
| 空闲 2.4 秒 | 59 | 3.40 ms | 5.0 ms | 25.3 ms | 9.8% |
| 移动 2.4 秒 | 70 | 2.97 ms | 4.4 ms | 43.4 ms | 28.2% |
| 缩放 1.2 秒 | 31 | 3.22 ms | 5.7 ms | 27.6 ms | 10.7% |
| 全屏覆盖 0.7 秒 | 0 | 0 ms | 0 ms | 不作为指标 | 不作为指标 |

本次 `performanceGatePassed=true`：分辨率、绘制耗时、空闲降频和全屏暂停均通过。`experienceTargetMet=false`：整体帧节奏仍受系统合成与调度波动影响，没有达到 20ms / 5% 的体验目标。

三轮中最好一轮已接近目标（移动 p95 21.1ms、慢帧 6.5%；缩放 p95 9.4ms、慢帧 0.5%），而 Renderer 绘制 p95 始终低于 8ms。后续优化应优先排查窗口合成、后台负载和帧调度，不应在缺少证据时继续削减地图绘制质量。

## 2026-09-05 卡顿根因与修复

本轮将活动状态目标由 60 FPS 提升至 120 FPS，并补充 `activeTargetIs120`、`target120DeliveryMet`、实际 Renderer FPS、Long Task 和 GPU 型号输出。修复内容：

- 帧调度改用绝对 deadline，避免 120 FPS 在 165 Hz 显示器上因“以上次晚到帧重新计时”持续漂移；镜头模拟改为每次 rAF 更新，不再丢掉未绘制帧的 `dt`。
- 25 张战斗抠图改为逐张后台预解码；47 个短音效统一限制为两路解码，峰值扫描改为零临时数组循环；两首大 BGM 改用 Howler HTML5 流式播放。
- 标题、HUD 和战斗中的无限 `filter` / `box-shadow` 动画改为合成友好的 `transform` / `opacity`。
- Pixi 粒子层仅在粒子存活时启动 ticker；空闲后停止并隐藏全屏透明 Canvas，避免首次战斗后永久多出一条渲染循环。
- Electron 在混合显卡机器上请求高性能 GPU。实测从 Intel Iris Xe 切换为 RTX 3060 后，移动场景稳定轮从约 50 FPS 提升到约 68 FPS；自动集显路径还出现一次 Chromium GPU command buffer invalid 错误。

最终 1920×1080 三轮中位数：空闲 30.4 Renderer FPS、draw p95 3.5 ms；移动 67.9 Renderer FPS、draw p95 4.5 ms；缩放 draw p95 3.8 ms；所有场景 Long Task 均为 0。`performanceGatePassed=true`、`activeTargetIs120=true`，但 `target120DeliveryMet=false`、`experienceTargetMet=false`。

Intel PresentMon 2.5.1 的 ETW 侧采样显示交换链为 `Composed: Flip`、`SyncInterval=0`；GPU busy p50 2.49 ms、p95 9.48 ms，而 GPU wait p50 3.88 ms、p95 17.47 ms，3D 引擎采样峰值约 64.6%。因此剩余上限是混合显卡/DWM 呈现等待，不是 JS 长任务或 GPU 算力饱和。1600×900 内部画布和 `desynchronized` Canvas A/B 均无收益，已回退以保留原生画质和更高吞吐。要在本机窗口化路径稳定交付 120 FPS，还需单独验证显示直连或更新 Intel 显示驱动；这属于系统级变更，不纳入本次代码修改。

当时的桌面诊断使用 `SDT_GPU_INFO` 与 `SDT_PERF_GPU=auto` 比较选卡路径；当前主包未提供 `diagnostics:gpu` 命令。这些参数仅作旧报告的复现背景。

## 现行构建体积归因

`npm run build` 的预算步骤输出 `[perf-budget:composition]` JSON：按扩展名累计字节/文件数、最大12个产物、最多12组重复路径（每组最多12条，另记完整副本数）。沿用原大小分组与哈希扫描，不额外读取唯一大小文件。它衡量构建目录原始字节，不代表首屏下载、解码内存或加载速度；gzip门仍按原口径单独计算。

先用该归因核对大文件用途、动态引用、素材许可和可替代质量，再决定产物排除/压缩或预算调整。重复路径是审查候选，不能直接删除源素材；阈值调整需记录内容规模、实际测量与目标环境依据。

### 战斗帧几何探测

固定画布角色（雾、常无语、白塔、黑箱、星月）始终用首个可用idle的alpha包围盒定位，只有该idle候选需要额外bitmap测量；其余帧仅加载Pixi纹理。首idle纹理缺失时继续尝试下一个idle，全部失败仍保静态兜底。未采用固定画布的兼容路径继续逐帧测量。原动作序列、纹理并发上限3保持不变；不要把省去的重复bitmap解码次数当作浏览器崩溃根因或实测常驻内存降幅。

### 战斗帧诊断对照（开发环境）

`?perfProbe=1&flightRecord=1` 保持正常动画；追加 `&framesDiagnostic=static` 才在本次开发页面使用 neutral 静态人物，跳过角色 Pixi 初始化与序列纹理加载。三个参数与 DEV 同时满足才生效，不持久化、不改变全局降动效或存档。战场背景、卡牌和玩法继续使用原路径。该对照一起移除角色 WebGL/Canvas renderer 与帧解码，不能单凭差异判断是哪一项导致异常。

公开性能面板“读角色帧”显示开关状态、实际 renderer backend、renderer-loading/app-init/app-ready/idle/frame-batch/all-ready 等阶段以及 `SDT.Battle._perf.frameCacheStats()` 摘要；未加载战斗模块时仍显示请求的开关状态。展开/按钮刷新，采样期间最多每秒刷新，不另加轮询。重大阶段变化通过 DEV 故障记录同步白名单事件，连续 frame-batch 不逐批写盘；现有2秒pulse读取同一摘要。

纹理计数只覆盖当前角色缓存中已登记的 Texture；按 BaseTexture 对象身份去重后取整数 realWidth×realHeight，RGBA估算为像素数×4。它不含正在加载或已取消待卸载的临时对象，不代表 RSS、GPU已上传纹理或浏览器总驻留。liveApps 是该模块已创建且可复用的应用数（0/1），activeFrameSessions 是当前帧播放对象数（0/1），不是操作系统renderer进程或游戏会话总数；backing尺寸是帧canvas实际像素。

### 角色帧退出释放

帧URL在模块内记录使用者。退出先取消记录并清空sprite，再卸载已完成且无使用者的纹理，不等待其他尚未完成的加载。迟到完成时仅在没有新使用者的情况下卸载；新场复用同URL进行中的加载时保留共享纹理。已经开始卸载的URL必须等该次卸载结束才重新加载，其他URL不受其阻塞。加载失败允许后续重试；没有修改Pixi依赖、worker设置或增加强制超时。行为契约见[帧退出释放测试](../tests/battle-frames-pending-release.test.js)；10-17原报告未保留，测试不能解释首次入场的code9。
