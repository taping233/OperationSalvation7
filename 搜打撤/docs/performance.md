# 性能方法与历史基准

## 生产资源发布规则

`vite.config.js` 动态复制与生成预取清单使用同一发布决定：旧根角色帧、被当前地图图表替代的节点稿和旧过场只按 `scripts/runtime-asset-redundancy-review.mjs` 的精确已审定清单省略；源文件保留，dev 仍可访问。每次构建检查角色 catalog、选择器指纹和动态资产消费者，缺失或未审定情况保守保留；构建期间选择变化或完整 Rollup 图恢复被省略引用时明确失败，不能输出请求缺件的预取清单。未来重新选用原稿需重新核验发布规则，不能仅刷新指纹绕过审查。

等字节 URL 别名每次重新校验原图和正本，重绘、分歧或缺正本时恢复独立发布。口粮原图与缩略图分别别名；缩略图清单保留旧逻辑查询键，让低倍率卡库继续选择缩略图，随后 `assetUrl` 指向实际发布的正本，启动再按最终 URL 去重。现用角色/宝箱帧、皮肤、字体和许可文档不由这份冗余清单排除。


本页维护测量方法、调度行为和历史结果。当前 Vite 性能需在当前平台内置浏览器、当前窗口采样；记录代码状态、设备、操作路径和采样条件，再做同条件比较。120 FPS 是努力目标，实际帧率与回归以对应测量报告为准。

## 当前 Vite 测量入口

使用开发地址的 `?perfProbe=1` 探针，并按实际任务采样地图移动、缩放、页面覆盖或战斗。分别记录绘制耗时、帧间隔、长任务和资源开销；受控动画与真实玩家操作注明各自范围。服务与浏览器约束见[质量门](quality-gates.md#内置浏览器验收)。

已有时点证据：[09-29 全场景账本](PERF-LEDGER-2026-09-29.md)、[09-29 照相馆专项](PHOTOLIB-PERF-TASK-2026-09-29.md)、[09-28 Vite 记录](archive/records-2026-09-28/VITE-IAB-PERFORMANCE-2026-09-28.md)。复用前核对代码、环境和操作是否仍相同。

## 当前优化

- `core/render-scheduler.js` 的活动绘制目标为 120 FPS；空闲地图在显式失效或活动切换时补绘，主循环保留约 4Hz 状态巡检。调度器没有 `idleFps` 配置。
- 标题或不透明全屏页面覆盖地图时不调用 Renderer。
- 静态天空、棋盘、渐变和壁纸继续复用缓存；资源完成加载后使调度器失效并补绘。
- HUD 仅在对应字段变化时写入 DOM。
- 照相馆分类标记在同一帧合并更新；换选复用标签尺寸，尺寸观察器或窗口变化重新测量。网格入场沿用重绘前的宽度，避免替换内容后立即读宽度；无样式的旧计数 `.bump` 状态不再触发布局读取。
- 照相馆卡牌图片由美术队列加载，不进入弹层 CSS 背景就绪检测。保持现有视觉的同窗口前后对照见[照相馆布局读取优化](evidence/2026-10-14-WF-photo-perf-opt/README.md)。
- 全局图标观察器按祖先关系合并新增子树；普通数值文本更新不扫描整页，标签属性变化只清理目标元素。无图标的字符串直接返回，避免建立两份逐字符引号索引。
- `Art.decodeIn` 按图片元素与源地址去重加载回调、解码和补绘；换源、失败与脱离文档分别清理，保留冷图的补绘并恢复原有内联可见性。
- `node scripts/css-redundancy-audit.mjs` 只读列出同文件声明覆盖候选；`--entry` 按入口样式顺序列出跨文件候选。候选须再核对浏览器支持、独立宿主与活跃占用，不能直接当作删除清单。本次清理与局部性能对照见[公共渲染优化记录](evidence/2026-10-16-runtime-perf/README.md)。

## 历史 Electron 基准（冻结）

`npm run perf` / `perf:soak` 启动 Electron 基准，属于冻结桌面线。以下方法和阈值用于解释旧报告。旧脚本按系统缩放比构造 1920×1080 物理像素内容区，采样空闲、移动、缩放与覆盖场景，再汇总多轮结果。

### 旧报告的两级判定

- 发布性能门槛 `performanceGatePassed`：物理内容区为 1920×1080；移动与缩放场景 Renderer 绘制耗时 p95 不高于 8ms；空闲 Renderer 调用数相对持续 60 FPS 至少下降 40%；`covered` 样本的 Renderer 调用数为 0。
- 体验目标 `experienceTargetMet`：移动与缩放的整体帧间隔 p95 不高于 20ms，慢帧比例低于 5%。它包含 Chromium 合成、系统调度和后台负载，不再与游戏自身 Renderer 耗时混为一个发布门槛。

数值会受机器、电源模式和后台程序影响；比较前后结果时应保持环境一致。

## 2026-09-04 实测（历史快照）

当时显示缩放比为 1.5，基准内容区为 1280×720 CSS 像素，对应 1920×1080 物理像素。接入运行时库后的三轮中位数如下：

| 场景 | Renderer 调用 | 平均绘制耗时 | 绘制耗时 p95 | 整体帧间隔 p95 | 慢帧率 |
|---|---:|---:|---:|---:|---:|
| 空闲 2.4 秒 | 59 | 3.40 ms | 5.0 ms | 25.3 ms | 9.8% |
| 移动 2.4 秒 | 70 | 2.97 ms | 4.4 ms | 43.4 ms | 28.2% |
| 缩放 1.2 秒 | 31 | 3.22 ms | 5.7 ms | 27.6 ms | 10.7% |
| 全屏覆盖 0.7 秒 | 0 | 0 ms | 0 ms | 不作为指标 | 不作为指标 |

本次 `performanceGatePassed=true`：分辨率、绘制耗时、空闲降频和全屏暂停均通过。`experienceTargetMet=false`：整体帧节奏仍受系统合成与调度波动影响，没有达到 20ms / 5% 的体验目标。

三轮中最好一轮已接近目标（移动 p95 21.1ms、慢帧 6.5%；缩放 p95 9.4ms、慢帧 0.5%），而 Renderer 绘制 p95 始终低于 8ms。后续优化应优先排查窗口合成、后台负载和帧调度，不应在缺少证据时继续削减地图绘制质量。

## 2026-09-05 卡顿根因与修复

本轮将活动状态目标由 60 FPS 提升至 120 FPS，并补充 `activeTargetIs120`、`target120DeliveryMet`、实际 Renderer FPS、Long Task 和 GPU 型号输出。修复内容：

- 帧调度改用绝对 deadline，避免 120 FPS 在 165 Hz 显示器上因“以上次晚到帧重新计时”持续漂移；镜头模拟改为每次 rAF 更新，不再丢掉未绘制帧的 `dt`。
- 25 张战斗抠图改为逐张后台预解码；47 个短音效统一限制为两路解码，峰值扫描改为零临时数组循环；两首大 BGM 改用 Howler HTML5 流式播放。
- 标题、HUD 和战斗中的无限 `filter` / `box-shadow` 动画改为合成友好的 `transform` / `opacity`。
- Pixi 粒子层仅在粒子存活时启动 ticker；空闲后停止并隐藏全屏透明 Canvas，避免首次战斗后永久多出一条渲染循环。
- Electron 在混合显卡机器上请求高性能 GPU。实测从 Intel Iris Xe 切换为 RTX 3060 后，移动场景稳定轮从约 50 FPS 提升到约 68 FPS；自动集显路径还出现一次 Chromium GPU command buffer invalid 错误。

最终 1920×1080 三轮中位数：空闲 30.4 Renderer FPS、draw p95 3.5 ms；移动 67.9 Renderer FPS、draw p95 4.5 ms；缩放 draw p95 3.8 ms；所有场景 Long Task 均为 0。`performanceGatePassed=true`、`activeTargetIs120=true`，但 `target120DeliveryMet=false`、`experienceTargetMet=false`。

Intel PresentMon 2.5.1 的 ETW 侧采样显示交换链为 `Composed: Flip`、`SyncInterval=0`；GPU busy p50 2.49 ms、p95 9.48 ms，而 GPU wait p50 3.88 ms、p95 17.47 ms，3D 引擎采样峰值约 64.6%。因此剩余上限是混合显卡/DWM 呈现等待，不是 JS 长任务或 GPU 算力饱和。1600×900 内部画布和 `desynchronized` Canvas A/B 均无收益，已回退以保留原生画质和更高吞吐。要在本机窗口化路径稳定交付 120 FPS，还需单独验证显示直连或更新 Intel 显示驱动；这属于系统级变更，不纳入本次代码修改。

当时的桌面诊断使用 `SDT_GPU_INFO` 与 `SDT_PERF_GPU=auto` 比较选卡路径；当前主包未提供 `diagnostics:gpu` 命令。这些参数仅作旧报告的复现背景。

## 资源体积基线（2026-09-04 历史快照）

下列数字属于 2026-09-04 的工作树与构建产物，不代表现在。需要现行源码体积时运行 `npm run assets:audit`；需要现行产物体积时，先满足共享工作区的构建约束，再运行 `npm run build` 和资产审计。09-04 源码资产为 312.16 MB；选择性复制动态资源并让 Vite 统一处理静态资源后，桌面游戏目录为 193.42 MB，占当时源码资产的 62.0%。旧视频、候选标题图和原始图标当时仍保留在源码素材目录，但不进入该次发布产物。

审计同时发现 12 组内容完全相同的源码文件，理论可回收 38.54 MB。它们当前仍作为原始素材保留；删除前应先统一语义映射并逐项验证引用。
