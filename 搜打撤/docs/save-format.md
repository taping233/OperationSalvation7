# 存档兼容契约

## localStorage 键

| 键 | 作用 |
|---|---|
| `sdt-save-v2-slot1..5` | 五个档位的进行中对局 |
| `sdt-base-v2-slot1..5` | 五个档位的基地与局外成长 |
| `sdt-save-v1` | 旧单档对局；启动时迁入档位 1 后删除 |
| `sdt-base-v1` | 旧全局基地；启动时复制到尚无基地数据的档位后删除 |

设置项、卡牌库和格子备注仍使用各自已有键，不与档位存档合并。

每个进行中对局保存顶层 `seed` 与 `mapSeed`，并记录 `generatorVersion`、`layoutVersion`、`geometryVersion`；`rngState` 保存各命名随机流的当前位置。读档先恢复随机流，再用 `mapSeed` 重建五层地图，确保同一局的拓扑、节点 ID 和几何坐标稳定。`geometryVersion` 只用于渲染缓存失效，不参与玩法判定。

地图版本字段的职责如下：

- `mapSeed`：本局地图的唯一重建输入。新局在确定运行 seed 后立即生成；不允许在应用启动时用临时随机数替代。
- `generatorVersion`：地图拓扑生成器版本。读档时当前代码重新生成并写入当前版本；旧档没有该字段时按当前生成器兼容读取。
- `layoutVersion`：网格到世界坐标的布局版本。节点中心距由布局层固定为约 120 世界像素，避免把旧的全局横移公式带入新图。
- `geometryVersion`：当前地图几何缓存签名；换 seed 或布局版本时改变。

旧存档兼容策略：缺少 `mapSeed` 时优先使用旧档 `seed` 作为地图 seed；连 `seed` 也缺少时使用带档位的固定回退 seed，保证重复读取得到同一张图。旧档的 `layerIdx` / `trackPos` 若超出新地图范围，则回退到该层入口，不静默指向另一层的随机节点。读取旧档不会保存动画中间态。

移动事务只在稳定节点落点后保存：对局进入 `moving` 状态时不写档；页面刷新、退出或崩溃后恢复到上一次已完成的 `layerIdx` / `trackPos`。动画完成后才递增 `turn`、结算节点事件并写入存档。

## 兼容要求

- 缺失字段使用当前默认值补齐；未知附加字段应忽略而不是令读档失败。
- 迁移必须先成功写入目标键，再删除旧键。
- 删除档位只删除对应对局与基地数据，不影响其他档位。
- 重构允许移动函数和模块，不允许静默更改字段含义、资源数量、卡牌归属或安全格规则。

固定兼容样本位于 `tests/fixtures/`，由 `tests/save-compat.test.js` 覆盖 v1、v2、跨档隔离、未完成对局、基地、职业、成就和卡背。任何存档格式变更都必须同步更新样本与迁移测试。
