# 存档兼容契约

## 火堆独立操作

`nodeRewards` 的 `type: fire` 收据保留 `version: 1` 及原生命、复原牌、职业卡字段。新收据同时记录布尔值 `healUsed`、`restoreUsed`、`bonusRolled`，分别用于回血、复原及职业卡单次概率判定；只用其中一项时可返回地图，读档后保留另一项机会。三字段必须同时存在或同时缺省。缺少这三字段的旧收据表示原版休整已结算，回血与复原均视为已用，避免重复领取。

## 战斗入场检查点

战斗保存 `restartVersion=1` 的入场检查点：敌人定义、开战选项、随机流、开战前的对局数据及已确认的首脑套牌。读档重新执行本场开战流程，不恢复出牌中途、半结算费用或敌方回合进度。

运行中战斗快照按卡牌UID记录在手注能次数 `handInfuseCounts`，快照返回独立冻结副本。正式入场检查点不保存这一中途计数，也不改变存档版本；兼容旧格式中途状态时，缺字段按空表恢复，不用整场注能总数猜测。延迟伤害保存目标索引，已有目标存活时沿用；旧任务缺索引时保留原公共回退方式。

新战斗在检查点、开战选项和敌人建立完毕且处于稳定节点后，调用对局保存，再执行入场效果和展示；不会先写入 `battle:null` 作为本场检查点。保存通过异步回执报告失败或成功，失败时明确提示未保存，重新载入以最近成功存档为准。检查点恢复中的 start 不进行这次入场保存，仍由 loadGame 在完整恢复成功后保存。

动作队列结算回到玩家阶段后沿既有8秒节流保存，前台可延至idle窗口（2秒超时）；敌方回合结束回到玩家阶段调用异步保存。上述保存仍写入场检查点，而非恢复半场局面；仅选择卡或等待不会产生动作收尾保存。保存需要同槽锁，关页事件不能绕过锁进行同步写入；异常退出以最后成功检查点为准。

## 背包占格派生

`ownedCards` 的逐张 UID、`safe`、`stored` 与散装 `inventory.count` 继续原样保存。占格由现行规则重新派生：装备每张1格，其余同名卡每3张1格，散装物资每3件1格；不在读档时拆写、删除或移动旧卡。旧档因新上限超过容量时保留全部内容，仅拒绝新增占格，整理后恢复正常收卡。安全格转移与奖励预估必须传入完整卡牌类型，共用 `card-capacity.js`。

地图背包发现把候选保存在源牌的 `ownedCards` 条目中。员工通行证C沿用 `bagDiscover: { version:1, cardIds:[候选ID] }`，固定1–3个不同的可随机获取传说候选；结构化职业能力卡发现另带 `poolKind:'classAbility'`，未带该字段的旧记录按传说池读取。普通Run序列化与读取保留该条目字段；无字段的旧卡首次使用时建立候选，取消、返回背包或重载后沿原候选，不消费源牌也不补发卡。候选暂不在现行合法卡池、池类型不符或记录损坏时保留源牌与记录并提示，不静默替换。点选只更新界面选择；确认时重新核对场景、源条目及容量，源牌移除与所选卡加入同次保存，失败回退本次内存交易，允许原候选重试。

## localStorage 键

| 键 | 作用 |
|---|---|
| `sdt-save-v2-slot1..5` | 五个档位的进行中对局 |
| `sdt-base-v2-slot1..5` | 五个档位的基地与局外成长 |
| `sdt-save-v1` | 旧单档对局；启动时迁入档位 1 后删除 |
| `sdt-base-v1` | 旧全局基地；启动时复制到尚无基地数据的档位后删除 |

设置项、卡牌库和格子备注仍使用各自已有键，不与档位存档合并。

基地 `collection[cardId]` 保留图鉴收录记录，新增可选 `protected` 布尔值控制同一稳定卡 id 的仓库保护；旧记录缺字段按受保护处理，只有显式 `false` 才解除保护。取消保护不删除收录记录，新经验转化首录写入 `protected:false`。不增加存档版本，也不批量改写旧记录。

新撤离的 `pendingExtraction.growth` 保存本次撤离经验实际结算前后的独立成长快照，最终回执沿用这份快照；内容包含人物、名义经验 `awardedXp`、满级前有效经验 `actualXp`、溢出 `overflowXp`、原始等级/经验前后、下一级差额及出征生命加成变化。该可选字段随现有结算事务保存和恢复，不从结算后当前人物状态倒推；旧待结算或回执缺字段时保留原收益，界面说明缺少等级变化明细，不补发经验。

新撤离草稿带 `pendingExtraction.sourceIdentityVersion:1`，待入库、待复原和已入库回执按稳定 `card.id` 与 `variantKey` 分组，无 ID 旧卡按名称分组。整理选择携带由该来源身份生成的 `sourceKey`；新草稿的同名多版本不接受有歧义的仅名称请求。缺此标记的旧草稿沿原名称分组和请求载荷处理，既有恢复日志与历史回执不升级或重算。

每个普通进行中对局保存顶层 `seed`、`mapSeed`、`generatorVersion`、`layoutVersion`、`geometryVersion` 与 canonical `mapSnapshot`；`rngState` 保存各命名随机流的位置。读档先纯校验快照和当前位置，再恢复随机流并重建四层地图的运行时派生字段。`geometryVersion` 只用于渲染缓存失效，不参与玩法判定。龙巢 `nestActive=true` 使用独立的 `nestPos` 等字段，不要求普通四层快照。

地图版本字段的职责如下：

- `mapSeed`：本局地图的唯一重建输入。新局在确定运行 seed 后立即生成；不允许在应用启动时用临时随机数替代。
- `generatorVersion`：生成该拓扑与节点分布的算法版本。新局为 `7`，已有 `3`、`4`、`5`、`6` 对局按各自版本恢复，不在读档时静默升级。
- `layoutVersion`：网格到世界坐标的布局版本。节点中心距由布局层固定为约 120 世界像素，避免把旧的全局横移公式带入新图。
- `geometryVersion`：当前地图几何缓存签名；换 seed 或布局版本时改变。
- `encounterRotationVersion`：顶层可选遭遇轮换标记。新局为 `1`，启用第三层既有普通档混编；保存写入 `1` 或 `0`，旧档缺字段时恢复为 `0`，保持原遭遇。该标记不改变地图快照、地图生成版本或旧档拓扑，也不额外推进随机流。
- `mapSnapshot`：普通 JSON 数据，无路线为 `snapshotVersion=1`，带路线为 `2`，保存四层节点 id/type/网格坐标、双向边、入口、出口和 forward door 描述。它是进行中普通地图的拓扑真源；`toLogical`、世界坐标、bounds 缓存、扁平节点表和 `Map` 对象均在校验后重建，不入存档。

无 `mapSnapshot` 的旧普通图只有在明确记录 `generatorVersion=3`、`layoutVersion=9`，并且存在真实 `mapSeed` 或 `seed` 时才允许由保留的 3/9 生成器重建并冻结。缺 seed、缺地图版本、未知版本或位置越界均拒绝恢复，原 run 串保留；不再制造 `legacy-slot-*` seed，也不把位置 clamp 到另一个节点。快照存在时，它与外层 seed/version 任一冲突都拒绝，不悄悄选择一侧。读取旧档不会保存动画中间态。

新局使用 `generatorVersion=7/layoutVersion=9`，由 `map-generator-v7.js` 生成，`map-exploration-adapter.js` 装配：节点数7/11/16/16，沿用6/9完整配额与火堆两战、连战及终局距离约束；四向双向连边保持全图连通，首层至少1个、后面各层至少2个非入口/出口的单路尽头，至少一个尽头承载宝箱/物资/事件，每层至多1个回环，分叉下限为1/2/2/2。新局不应用旧L2路线叠层，保存无routeVersion的 `snapshotVersion=1`。校验7/9快照时同时检查探索结构，不把旧密集图直接标成7/9接收。

已有6/9快照仍检查原有火堆两战等约束，不追加探索尽头要求；5/9按其完整配额与原有约束恢复，不追加火堆两战限制；4/9继续接受原双设施或交替设施的完整旧配额（7/12/17/17），不删格、不重排，也不接受各层配额混用；3/9仍按旧结构契约恢复。4/9至7/9缺少快照时拒绝恢复，不根据seed猜造已探索状态。未知生成版本继续拒绝并保留原串。

移动事务只在稳定节点落点后保存：对局进入 `moving` 状态时不写档；页面刷新、退出或崩溃后恢复到上一次已完成的 `layerIdx` / `trackPos`。动画完成后才递增 `turn`、结算节点事件并写入存档。

宝箱奖励快照的 `current.rewardStage` 保存 `chest`（尚未打开）、`opening`（开箱中）或 `cards`（卡牌/金币已揭晓）。未开箱在奖励总览中展示；开箱中断后再次展开卡牌层直接显示已冻结内容，不重新掷卡。缺阶段字段的旧快照按卡牌领奖处理。`current.choiceCount` 为附赠追加前的原候选数量（可选正整数，不大于 cards 长度）；阿猫附赠追加到 cards 并独立领取，三选一只放弃该边界内的其他候选，旧快照缺字段时按原 cards 全长处理。

宝箱总览沿用 `version=1`，增加可选 `screen`（`overview` 或 `cards`）；`queue` 各槽位可保存独立 `reward` 和 `completed`，活动槽位的 `reward` 与兼容入口 `current` 表示同一份内容和进度。卡牌层关闭只切回总览，不消费剩余箱子或推进战后结算；首次打开后候选保持固定。`claimMode` 为 `one` 或 `all`，区分选一与全部可领，避免箱型配置变化影响旧固定奖励。旧档未保存 `screen` 时，`index` 之前且无内容的槽位按已经结算处理，不补掷；旧中箱按选一恢复，其余旧箱按原全部可领恢复。

`nodeChestRewards` 按 `层索引,节点索引` 保存各节点的待领宝箱或固定奖励快照，快照沿用上段结构并绑定本局 seed 与整数坐标。暂离、移动或领取别处奖励不覆盖原节点的候选和领取进度；重进先恢复待领奖，再判断节点完成，战斗节点不会重复开战。领完或确认放弃后移除对应待领记录。旧档缺字段按空表读取，已有 `chestReward` 兼容导入其归属节点；活动领奖仍保留 `chestReward`，地图生成版本不变。

战后领奖暂离地图前，沿现有 Base+Run 事务提交胜利进度，同时保留待领奖快照；`context.battleSettlement.progressCommitted` 记录已完成的胜利记账，恢复或领完剩余奖励不重复累计。旧快照缺该字段时沿原事务收尾。活动 `chestReward` 与节点表中同坐标快照须表示相同进度，冲突时拒绝读取并保留原档。

奖励页返回地图时，保存待领奖快照或地图状态失败均保留当前领奖界面、已领索引和剩余候选，显示重试提示；保存成功后才关闭奖励页。提示仅属于本次界面，不新增存档字段，重试不重新发奖或重抽候选。

## 节点事件的未领候选

`nodeRewards` 按 `层索引,节点索引` 保存节点收益。普通未知事件首次抽取后，使用 `version=1`、`type=event`、`eventId` 绑定本节点的事件卡 ID，并在加载叙事前保存；退出或读档重进直接读取该 ID，不再次抽事件。缺少节点记录的旧档首次进入时补建，原有历史日志不用于推断节点归属。未知或暂不可用的事件 ID 保留原记录，显示返回地图入口，不静默替换事件。该绑定不改变首次抽取的卡池、权重或地图种子。

药摊与装备征用使用 `version=1`、`type=event-choice` 记录：

- `eventId` 为 `ev19-potions` 或 `ev19-quartermaster`；`cardIds` 保存首次确定的 1–3 个不同候选 ID，重进与恢复不重新抽取
- `paidCoins` 分别为 0 或 3；装备征用的扣款后余额与候选在同一份普通 Run 快照保存，恢复候选不再次扣款
- `taken=null` 表示尚未锁定选择；普通卡成功收卡后写入索引，阿猫的礼物则在同步转入固定领奖页时写入索引并锁定所选卡，实际主卡与附赠由同份 `chestReward` 独立领取。两种成功路径均标记节点已完成；普通卡容量不足或阿猫领奖页未能建立时不推进这两个状态

未领时可整理背包或返回地图，原候选保留在原节点；读档位于该节点时直接恢复选择页，位于其他节点时不强制弹回。完成后的索引保留，禁止重复领取。旧档缺少这些记录时沿用原恢复流程，不补发奖励、不改变地图快照版本。候选 ID 暂时不在现行卡库中时保留记录并显示不可用，不擅自换卡。

地下商场黑市命中后，三张已确定奖品进入现有 `chestReward` 卡牌领奖快照；容量不足与部分领取均保留未领奖品。恢复沿用原奖品与已领索引，不重新投币或掷命中结果；明确确认永久放弃时仍沿用现有弃领规则。

祭坛复原奖励也保存在 `nodeRewards`，使用 `version=1`、`type=restore`。`source` 为 `altar-reward`（主奖励，最多 3 次）或 `altar-offering`（道具献祭，最多 2 次）；`total` 与 `left` 为总次数和剩余次数，`restoredIds` 按实际复原顺序记录卡牌 ID。`hpBefore`、`hpAfter`、`hpGain` 保存已经结算的回血，`finished` 表示次数用完或玩家明确结束。每次复原与当前卡区同档保存；暂离地图保留剩余次数，重进不重复回血或献祭。旧档没有此记录时不补发历史收益。

## 进行中对局的战斗统计

`runBattleStats` 保存 `version=1`、`runId`、`fought`、`won` 和最多末 40 场 `log`。`runId` 来自当前档位的 `_r2` 身份；全新局首次保存尚未生成身份时，只允许空的 0 场记录，随后随正常保存绑定。读取必须匹配当前对局身份，替换本局内存计数而不累加；新开局清零，重开尚未结束的战斗不增加场次。

计数须为非负安全整数且胜场不超过总场次。流水仅保留现有战斗字段，敌人名及编组名最多 256 字符，编组最多 40 张；不保存额外页面或浏览器信息。无字段的旧档、版本不支持、统计损坏或身份不匹配时，本局战斗统计从 0 开始，不从地图、事件日志或其他档位猜造已丢的历史胜场，其他合法对局内容仍可恢复。

真实战斗先记入计数再通知结算及保存，同一次结束通知不能重复计数；`devSample` 隔离战斗不进入玩家计数。终局跑局记录仍使用 `sdt-run-records` 原环形缓冲，`battles` 为本局总数，`lastBattles` 仍只保留末 10 场，并附 `runId` 供对账。数据页继续汇总所有已结算记录，来源标记与真人/辅助局口径不变。旧终局记录不会因此补写或修正。

## 兼容要求

- RunStorage 顶层仍是可扩展对象：与地图无关的旧缺失字段可由现有迁移/default 补齐，未知顶层字段可保留或忽略。`mapSnapshot` 是独立的严格 schema；未知键、非 JSON 值、重复/越界/单向边、额外跨层传送边、重复坐标和未知快照版本均拒绝，不能用“顶层可扩展”绕过。
- 迁移必须先成功写入目标键，再删除旧键。
- 删除档位只删除对应对局与基地数据，不影响其他档位。删除按 Run 后 Base 顺序执行：Run 删除未完整完成时不继续删 Base；Base 删除失败则明确报告对局已删、基地未删，允许重试完成。两键删除不具备原子保证，不回填已删除原串；重开只在删除成功后初始化，全部清空按档位报告结果。
- 重构允许移动函数和模块，不允许静默更改字段含义、资源数量、卡牌归属或安全格规则。

固定兼容样本位于 `tests/fixtures/`，由 `tests/save-compat.test.js` 覆盖 RunStorage v1/v2 字段迁移、跨档隔离、未完成对局、基地、职业、成就和卡背。这些 fixture 没有地图版本；原地图恢复另由地图快照测试覆盖。存档格式变更同步更新相应样本与迁移测试。

地图恢复在本次调用内复用完整校验生成的隔离副本，再还原运行时节点；不跨调用缓存校验结果。公开还原入口仍执行完整校验，运行节点、逻辑节点和快照的可变边数组及记录互不共享。已校验的标量记录与双整数边直接复制，避免逐节点 JSON 序列化与解析。

## 路线快照 v2（routeVersion 分派）

本节维护已有3/9至6/9的路线快照恢复。6/9曾先运行 `r5-routes-v1` 覆盖，再尝试一次 L2 局部路线 `r5-routes-v2`；这类对局保存 `snapshotVersion:2`、对应 `routeVersion` 与严格 `routePlan`。第2层补给支路通往商店，旧快照中的火堆支路仍按原计划恢复。原回退计划继续记录 `NO_VALID_FORK`、`DISTANCE_LIMIT`、`PACING_LIMIT` 或 `FINAL_QUALITY_REJECTED`。7/9新局使用上节独立拓扑快照，不接受旧路线协议外壳。

v2 应用计划记录叉口、守卫、物资、休整节点 ID，最多一对完整节点定义互换、两对双向删边，以及 `baseFingerprint` 和原 `baseRoutePlan`。读取时先校验现图质量、实际战斗门槛和到达时机，再严格逆还原申报的互换与边；核对类型预算、设施/出口距离限制、最长连续非战简单路径不增长，并验证逆前态所有层完整四向边、唯一入口/出口类型及恰好三对标准相邻层出口到入口的门，再核对一致性指纹并按冻结的 v1 协议校验原计划。指纹用于发现数据不一致，不是存档认证签名。回退计划也须校验所有层同一规范拓扑、原图指纹和原 v1 计划，不能以回退状态绕过快照校验。

已有 `r5-routes-v1` 快照继续使用原协议：应用计划须与快照内起点、汇合点、补给 chest、交战 battle 和四条分支边一致；回退只记录状态与原因。旧 `snapshotVersion: 1` 与无快照的旧 3/9 对局仍走原恢复逻辑。已有 5/9、4/9 或 3/9 对局不补做新覆盖；5/9和4/9缺快照不按种子重建。未知路线版本、外层与快照版本冲突、计划节点/边/类型不符时保留原始存档并拒绝载入。顶层 run 仍允许既有扩展字段；`mapSnapshot` v1/v2 各自执行严格字段合同。

## 基地持久快照与运行内存

基地卡牌入库按稳定 `card.id` 与 `variantKey` 保留身份；旧无 ID 卡牌仅按名称合并。基地仓库、复原、撤离与终局抢运共用此口径，背包同名占格规则不变。整备预设中重复卡牌引用合并后的数量仍须不超过 99；超限保存返回失败并保留原预设。

基地读取仍按原始串指纹缓存解析和迁移结果。`peek`、`use`、内部命令读取与外部刷新在所有权边界取得独立的嵌套副本；预览或当前 `Base.data` 的未保存修改不能污染同一原串的下一次读取。成功保存后缓存代表实际写入的 JSON 原串，与活动运行态独立。

通用基地草稿命令在写入失败时保持原运行态及未变化分支引用。游玩时间、宠物蛋保底、局内成长等已有 checkpoint 命令仍可先推进当前内存并明确报告未持久化；同一活动会话后续成功保存可包含这些值，重新装载则以已落盘快照为准。基地与对局使用两个存储键；需要跨键提交的流程通过恢复日志推进。出征使用 `departureStart` 日志，在同槽 Web Lock 内保存扣仓后的 Base 与首份 Run；日志中的 runId 同时作为请求身份，首次 Run 修订号为 0。写入中断后，重试或重新选档按原串与日志身份校验完成同一次出征；出现日志前后值之外的新存档时保留现场并拒绝覆盖。日志写入前失败不扣仓，提交未完成时不发布新局，原内存与随机流保持不变。

## 上一版对局回退的原串保护

读取主档不自动覆盖原串。`prev` 候选通过版本、卡区结构、奖励、撤离身份和地图完整预检后，玩家查看保存时间与本局时长并明确确认，才在同槽锁内逐字节恢复；候选预览后主串或备档有变化则拒绝覆盖。恢复不重建探索身份或递增修订号，完整装载后才授予运行态写入基线。未来版本主档及待恢复事务禁止用旧备档覆盖。

确认恢复时先保全主档原串到 `corrupt`，失败则保留主档与 `prev`，提示检查存储后重试；写主键失败同样不声称恢复成功。备档候选无效不会覆盖原主档坏串备份。异常基地不会当成空槽直接重开；显式覆盖重开先保全原始 Base/Run 主串到各自 `preserved` 键，保全失败不清空档位。

## 装载与回写结果

读档顶层必须是普通记录，不能是数组或标量。缺失 `version` 仍按历史版本 0 迁移；显式版本须为非负整数，字符串、空值、小数及其他非法形状视为损坏，合法但高于当前版本的整数单独报告版本过新。原始存档键保留，损坏备份失败时只承诺原档保留，不声称备份成功。

业务预检复用现有地图、撤离身份和恢复日志检查，只验证真实装载消费者需要的容器与记录形状；不按当前卡库过滤未知卡 ID，不丢弃坏数组元素后重存，也不新增资源数量或平衡限制。固定旧档迁移样本与可恢复的旧 3/9 地图分别验证，前者不代表能恢复原地图。

| 字段 | 结构前提与兼容默认 |
|---|---|
| `inventory`、`cardBox` | 数组元素为记录；顶层缺失/null 仍归为空数组 |
| `ownedCards`、`usedPocket` | 数组元素及其 `card` 都是记录；顶层缺失/null 仍归为空数组 |
| `cardOrder`、`eventLog`、`discovered` | 数组；缺失/null 仍使用既有空集合默认 |
| `visited`、`seen`、`shopStocks` | 记录；缺失/null 使用空记录。已有商店货架为数组，普通在售项要求 `card` 记录，空位/售罄/神秘项保留原语义 |
| 龙巢 `nestRunes`、`nestEquipped`、`pendingRunePick` | 缺失/null 保留原默认；存在的符文为记录且 `attrs` 是数组。只有严格 `nestActive === true` 采用龙巢分支 |
| 研究所 `nestAltarChoice` | 可选 `{position:9, remaining:0..2}`，表示已选择祭坛重掷分支及剩余次数；缺失/null 为尚未选择，旧档沿此默认。首次重掷后禁止再领取英雄/职业卡，重入及读档保留剩余次数 |
| 研究所 `nestShopStocks` | 可选货架表，按第 `3`、`8` 格分别保存 `cardSlots`（4 格随机卡）、`classSlots`（3 格职业卡）、`runeSlots`（3 格符文）的首次结果、价格与 `sold`。首次生成及购买同币、牌盒、符文一起保存；重入和读档不重掷、不恢复已售商品。旧档缺失/null 按空表，首次进入才生成；新研究所开局重置 |
| 研究所 `nestBossName`、`nestKills`、`nestBossDown` | 所主模板按保存的已知名称恢复，不因读档另掷随机数。击杀数保存为非负安全整数，所主击破保存为布尔值；切档覆盖本地旧值。旧档缺失/null 默认 `0`/`false`，不推算缺失的历史战绩 |
| `battle` | 缺失/null 保留；存在时为记录。按真实恢复分支校验其直接消费集合，不另建完整战斗 schema |
| `battle.run` | 重启检查点直接应用到运行态，因此同名集合存在时必须满足消费形状；不会套用顶层装载的 null→空数组默认 |

结构拒绝返回 `INVALID_RUN_STRUCTURE` 并指出字段路径。读取缓存与返回给装载者的嵌套对象隔离，运行态修改卡实例或地图不会污染同一原串的下次读取。正常重读或缺档清除陈旧读取异常；列表与菜单预检均不推进写入基线。

实际装载先取得与读入原串绑定的内部凭据，完成全部纯预检后，才在运行态副作用前采纳该原串为写入基线。采纳时当前串已变则返回 `STALE_SLOT`，读取异常则返回 `STORAGE_READ_FAILED`，原写入基线保持。拒绝坏结构、坏地图或坏撤离记录后，仍在运行的旧局不能因此获准覆盖另一标签的替换档；菜单对替换档的成功预检也不授予这种覆盖权限。实际成功装载最新合法档后，才可基于它继续保存。既有 `readForLoad` 直接消费者保持兼容，生产预检不再用它提前接纳基线。

`loadGame` 仍同步返回，`ok` 表示装载分支是否成功。`persistence` 记录这次装载实际发起的保存；异步 Base 写入结束前为 `pending`，调用方等待同一返回对象的 `pendingPersistence` Promise 取得最终 `{ok, code?}`。Promise 不进入游戏状态或存档：

```js
{
  status: 'not_attempted' | 'pending' | 'succeeded' | 'failed',
  attempts: [{ target: 'base' | 'run', reason: '保存原因', ok: true /* 等待时 null，失败时 false */, pending: true /* 仅等待时存在 */, code: '可选失败码' }]
}
```

零次保存调用为 `not_attempted`；存在未完成 Base 写入时为 `pending`，全部完成后所有调用成功为 `succeeded`，任一调用失败为 `failed`。后一次成功不能抹掉本次装载较早的失败。明细包含术语迁移、时长迁移、普通地图 `enterLayer` 保存及战斗恢复回写；运行态守卫提前拦住的保存不算写入尝试。

`reason` 为 `card_rename`、`elapsed_migration`、`elapsed_recovery`、`play_time_sync` 或 `save_game`。基地失败码为 `BASE_SAVE_FAILED`，对局失败码为 `RUN_SAVE_FAILED`，具体冲突与锁失败同时由存储层和页面保存提示报告。收集上下文只登记本次装载发起的调用；已登记异步调用在 `pendingPersistence` 完成前更新对应明细，后续无关保存不加入此回执。

装载分支成功但回写失败时，原返回对象可保留 `ok: true`，最终 `pendingPersistence` 返回失败。菜单与 Agent `enterSlot` 等待最终结果，失败不宣称进入成功，并保留原档与可重试入口；已经恢复的内存不因此伪装成持久化成功。预检拒绝仍返回 `preserveRun: true`，不先修改随机流、地图、`Base.use` 或运行态。

Base 与 Run 公开写入、删除和旧档迁移均为异步同槽锁操作。`saveGame(): Promise<boolean|undefined>` 只确认 Run；`saveSession(): Promise<{ok, code?, message?}>` 等待 Base 与 Run 回执，退出和依赖保存结果的领奖流程必须等待实际结果。`sdt-save-state` 事件分别报告 `scope:run` 的对局检查点与 `scope:session` 的整档保存状态。checkpoint 可立即更新内存，持久失败以 `persisted:false` 报告；准备事务等待期间发生 checkpoint 时，协调器先保存它，再拒绝旧准备版本。

## 游玩时长与事务收据

基地 `stats.playTimeCheckpoint` 记录当前探索的 `{runId, elapsed}`，与累计 `playSeconds` 同次保存。对局的 `elapsedTimeBaseline` 保留本次探索建立检查点时的兼容基线；恢复时按同一探索在基地实际累计的位置补回差额，不以累计总时长和本局时长直接比较。旧档没有该字段时保留历史 max 迁移语义，从首次新版载入的位置建立基线，不猜补此前缺失秒数。

活动探索保留完整收据；出征和终局提交时，闭局收据压缩为最近 8 局各最新一条，非探索的永久请求不裁剪。旧闭局请求无法凭已失效的探索身份或修订号再次提交。活动局较长或非探索请求增多仍会扩大存档，当前限额针对跨局积累。

## 整档导入导出

`sdt-slot-archive` v1 包含 Base、Run、上一 Run 检查点、事务日志、坏串备份、显式覆盖保全串及导入恢复记录；字段保留原始字符串并附 SHA-256 完整性校验。导出允许异常档保全。导入先校验包、当前支持版本及主档/备档完整结构，再展示目标槽和保存信息；明确确认后在同槽锁内复核目标未变化，失败回滚原始键。中断留下 `sdt-import-v1-slotN` 恢复记录并阻止普通写入，可明确恢复导入前原档。

过新或损坏主档、包含未完成事务的包允许导出，但当前版本拒绝直接导入；应先在兼容版本或来源档位完成恢复，再重新导出。导入不执行包中的代码，不按现行卡库删除未知卡牌。目标档位原串回滚失败时保留前后完整记录供重试和导出。
