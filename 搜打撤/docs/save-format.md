# 存档兼容契约

## localStorage 键

| 键 | 作用 |
|---|---|
| `sdt-save-v2-slot1..5` | 五个档位的进行中对局 |
| `sdt-base-v2-slot1..5` | 五个档位的基地与局外成长 |
| `sdt-save-v1` | 旧单档对局；启动时迁入档位 1 后删除 |
| `sdt-base-v1` | 旧全局基地；启动时复制到尚无基地数据的档位后删除 |

设置项、卡牌库和格子备注仍使用各自已有键，不与档位存档合并。

每个普通进行中对局保存顶层 `seed`、`mapSeed`、`generatorVersion`、`layoutVersion`、`geometryVersion` 与 canonical `mapSnapshot`；`rngState` 保存各命名随机流的位置。读档先纯校验快照和当前位置，再恢复随机流并重建四层地图的运行时派生字段。`geometryVersion` 只用于渲染缓存失效，不参与玩法判定。龙巢 `nestActive=true` 使用独立的 `nestPos` 等字段，不要求普通四层快照。

地图版本字段的职责如下：

- `mapSeed`：本局地图的唯一重建输入。新局在确定运行 seed 后立即生成；不允许在应用启动时用临时随机数替代。
- `generatorVersion`：生成该拓扑的算法版本，不再在读档时静默升级。
- `layoutVersion`：网格到世界坐标的布局版本。节点中心距由布局层固定为约 120 世界像素，避免把旧的全局横移公式带入新图。
- `geometryVersion`：当前地图几何缓存签名；换 seed 或布局版本时改变。
- `encounterRotationVersion`：顶层可选遭遇轮换标记。新局为 `1`，启用第三层既有普通档混编；保存写入 `1` 或 `0`，旧档缺字段时恢复为 `0`，保持原遭遇。该标记不改变地图快照、地图生成版本或旧档拓扑，也不额外推进随机流。
- `mapSnapshot`：`snapshotVersion=1` 的普通 JSON 数据，保存四层节点 id/type/网格坐标、双向边、入口、出口和 forward door 描述。它是进行中普通地图的拓扑真源；`toLogical`、世界坐标、bounds 缓存、扁平节点表和 `Map` 对象均在校验后重建，不入存档。

无 `mapSnapshot` 的旧普通图只有在明确记录 `generatorVersion=3`、`layoutVersion=9`，并且存在真实 `mapSeed` 或 `seed` 时才允许由保留的 3/9 生成器重建并冻结。缺 seed、缺地图版本、未知版本或位置越界均拒绝恢复，原 run 串保留；不再制造 `legacy-slot-*` seed，也不把位置 clamp 到另一个节点。快照存在时，它与外层 seed/version 任一冲突都拒绝，不悄悄选择一侧。读取旧档不会保存动画中间态。

移动事务只在稳定节点落点后保存：对局进入 `moving` 状态时不写档；页面刷新、退出或崩溃后恢复到上一次已完成的 `layerIdx` / `trackPos`。动画完成后才递增 `turn`、结算节点事件并写入存档。

宝箱奖励快照的 `current.rewardStage` 保存 `chest`（尚未打开）、`opening`（开箱中）或 `cards`（卡牌/金币已揭晓）。未开箱在奖励总览中展示；开箱中断后再次展开卡牌层直接显示已冻结内容，不重新掷卡。缺阶段字段的旧快照按卡牌领奖处理。`current.choiceCount` 为附赠追加前的原候选数量（可选正整数，不大于 cards 长度）；阿猫附赠追加到 cards 并独立领取，三选一只放弃该边界内的其他候选，旧快照缺字段时按原 cards 全长处理。

宝箱总览沿用 `version=1`，增加可选 `screen`（`overview` 或 `cards`）；`queue` 各槽位可保存独立 `reward` 和 `completed`，活动槽位的 `reward` 与兼容入口 `current` 表示同一份内容和进度。卡牌层关闭只切回总览，不消费剩余箱子或推进战后结算；首次打开后候选保持固定。`claimMode` 为 `one` 或 `all`，区分选一与全部可领，避免箱型配置变化影响旧固定奖励。旧档未保存 `screen` 时，`index` 之前且无内容的槽位按已经结算处理，不补掷；旧中箱按选一恢复，其余旧箱按原全部可领恢复。

`nodeChestRewards` 按 `层索引,节点索引` 保存各节点的待领宝箱或固定奖励快照，快照沿用上段结构并绑定本局 seed 与整数坐标。暂离、移动或领取别处奖励不覆盖原节点的候选和领取进度；重进先恢复待领奖，再判断节点完成，战斗节点不会重复开战。领完或确认放弃后移除对应待领记录。旧档缺字段按空表读取，已有 `chestReward` 兼容导入其归属节点；活动领奖仍保留 `chestReward`，地图生成版本不变。

战后领奖暂离地图前，沿现有 Base+Run 事务提交胜利进度，同时保留待领奖快照；`context.battleSettlement.progressCommitted` 记录已完成的胜利记账，恢复或领完剩余奖励不重复累计。旧快照缺该字段时沿原事务收尾。活动 `chestReward` 与节点表中同坐标快照须表示相同进度，冲突时拒绝读取并保留原档。

## 节点事件的未领候选

`nodeRewards` 按 `层索引,节点索引` 保存节点收益。普通未知事件首次抽取后，使用 `version=1`、`type=event`、`eventId` 绑定本节点的事件卡 ID，并在加载叙事前保存；退出或读档重进直接读取该 ID，不再次抽事件。缺少节点记录的旧档首次进入时补建，原有历史日志不用于推断节点归属。未知或暂不可用的事件 ID 保留原记录，显示返回地图入口，不静默替换事件。该绑定不改变首次抽取的卡池、权重或地图种子。

药摊与装备征用使用 `version=1`、`type=event-choice` 记录：

- `eventId` 为 `ev19-potions` 或 `ev19-quartermaster`；`cardIds` 保存首次确定的 1–3 个不同候选 ID，重进与恢复不重新抽取
- `paidCoins` 分别为 0 或 3；装备征用的扣款后余额与候选在同一份普通 Run 快照保存，恢复候选不再次扣款
- `taken=null` 表示尚未锁定选择；普通卡成功收卡后写入索引，阿猫的礼物则在同步转入固定领奖页时写入索引并锁定所选卡，实际主卡与附赠由同份 `chestReward` 独立领取。两种成功路径均标记节点已完成；普通卡容量不足或阿猫领奖页未能建立时不推进这两个状态

未领时可整理背包或返回地图，原候选保留在原节点；读档位于该节点时直接恢复选择页，位于其他节点时不强制弹回。完成后的索引保留，禁止重复领取。旧档缺少这些记录时沿用原恢复流程，不补发奖励、不改变地图快照版本。候选 ID 暂时不在现行卡库中时保留记录并显示不可用，不擅自换卡。

地下商场黑市命中后，三张已确定奖品进入现有 `chestReward` 卡牌领奖快照；容量不足与部分领取均保留未领奖品。恢复沿用原奖品与已领索引，不重新投币或掷命中结果；明确确认永久放弃时仍沿用现有弃领规则。

祭坛复原奖励也保存在 `nodeRewards`，使用 `version=1`、`type=restore`。`source` 为 `altar-reward`（主奖励，最多 3 次）或 `altar-offering`（道具献祭，最多 2 次）；`total` 与 `left` 为总次数和剩余次数，`restoredIds` 按实际复原顺序记录卡牌 ID。`hpBefore`、`hpAfter`、`hpGain` 保存已经结算的回血，`finished` 表示次数用完或玩家明确结束。每次复原与当前卡区同档保存；暂离地图保留剩余次数，重进不重复回血或献祭。旧档没有此记录时不补发历史收益。

## 进行中对局的战斗统计

`runBattleStats` 保存 `version=1`、`runId`、`fought`、`won` 和最多末 40 场 `log`。`runId` 来自当前档位的 `_r2` 身份；全新局首次保存尚未生成身份时，只允许空的 0 场记录，随后随正常保存绑定。读取必须匹配当前对局身份，替换本局内存计数而不累加；新开局清零，重开尚未结束的战斗不增加场次。

计数须为非负安全整数且胜场不超过总场次。流水仅保留现有战斗字段，敌人名及编组名最多 256 字符，编组最多 40 张；不保存额外页面或浏览器信息。无字段的旧档、版本不支持、统计损坏或身份不匹配时，本局战斗统计从 0 开始，不从地图、事件日志或其他档位猜造已丢的历史胜场，其他合法对局内容仍可恢复。

真实战斗先记入计数再通知结算及保存，同一次结束通知不能重复计数；`devSample` 隔离战斗不进入玩家计数。终局跑局记录仍使用 `sdt-run-records` 原环形缓冲，`battles` 为本局总数，`lastBattles` 仍只保留末 10 场，并附 `runId` 供对账。数据页继续汇总所有已结算记录，来源标记与真人/辅助局口径不变。旧终局记录不会因此补写或修正。

## 兼容要求

- RunStorage 顶层仍是可扩展对象：与地图无关的旧缺失字段可由现有迁移/default 补齐，未知顶层字段可保留或忽略。`mapSnapshot` 是独立的严格 schema；未知键、非 JSON 值、重复/越界/单向边、额外跨层传送边、重复坐标和未知快照版本均拒绝，不能用“顶层可扩展”绕过。
- 迁移必须先成功写入目标键，再删除旧键。
- 删除档位只删除对应对局与基地数据，不影响其他档位。删除按 Run 后 Base 顺序执行：Run 删除未完整完成时不继续删 Base；Base 删除失败则明确报告对局已删、基地未删，允许重试完成。两键删除不具备原子保证，不回填已删除原串；重开只在删除成功后初始化，全部清空按档位报告结果。
- 重构允许移动函数和模块，不允许静默更改字段含义、资源数量、卡牌归属或安全格规则。

固定兼容样本位于 `tests/fixtures/`，由 `tests/save-compat.test.js` 覆盖 RunStorage v1/v2 字段迁移、跨档隔离、未完成对局、基地、职业、成就和卡背。这些 fixture 没有地图版本；原地图恢复另由地图快照测试覆盖。存档格式变更同步更新相应样本与迁移测试。

## 路线快照 v2（routeVersion: r5-routes-v1）

新开的普通远征在现行 3/9 地图生成后尝试一次 `r5-routes-v1` 覆盖。成功或有诊断回退的新局均保存 `snapshotVersion: 2`、外层 `routeVersion`，以及严格的 `routePlan`；应用计划必须与快照内起点、汇合点、补给 chest、交战 battle 和四条分支边一致。回退计划只保存状态与原因，不宣称存在双路线。

旧 `snapshotVersion: 1` 与无快照的旧 3/9 对局仍走原恢复逻辑，绝不补做覆盖。未知路线版本、外层与快照版本冲突、计划节点/边/类型不符时保留原始存档并拒绝载入。顶层 run 仍允许既有扩展字段；`mapSnapshot` v1/v2 各自执行严格字段合同。

## 基地持久快照与运行内存

基地读取仍按原始串指纹缓存解析和迁移结果。`peek`、`use`、内部命令读取与外部刷新在所有权边界取得独立的嵌套副本；预览或当前 `Base.data` 的未保存修改不能污染同一原串的下一次读取。成功保存后缓存代表实际写入的 JSON 原串，与活动运行态独立。

通用基地草稿命令在写入失败时保持原运行态及未变化分支引用。游玩时间、宠物蛋保底、局内成长等已有 checkpoint 命令仍可先推进当前内存并明确报告未持久化；同一活动会话后续成功保存可包含这些值，重新装载则以已落盘快照为准。基地与对局仍分别持久化，不新增跨存储原子保证。

## 上一版对局回退的原串保护

损坏主档只在本次坏原串备份成功后，才允许用有效 `prev` 原串逐字节自愈主键；验证损坏 `prev` 时不改写主档的 `corrupt` 备份。有效主档、未来版本及待恢复事务沿用既有路径，回退不重建探索身份或递增修订号。

坏原串备份写失败时保留主档与 `prev`，暂不装载或自愈，并提示检查存储后重试。有效 `prev` 未因此丢失或判损坏；恢复可写后再次进入即可重试原回退流程。这项保护避免装载后的自动保存覆盖唯一坏原串，不新增只读恢复状态。自愈主键写失败同样不声称恢复成功，原串与读取异常保持可诊断。

## 装载与回写结果

读档顶层必须是普通记录，不能是数组或标量。缺失 `version` 仍按历史版本 0 迁移；显式版本须为非负整数，字符串、空值、小数及其他非法形状视为损坏，合法但高于当前版本的整数单独报告版本过新。原始存档键保留，损坏备份失败时只承诺原档保留，不声称备份成功。

业务预检复用现有地图、撤离身份和恢复日志检查，只验证真实装载消费者需要的容器与记录形状；不按当前卡库过滤未知卡 ID，不丢弃坏数组元素后重存，也不新增资源数量或平衡限制。固定旧档迁移样本与可恢复的旧 3/9 地图分别验证，前者不代表能恢复原地图。

| 字段 | 结构前提与兼容默认 |
|---|---|
| `inventory`、`cardBox` | 数组元素为记录；顶层缺失/null 仍归为空数组 |
| `ownedCards`、`usedPocket` | 数组元素及其 `card` 都是记录；顶层缺失/null 仍归为空数组 |
| `cardOrder`、`eventLog`、`discovered` | 数组；缺失/null 仍使用既有空集合默认 |
| `visited`、`seen`、`shopStocks` | 记录；缺失/null 使用空记录。已有商店货架为数组，普通在售项要求 `card` 记录，空位/售罄/神秘项保留原语义 |
| 龙巢 `nestRunes`、`nestEquipped`、`pendingRunePick` | 缺失/null 保留原默认；存在的符文为记录且 `attrs` 是数组。只有严格 `nestActive === true` 采用龙巢分支 |
| `battle` | 缺失/null 保留；存在时为记录。按真实恢复分支校验其直接消费集合，不另建完整战斗 schema |
| `battle.run` | 重启检查点直接应用到运行态，因此同名集合存在时必须满足消费形状；不会套用顶层装载的 null→空数组默认 |

结构拒绝返回 `INVALID_RUN_STRUCTURE` 并指出字段路径。读取缓存与返回给装载者的嵌套对象隔离，运行态修改卡实例或地图不会污染同一原串的下次读取。正常重读或缺档清除陈旧读取异常；列表与菜单预检均不推进写入基线。

实际装载先取得与读入原串绑定的内部凭据，完成全部纯预检后，才在运行态副作用前采纳该原串为写入基线。采纳时当前串已变则返回 `STALE_SLOT`，读取异常则返回 `STORAGE_READ_FAILED`，原写入基线保持。拒绝坏结构、坏地图或坏撤离记录后，仍在运行的旧局不能因此获准覆盖另一标签的替换档；菜单对替换档的成功预检也不授予这种覆盖权限。实际成功装载最新合法档后，才可基于它继续保存。既有 `readForLoad` 直接消费者保持兼容，生产预检不再用它提前接纳基线。

`loadGame` 的 `ok` 继续表示装载分支是否成功。返回的 `persistence` 单独描述本次同步装载中实际调用的保存，不代表整个档位的事务保证：

```js
{
  status: 'not_attempted' | 'succeeded' | 'failed',
  attempts: [{ target: 'base' | 'run', reason: '保存原因', ok: true /* 或 false */, code: '可选失败码' }]
}
```

零次保存调用为 `not_attempted`，所有调用成功为 `succeeded`，任一调用失败为 `failed`；后一次成功不能抹掉先前失败。保存明细包括原有术语迁移、时长迁移、普通地图 `enterLayer` 的保存及战斗恢复回写；不为生成结果增加保存次数。常规保存被运行态守卫提前拦住时不算写入尝试。

`reason` 为 `card_rename`、`elapsed_migration`、`play_time_sync` 或 `save_game`。基地失败码为 `BASE_SAVE_FAILED`；对局失败码优先采用存储层的 `STALE_SLOT`、`RECOVERY_REQUIRED` 或 `STORAGE`，否则为 `RUN_SAVE_FAILED`。正常返回、预检拒绝和抛错都会释放本次收集上下文，后续保存不再修改已返回的结果。

装载成功且可继续时，即使回写失败仍可返回 `ok: true`，同时提示本次部分进度未保存。菜单进入与 Agent `enterSlot` 的成功表示进入完成；持久化结果由 `persistence` 单列。转场归属、战斗加载身份及完成凭据沿现有协议处理。预检拒绝返回 `preserveRun: true`，原 run/base/journal 串保留，且不会先修改随机流、安装地图、调用 `Base.use` 或赋值运行态。
