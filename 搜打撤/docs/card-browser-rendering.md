# 分页卡面按需构建

照相馆的「生物」分类包含二至四层的九种精英图鉴卡。它们从现行遭遇池和怪物模板生成，复用各自正式立绘，展示基础攻血、所在层数及能力说明；不进入商店、发现或随机获取池，也不能作为战斗手牌使用。入口由完整卡库提供，支持按名称搜索与卡牌详情查看。

收藏页和人物招式页只在当前可见分页构建完整卡面。条目的轻量按钮、稳定ID和辅助标签仍在DOM中，选择与卡牌详情继续使用完整数据。人物招式页直接展示所选人物的全部招式，保留翻页与放大，已移除类型、搜索和归档状态筛选栏。

公共 `bindCardBrowser` 接收可选 `renderArt(item)`，返回卡面HTML后写入条目的 `[data-browser-art]` 容器。分页和尺寸变化先确定可见条目，再构建缺失的卡面；已浏览卡面在本次页面生命周期内复用。返回 `null` 或 `undefined` 表示暂无内容，下次刷新仍可重试。新的容器节点会重新渲染。正文沿用现有Cards.cardHTML与Icons.rich，不另建简化卡面版本。

渲染回调与已构建标记仅保存在当前DOM实例的WeakMap/WeakSet中，不进入跨页位置缓存。收藏页在首次分页前应用已保存的筛选条件，不会先构建未过滤的第一页；人物招式按人物保留分页位置。整页替换后使用新数据源和新渲染器。

收藏卡面槽已有固定宽高，人物卡池已有固定宽度与长宽比，按需填充不更改这些尺寸。点击、翻页、PageUp/PageDown、重排焦点和放大仍由原逻辑处理。仓库为连续滚动网格，本批没有将其改成分页，也没有改变容量或库存数据。

测试：`card-browser-deferred-art.test.js`、`hub-visible-card-faces.test.js` 及现有分页/收藏/人物测试。工作量、CPU模拟对照及实页边界见 [验证记录](evidence/2026-10-20-visible-card-face/README.md)。

切页先准备当前页全部新卡面的HTML与图标转换，全部成功后才更新可见条目、分页状态及DOM。渲染器抛错会原样向上传播，旧页内容、按钮和焦点保持可用，之后可重试同一目标页；不吞错或生成替代假卡面。
