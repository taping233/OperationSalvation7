## 1. 问题、目标与价值

E1 已确认 battle.snapshot.js 对卡牌只做浅复制；编组、注能、发现、待选目标、待用物品和装备等投影可能与运行卡牌共享 rules 等嵌套数据。现有测试只覆盖部分嵌套状态，BattleSnapshot 尚缺实际静态约束。

本批交付：这些快照卡牌纯数据与真实卡牌双向隔离，快照卡牌递归只读；快照构造器及已有生产消费者 battle.preview.js 的快照使用进入明确的类型检查范围。保持预览伤害、合法性与 unknown 降级语义，保持快照字段形状及缓存语义。

价值：阻止观察面反写卡牌规则，并在维护时拦截边界错误。验收靠隔离、调用和行为证据，不靠类型声明数量或文件数量。

本批不承诺所有游戏观察面全面只读。GameStore 的地图引用、findCard 兼容读口、Agent 分派成功语义、普通胜利两写事务、旧局懒加载与全卡库迁移均不在本批。

## 3. 实现约束

1. 以当前源码实际卡牌承载路径为准逐项枚举：infusing.card、discovering.options、deckSelection.cards[].card、pendingTarget.card、pendingItem.card、equipped[].card，以及 potionBar/其他已有卡牌字段（没有嵌套卡牌时明确不适用）。卡牌 rules、嵌套数组、对象及纯数据扩展字段不得继续与源共享可变引用。
2. 对支持的卡牌数据复制后再冻结；不得冻结或改写源卡、源规则或运行时容器。源后续合法更新不改变已发出的快照，新快照应反映更新。不要使用 JSON 序列化破坏 undefined 等现有字段语义。
3. 复用现有可用工具须先核对语义与依赖成本；不要为了复用引入 hub 单例/DOM 依赖。局部小 helper 可接受，不建立跨仓通用序列化框架。不支持的非纯数据对象按实际输入说明边界，不能静默生成错误规则。无需凭空支持任意对象图或收紧外部存档格式。
4. 不改变选牌 Set 转数组、手牌 UID、装备索引、指向状态、potionBar 展示形状。保留 createBattleSnapshotSignature 对实际值的失效语义；不要引入无失效机制的卡牌引用缓存。
5. JSDoc + 必要 d.ts，表达真实输入/输出及深只读卡牌边界。其余字段按现有真实保证声明，不把浅冻结声称全图深只读；不复制第二份权威状态。
6. battle.preview.js 的 previewAction 参数实际引用快照契约，生产源码本身接受诊断。卡牌/状态字段以使用点建立准确最小结构，未知扩展可用 unknown 并收窄；不得用无依据 any、无条件类型断言、ts-ignore/ts-nocheck 或过滤错误制造通过。
7. 新检查入口不改原 jsconfig，也不把整个游戏加入 checkJs。可使用独立 allowJs + 显式文件内 @ts-check 的逐文件模式，明确哪些新文件被检查、哪些仅导入推导；既有检查不能减弱。若直接 checkJs 带来依赖检查扩散，报清边界，不借机修改一大片依赖。
8. 允许类型测试通过内存虚拟文件构造错误调用，收集 options/global/syntactic/semantic 全部适用诊断。正例必须真实 import 生产函数；负例不得只验证一份与运行模块无关的接口。至少证明构造输入错误、快照卡牌嵌套写入、previewAction 快照错字段被拒绝，并防止结果退化为 any。
9. 不重构伤害预览语义、规则解释、存档和结算；不移除旧路径。禁止删除文件或死代码，包含临时产物，不做清理。
