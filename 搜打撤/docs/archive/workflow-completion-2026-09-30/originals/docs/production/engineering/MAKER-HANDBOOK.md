# 后续制作者操作手册

适用范围：Vite《搜打撤》。本页帮助后续人类或 Agent 制作者找到修改入口、同步文档和最小验证。开始前先读[制作资料入口](../README.md)、[当前状态](../../STATUS.md)及[代码与数据工作流](CODE-DATA-WORKFLOW.md)，再核对实时 Git 状态、最近提交和文件归属。具体文件位置以当前源码为准；历史报告不代替当前接线。

## 一次改动的共同流程

1. 写明要改变的可观察行为或工程问题、涉及的状态所有者、保留的兼容语义和完成标准。
2. 按下表定位权威来源与消费者；共享文件被其他会话占用时先协调边界，不覆盖在途修改。
3. 先复用现有校验与测试入口，必要时补一个能识别实际失败的样本，再修改实现。
4. 对受影响范围做定向验证；玩家可见变化到 Codex 内置浏览器当前窗口查看真实路径和控制台。公共架构或阶段收尾按[质量门](../../quality-gates.md)做全量检查。
5. 在自己的现行记录中写时间、HEAD/远端引用差异、工作区状态、命令与结果、实页或图片证据、未核实项。提交、推送、发布、回滚和任何删除依项目约束另行确认。

## 按修改类型找入口

| 要做什么 | 先读与权威位置 | 同步和验证重点 |
| --- | --- | --- |
| 调整跨模块数值、容量或概率 | [玩家规则](../../rules.md)、core/rule-config.js 与 core/rules.js；地图内容另查 core/mapData.js 和 run/game.run.data.js | 预估与实际结算须同源；跑 rule-config 及相关结算/地图定向测试，检查随机调用位置是否改变。同步规则文档。 |
| 修改或新增卡牌 | [卡牌规格入口](../../cards/README.md)、cards 域真实来源、cards.sync 各批次及同步脚本 | 不手改生成的 cards-sync.json；检查稳定 id、旧档播种、规则字段与自然语言一致、结构化/旧解释器边界。跑对应卡牌、同步及效果审计测试；游戏全书按明确需求生成。 |
| 修改事件或剧情 | narrative/events.ink、编译脚本、run 事件效果端口 | 不手改 generated/narrative-events.js；检查选项文本、效果接线、剧情覆盖测试与真实事件流程。 |
| 修改存档、结算或跨局奖励 | [存档契约](../../save-format.md)、hub/game.storage.js、Base/Run 命令与恢复日志 | 保留旧档样本，明确保存失败、重复请求和中断后的行为；补迁移/恢复定向测试。Base/Run 是分离存储，不能将单边成功表述成整体原子提交。 |
| 新增或替换图片、字体、音效 | [视觉规范](../art/VISUAL-BIBLE.md)、game/art-source、game/assets、art-mapping.json、asset-manifest.json | 记录来源/授权与运行引用，检查裁切、透明度、加载和当前页面真实显示；资源清单与文件存在不等于实际使用。资产审计可辅助查体积与重复项。 |
| 修改页面布局或交互 | [视觉规范](../art/VISUAL-BIBLE.md)、对应页面模块与 CSS、[开发指南](../../development.md) | 检查默认、焦点、选中、禁用、失败状态及中文输入；相关定向测试后验当前窗口实际页面。单张静态截图不代表流程通过。 |
| 修改 Agent 观察、动作或策略 | [接口协议](../../agent-protocol.md)、agent/state、surface、runner、protocol 与[实验复现约定](AGENT-EXPERIMENTS.md) | 观察与动作必须反映真实业务命令和异步完成结果；接口变更补契约测试。策略收益用同版本、同种子、同设置的同轮配对，不以旧绝对成功率判定。 |

上表是定位导航，未列尽所有实现文件。动手前用源码搜索确认调用方，并查看[模块边界](../../architecture.md)与[源码目录说明](../../../game/src/README.md)。如果生成物、样式、存档或 Agent 结果出现冲突，先确认哪个文件是源、哪个是派生，再决定修改位置。

## 交接最少留下什么

对下一位制作者，交接至少应回答：本轮为什么改、最终改了哪些文件、对应测试或实页实际做了什么、哪些结果尚未验证、已知兼容风险、下一步从哪个入口继续。实验工作还需记录可复现的代码状态、种子、开关和原始输出。当前代码、规则、状态的导航始终从[状态入口](../../STATUS.md)开始。
