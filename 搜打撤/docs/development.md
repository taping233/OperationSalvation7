# 开发指南

## 环境与命令

当前仅开发 Vite，Codex / ZCode 共用根 AGENTS.md 与 [双端工作流](README.md#双端工作流)。优先现有 Node.js/依赖；确需首次安装时按任务授权处理，命令示例不授权安装、改全局配置或启动冻结的桌面线。

```powershell
npm run web
npm run narrative:compile
npm test
npm run typecheck
npm run build
node game/selftest.js
node scripts/check-version.cjs
npm run assets:audit
```

`npm run perf` 是冻结的 Electron 历史基准，不作为当前入口。性能方法参考 [全场景账本 PERF-LEDGER-2026-09-29](PERF-LEDGER-2026-09-29.md)，其中历史脚本须先核对是否满足[质量门](quality-gates.md)的平台边界。开发地址加 `?perfProbe=1` 的探针方法与首次有限范围结果见 [Vite 内置浏览器性能记录](archive/records-2026-09-28/VITE-IAB-PERFORMANCE-2026-09-28.md)，受控平移 drawHz 不能代替真实移动的交付帧率。

日常路径见[流程指南](WORKFLOW-TOOLS.md)，定向反馈、提交门与 CI 实际覆盖统一见[质量门](quality-gates.md)。依赖方向与按需加载边界可定向运行 `npm run test:target -- tests/architecture-boundaries.test.js tests/contracts.test.js`；照相馆页面 `game.cardslib.page.js` 只允许由轻门面 `game.cardslib.js` 动态加载。

历史桌面技术说明（冻结，须老板另行解冻与授权才能执行）：原生 `app://` 不解析 `howler` 等裸模块导入；`desktop-app` 的 `prestart` 先构建 Vite，再从 `desktop-app/game` 加载，`prestart` / `predist` 检查文件与版本。此说明不作为当前开发/验收入口。

桌面故障修复：`game-file-protocol.cjs` 为 `app://sdt` 直接返回包内文件流，明确样式、脚本、字体和音视频类型，支持 HEAD 与单段 Range；路径越界、缺失和读取失败返回明确状态。保持原协议与存档来源，窗口关闭时通过预先保存的事件对象清理监听，不再访问已销毁窗口的 `webContents`。

便携包的`portable.unpackDirName:true`使用每次启动独立解压目录，避免重复启动或第二实例退出清理正在运行的资源。交付脚本在构建器退出0后，用实际EXE以无窗口Node模式进行两次重叠启动，核验目录隔离及资源存续；失败不进入交付步骤。可手动运行`node desktop-app/verify-portable.cjs <EXE路径> <报告路径>`。该检查覆盖启动器生命周期，不替代真实游戏画面验收。

`runtime-guard.cjs`在游戏窗口存活期间持续记录资源/脚本错误、渲染器和GPU子进程退出、主进程致命异常；日志位于用户数据目录的`logs/desktop.jsonl`，超过256KiB时保留约128KiB尾部。渲染器异常退出后提供从最近存档重新进入或退出游戏的选择；启动阶段仍由加载窗处理，正常退出不弹恢复框。日志写入失败不改变原错误处理，主进程异常监测不吞掉致命异常。

开发工具在生产版保留入口，但控制台与测试节点实现仅在首次使用时加载；`game.run.js` 通过 `game.run.dev-loader.js` 提供轻门面。加载失败可重试，等待期间按 Esc 或再次按 Ctrl+L 可取消控制台入口，切换页面、档位或对局后旧请求不再打开页面。Agent 场景仍直接调用开发运行模块的同步节点操作，不能将其未经等待地替换为异步门面。

## 修改约定

- 背包中的珍珠盒、法师锦囊复用 `game.container-store.view.js` 与 `battle-decision-unified` 二级面板：300px 卡面、独立全文详情、即时整叠存取、常驻容量和不可用原因。收纳机制置于默认折叠说明；返回与 Esc 沿各容器原生命周期守卫。容器样式直接加载共享 CSS，不依赖先进入战斗。

- 跨模块规则数值优先修改 `game/src/core/rule-config.js`，由 `core/rules.js` 提供兼容门面；地图格子和卡牌数据使用各自数据文件。概率和容量校验须通过 `tests/rule-config.test.js`，不得让预估和实际结算各维护一份常量。
- 新模块必须保持单向 ESM 依赖，并在契约测试中通过循环图检查。
- 事件叙事优先修改 `narrative/events.ink`；不要手改 `src/generated/narrative-events.js`，它会在开发、测试和构建前自动重新生成。
- 领域逻辑不直接操作 DOM；视图不直接修改其他模块的私有状态。
- 基地购买、拆包、领奖使用 `Base.purchase/openCardPack/grantReward`；复合命令在一个草稿中准备并只持久化一次。不要在 UI 先扣资源、再调用入库、最后忽略保存结果。
- `npm run typecheck` 按 [统一配置清单](../scripts/check-type-coverage.mjs)并行编译，再用真实注错探针核验全部自有运行实现。全域 `jsconfig.runtime.json` 启用 `checkJs:true / strict:false`；原严格配置保留，接口 fixture 与实际实现覆盖分开统计。当前为 537/537 实现受检、49/537 strict，边界见[架构说明](architecture.md)。新增源码必须被实际检查，补具体 JSDoc、具名端口与正反例；不能用忽略诊断或排除文件通过覆盖门。运行时门面声明只在 runtime 配置解析，不能替代原实现的检查。
- 样式按页面职责放入 `css/base.css`、`cards.css`、`overlays.css`、`hub.css`、`battle.css` 或 `scenes.css`；主题覆盖文件保持在这些基础样式之后加载。
- 存档字段或键名如需变化，先添加迁移与固定旧档测试。
- 构建/实验产物写入已忽略目录，不提交 `dist` 或 `desktop-app/game`；验收报告/截图集中 `docs/evidence/<日期>-<任务>/`，是否提交仍需老板明确授权。
- CSS 与 `new URL(..., import.meta.url)` 可识别的资源交给 Vite 生成哈希文件；只有卡牌、立绘、图标和音效等运行时动态路径目录由构建插件原样复制。新增动态资源族时必须同步更新 `vite.config.js` 的 `RUNTIME_ASSET_DIRS`。
- 生产复制清单按 Rollup 完整运行模块图（含异步功能）排除未引用的试听音效目录 `sfx/alternatives`、`sfx/winter-v5`、`sfx/winter-v6-ten`；源码与开发试听页仍保留。运行模块引用某目录时恢复复制；拿不到模块图时全部保留。
- 字体仍由 Vite 输出原字节哈希文件；`game/assets/fonts/LICENSE-*.txt` 等现有许可文件原样复制到发布包的 `assets/fonts/`，不重复复制字体，也不修改 HarmonyOS 字体。
- `npm run assets:audit` 会报告源码/桌面产物体积、最大文件和内容完全相同的重复资源组；原始素材不因构建瘦身而删除。

## 界面实现约定

- 地图底栏「全景」/ G 按当前层全部节点位置取景；未探明地点仍由原渲染器显示无类型剪影，不改变迷雾或可点击范围。「定位」/ F 只框当前位置与相邻路线。相机按屏幕比例预留上方 HUD、下方节点名称/状态及底栏空间，展开地点详情时扣除其宽度。全景允许缩小至 0.08，滚轮和镜头过渡沿用此下限，避免低倍全景操作时反向跳大。复核入口为 `dev/map-overview-review.html`，真实 Camera/Renderer 配固定内存构造数据，不能代替自然对局验证。
- 节点纯呈现复核入口 `dev/node-design-review.html` 复用生产场景壳及营火/祭坛/补给 view，不加载主游戏、音频或存档。按钮切换8种固定场景；“检查可见布局”只读公开 DOM 尺寸，报告横溢和不可滚动祖先裁切，不自动判美术通过。工具可收起，Esc 恢复。当前入口与边界可查[节点复核夹具](../game/dev/node-design-review.html)及[夹具契约测试](../tests/node-design-review.test.js)；原 `2026-10-17-map-full-overview/REVIEW.md` 短评及证据目录缺失，历史视觉结论待补原始记录或重验。实页截图、真实输入、几何与逻辑证据分别登记。

- 战斗二级界面由 `battle.decision-shell.js` 与 `battle.secondary-overlay.js` 共用容器：抉择、发现、手牌选择/支付、注能、剩余牌库、消耗牌、设置、首脑规则与结束回合风险提示保留当前场次的真实战场节点，并在开层与更新时以当前快照刷新能量、手牌和单位；透明输入层上按内容量居中显示冷灰蓝、纸白细框面板，沿用 `feedback-theme` 配色。背景战场设置 inert 与 aria-hidden，选择期间屏蔽手牌数字键，焦点和 Escape 仍沿原取消语义；强制选择不新增取消。返回时恢复同一战场节点，直接读档进入选择时先以真实快照建立战场。详情保持父选择、滚动和返回焦点，不新增结算等待。战斗背包当前命令禁止打开，保留视图兼容容器；开战前编组没有已存在战场，仍属准备界面。手牌现行入口为悬停/选中阅读，不启用保留的独立手牌详情模块。

- 战斗手牌的「注能」按钮按内容高度显示在卡面右上方；按钮进入选材，鼠标按卡面仍沿拿牌流程，拿起后可按 Esc 归位再操作按钮。
- 注能面板先展示材料名称、增减和已选/持有数量，再显示卡面；材料列表独立滚动，底部材料摘要紧凑排列。左侧保留完整效果文字与消耗风险，重复卡面默认折叠，同次选择重绘保留展开状态。费用、材料消耗时点、取消与基础效果直接打出仍由原战斗命令控制。

- 设置中的画质、动画绘制上限与减少动态效果的覆盖边界统一见[性能说明](performance.md#当前优化)，不以设置值承诺实际帧率。
- 地图生命条由 `ui/map-health-hud.js` 接入 `hud.js`：点击、Enter或空格展开当前生命/上限，Escape、失焦或外部按下关闭，保留悬停与聚焦阅读；输入不冒泡成地图移动。正生命不高于上限25%静态标“偏低”，零血标“耗尽”；增减文字最多显示1秒，连续变化替换，首次载入、重载和隐藏后回场不误播。减少动态效果保留差额文字，停用位移、闪光和进度过渡。
- 回合标题由 `battle.turn-feedback.js` 消费真实 `player-turn-start`、`enemy-turn-start`、`extra-turn-start` 事件：54px主标题与20px实际回合数在舞台上方短显，能量和本批入手卡以细线高亮；首回合沿已有资源就绪信号显示。事件按场次/序号去重，读档、重绘不补播；连续阶段只保留一个标题，关闭或移除舞台清理。`ui/feedback-theme.js` 与 `feedback-theme.css` 为标题及卡牌结果提供冷灰蓝、纸白、克制金线与共用入场/停留/飞行节奏。
- 卡牌结果演出统一由 `ui/card-result-feedback.js` 展示已经结算的事件：完整卡面短暂展示后飞向真实目的地，双通道与同名合并避免逐张阻塞；待播最多8组，超量明确显示另有多少次已结算。减少动态时静态短显；关闭、切场或宿主移除清理动画与计时，不添加授予、支付、随机或结算等待。
- 战斗适配 `battle/view/battle.card-feedback.js` 只展示真实获取、洗入牌库、随机释放与追加施放；普通抽牌沿原飞入，排队施放不冒称入手。目的地按实际手牌、同名叠、翻页入口、牌库或敌人确定；追加施放无目标记录时只展示释放，不虚构目标。结果栏“卡牌动态”默认折叠，保留最近6组；免费发现被纯注能拒绝后留手按真实获取展示，玩法边界见[规则](rules.md#4-祝福诅咒与时点)。
- 奖励适配 `ui/reward-card-feedback.js` 接普通/职业搜刮点的单领、三选一、附赠、全部收下及随行补给：原授予成功并重绘后才播放，满包失败或重复领取不播，批量只展示成功项。飞向当前可见容量行或整理背包入口；目标隐藏、不可交互或滚出可见区时短显“已入背包”。正常领取重绘保留队列，离开奖励页或换模式清理，不新增确认。

- 照相馆每次打开绑定当前页面和档位，换页或关页释放本页观察器、队列与输入监听；照片与引用按稳定 ID 的首项展示，旧页面回调不会改变新页面，备注支持任意已允许字符串 ID 并保持保存与导出一致。

- 基地物资栏的木材、口粮、钥匙、储备币使用 `assets/icons/base-v12/` 的黑灰青绿 E 版图标。数量在左、图标在右，统一使用深色双线圆角胶囊和白色数量字。资源栏全部只读，悬停或键盘聚焦显示名称，不打开卡牌。基地子页按导航方向从左右进入，返回首页不重播底部导航的上下展开。

- 通用界面进入/退出的分块错峰、方向、缓动与时长在 `game/src/ui/surface-motion.js` 修改；`interface-motion.js` 在公共界面入口自动挂载。基地初次进入由 `camp-entry.js` / `camp-entry.css` 编排选档到基地的入口过场；主页进入独立子页，同页筛选与操作刷新不重播入口。首页与制作名单沿已有生命周期接入，战斗轻面板用快档，减少动态效果时禁用。实际隐藏、焦点和业务回调仍由原界面入口管理。
- 桌面启动由 `desktop-app/startup-window.cjs` / `preload.js` 与 `game/src/ui/startup-transition.js` 交接：加载窗在游戏所在显示器的可用区居中，以可拖动小窗显示，退出/重试按钮保持可点击。首页初始化完成立即同步真实状态，首页控件可用后双帧通知就绪，隐藏窗口无帧回调时250ms兜底；随后准备通用 `createCityCut` 城门切幕，画面就绪后切换窗口，按共用 `cityCutDuration` 揭开首页。减少动态效果时直接进入；切幕握手超过4.5秒回退到已就绪首页，15秒仍无启动就绪信号则显示可重试失败。普通网页打开不自动播放；预览为 `game/dev/startup-transition-preview.html`。加载百分比为模拟值，真实就绪信号负责完成与切入。
- 基地主页使用原 A21 室内图 `assets/scenes/base-operations-v5.webp`；顶部档案与物资、右侧出征整备与行动难度、基地/角色/后勤/交易所/收藏室/建设/庭院七项底部玻璃导航贯穿各房间。左上基地事务栏仅显示真实可扩建、可孵化和待领奖励，点击进入对应房间，事务栏常驻，无可处理事务时显示“暂无待处理事务”。角色界面使用完整原立绘、圆角矩形资料框与操作按钮；角色条头像完整 contain。仓库卡格仅保留卡面与数量，单击沿原特写入口放大，卡牌列表占满内容区；交易所商品使用完整卡牌，币值复用顶部资源栏的 E 版图标与数量胶囊。整备、购买、出售、孵化和扩建仍沿既有业务命令。
- 队员默认人物培养，招式、外观、伙伴按需跳转；横向头像名册以青蓝状态区分当前人物，原竖图完整放入横向白底画布，资料区共同使用白底。孵化单独进入，先回伙伴；培养选卡保留人物来源和筛选。交易所由 `hub.trade-shop-v5.js` 展示四列购入/出售陈列与同页交易台，商品图、价格和持有量各有固定位置；右侧交易台、收藏室卡背和故事阅读区沿用石墨灰底与青蓝操作状态。复用原购买/出售命令、收藏保护及就地二次确认；出售选择与提交按完整库存堆身份定位，同名不同变体互不代售；换页/换档解除确认，保存失败不改库存。现有仓库特写的收藏/使用和快捷操作保持兼容。返回键与Esc沿同一父级返回，卡背解锁目标回卡背，交易所/扩建回来源页。物资显示在主页上栏与仓库标题栏，木材和口粮点击查看原卡。

- 出征开场和地图遭遇战/首脑节点在 `game.run.scenes.js` 的 `showRunTransition` 选择 `city-cut`，共用斜切与字牌工厂；出征使用专绘雪地路线图，遭遇战抵达后及首脑确认迎战后均通过 `enterNode` 接入同一切幕，使用雪山残门通用远征图和“旅途继续”文案；不增加接敌确认页。图片、字牌、档案线条、水印尺寸和切幕动画沿共用样式，不设战斗专用覆盖；默认时长共用 cityCutDuration，显式入口时长及 Turbo 决定实际时长，自动结束、点击跳过、状态恢复与上下文守卫保持；`interface-motion.js`跳过此切幕的通用区域入场，其他节点继续使用原场景，减少动态时回到原静态过场。
- 战斗意图短标签显示实际动作名称和预览数值，基础攻击以“攻 N”与下一步意图区分。单位信息差分同步转换图标，避免原始占位符先显示一帧。手牌“完整规则”入口保留原查看/使用流程；短、中长度规则在悬停或键盘聚焦时完整显示，较密规则保留节选。超过70字的详情使用安全富文本全文栏；战斗和仓库全文栏复用字级、行距和直立术语强调，卡面正文仍随卡宽缩放。
- 战斗就绪状态绑定实际挂载的舞台；同场二级面板保留舞台和资源等待；只有实际重建舞台时才重新等待背景解码、角色首帧和卡图就绪。排队动作先呈现当前忙碌快照，再等待该舞台就绪或玩家明确选择简化显示后执行，费用、随机和多段反馈保持原顺序。隐藏、取消或换场立即终止旧等待，迟到资源不能复活旧动作；已就绪舞台的后续动作复用现有场景。
- 战斗单位序列帧优先使用 WebGL；浏览器的 WebGL 不可用时，按需加载同版本的官方 Pixi Canvas 2D 兼容模块。两种后端共用帧时序、宿主归属、取消与卸载清理；Canvas 兼容模块独立分块，不作为正常 WebGL 路径的静态依赖。后端初始化仍失败时沿用简化画面入口。
- 战斗雪景三层静态图由 `battle.view.js` 解码并挂载，独立于 Pixi 单位帧。选择“以简化画面继续”后保留已就绪背景，同场选择面板保留已挂载静态背景，不重试单位序列帧；尚未就绪的背景可在本场稍后解码成功时显示，简化显示状态和提示不变。真正的背景解码失败仍隐藏未就绪图层并输出告警，二级面板打开期间成功解码仍展示同舞台背景；关闭、离开战斗或换场次后旧异步结果不能挂回。
- 首页成就入口先以月桂盾徽专用图斜切揭幕，装饰层980ms内清理，关闭或换页立即移除，减少动态效果时不挂切幕；页面和输入沿原时点开放。成就页初入展开标题、总览与首屏奖章，导航/搜索/结果计数/退出控件保持静止；最多12枚可见奖章错峰落位，真实进度条展开，总览有低亮呼吸光和水印轻移，悬停徽章抬升扫光。内部动效在 `achievement-motion.js` 维护：分类高亮沿选项移动，奖章随分类方向短幅进入；筛选/布局切换保留浏览来源，来源被筛掉时取相邻可见项，搜索即时更新。详情可由关闭键/背景/Esc关闭，恢复来源焦点且不强制滚动；减少动态时停用动效。
- 成就奖章按行列成组错峰；连续切分类时高亮从当前位置续行。详情徽章按来源方向短幅展开并收回；已获得奖章悬停抬升扫光，未获得奖章仅轻抬。
- 游戏只使用 1920×1080（16:9）横屏布局，由 `ui-scale.js` 取窗口宽高比例的较小值统一缩放；布局原点在窗口左上，多余区域留边，不提供竖屏或窄窗重排，也不单独放大文字、按钮或基地。样式以 `--game-layout-width` / `--game-layout-height` 表示游戏尺寸，不直接依赖窗口尺寸；显示边界使用 `UiScale.viewport()`，坐标通过 `UiScale.rect()` 换算。`position: fixed` 弹层也以横屏画面为边界。
- 启动时会移除原生 `title` 属性，提示使用自绘文字层。输入框事件不能触发整页重建；处理 Escape 前先判断 `isComposing`，避免中断中文输入。
- 选档、基地与地图退出键共用 `.archive-back`，尺寸、图标大小、基础外观与按压几何在 `game/css/archive-back.css` 维护；触碰变色沿下述共用来源。各页面保留原退出动作，地图工具栏定位也在该来源维护。
- 返回/退出、地图帮助/静音、弹窗关闭键的触碰与键盘焦点变色统一在 `navigation-feedback.css` 维护，由 `archive-back.css` 导入；石墨底、白图标、160ms过渡，减少动态时即时变色。只选明确导航控件，危险操作和主行动按钮沿各自规则。
- overlay 背景由 inert 隔离；新增常驻层时同步更新排除名单。图片挂载后调用 `SDT.Art.decodeIn(el)`，避免内置浏览器合成黑窗。
- 同一候选选择面板内卡牌不得重复。动画与空闲态性能规则见 `performance.md`；卡牌规则和数据来源见 `rules.md`、`architecture.md` 与生成的 `game-compendium.md`。

## 玩法原型

- 验证性玩法先用临时原型回答一个问题，机制试验控制在 30~90 分钟；使用灰箱素材，记录实际观察，再决定是否进入正式实现。
- spike 代码不得直接进入主源码目录；落地时重写命名与结构（原型回答的是问题，不是交付物）。

后勤仓库显示完整筛选结果，卡牌网格向下滚动浏览，切换筛选回到顶部；卡牌详情关闭后保留列表滚动位置。仓库与交易所使用深色卡牌详情面板，左侧完整大卡与右侧资料栏分开；资料栏依次显示名称与品质、卡牌效果、持有与操作，关闭键位于资料栏右上角。仓库详情只提供收藏相关操作，出售由交易所交易台负责；补给卡牌详情只读；待复原卡牌按整堆复原，按钮显示本次实际张数和钥匙费用，仓库空位按整堆数量预检。详情数量变化需重新打开。交易所列表点击选中卡牌并直接放大，右侧交易台仍负责购入和出售。

- 共用界面动画：同一基地页的内容刷新保留正在播放的入场，实际导航或离开时清理；页面动画分区失配时回退到可见内容区域。主动重播先提交无阶段标记的样式，再设置新入场阶段，以支持同帧连续关闭/重开。地图右上金币和攻击使用方舟节点参考板画法的原创图标，显示64px，资源条无底框。

- 祭坛的地图节点、地点详情、仪式/回赠页头与研究所祭坛标题共用 `altar-symbol-1017-v2.webp` 原创RGBA图源；通用 `altar` 图标按同一主体边界显示。首脑图标与紧急撤离共用献祭的 `crystal` 保持独立语义。

- 继续对局的过场期间预热战斗模块及地图实际图片；过场结束逻辑先恢复原状态，保留自有画面直到loadGame完成、地图布局落定与首帧预绘，再以220ms揭幕。预绘清除上一局背景快照与尺寸防抖；图片失败或3秒未就绪沿原降级呈现。恢复战斗、奖励、研究所或选角仍由原入口负责，过场释放仅收自己拥有的画面，不改恢复后的状态。

- 共用整页导航在同步挂载后等待首屏代表图片、背景就绪、字体及布局绘制机会，再启动区域入场并淡去遮层；最多12张首屏图、1500ms兜底，长卡牌列表仍懒加载。关闭/换页取消旧准备。基地初入、设置、成就、整备专用切幕等待画面准备后再计演出时长；照相馆独立加载流程补同一视觉等待。出征与局内全屏页返回地图预绘首帧后撤幕；返回4500ms兜底，新的页面/战斗/换局接管取消旧遮层。共用动效存在时overlay不重复播放legacy外壳动画或swap强制布局。

### 卡片展示热路径

`cards.view.js` 的描述富文本缓存只使用规范化后的展示文本作键，最多256项、单项原文不超过2048字符；不同卡牌可复用相同文字，动态文本变化自然失效。整卡HTML原有WeakMap与选项语义保持不变。`ui/card-browser.js` 刷新仍读取当前DOM过滤、尺寸和页码，逐值检查后才写显示状态与分页文案；不以旧结果快照跳过读取，因此外部过滤、翻页、列数或DOM状态变化仍能修正。已脱离页面的根节点继续直接返回。

- 开箱呈现由 `chest-opening-art.js` 的帧组与 `safeOpeningHTML` 共用维护；总览开箱后进入现行揭晓动画与奖励选择，不经过独立“领取搜刮点”页。`chest-opening.css` 仅保留当前开箱动画样式。
- 搜刮点生成数量由 `map.json` 的 `chestKinds` 驱动：small 为 `cards:1`，职业 small 共用该数量，medium 保持 `pickFrom:3`。总览先读奖励快照的数量与 `claimMode`，再回退配置；已生成快照不按新配置重建，兼容边界见 [掉落规则](rules.md#5-卡牌掉落与事件)。

- 奖励原地整理由 `game.reward-organizer.js` 对接真实背包容量：能否收牌与能否移安全格分别判断，安全格满但背包有空格或同名叠位时仍可领取。整叠移入按安全格新增格数判断，不足时禁用按钮并显示所需/剩余格数；容器内、已在安全格和初始攻击不列入腾位对象。领取沿原奖励授予入口，点击时重新检查容量与当前奖励状态，旧页面按钮不能重复领取。

- 共享奖励领取按钮由 `rewardClaimHTML` 输出：搜刮点与物资选择的卡下操作、单卡底栏和放大详情均传入实际卡名，可访问名称包含动作与卡名，可见短文案保持不变；动态名称统一按HTML属性转义。
- 固定事件领取以 `reward-standalone-picker` 显式复用搜刮点 picker 的卡区、容量提示和按钮样式，保留事件来源/标题；单卡居中、空操作栏隐藏，完成后仍由原继续探索动作收尾。仅搜刮点 picker 与该独立入口共享规则，不扩展到入口补给或资源二选一；`overviewMode`、奖励恢复及授予事务不变。

- 搜刮点金币入口：总览 `chestOverviewCoins` 只收已生成箱的未领币，`chestOpen/chestNext` 确定当前箱后调用同一个 `collectCoinsOnce`。总览模式的单领、全拿与放弃不触发收币；固定事件奖励带 `source/title` 的非总览兼容入口保留全拿、确认放弃、继续时收币，单领仍独立。`coinsReceived` 与快照同存，不按 UI 文案猜测领取事实。

- 撤离整理和成功页由 `ui/extraction-rewards-view.js` 共用卡面、资源与容量组件，沿用冬日撤离原画及 `feedback-theme` 冷灰蓝/纸白配色。主层保留待入库/已入库卡面与数量、仓容、待复原数和当前动作；概率规则、复原名单、损失明细和远征记录默认折叠。未入库卡的永久放弃风险始终在底栏显示。有余卡时先展开逐项名称/数量确认，默认聚焦「返回整理」，确认后才永久放弃；零余卡直接完成。确认复检档位、对局、请求序号与剩余卡签名，旧页面回调失效。「按估值入库」沿用估值降序，同价按背包原次序，与卡面稀有度排序无关；估值不表示实战强度或可出售。入库立即保存，本页没有撤回或换选入口。呈现消费统一回执，不合并仓库卡与待复原卡，不改入库事务或随机结果。

### 冬日页面统一组件

营火决策使用 `ui/fire-rest-view.js` 的收益三项、容量与一次性风险常显、休整说明默认折叠；营火结果卡面保原尺寸，标明已复原/额外获得，继续按钮不再附重复说明。`ui/ui-disclosure.js` 与 `css/ui-design-system.css` 共用冷灰蓝/纸白token、间距和原生说明折叠；撤离待复原说明接入同组件，容量/丢失风险不折叠。组件只管呈现，不更改营火随机、先额外发牌后复原、容量检查或撤离事务。执行规则见[视觉规范](production/art/VISUAL-BIBLE.md#页面执行规范冬日界面体系)，首批实页复核尚待进行。

祭坛激活/回赠使用 `ui/node-decision-view.js`：事实区共用 `uiDecisionFacts`，祭坛代价→收益选项共用 `uiDecisionChoice`，解释复用 `uiDisclosure`。碎片不足/道具已用的原因、永久献祭、容量和二选一后果留主层；退出移到既有底部动作区，事件action ID与事务保持。祭坛仍用专属 `altar` 图标；献祭选卡的 `crystal` 另有含义，不在本轮替换。覆盖与待核项维护于[页面矩阵](production/art/UI-PAGE-COVERAGE.md)。

远征背包三分区显式接入 `bag-design-system.css` 与共享说明组件。标题占格独立于卡牌张数；张数由真实 `cardStacks` 聚合且不随筛选变化，散装物资另计件数，盒内卡继续独立显示。安全格移动后失去保护、丢弃不可取回、消耗区火堆不可复原数量与撤离散失风险在主层，叠放/操作/复原解释默认折叠。卡面宽度、五列网格与水平内距保持，未改存储、跨区移动或复原/销毁命令。三个分区状态为已改未视觉，详见覆盖矩阵；当前生产冻结待合并复核。

### 扰敌双目标选择

扰敌在卡牌目标会话中依次选择两名不同存活敌人。第一名先攻击，第二名存活时反击；选满之前不扣能量或移出手牌，Esc 取消保留卡牌。第二次选择只排除第一名敌人实例的高亮，同种其他敌人仍可选择；若第一名已失效，重新开始选择。施放重放固定原两名目标，不自动改打第三名。自动施放旧入口继续沿用无显式目标对时的锚点兼容，临时目标对不写入存档。

回归入口：`tests/provoke-target-contract.test.js`（结算/取消/重放/存档）、`tests/battle-hand-inspector.test.js`（真实DOM双选、提示、高亮、Esc）。实页验证条件与本批证据见 `evidence/2026-10-17-code-contract-workflow/REPORT.md`。
