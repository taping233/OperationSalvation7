# Agent 策略迭代手册

本页维护策略实验的操作方法：提出单变量假设，使用同条件配对实验，在独立验收集确认后决定晋级。代码、参数和产物的复现要求见[实验复现约定](production/engineering/AGENT-EXPERIMENTS.md)。第 6 节起保留 09-26 至 09-27 的历史跑次和能力快照。

## 0. 术语与文件

| 角色 | ML 对应 | 本项目实体 |
|---|---|---|
| 样本 | 一局游戏 | 一个 seed（决定地图/掉落/战斗全链路） |
| 测试集 | held-out set | 固定 seed 底：`--seed-base N`，第 i 局 seed=N+i |
| 模型 | policy | `agent.policy.js` 的 strategic 分支（greedy=v1 冻结对照） |
| 损失 | 多指标标量 | 撤离率↑ 均层↑ 带出价值↑ 弃局率↓（弃局>5%=硬约束直接毙） |
| 显著性检验 | 配对符号检验 | `agent-compare.mjs` 按 seed 配对并统计逐局胜负 |
| 实验跟踪 | MLflow/W&B | `output/agent-ledger.jsonl`（`agent-ledger.mjs add/list`） |

## 1. 两个 seed 底（T/V 分离，防过拟合）

```
T 调参集：--seed-base 77001  （假设筛选、调参、消融都在这里）
V 验收集：--seed-base <另定，迭代若干轮后轮换> （只有过 T 显著的候选才许跑）
```

- **规则：任何假设先在 T 上做配对；V 只用于终验；连续 3 个 promote 后轮换 V 的 seed 底**
  （防止策略对 V 过拟合——ML 的 test set 泄漏防护）。
  **T 底对称轮换（09-26 老板拍板）：连续 3 个 promote 后 T 底同步换新号（换底写入台账）**。
  固定底被多个假设反复检验会增加假阳性风险，
  ledger/compare 已有 verdict 枚举校验；同底已跑假设数记账暂靠台账人工看。
- 批跑通过 `agent-batch.mjs` 的 cleanup 保持局间开档条件一致。用 `--selfcheck 1` 复跑同 seed 检查结果漂移；失败时先定位运行环境或正确性问题，再进行策略比较。

## 2. 单轮迭代协议（一轮 ≈ 15-30 分钟，T 配对 100+100 局跑批占大头）

```
1. 假设    从死因分桶（deathByLayer/deathBucket）/弃局 trace/停因分布里来，
           一句话写清"改什么、为什么该有效"
2. 实现    只改一个变量（消融原则：一轮一个操作点，改多了归因就废）
3. T 配对  跑两遍同 seed 底（challenger vs 当前 champion），每轮各 100 局
           （老板 2026-09-26 定：以每轮一百次迭代为准——40 局对 ±5% 级改进
            检出力不足；ES 首代 20 局 fitness 65% 独立复验即回落 60% 是教训）
           npx vite-node game/tools/agent-batch.mjs --runs 100 --policy strategic \
             --seed-base 77001 --out output/agent-exp-<名>
4. 判决    node game/tools/agent-compare.mjs <challenger> <champion>
           p<0.05 且方向正 → 进 V 验收集；否则早停丢弃（省算力，ML early stopping）
           弃局率>5% → 直接毙，不看 p 值
5. V 终验  过 T 的候选换 V seed 底再配对 100 局，V 也显著才 promote
           V 底轮换：连续 3 个 promote 后换 seed 底（防对验收集过拟合）
6. 记账    保留 T/V 原始产物与 compare 输出；晋级记录须给 --split verify、--verify、--compare
           完整命令见 production/engineering/AGENT-EXPERIMENTS.md
```

### 为什么配对（而不是比裸均值）

同一 seed 与运行条件提供共同的随机起点；不同策略仍可能选择不同路线并消耗不同随机序列。按 seed 比较每局结果，可减少不同地图分布对策略收益判断的干扰。晋级还需满足产物来源、完整配对和独立 V 集的检查。

## 3. 实验设计三原则

1. **一轮一变量（消融）**：R1-R4 的教训是 R4 一次加了火堆强偏好+扫图条件化+甲门，
   回退了说不清谁的锅。要归因就只改一个操作点。
2. **对照冻结（baseline）**：greedy=v1 永久冻结对照组；champion 每次 promote 后冻结进台账，
   新候选永远跟"现任"比，不跟历史最好比（防 cherry-pick）。
3. **早停（early stopping）**：T 不显著就不进 V；弃局硬约束不过直接毙。
   如需扩大样本，先声明扩容条件并保留已有结果；避免只保留显著的跑次。

## 4. 搜索策略（改哪里、按什么顺序）

优先级从高到低（R1-R4 数据支撑：新操作点 >> 调参）：

1. **补操作面**（最高杠杆）：从死亡/弃局分桶里找"有动作没用上"的场景
   ——R3 的背包回复+护甲线是先例：撤离 3%→4%、弃局 10→6 一次到位。
2. **修根因（bug 类）**：弃局 trace-lite 现场 → 修熔断/口径/死锁——这类不看 p 值，
   是正确性修复不是策略假设，修完直接换 champion。
3. **消融验证**：给 champion 加新点后，反向去掉它跑一轮——确认贡献是真收益（ML ablation study）。
4. **调参**（最低杠杆）：阈值/权重微调。R2 教训：纯保守化调参撤离 3%→2%，方向错了还费算力。
   调参只在前面三类用尽后做，且必须过配对。

### 搜索空间参考（strategic 策略的可调维度）

- 血线门：fire/shop/battle/door 各自的 hpRatio 阈值（0.45/0.5/0.75 档）
- 评分权重：各节点类型 base、fwd、backtrack、forceProgress
- 战斗：喝药威胁线（60%）、AOE 加权（1.7×）、护甲成本门（挡3/挡7）、砸击时机
- 整备/商店/事件：留位数、留币数、eventScore 权重

## 5. 数据分析系统的指标口径（已在 agent.stats 聚合）

- 结局：clear/extract/death/abandon（abandon 单列——它是质量信号不是策略失败）
- 深度：均层、死亡层分布（`deathByLayer`）
- **死因分桶 `deathBucket`（09-26 补强）**：`L{层}N{节点}/{战斗中|战后}` 维度聚合，
  recordRun 记 `node`（trackPos）定位键，批跑汇总自动打印 top6——开假设先看这个
  （死亡主力层 2/3 但旧口径只到层，够不着"死在哪个节点"）
- **战斗流水 `lastBattles`（09-26 解剖仪表）**：末 10 场 `{胜负/层×节点/敌编组/战后hp/回合}`
  ——死因定位从"死亡层"下沉到"哪场战斗掉的血"；批跑每局前 `resetRunCounters()` 防串局
  （弃局兜底路径不经 recordRun）
- 产出：带出价值分布与均值、`topCards`
- 效率：avgRunMs、avgStepMs、maxStepMs（**单局>1s 必查因——老板 09-26 规矩**）
- 切片：按职业/模式/驱动（driver）分组

### 09-27 基线快照

- **champion = strategic（DEFAULT 权重）**，死锁第一批+撤离保存修复（r15）后的真实成绩：
  **T 底 100 局：撤离 46%、均层 2.93、弃局 2%；V 底 100 局：撤离 51%、均层 2.99、弃局 1%**

- 历史口径（死锁污染，仅作参考）：T 52.5%/V 50%（r9）、T 42.5%（清档修复后）——
  死锁族压低了全部旧数据；**r2 best T 59%/60% 也是污染口径**，r2c 三验 V 无差异维持弃案
- 弃局历史：55%→6→0→2%（当前，达标 <5%）
- **耗时口径（r9 查因结论）**：V 集 2191ms/局，高于 r7 的 1407ms——不是单步变慢
  （分阶段步耗 map 5ms / overlay 10ms / battle 16ms 与前版持平），而是**局更深了**：
  局均步 144→185、局均战斗 6→8（赢面变大 → 打得更久更远）。按阶段分桶
  `record.phaseMs`（批跑内建）可随时复核。

### 修根因清单（r1-r7，全部走"修根因通道"非调参）
1. **intentDamage 字段错位**：引擎 intent 是 `{kind:'strike', damage, hits}`，策略读 `type!=='attack'` 恒返 0 → flee/护甲门/威胁喝药三处保命全失效（flee 0/120 局触发）
2. **fledNodes 惩罚够不着**：检查写在 base 分支，已访格 seen 行提前返回绕过 → 逃→绕回死循环；改为 seen 前判 0 分
3. **seen 短路滞环解锁**：整层踏完门也是 seen(2 分)，door 解锁/forceProgress 在 base 分支够不着 → 出口豁免（只 door/extraction 滞环时落完整打分）
4. **fled 0 分墙反噬**：唯一通路穿过 fleeing 格时死锁（血 14% 无药）→ 滞环时解锁 fled 惩罚
5. **同格连逃死循环**：extraction 被 boss 锁、boss 战必逃、逃出资源耗尽 → 决死规则（同格只逃一次，death 2 分 > abandon 0 分）
6. **extraction 锁判定**：bossKilled=false 时终局撤离点 95 分勾着反复撞门被拒 → 判 -100 让位给 boss/altar
7. **协议白名单漏砸击三件套**：bagSlam/resolveSlam/resolveDart 动作面与引擎 commands 都有，
   白名单独漏 → 334 次 BATTLE_COMMAND_UNKNOWN，砸击（省卡核心操作）整条链路走不通。
   补齐后 T 集撤离 25%→52.5%（单根因最大涨幅）——**动作面覆盖度要靠 trace 实测计数审计，
   不能只看"动作面定义了"**

## 6.5 架构升级三件套（2026-09-26 第二阶段，ledger r12+/e*）

老板拍板路线：**向量化 + ES 进化 + 2步前瞻**。落地与判决：

1. **权重向量 `game/src/agent/agent.weights.js`**（✅ 完成；**09-26 下午扩展：58 标量七簇**）
   - 打分卡 36 个标量抽成 `base/gate/geo` 三维向量 W，DEFAULT 与原字面量逐值相等
   - **09-26 扩展 +22 叶子**：`battle`（喝药双线/护甲双门/AOE 加权与触发敌数/砸击能量门，
     7 标量）+ `shop`（经济留币三参/买药血线/货架三项加权/整备预算，8 标量）+
     `event`（事件词权重四项+低血档，5 标量）+ `deck`（稀有度主权重 + 克制维度，
     2 标量）。**行为保持验证：T 底 40/40 配对全平**（vec-pre vs vec-post）
   - **deck.counterWeight 默认 0**：克制维度（多敌 AOE 加分/高血编组大伤卡加分）已
     接线但行为与纯稀有度完全一致，ES 可搜——boss 选牌盲区的无风险开洞
   - **公共路径参数必须 strategic 守卫**（喝药血线在 v1/strategic 共用路径上，直接读 W
     会污染冻结对照组——参数化时一律检查消费路径是否 strategic-only）
   - v1 greedy 对照组继续用字面量冻结（否则 ES 调 W 会污染基线）
   - 注入通道：`agent-batch --weights <file|json>` → `globalThis.__SDT_AGENT_WEIGHTS` 深合并
   - **仍硬编码在 agent.policy.js 的**：flee 判据/决死/滞环/反振荡（冻结区）、斩杀与
     性价比优先级结构、地图侧 fled 格血线（map 语义非 shop）、eventScore 数值缩放
     （×4/×6/×3/40/8——启发式细部，进 W 会让空间爆炸）

2. **2步前瞻**（❌ 按数据判丢弃，方法论完整走了一遍）
   - 假设：`value(a) = score(a) + γ·max邻居score`，替代贪心单步
   - γ=0.5：撤离 52.5%→35%、弃局 20% → **硬约束毙**
   - γ=0.2 加样本：p=0.20 不显著 → **早停丢弃**
   - 过程中修掉 2 个真根因（前瞻放大暴露的）：①邻居视角继承滞环解锁→门虚高
     （scdbg: score=2 → value=17.8）②回浅层门滞环放行→两层门横跳（cur=1:0 连续4次）
   - 教训：**新决策规则会放大旧打分的隐性缺陷——先修放大暴露的根因，再判新规则**

3. **ES 进化器 `game/tools/agent-evolve.mjs`**（✅ 冒烟 + r1 正式跑 + 三缺陷修复；
   **09-26 傍晚训练策略升级：分簇进化 + σ 自适应**）
   - 黑盒优化：扰动 W → 固定 seed 底评估 → top2 精英均值 → σ 衰减
   - **分簇进化（09-26）**：`--cluster auto`（默认）按代轮换目标簇
     （base/gate/geo/battle/shop/event/deck），每代只扰动目标簇叶子 + EXPLORE 个全空间
     探索者——58 维空间 pop 4-6 全均匀扰动采样密度太稀（r1 诊断：6 扰动 5 降），
     聚焦单簇把同等预算采样密度提一个量级；`--cluster all` 回旧行为，簇名=固定消融
   - **σ 自适应（1/5 成功法则，09-26）**：合规个体改善率 >20% → σ 放大 ×1.18；
     否则收窄 ×0.85；夹 [0.01, 0.25]。替代固定 0.85 衰减——信号强不急着收，
     信号弱果断收敛。`--sigma-grow/min/max` 可调
   - **σ 默认 0.06**（r1 诊断：0.15 的扰动幅度 > 100 局评估噪声能分辨的信号，
     6 个体里 5 个净变差——步长必须小于信噪比允许的量级）
   - **fitness = 同 seed 底逐局配对 Δ**（r1 诊断：裸 fitness 100 局噪声 ±5pp > 扰动真实效应，
     精英选择实际在挑噪声——r1 最高分 i3 的"优势"是拿弃局 8% 换的假象）。
     per-seed 分值 extract+100/clear+50/层×10/弃局−200，个体逐局减基线；g0 建参照表 Δ=0
   - **硬约束双闸**：弃局罚项 + **>5% 判负过滤**（r1 实证罚项单闸被击穿：
     8% 弃局个体 fitness 仍全场最高并当选 best）——判负者不进精英、不当 best、不 steering μ
   - 根因常数冻结区（`FROZEN_KEYS`：geo.ban / base.extractLocked / gate.battleBan / base.battleBan）
   - 每代个体明细自动追加 ledger；产物 `best-weights.json`（违约束个体不会当选）
   - **r1 判决（gen1×pop6×100 局）**：top1 弃 8%、top2 弃 6% 双双硬约束毙，唯一合规 Δ+2=
     噪声平 → **无个体晋级，champion 不变**。诊断三因：①噪声>信号（已改配对）
     ②地图簇平台化（6 扰动 5 降）③天花板在战斗（50% 死于战斗，W 够不着）→ 转修根因通道
   - 监督：内建墙钟（局数×35s+120s）+异常停车归因（exit 3）+progress.jsonl；
     外部 `agent-supervise.mjs`（STALL/EVAL-OVERRUN/VANISHED/MAX-TIME，异常杀进程+归因报告）

## 6.6 工具链修复批（2026-09-26 下午，全链冒烟验证过）

系统审计出 13 项问题，老板拍板全修 + 三项路线决策（漂移哨兵/T 底对称轮换/下轮主攻
战斗内埋点）。落地的修复：

1. **evolve 收尾强制 `process.exit(0)`**：产物落盘后靠事件循环排空退出会被残留句柄
   挂死（09-26 实证：主流程跑完零 CPU 挂 60 分钟，只能 supervise 按 STALL 收尸）
2. **超时局独立口径**（三处）：batch `summary.meta.timeoutRuns`（outcome 仍记 abandon
   保 schema 兼容，上层一律按 stopReason 区分）→ evolve fitness 弃局率剔除超时、单独
   −300/局 且 >5% 并入硬约束 → compare 增超时率行 + >5% 毙判决。弃局=策略止损、
   超时=卡死故障，不再混桶
3. **冷启动根因修复**（见 §1）：局间清档，首局不再特殊；`--selfcheck 1` 漂移哨兵
4. **compare 检验力**：输出有效 n、最小可检测赢率；不显著时用"剩余平局全倒向
   challenger 能否翻盘"判据区分**证据不足（可加跑）与终局性否定（真早停）**——
   早停纪律不变，但不错杀样本不足的假设
5. **compare 对齐校验**：两侧局数不等/配对率<100%/seed 重复/seed=null 显式警告
6. **supervise 进程判定收窄至 node.exe**：bash/npx/cmd 包装壳不再计入（实测一条训练链
   被数成 9 → 修后 3），壳残留不再让 alive 恒真、VANISHED 恢复可达；杀进程改
   `taskkill /T` 杀整树（Stop-Process 单杀留孤儿 batch）
7. **ledger tag 隔离**：evolve `--ledger-tag smoke` 冒烟不入正式视图（list 默认过滤），
   `--tag smoke` 反查；verdict 'candidate'→'hold' 对齐 §0 枚举，list 对存量越界枚举报警
8. **batch 噪音/防呆**：version.json fetch 桩（boot 走 Node 全局 fetch，jsdom 下必炸
   ERR_INVALID_URL 污染 stderr 与 supervise 归因报告）；`--policy llm` 未配 key 直接
   拒跑（未配置时 llm 静默退化贪心，100 局跑完是假 LLM 数据）
