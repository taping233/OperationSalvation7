# 仓库卡面构造

仓库与待复原页保留连续滚动网格。进入时按当前库存建立按钮、数量、保护标记和卡面占位槽，后续按稳定堆键接入新增与耗尽；仍在库存的卡格和已构造卡图继续复用。复杂卡面仅在当前可见区域及上下各600px的邻屏内构造。进入页面和修改筛选时立即补齐当前窗口，后续滚动由`IntersectionObserver`补齐，新增占位沿同一观察器接入。

卡槽沿用现有卡框宽高比和网格尺寸，选择、筛选、快捷键、滚动位置以及待复原业务继续走原仓库逻辑。键盘焦点进入未构造的按钮时立即补卡，因此Home/End、方向键和Tab不依赖观察回调时序。

补卡时按当前库存稳定堆键重新定位卡牌，找不到对应堆叠时保留当前身份边界。每个卡面在当前页面只构造一次。材料、保护、转化、孵化及拆包通过现有收藏视图原位同步数量、保护、筛选与资源；耗尽卡格退出列表，选择转向附近仍可用的卡格。需要整页重建的其他操作沿现有浏览状态恢复。

库存变化只为新增堆构造按钮；存量卡格更新变化的数量、名称与保护标记。类型和品质下拉同步新增选项，保留当前选值与输入焦点；选值暂时没有库存时仍保持显示，筛选状态与页面一致。

仓库详情通过既有大卡浏览按当前筛选连续翻卡，每张按现行唯一库存堆重建动作；`getItems/getIndex`提供实时列表与序号。保存中沿`canNavigate`暂停翻卡及说明引用跳转，完成后恢复；`_refreshCardZoomBrowse`同步数量和按钮。说明引用返回时，`onReopen`按最新库存重新打开来源详情。关闭详情后，本次保存完成仍更新有效的仓库列表。

材料详情支持连续部分使用，保留详情和操作焦点；耗尽后收回详情，回到仓库的可用位置。待复原详情按当前浏览卡牌重建操作，保存、钥匙或容量失败原位提示重试；成功后再关闭并播放既有复原演出，反馈使用本次实际数量和成本。

待复原的说明引用返回同样按当前唯一堆重建详情。复原中使用既有按钮忙态暂停跨卡；主动关闭详情后，已完成结果仍通过当前仓库刷新入口同步数量与资源，失败反馈留在有效基地页面。对应接线见[背包与整备浏览收拢](evidence/2026-10-26-flow-goals-round15/README.md)，待老板统一验收。

卡包与伙伴蛋详情使用同一操作反馈入口，等待保存时显示进度并暂挂消费按钮；失败保留详情重试。成功后有余量继续当前详情，耗尽才收回；卡包原位接入新卡堆，并显示本次实际获得的卡牌。孵化成本取Base配置，保护、转化及孵化的保存结果与后续成就检查分别反馈。

观察器只服务当前页面和存档。离页时释放观察器，过期回调不再写 DOM。没有 `IntersectionObserver` 的环境按当前筛选一次补齐卡面，保持浏览功能。

实现：`game/src/hub/hub.warehouse.js`、`game.hub.pages.js`，复用`collection-view-art.js`与`card-zoom-controller.js`。早期受控成本对照见[2026-10-20验证记录](evidence/2026-10-20-warehouse-window/README.md)。
