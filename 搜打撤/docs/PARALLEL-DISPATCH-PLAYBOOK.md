# 并行派工手册（PARALLEL-DISPATCH-PLAYBOOK）

> 适用场景：老板点名使用子代理或多会话并行推进时。2026-09-26~09-29 多轮实战沉淀，细节见文末先例索引。

## 派工前

- **默认不用子代理，老板点名才用**；任务书给「验收标准 + 属地边界」，不规定步骤（老板原则 4）。
- 任务书四要素：**目标 / 验收标准**（做成什么样算完成、如何验证）**/ 属地边界**（只许改哪些文件）**/ 回报格式**。
- **按当次可用额度和不相交属地确定并发**，保留主会话集成能力；老板明确并行数量优先。历史 ZCode 第三任务弹射不设定 Codex 固定上限，能力错误先核实再退回可用数量。

## 工作树与环境

- Codex 优先复用已附着且适合的工作树；ZCode 使用当前已授权工作树入口；需要新建时明确基线与属地并登记。历史路径 `~/.codex/worktrees/<slug>/代号柒` 仅为本机先例，不是两端固定约定；`搜打撤/desktop-app/*` 是打包副本，不是工作树。
- 工作树无 node_modules：junction 到主线（`cmd //c "mklink /J ..."`）或 `node 主线/node_modules/vitest/vitest.mjs --root <WT>/搜打撤`。
- 主线依赖是否齐备以现场为准；依赖复用须核对路径与内容，示例不授权安装。工作树处置沿根 AGENTS.md 授权边界；平台管理的工作树按其生命周期工具处理。
- 实机观察用**隔离副本**（HMR 整页刷新会杀实机会话）：`.exp-observe` 式纯副本 + 手动同步改文件；junction 跨根会让 Vite 解析失败；改副本内文件也触发重启，跑局前冻结编辑。
- 两端仅用各自内置浏览器与当前窗口，入口及证据口径见 [质量门](quality-gates.md#内置浏览器验收)；内置桥故障不得切外部 Edge/CDP/headless。

## 上下文打包（repomix）

- 给子代理喂大上下文用 repomix（已全局安装，`repomix --version` 验证）：
  `repomix --include "game/src/battle/**" --style xml --output <产物路径>`（battle 域约 850KB 实测）
- 产物给子代理当只读知识包，**不进 git**（写 .tmp 或系统临时目录）；属地纪律不变——
  子代理仍只改任务书属地内的文件，打包只是省它逐文件 rg 的探查成本。
- 全仓打包前先剔除 evidence/报告类目录（`--ignore`），避免把带日期记录喂进上下文。

## 协作纪律

- 跨域协作用**编号请求协议**（EXP/CODE/ART-xxx）：各线各记各文件、保存窗口预告、联合验证窗口（先例：`docs/zcode-dual-track-9h-20260927/` 三文件制）。
- 平时仅提交已授权属地；老板明确授权打包提交时，按根 AGENTS.md 的例外受理全部完成未提交改动。先核对完成归属、在途 mtime 与整个 index，半成品和未授权内容不能混入。
- 协作登记与半成品工作区边界沿根 AGENTS.md；主会话统一登记批次及子代理属地，避免每个子代理重复登一套流程。
- 主会话按产出类型复核定向证据与集成边界；游戏玩家可见行为按质量门补实页，内部流程不加游戏实机步骤。审查代理只出清单，实施代理只修属地，跨域接口先协调。
- 收尾及时核对自有改动、验收与遗留；提交须老板明确授权。完成未提交时在 REGISTRY 标注具体路径/归属与证据，不在记忆复制占用；获授权后按受理范围核对整个 index，不能仅凭已有 staged 内容推断可提交。
