## Issue 状态机（不交半成品的机制，严格执行）
open（评审员开出：截图证据+透镜之问的回答+P0/P1/P2；答不出透镜之问不许开）
→ fixing（修理工领走，STATE.md 登记文件划线）→ verifying（修理工完成：
实机 before/after 截图 + 相关单测通过）→ reviewing（评审员复核）
→ closed，或 reopened（回 fixing，注明理由）。
分支：stuck（见容错节，卡住协议）；wontfix（评审员+主代理双签，附理由）；
gameplay（玩法类待拍板，主代理汇入终报）。
禁止跳步：没有 before/after 不许进 reviewing；评审员未复核不许 closed。

## 每波收尾（你亲自验收）
1. 台账真实：抽查 2-3 条已修 issue——截图是新的（时间戳对得上）、
   git diff 与描述一致；发现假完成整条退回并记 LOG。
2. 方向对照：本波 issue 分布是否服务【本波主目的】——
   视觉波开出大半玩法类 issue = 评审员走偏，换评审员重审，而不是顺着跑。
3. 修理工各跑相关单测（npx vitest run <file>，不跑全量不 build）。
4. 过一遍性能铁律：新增动画不出画面即暂停、常驻层只走合成器、idle 预热。
5. 质量失真警报：单波 wontfix 率 >40%，或复核清一色「通过」无一条打回
   = 评审与修复有一方失真，停波根因分析后再继续。

## 容错与纠偏（遇到意料之外的情况，按此处置，不临场发明）
- 主目的裁决：任何冲突先对主目的锚——「可见可摸的体验变好」。
  技术上有趣但玩家看不见的优化，一律记台账降级，不占波次资源。
- 卡住协议：修理工同一 issue 连续 3 次尝试无实质进展，必须转 stuck 移交，
  附「试了什么、为什么不行」清单。不许默默换方向死磕，不许空手回来。
  你对 stuck 的处置选项：换人重试（带上前任清单）/ 拆小 issue / 降优先级 /
  wontfix 双签 / 升格为独立小任务。三种以上处置都试过仍不通才许 wontfix。
- 越界冲动：修理工发现划线外的大问题（玩法/架构/别的域）→ 只许记台账标
  escalation，绝不亲手扩修。发现崩溃/坏档类 P0 例外：立即上报你，
  你可以临时授权一人专修（工程修复在授权范围内），修完回归波次。
- 狂奔信号（满足任一即干预）：单个子代理长时间只有一个 issue 且台账无中间记录；
  diff 触及划线外文件；产出与本波主目的无关。干预方式：叫停该任务，
  划线外改动由你逐文件裁决保留或手工还原（不跑 git checkout/reset），
  人员换新任务并带上书面教训。
- 停滞分级响应：连续两波零 issue 关闭 → ①降级：评审员只审不修找根因；
  ②换道：换视角切入同一问题域（如从代码结构角度替代从视觉角度）；
  ③收缩：范围缩到 P0 issue 清单，其余全部转 open 移交下轮。逐级使用。
- 关键链路 fallback：起服失败→查端口占用/换端口/重启 node 进程；
  浏览器自动化失灵→evaluate 合成事件/重开实例；抽书装不了库→先
  pip install pypdf，再不行 PyMuPDF，再不行按字节切段处理——
  四步全败才许声明「书未接入」，后续波次用基准卡+自建分析兜底继续，
  任务绝不因单点失败停摆，声明进终报。
- 降级模式：实机验证彻底不可用时，明确记录原因，改用可得的最强验证
  （代码 review+单测+headless 截图），改造不停。
- 包络末端收尾：到点时所有 issue 只许两种终态——closed，或 open
  （附完整证据与进度注记移交下轮）。fixing/verifying 悬着不许收工：
  要么走完状态机，要么退回 open。

## 阶段三：收敛（W8，判据：零 P0/P1 + 性能回归达标 + 终报落盘）

## 子代理通用铁律（原样写进每个派发提示词）
1. 必读 GAME-UNDERSTANDING.md + RUBRIC.md 对应节 + 指定的书章节后再动手；
   开 issue 前先回答透镜之问。
2. 文件划线不越界；热点文件（index.html、全局 css、ui-scale.js、battle view 各片）
   同一波只派一人；发现范围外的问题只记台账不扩修。
3. 卡住协议：连续 3 次尝试无进展必须 stuck 移交，附已试清单。
4. 禁止：git 提交/推送/回滚、删除任何文件（含历史临时文件，一律进报批队列）、
   碰 game/src/agent/**、game/tools/agent-*.mjs、src/generated/**、Godot/Unity 目录。
5. 禁改玩法数值与机制行为（卡牌效果/数值/规则）；打击感、动效、音效、布局、
   文案、素材接线全放开，鼓励迭代更新。玩法类发现记台账标 gameplay。
6. 新素材默认不生成；既有未接线素材可挂接；确需新图进报批队列。
7. 项目坑：overlay 输入禁整页重建（sameNode 不变量）、Esc 要 isComposing 守卫、
   inert 隔离误伤兄弟层（新常驻层加排除名单）、坐标必须过 uiRect()、
   浏览器 locator 失灵改用 evaluate 合成事件、截图全黑先等动画、
   HMR 重载打断测试序列。
8. 反放弃铁律：查不到外部基准或问题开放，不是空手而归的理由——
   必须先自己构建分析（自己画体验地图、自定评估维度、写明推理）再动手。
9. 证据纪律：每个结论绑定截图/文件路径/数字；禁止「可以考虑/或许/建议进一步评估」
   式 hedging——每句话要么是决定、要么是证据。
