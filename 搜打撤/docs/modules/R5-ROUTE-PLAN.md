# R5 两路线与进行中地图恢复（预备，未派发）

## 起点与优先顺序

当前 `game.session.js/loadGame` 每次调用 `buildDerived(restoredMapSeed)`，保存种子和版本但不保存拓扑；`map-generator.js` 的 layoutVersion=9 明言旧图按新版本重生成。先解决进行中地图不洗图，才能增加模板。不得一边声称保留旧局，一边用新生成器重建它。

## R5-a 地图快照基础

玩家可见：刷新后仍在相同节点，已知路线/节点类型/连边不变。输入已生成plain-data layerData、种子、版本与位置，输出可验证MapSnapshot；恢复先完整校验，再替换派生坐标。新增快照只由稳定节点保存。

范围：独立快照校验模块，`game.session.js` 最小生成/保存/恢复接线，定向地图/旧档测试和文档。保留R2存储守卫与全部其他未提交改动；不动经济、卡库或龙巢规则。

合法旧档无快照：仅在可证明对应版本生成器存在时重建并冻结；未知或无法恢复的版本明确报错并保留原串，不静默生成新图，不覆盖玩家档。实施前列出实际版本分布与已有兼容策略，不能仅凭这一方案删除历史兼容。

验收：完整快照一致性、重复加载、未知版本/坏边/越界位置均不写坏档；100种子连通和既定配额回归；IAB新测试局走到稳定节点→刷新→节点及路径相同。通过后再派R5-b。

根预读补充：`layeredMap.js` 同时保留 nodes 与 logical，恢复时必须验证或重建同源关系，不能让显示和实际走格读取两套冲突类型。`buildDerived` 还生成 toLogical(Map)、nodePos、layerBounds、cellDefs；这些运行时派生物不能直接序列化冒充拓扑。新快照需保存完整节点/边/入口/门/祭坛等权威数据，位置和实际存档一同验证。冻结当前3/9生成器的兼容能力后才能改新图；无版本旧fixture确实存在，若无法证明其原图，必须明确区分“存储层可读取”与“恢复原图可保证”，不能凭空宣布兼容全部历史地图。龙巢独立地图存档也会经过loadGame，评审必须说明如何避免无关普通图门槛误挡龙巢续局。

## R5-b 两组路线模板

保持四层主图、节点总量与撤离费用；在现有事件槽和已有节点配置中形成两类风险选择：较低交战投入的补给绕行、较高交战投入的深入探索。名称是工作名，收益只引用实际现有奖励池，不凭空加职业收藏来源或承诺掉落。

输入seed/version/worldConditions/routeCatalog，输出稳定节点、边、已知风险与目标提示；缺剧情条件仍可完成基础路线。未探索节点不能因提示暴露未获知奖励；若信息来源不足则明示未知。

优先评估独立路线覆盖层：保留现3/9基础生成器及旧图重建函数原样，新局才应用带routeVersion的两组有界模板，最终整图写快照。若无需改生成器，勿为了版本管理复制一套大型生成器；但必须证明旧3/9无快照档重建时不偷偷应用新路线。模板要产生真实可选路径/内容差异并保留配额，不是只给原图两条路径起新名字。先给两个确定种子的节点/类型/选择矩阵，根审后接UI。

正常验收：给出两组固定种子，选择前能看懂差异，选择后在真实IAB遇到对应内容；实际记录两条流程及刷新恢复。失败/重试：模板不满足约束时有限回退原生成器并保留可追溯原因；无无限重掷；载入不重新随机奖励。停止点为Friday实机验收，不扩层数、不批量增地图。

根R5-b可行性抽样（不改运行时）：对 `r5-check-0..99` 的原3/9图枚举同层四格回路，L1有79/100、L2/L3/L4均100/100，L2最少2个对角分叉对。可优先在L2寻找两条局部绕行并有界互换现有普通节点内容，保留总配额与几何；这只是几何可行性，不证明内容约束全部满足。固定审核种子定为 `r5-route-a`、`r5-route-b`。不因L1没有回路重掷整张地图。
