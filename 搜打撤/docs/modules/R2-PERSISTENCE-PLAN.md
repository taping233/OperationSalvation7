# R2 后续拆包计划（未派发、未实现）

进入条件：R1 当前返工通过 Friday 实机验收。不得因本文存在就并发启动实现。

## 现状与原则

R0 审计已经证明三条结算路径先清 run 再保存 base；`RunStorage.remove` 吞失败，旧 `write/read` 不含事务恢复；M01 仅保护单个基地键。必须修复这个断点，但不能借机决定职业收藏新来源或安全格新规则。

用户可见结果目标：结算明确显示带回、损失、永久记录；保存失败时不宣称完成，刷新能继续处理，不重复扣卡/发奖。

## R2-a：两键可恢复提交边界

只实现并验证经过版本化的基地/对局提交与恢复门面，领域输入为已经准备好的 afterBase/afterRun（或明确关闭）。不从 rarity、safe、brought 推断经济规则。正常读取先处理待恢复日志，坏日志/未知版本保留数据并拒绝覆盖。

允许范围：base.commands.js、game.storage.js 的最小适配、必要私有事务模块、真实存储适配回归、仅 docs 的验收页。运行时交易接线必须后续逐条审阅；未接线时明确只完成基础边界，不能称玩家结算已经修好。

输入必须分别包含 slotId、requestId、expectedBaseRevision、expectedRunRevision、commandIdentity 和业务变更；保留稳定 runId。已完成请求的收据先于旧修订号判定。相同 requestId 换参数报冲突，新过期请求拒绝，不自动重放消费。

验收：日志写前/后、基地写后、运行档写后、结束标记前/后的故障注入，分别重新创建模块以模拟重启。每个结果只能对应一致的旧状态或一致的新状态，无法恢复时明确拒绝进入；不允许半份入库配合关闭对局。不得声称 localStorage 多键天然原子。恢复算法必须先书面说明采用回滚还是重做，错误 UI 语义与其一致。

并发风险：自动存档、切档、第二标签不能覆盖 pending transaction。五档隔离，旧 v1/v2 模板、坏档和未来版本、相同请求跨重启重试必须独立验证。直接 I/O 故障测试不得触碰真实玩家 localStorage。

停止点：真实适配测试通过、恢复行为可解释、待接线列表确定；交 Friday 验收再进入下一小包。

### R2-a 实施前的设计门

先交最多一页设计给Friday，获根任务审阅后再改runtime：具体键名/格式、重做或回滚的状态表、当前base内存缓存如何刷新、runId与revision首次建立/旧档兼容、重启收据、第二标签与旧自动保存如何阻止覆盖。`base.js`的最小守卫/适配也可纳入本包，但不改经济函数。

现有 `Base.save()` 为同步写，`RunStorage.write/remove` 也同步。不能拿 localStorage 的“先检查锁再写锁”声称跨标签互斥；若需要Web Locks会影响同步旧入口，必须先说明接入范围。只实现尚未接线的门面时必须明确隔离、不可对外承诺完整结算或并发保证；不要为了测试绿灯给真实旧入口留下绕过pending日志的通道。

真实故障验收使用独立存储适配器/专属QA命名空间，在测试页显示旧/新快照、故障点、恢复结果与重复收据。不在游戏origin的玩家键上注入配额或删键。未提交写入与已持久化但等待恢复的状态不能都用“没有扣除”文案；错误语义须匹配恢复算法。

## R2-b：开局预设与来源

R2-a目前的`commitBaseAndRun`仅接受已有进行中run；“不存在run→建立新run”的事务分支尚未实现，不能直接把出征按钮接上就称完成。R2-b先补明确的create-run前置条件、稳定runId和不存在运行档的期望，覆盖重复点击/库存变化/中断后重启，再改业务入口。

按稳定 CardRef/stackKey 核对库存；区分基地带入、职业开局赠予、局内奖励、初始牌。沿用未知旧数据的兼容分支，不伪造旧卡来源。M06 必须用与实际出征相同的核验规则；旧“职业禁带”与用户方向冲突单列，不得继续复制。

验收：预览后库存改变→拒绝且不创建 run；重复点击→扣一次；写失败→不进对局/可恢复；取消→不扣卡；选人物/宠物究竟在哪一步生效，UI与命令一致。

## R2-c：三结局接线与可解释收据

逐条接成功撤离、死亡、放弃，不一次改完三条再检查。当前保留规则与用户要求相冲突的部分须等决定后接入；不能凭“默认”把旧行为固化为新设计。

每条需要真实流程证据、一次失败、一次刷新和重试。成功撤离整理容量、合法堆叠、未选物品损失必须明确；奖品/统计/解锁只能随一次已完成收据持久化。先提供收据再关闭页面，提交失败可继续处理。

## 必须老板决定的项

职业实物禁止带出后永久职业收藏的获得入口；安全格/珍珠盒在死亡和放弃时保留哪些来源。不能发明自动登记、复制卡或额外经验来填坑。该依赖仅限制经济接线，独立恢复边界和其他玩法包可继续规划。
