# R4-a 黑像可编辑拆件绑定与动作样板设计

日期：2026-09-21｜状态：待根任务评审｜本阶段只做方案，不制作或接入资产

## 1. 决策与停止点

首个动作样板选择 **黑像（`heixiang`，战士）**。本方案的下一步是制作一套真正可编辑的拆件绑定，输出待机和巨剑攻击两段固定画布序列；根任务批准 R4-b 以前，不拆件、不补画、不导出帧、不修改 `battle.frames.js` / `battle.view.js`。

选择黑像的理由：

1. 当前 `game/assets/portraits/frames/` 只有 `wu`、`baita`、`changwuyu` 三人，黑像没有旧帧。用黑像能明确验证“从静态图建立可编辑绑定”，不会把旧序列帧换名冒充新绑定。
2. 巨剑攻击在战斗尺寸下有清楚的方向和重量感，待机与攻击轮廓差异大，适合检验关节、前后层、脚底和极限姿势。
3. 现有透明战斗图为 832×1216，人物 alpha 边界是 `x=35..673, y=58..1202`，有足够像素作为拆件底稿；但双臂、双手和剑柄重叠严重，正好能暴露补洞质量，无法靠矩形裁切蒙混过关。
4. 黑像现图没有咖啡道具，处于持剑战斗姿态；它和最新全身立绘的“咖啡杯＋背负大剑”有明确用途差异，可定义为同一身份的战斗姿态变体。攻击样板不需要让咖啡杯在战斗里凭空消失。

不选“无”作为首样板：旧 `frames/wu/idle.webp` 的墨镜戴在眼睛上，而最新 `character-bible/wu.md` 要求墨镜横架头顶、两眼完全可见。旧帧可作为播放器兼容样本，不能作为新绑定身份基准。

本包的通过含义仅是“方案可实施”；不代表黑像动作已完成、美术已认可或战斗已接入。

### 2.2 战斗图与最新 Bible 的差异

- 一致：男性、深肤色、高大壮硕、两侧短顶发后梳、露额、黑灰战术服、观众视角右侧单肩甲、棕橙围巾、宽刃巨剑、沉稳坏笑。

- 需要钉住：琥珀眼、左脸颊缝线疤、额头完全露出、围巾只有一条长尾、肩甲侧别颠倒、巨剑无纹。任何补画不得把围巾变披风、把剑变细剑或给脸加刘海。
- 已见缺陷：透明边缘有红／蓝彩边，剑刃和靴边有白色 alpha 杂点；双手与柄缠在一起，胸口和前臂遮挡区没有可直接旋转的完整像素。拆出矩形再转动会立即露洞，不能算绑定。

## 3. 画布、坐标与固定轴心

### 3.1 输出画布

- 全动作统一 **928×760 RGBA**。确定性运动学验证表明，统一平移后的剑柄约 `(457,258)`、剑尖约 `(438,719)`、剑长 `461.391px`；原提案 `-112°..+76°` 在640宽画布必然越界。修订为紧凑但仍可辨认的真实挥剑范围 `-72°..+58°`，928宽能保留至少12px安全边距。
- 不允许待机 512×760、攻击另换尺寸。所有帧共享一套画布、缩放和 pivot，避免动作切换时人物跳大跳小。
- 固定 pivot：像素 `(320,731)`，归一化 `(0.344828,0.961842)`，语义为两脚接地线中点。人物有意偏左，为蓄力时右上方剑尖留空间。
- 安全边距：左右至少 12px，顶至少 12px，脚底以下 29px。剑尖、围巾尾和肩甲都算内容，不能裁切后靠逐帧缩小补救。
- 基准人物 alpha 目标：待机帧约 `x=81..471, y=46..746`。攻击可以扩到 `x=12..916`，脚底仍锁在 `y=731`。

几何门由 `node docs/modules/r4-a-kinematics.mjs` 复现。脚本写出 `R4-A-RIG-KINEMATICS.json` 和四关键姿势灰盒 `R4-A-RIG-POSES.svg`；灰盒只验证边界、轴心和约束，不代表美术质量。

源图到绑定画布的基准映射，用于第一帧对齐和复核，不用于自动矩形裁切：

```text
source alpha bounds = (35,58) .. (673,1202)
scale = 0.611
rigX = 125 + (sourceX - 35) * 0.611
rigY =  30 + (sourceY - 58) * 0.611
```

R4-b 必须在 manifest 直接写 `canvas` 和 `pivot`。播放器不得再用逐帧 alpha 包围盒改变高度或脚底；alpha box 只做溢出／空帧 QA。

### 4.2 必须补画的隐藏区域

1. **完整胸口与肋部**：现图约源坐标 `x=345..585, y=270..465` 被交叉前臂覆盖。补出紧身高领作战服的连续褶皱和冷灰高光；不新增徽记。
2. **两侧上臂内面和肘窝**：每段向遮挡区延伸至少 24 源像素，形成圆形关节帽；不能只沿可见轮廓切到边。
3. **两只手套与腕口**：分别补完整手背、拇指根和腕口。剑柄从手层下穿过，手指前景片再覆盖；原图粘连像素不得同时保留在手和剑两层。
4. **完整剑柄／护手**：补齐两手之间与手后方被遮部分，保持缠布柄、银灰宽刃、无纹饰。剑必须是一件刚体，不能把刃和柄分别晃动。
5. **颈部与围巾下缘**：补出被围巾挡住的颈口和上胸；围巾颈圈另做遮盖片，保证头部 ±4° 不露透明洞。
6. **肩甲后缘和左上臂**：肩甲从上臂分开，补其背面暗部；攻击抬臂时肩甲不得像橡胶随手臂拉伸。
7. **腰带下方、腿根和大腿包背面**：补出腿根连接；包作为腰带子层，不与大腿一起扭曲。
8. **围巾三段接缝**：每段至少 18px 重叠并补背面暗色；尾端破洞形状保持，不能在循环中忽然闭合。
9. **边缘清理**：所有分件在 premultiplied-alpha 黑底和棋盘格各检查一次。去除现图红／蓝彩边与白色 alpha 杂点，但不侵蚀围巾破边、发梢和剑锋。

若以上区域无法从现图通过人工延展、克隆和结构补绘得到可信结果，才进入局部生成补画。不得整人重生图代替拆件，也不得覆盖旧图。

## 5. 动作设计与关键姿势

### 5.1 待机 `idle`：6 帧，2900ms 循环

目标是“重、稳、仍在呼吸”，不做整图上下摇摆。

- 帧 0：基准持剑站姿，双脚锁地。
- 帧 1：吸气峰值；`chest y=-2px`、胸廓 `scaleY=1.008`，头 `-0.6°`，肩各外转不超过 `1.2°`。
- 帧 3：呼气峰值；`chest y=+1px`、`scaleY=0.996`，头 `+0.8°`。
- 帧 4：围巾尾滞后到反向最大，根／中／尾相对角度依次不超过 `2°/4°/7°`。
- 帧 5：回到与帧 0 像素姿势一致，循环接缝不重复停顿。
- `root_feet`、两脚 toe 和剑尖待机接地点全程误差 ≤1px；骨盆 y 变化 ≤1px。坏笑、眼色和疤痕不做形变。

### 5.2 攻击 `atk`：10 帧，600ms，不循环

动作方向按游戏站位定义：角色面朝右，先把剑收向画面左侧身后，再向画面右侧敌人方向斜劈，最后归位。延续现有播放器 `atk-wind 320ms + atk-hit 280ms`，以后 manifest 可把10帧分成 `wind=[0..4]`、`hit=[5..9]`，无需伤害回调。

| 帧 | 阶段 | 关键范围 |
|---:|---|---|
| 0 | 基准 | 与 idle 帧0完全一致 |
| 1 | 预备下沉 | root固定；骨盆 `(x=-2,y=+3px)`、`-2°`；近膝弯 `8°`；剑 `+12°` 向画面左侧收 |
| 2～3 | 收剑 | torso保持面向右；近肩、近肘由固定骨长IK求解；剑依次 `+32°/+48°`，继续收向左后方；头反向补偿 `+3..5°` |
| 4 | 蓄力峰 | 剑 `+58°` 收向画面左侧；骨盆相对root `(-5,+4px)`，胸廓 `(+6,-3px)`；围巾尾滞后 `+10..16°` |
| 5 | 启动 | 骨盆旋转由 `-4°` 转 `+4°`，torso开始前压；两脚toe仍由IK锁定 |
| 6～7 | 命中主姿势 | 剑跨到 `-42..-72°`，剑尖到画面右侧敌人方向；骨盆相对root最多 `(+7,+2px)`，胸廓最多 `(+18,-4px)`；双手目标随剑柄，肩肘由固定骨长两节IK求解 |
| 8 | 回收 | 剑回 `-24°`；骨盆 `(x=+2,y=+1px)`；肩肘逐步还原 |
| 9 | 归位 | 与 idle 帧0一致；下一 tick 接 idle 不跳变 |

硬限制：头部全程旋转 `[-5°, +6°]`；肩甲只做刚体旋转，不缩放；上臂和前臂每段缩放在 `[0.98,1.02]`；剑只做刚体变换；双脚至少一只 toe 全程锁定，命中帧也不得把身体整体摇到目标处。

## 6. 可编辑源与可复现导出

R4-b 计划目录，不在本阶段创建：

```text
game/art-source/characters/heixiang-rig-v1/
  source/heixiang-rig-v1.ora
  source/README.md
  layers/*.png
  rig/heixiang-rig-v1.json
  motion/idle.json
  motion/atk.json
  qa/pose-board.png
  qa/alpha-checker.png
game/assets/portraits/frames/heixiang/
  manifest.json
  idle-00.webp ... idle-09.webp
  atk-00.webp  ... atk-13.webp
game/tools/export-heixiang-rig.mjs
```

- `heixiang-rig-v1.ora` 作为美术可编辑主文件。OpenRaster 保留命名图层、层级与原始像素，不锁定某个收费软件；旧战斗图以只读参考层导入。
- `layers/*.png` 是导出脚本使用的展开图层，每层透明边界包含关节帽，不是矩形截图；文件名与上文层 ID 一致。
- `rig.json` 记录画布、pivot、骨骼父子、关节、默认 z、分件源 hash 和源图 hash；两个 motion JSON 只记录关键帧变换和 z 切换。
- `export-heixiang-rig.mjs` 读取同一 JSON，以固定采样时间插值，合成928×760 RGBA后写无损PNG中间帧，再由仓库已有 `ffmpeg` 转成lossless WebP。不得手工逐张拖位置后导出。
- 脚本必须支持 `--check`：验证源 hash、16帧齐全、尺寸一致、alpha非空、pivot不变、内容未越界；支持 `--pose-board` 输出待机／蓄力／命中／回收四姿势对照。
- 若当前 Node 环境没有可用的 2D 合成库，R4-b 不临时安装依赖；先用已有 Python/Pillow 或浏览器 Canvas 的受控导出器，并把实际运行时路径写入 README。工具链未验证前不能称“可复现导出已完成”。

另一执行者的修改验收：只改 `motion/atk.json` 的 `elbow_near` 命中角度，重跑同一命令；输出仅对应帧 hash 变化，画布、pivot、其他帧和源图 hash 不变。

R4-b 的最小播放器适配方向：若 manifest 存在，按显式列表、画布和 pivot 加载，sprite 直接使用固定画布几何；缺 manifest 的旧角色继续走原探测回退。单帧缺失跳过且仍按 manifest 总时长重新分配；整动作缺失回 idle；整包失败恢复静态 `battle/heixiang.webp`。不得用每帧 alpha box 重新缩放 manifest 包。

## 8. 预算

- 帧数：idle 6＋attack 10＝**16帧**，低于30帧上限。
- 原始 RGBA：`928×760×4×16 = 45,137,920 bytes`，约 **43.047 MiB**，低于30张512×760的44.531MiB参考预算。
- GPU常驻：播放器继续只保留当前角色包；不得同时预载五名角色动作。WebP磁盘大小需在 R4-b 实测记录，不预估冒充结果。
- 帧率：待机约3.45fps；攻击约23.3fps的离散姿势采样，由现有30fps上限播放器按时长切换，不引入全屏持续 ticker。
- 制作量：18个图层、23个关节点、9类补洞区、2段动作。先做四张关键姿势 board，通过裂缝／身份／脚底评审后再补中间帧。

## 9. 质量风险与验收门

| 风险 | 预防／验收 |
|---|---|
| 双臂拆开露胸洞 | 先完成 `torso_fill` 与关节帽；关键姿势在透明棋盘和深色战场各放大200%检查 |

| 彩边和白色杂点 | 直alpha和premultiplied-alpha两种底色检查；不以整体腐蚀 alpha 修掉发梢 |
| 肩甲橡胶化 | 肩甲独立刚体，只继承上臂部分旋转；不做非等比缩放 |

| 旧播放器只探测5帧 | manifest 显式列16帧；旧角色继续原回退，不能扩 MAX_PROBE 冒充 manifest |
