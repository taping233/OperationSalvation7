## 代码复核问题

1. Pixi 使用共享投影，DOM 家具仍使用 `--gx/--gy` 矩形比例；编辑 grid 的裁切区域又是一套独立位置。三套坐标同时存在。
2. 草稿变化只更新 DOM 文本按钮，不调用 Pixi 草稿重绘；玩家不能看到实际家具预览。取消同样需重绘恢复。
3. 放置反算坐标强行 clamp 到 0..7/1..5，区域外点击会误落到边界。墙区与地面需按实际多边形 hit-test，非法位置应反馈而非偷偷改格。
4. visibilitychange 只停不恢复；切回页面 active 仍可能为 false，所有 emit 失效。需要区分路由 active 与 document.hidden，恢复可操作且隐藏不耗资源。
5. Pixi/WebGL 降级时 actorAsset 存在但 DOM 只渲染名字，没有角色图；需保留明确降级。
6. 收起面板和重新打开应保留草稿或明确取消；购买/展位即时更新不能无提示清掉未保存草稿。

## 修订设计：先建立可信的房间空间

不要再用不匹配的全幅透视照片作为等距地面。既有场景可退到窗外/背景氛围层；实际可摆放区必须具有清晰边界和统一等距投影。当前不要求伪造正式插画：允许明确的设计原型地面/墙面，正式贴图缺口单列。人物、家具、展位的脚底必须落在实际场景内。

正常浏览采用一室构图：收藏展示区位于房间后侧两端，人物站在可见地面中后侧；整备/布置/出征热点分别沿房间下缘、左缘、右缘组织。命中目标可大，视觉上不能五颗空菱形挤成一团。标签水平、字可读、不挡卡面或人物脸。

编辑时在右侧留独立侧栏并为地面提供足够宽度，顶部按钮横向清楚排列；若宽度不足改底部面板。逻辑格→Pixi/DOM/SVG 网格统一使用同一变换（包括 contain 偏移与缩放），地面每格轮廓可见，物件预览与鼠标点一致。
