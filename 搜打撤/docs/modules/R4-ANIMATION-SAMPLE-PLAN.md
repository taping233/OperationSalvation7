# R4 单角色动作样板（准备，未派发）

## 可见变化与质量门

一名角色在真实战斗中有可辨认的待机与攻击，脚底稳定，攻击来自关节运动而不是整张立绘摇晃。先做离线可编辑源和对照，再接现有 Pixi 序列帧；不换引擎、不引入收费骨骼运行时。

Friday 已检查：现有 `battle.frames.js` 为 Pixi 7 序列帧，wu/baita/changwuyu 有旧帧；每动作探测上限5，逐帧自动alpha归一化会影响真正绑定帧的固定pivot。黑像只有静态战斗图，双手叠在剑柄、手臂与躯干遮挡明显。不能机械矩形裁剪后宣称绑定完成；需要遮挡区补画和关节遮盖。

选材补充：旧 `frames/wu/idle.webp` 虽易拆件，但实图为墨镜戴在眼睛上、侧身持剑，不能因它已有帧就当作符合最新 bible（墨镜在头顶）的新美术基准。黑像 battle 图也带既有彩边和白色 alpha 杂点。方案必须明确沿用的历史缺陷、需要处理的区域及处理途径；源资产保留原样，不借样板覆盖其他会话待定立绘。

## R4-a 先交制作方案

输入：角色 bible、实际透明战斗素材、M04 比例/轴心标准、现有播放器。输出：选一人、拆件层级/关节坐标、需要补画区域、源格式和可复现导出路径、预计帧数与时长。保留原素材；源和新导出放单独目录。先展示待机/攻击关键姿势对照，由 Friday 检查裂缝、穿插、身份及脚底。失败则修订拆件方案，不先替换游戏。

角色外观沿 `docs/character-bible/`，生成或补画按 NovelAI V5 painterly 管线和已批准额度；中文提示词先记录，老板审美认可仍独立待定。不得为赶进度重画一个陌生人物或把几何人偶算正式角色。

## R4-b 接口与文件范围

输入 `AnimationPack` 显式角色/皮肤ID、画布尺寸、固定pivot、动作有序帧路径及 durationMs/loop；输出完成、跳过或fallback的表现结果。只消费已确认动作，不通过命中帧伤害回调改规则。每个行动收据的关键音效至多一次。

样板控制规模：先沿用512×760量级的透明帧，待机+攻击合计优先不超过30帧；一套原始RGBA约44.5MiB，不能同时常驻多角色帧。动作伸展若需更宽画布，manifest必须明确新尺寸及预算，不能用逐帧缩人掩盖裁切。脚底轴心和角色尺度按整套共同边界锁定，攻击极限姿势也要完整在画布内。

允许：新拆件/绑定源、导出脚本和manifest、`battle.frames.js` 最小适配、必要 `battle.view.js` 表现接线、定向测试与交付文档。禁止：重写战斗核心/卡库/存档、替换其他角色资产、引入 Spine、混合工作区build。

## 验收与停止点

正常：另一执行者修改一个关节姿势并重导出；至少一个动作超过旧探测上限而所有manifest帧仍按序加载；待机连续、攻击前后脚底同轴；两档倍率下动作清楚；真实战斗中播放新动作，旧角色仍可用。

失败：缺单帧/缺整包、隐藏、卸载、跳过、减少动态效果均有明确结束或静态回退，不锁住规则。固定轴心不能被逐帧包围盒缩放破坏。

重试：同receipt不重复关键音效；隐藏后重新进入只恢复当前有效表现；缓存资源清理有证据。相同初态有/无演出规则状态相同。

停止点：R4-a关键姿势先评审；合格再派R4-b，不并行。R4最终由Friday IAB验收，老板审美认可及扩量决定保持待定，不无限拓展全员动作。
