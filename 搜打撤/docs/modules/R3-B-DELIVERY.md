# R3-b 出牌边界交付

## 玩家规则变化

- 一张普通手牌合法结算并离开手牌后，迟到或重复的相同 UID 出牌命令不再重复扣费、伤害或移动卡牌。
- 「不朽斩」等结算后仍在手牌的卡可以继续合法使用。
- BOSS 战中进入弃牌堆、洗回并重新抽到手里的同一 UID 可以再次合法使用。
- 既有内部直接释放仍走原 `queueCardExecution(..., true)`，不受普通玩家命令入口守卫阻断。

## 最小实现

`game/src/battle.core.js` 的玩家 `play()` 入口在解析卡牌前要求 UID 当前存在于 `hand`。守卫不保存历史 UID，因此不会误伤保留牌或洗回重抽。

每次真实 `queueCardExecution` 提交会生成冻结的表现收据：

```text
{ battleToken, actionSeq }
```

- `battleToken` 复用现有战斗实例令牌。
- `actionSeq` 每场从 1 开始，只在真实队列提交处递增。
- 同一次提交的 `play` 动画事件携带同一个 receipt。
- 非法重复命令不会进入队列、不会生成 receipt，也不会取消当前药水点选。
- 保留牌、洗回重抽及内部直接释放的下一次合法提交会取得新序号。

receipt 仅是供后续表现层使用的去重接口；R3-b 没有消费它，因此本包不宣称已经避免动画或音效重复。合法提交序号允许因动作取消而出现空洞，只保证同一战斗内单调且唯一。规则结算仍由现有 action queue 驱动，不依赖动画回调，也不写入存档。

## freeCast 边界

没有复活 `freeCastTarget`。当前 `freeCast` 集合没有可达的 `.add()` 或外部设置路径；真实直接释放通过 `queueCardExecution(..., true)` 完成。低能量等待目标矛盾仅保留在复现报告中，未为死分支增加机制或测试入口。

原验收点：

- 普通战与 BOSS 战各验证一次正常出牌仍只结算一次。

- receipt 尚未接入 R4 表现消费，本包只提供真实 `play` 事件上的只读字段。
