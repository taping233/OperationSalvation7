# R7 遭遇差异与 Vite 集成（预备，未派发）

## R7-a 两组遭遇

只复用真实既有敌人和行为，做两组需要不同击杀顺序的组合。先提交每个敌人真实ID/行为入口、组合用途、两种合法出牌顺序的独立预期，再改配置；不是给同一种怪换名字或改血量。保留既定各层数量、掉落规则与首脑。

根代码预读：怪物/遭遇数据实际在 `game/data/map.json`，组队入口为 `game.run.scenes.js/buildEncounter`。`charge`/`guard`/`volley` 虽有行为名字，当前敌方回合主要仍是同样单次普攻，不能把数据中的“机动兵蓄力”说明当作已实现机制。明确有附加作用的普通怪为burn（命中附2回合灼烧）和curse（命中施诅咒）；保护/庇幕及特殊蓄力主要属于龙巢/首脑，本轮不得拿冻结范围或未实现标签伪造差异。若仅靠现有合法普通池无法形成两组有意义差异，先提交缺口与最小新增行为方案给Friday重审，不先扩大实现。

输入层级、已批准遭遇目录及随机流，输出敌人组、可信意图与既有奖励池标识；不执行奖励提交。允许遭遇目录/组队选择器及最小提示，不改卡库/结算经济。

验收：固定初态两种行动顺序实际形成可解释的受伤或资源差异；IAB每组各走两种顺序；随机重复能复现、无合法组时回退原遭遇、重载不重复摇出新阵容。R3预览和命令不能回归。通过即停，不扩全层敌人AI重构。

## R7-b 集成与本地反馈

产出一份玩家可读的变更清单、可追溯模块验收表和本地反馈入口。反馈只由用户主动导出，不联网发送；记录游戏版本、入口、步骤、期望/实际，可选截图，不默认包含玩家完整档案或机器隐私路径。

复用优先：当前 `game.menu.js` 已有全局右键建议层和设置中的留言库，浏览器保存在`sdt-suggestions-v1`，但没有朋友导出的明确闭环。应在既有入口上加可选结构字段/版本和单条导出，不另造第二套反馈UI或改旧留言。保存成功提示不得继续承诺“Friday会看到”——本地浏览器记录不会自动送达制作人，应明确本地保存及主动导出方法。缺版本字段的旧留言仍可读取。

每项标记：已接游戏且实机通过 / 独立模块通过但未接游戏 / 未验收 / 待制作人规则或审美。不能以总测试数字盖过R0、R2或剧情依赖缺口。

测试按本批最终改动运行所需定向集成，完整suite使用--no-file-parallelism；既有失败与新回归逐条区别。混合工作区禁止直接build/打包；如确需可分离版本先给明确文件范围和来源，不恢复冻结Godot/Unity/EXE。现有Vite浏览器交付仍为主线。

实机必须有新测试档整备→基地→出征→战斗→结算→回基地→刷新，并分别记录成功撤离/死亡/放弃。不可覆写01—04档；QA05和隔离夹具已占用情况以台账为准。未达依赖门的结算不做“按旧代码就算通过”的验收。

停止点：整批已授权范围收口且无剩余可独立工作后给老板一次成果与未决清单；整批真正完成才暂停自动化。缺规则导致未完成则如实通知必须决策，不宣称全部完成。

根IAB预查（R5-a实现等待期间，只读现有UI）：设置→查看历史留言，空状态仍写“在游戏任意界面右键即可写给Friday”。R7-b须一并改为本地记录/导出后交给制作者，不能只改保存成功toast；现有入口位置可保留。

根补充遭遇审查口径：`battle.core.js` 的burn/curse只有实际对玩家造成伤害（dealt>0）后触发，策略提示不能说“每回合无条件附状态”；护盾/格挡完全挡住时不触发附加。`buildEncounter`现用层内单一entry重复1–3只，混编新增必须显式列出对既定编组规则的有限变化，精英概率和奖励来源继续保留。

## R7 只读预研收口（05:38，尚未实施）

R7-a候选限定两条固定双人组：L2 `archer`（5攻3血）+`cavalry`（5攻6血），L4 `fire_el`（10攻7血、命中附灼烧）+`grass_el`（5攻12血、命中附随机诅咒）。前者形成不同减员成本，后者形成即时伤害与状态风险。不用未实现charge/guard名字冒充机制，不加新AI。真实BattleSession用合法现有牌核验不同目标顺序，例如L4两张4伤初始攻击分别集中于7血灼热或12血滋生，比较实际受伤和状态；全防住不得施咒。

选择器先维持既有elite抽取（L3 3%、L4 10%），再从合法原entries/新groups一次确定选择，不重掷；新group固定2只，旧entry数量区间和rollCount不变。添加group是对旧“同种1—3只”的明确有限调整；不声称全部旧概率分布完全不变。坏group回退原entry、不因缺ID崩战斗。checkpoint恢复使用既有enemyDefs及opts，不再次组怪。修正L2蓄力/打断、L3冲锋/防守等虚假strategy，玩家文字只说能实际感知的威胁，不写实现原理。

可在已有开发节点菜单增加两个明确命名的混编样本，复用同一目录解析+真实startBattle/视图，不占档、不写玩家存档。限定 `game/index.html`、`game.boot.js`、`game.run.dev.js` 局部接线，不加seed输入/任意阵容注入。根会分别重开样本比较两种目标顺序，证据明确标为场景验收；正式随机选取由真实buildEncounter测试另证。

R7-b文件限既有 `game/index.html #sugLayer`、`game.menu.js`、`game/css/overlays.css`（复核winter覆盖），必要纯反馈编解码模块与测试。版本沿用 `game/version.json → game.boot.js → #gameVersion`，缺失显示未知，不臆造版本。可选步骤/期望/实际+正文，忙碌防重复保存；失败保持输入与页面供重试。复用原localStorage键，坏存储不静默覆盖，旧留言兼容且不回写改写。

本轮不增加图片上传/内嵌存储，避免本地配额膨胀。单条JSON导出字段白名单，仅时间/版本/玩家可读页面与位置/填写内容；不默认导出selector、完整URL、机器路径、档案或localStorage全集。旧条目缺版本仍可导出，文件名安全，Blob URL在下载触发后回收。主动导出不自动发送，所有旧“Friday会看到/写给Friday”用户文案统一纠正。正常/失败/重试验收包括存储失败保持、双击一次、刷新保留、旧留言、安全转义、导出内容和无自动网络传输。

样本入口安全门：旧 `devEnsureRun()` 在已有runActive时会复用当前局，新混编样本不能直接沿用这条分支。仅允许无activeSlot且无真实进行中局的标题测试环境；若有已选玩家档/进行中局则拒绝提示，不能为了测试清档/清slot。样本的卡牌/生命起点须写明与正常新局的异同，测试应证明无任何玩家档写入。
