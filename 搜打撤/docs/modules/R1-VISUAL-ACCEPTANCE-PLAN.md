# R1 基地视觉收口：待派发计划

当前仅规划，R0 审计后由 Friday 决定派发时点；不与运行中的实现包并行。

## 需要纠正的体验

上一轮真实场景可操作，但仍是灰盒：白底人物插画像一张贴纸；收藏展位和圆形热点叠在一起；房间内出现 PROTO、CHAIR 等内部文字；门口与家具缺少明确空间关系。不能因为 37 个测试通过就把这些问题算作视觉完成。

## 首包范围：空间与交互可读性

输入：现有 M04 VisualPack、M05 HomeSceneView、权威角色素材和六家具数据。输出仍是相同业务接口，不加货币、不改家具价格、不更改存档。

先审查已有可用透明角色素材和场景素材，记录来源，不直接将一张不匹配透视的背景盖在网格上。房间、家具和点击布局必须共享投影和脚底锚点；素材制作需求不足时先列清单，不能用伪透明或遮挡图层掩盖错误。

允许修改：home.scene.js、home.visuals.js、home-scene.css、对应专用测试和本包新视觉资产。art.js 只允许必要的受控适配，game.hub.js 只限界面接线，修改前登记。不得触碰战斗、卡库、地图和经济。

## 独立验收

1. 玩家一眼能区分展柜、整备台、驻留人物、家具工坊和出口；热点不遮卡名、人物脸及关键家具。
2. 正常界面不显示 display-left、PROTO 等内部实现标签；编辑网格和锚点只在编辑模式出现。
3. 人物脚底落在地面，图片不带白色矩形边框；若无合适素材，用明确的人物肖像框方案并标记未完成场景角色，不能伪称绑定。
4. 六类家具投影与地面一致、层级合理。已有座椅重载后位置不漂移；灯放桌面的支撑规则保持。
5. 编辑反馈说明选中家具、可放/不可放原因、是否有未保存改动；取消不写档，保存失败不显示成功。
6. 鼠标和键盘可触达五热点与旧入口；当前实际浏览器尺寸无溢出，无损坏图片，主要按钮点击目标不少于 44px。
7. 请求 1280×720、1920×1080 后先核对实际 DOM 尺寸；工具不支持时如实列未验证，不用截图文件像素替代 DOM 尺寸。
8. 隐藏和退出暂停动画，连续进出不残留画布或事件监听器。

## Friday 验收与返工

同一档位、同一家具布局截图与旧版本对照；通过真实界面完成购买、摆放、取消、保存、收藏展示与重开。检查 1—8 后写下“改善了什么/仍然难看或难用什么”，不以素材数量作为成果。若角色像贴纸、热点遮挡或家具悬空，退回本包修订，不派下一个内容模块。

停止点：可读、统一、可操作的房间首包。正式美术、所有角色动画和生产排班不混入本包；老板的审美反馈作为独立外部验收，不代签。
