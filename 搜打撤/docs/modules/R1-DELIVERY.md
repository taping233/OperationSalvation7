# R1-a 基地空间与交互可读性交付

## 第一次实机退回后的修订设计（编码前冻结）

- 透视照片只保留在房间上方约三分之一作为窗外氛围，不再承担地面。实际房间由一套随视口 contain 的 8×6 菱形投影绘制明确墙沿、地板和格边界。
- 新增单一动态变换：逻辑格、Pixi 家具/人物、DOM 展位、编辑格与命中区全部消费同一 `createHomeProjection/projectHomePoint`。编辑侧栏打开时，同一变换自动缩入剩余可用宽度。
- 编辑网格改为逐格菱形按钮。草稿家具在 Pixi 中即时重绘，格按钮只承担命中和状态提示；不再使用矩形 `--gx/--gy`，地面外点击只报错，不钳制到边界。
- 人物脚落在中后场有效地板格；展位落在后墙两端，并限制卡面高度。五入口改为舞台左、右、下缘分区的水平文字按钮，不继续围绕中心点堆叠。
- `setActive` 只记录路由状态，页面隐藏状态单独控制 ticker；标签恢复时自动恢复可操作状态。WebGL/Pixi 失败时，DOM 降级层显示实际透明人物图，而不是只留名字。
- `update(next)` 若存在未保存草稿则保留草稿和选择，不因购买家具或更新展品静默覆盖；若无草稿才接受新保存布局。收起只收起，取消才恢复存档。

## 实施前设计冻结

- 玩家可见变化：基地成为单一暗色冬夜作战室构图。场景主体固定在共享等距投影内；收藏展柜位于左右后场，驻留人物站在中后场地面，整备台/家具工坊/出口位于前场。热点改为边缘铭牌，不覆盖人物脸、卡名或家具。
- 人物策略：优先复用 `assets/portraits/battle/<character>.webp` 或现有透明帧，并使用脚底中心锚点；不再把 `classArt()` 的全身展示卡直接贴到房间。没有透明合适素材时降级成与房间一致的暗色肖像框，并明确标记素材缺口。
- 投影策略：房间、六家具、编辑网格和命中区只消费 `VisualPack.roomSpec.projection`，由同一 `projectHomeCell` 计算；家具 pivot 服从 VisualPack，不在场景里另写一套比例。
- 展位策略：两个永久收藏展位显示真实卡面和中文名；正常界面隐藏 `display-left/right`、`PROTO`、实例 ID 和网格坐标。空展位显示“待陈列收藏”。
- 编辑反馈：仅编辑模式显示网格；明确当前选中家具、未保存状态、合法/非法放置原因。取消恢复已保存布局且不写命令，保存失败保留草稿并显示原因。
- 美术边界：本包不生成新 bitmap，不把现有 SVG 几何样张冒充正式房间。缺少最终房间与六家具 bitmap 将写成正式资产缺口；若后续生成，必须另走 NovelAI V5 权威 painterly 流程。

## 验收样例

- 正常：已有座椅和展品进入基地，人物脚底、座椅与展位保持同一空间；进入编辑模式选择家具，合法格显示预览，保存成功后重进位置不漂移。
- 失败：重叠、越界、桌灯缺工作桌支撑时显示具体原因；保存失败不显示“已保存”。
- 取消：移动家具后显示“有未保存改动”，点击取消恢复已保存位置，不发 `submitLayout`。
- 重载：同一档位刷新后家具、展位和币与保存结果一致；连续进入退出 10 次无残留 canvas/listener。
- 视口：实际 DOM 分别核对 1280×720 与 1920×1080；工具不支持的尺寸列未验证。

完成上述空间、热点与编辑反馈，并给出定向测试和可获得的内置浏览器证据后停止；不进入新经济、结算、地图、正式新美术或动画扩量。

## 实际交付

- 房间底图改用仓库已有正式 `scenes/winter-expedition/supply-room.webp`，并以暗色遮罩统一冬夜基地氛围；没有生成或采购新图。
- 驻留人物按 `characterId` 使用已有透明 `portraits/battle/*.webp`，以脚底中心锚点放入与家具相同的 VisualPack 投影和深度排序；只有缺素材时才退回暗色肖像框。
- 两个收藏展位读取真实 `home.displays` 引用，展示收藏中文名和既有卡面 HTML；无图时保留名称文字，不把无图误作空展位。
- 五个热点依照 VisualPack 锚点落位，改为 44px 边缘菱形铭牌；家具热点直接打开布置面板，旧商店仍保留在下方快捷入口。
- 六家具继续使用 M04 样张，但在 Pixi 层裁掉图片底部的英文 `PROTO` 标注，并保持地毯/墙饰/地面物件分层。样张状态仍是 `prototype`，没有冒充最终家具。
- 正常房间不显示网格、内部展位 ID、实例 ID或英文原型标签；编辑模式用中文家具名和“收藏展位 1/2”。
- 编辑面板会显示当前选中、未保存或首个非法原因；非法草稿禁用保存。取消恢复已保存布局且不提交；保存失败沿用错误回执，不显示成功。
- ResizeObserver 只重绘当前场景，`setActive(false)` 停止 ticker，`dispose()` 解绑监听、观察器并销毁 Pixi；既有 10 次进出测试继续覆盖清理。

## 第一次实机退回后的实际返工

- 上述“房间底图”方案已被本节取代：`supply-room.webp` 现在保持 658×370 宽高比，只在舞台上部作为低透明氛围图。8×6 房间由明确的菱形地板承担，照片不再作为家具放置平面。

- 编辑格改为逐格菱形按钮；草稿、拿起、取消和视口变化都会重绘 Pixi。地面外点击仅显示“不自动吸附”，不再 clamp 到合法边界。
