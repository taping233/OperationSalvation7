# 非战斗卡牌规则迁移验收基线

日期：2026-09-23。范围：`base.js` 材料折算/钥匙计数、`game.bag.js` 道具使用。此文记录当前行为供后续结构化迁移逐项对照，不代表目标设计，也不主张描述文字继续作为最终规则来源。

## 自动化基线

- `tests/base-material-rule-baseline.test.js`：加载旧格式 slot 存档实例（卡牌带稳定 id，但没有 `rules`），验证 `tt3-wood-bundle` 的描述 `木材 ×3`、整堆数量 2 折入 6 木材；验证 `tt-key-one` 的 `钥匙 ×3` 加入真实钥匙储备，并核对仓库卡与真实储备的钥匙总数。另验证缺少 `×N` 的 `tt-key` 按每张 1 把计数。
- 这些断言刻画现有实现：材料类型按卡名中的“木材/口粮/钥匙”识别；数量由 `desc` 的 `×N` 提取，缺省 1；`keyCount()` 把 `data.keys` 与仓库钥匙卡数量相加。不可把结果解释成描述改写后仍等价。

## 背包道具可执行用例

当前自动化测试尚未建立。`game.bag.js` 的 `useOwnedCard(uid)` 和 `cardHealAmount(card)` 是私有闭包；对外只导出 `showBackpack` 等 UI 入口。调用路径读取模块单例的背包、生命值、消耗口袋，并通过 `UI.act`/详情面板交互。因此纯规则单测无法证明实际消耗、治疗和复原结果；后续应从真实背包入口搭建集成测试或用内置浏览器执行下列步骤。

所有用例先在新测试档准备对应卡牌，记录使用前生命、背包卡牌和消耗口袋；打开背包，点击卡牌查看特写，再点“使用这张道具”。使用后检查同一状态项和日志。

| 稳定 id / 场景 | 准备与操作 | 当前行为基线 |
| --- | --- | --- |
| `tt3-savior-elixir` 治疗 | 生命低于上限；将该旧档道具放入背包并使用 | `desc` 为“回复 99 点生命。”；`cardHealAmount` 从描述提取 99，调用 `game.heal(99)`；道具从背包移除。记录实际生命上限钳制结果。 |
| `tt3-savior-elixir` 满血 | 生命等于上限，使用同一道具 | 提示“生命值已满，暂时不需要使用”；道具不移除。 |
| `tt-crystal` 复原 | 消耗口袋准备至少 4 张卡，背包留至少 3 个空位；使用能源结晶 | 最多复原 3 张；能源结晶消耗；卡牌从消耗口袋转入背包。 |
| `tt-crystal` 背包容量边界 | 消耗口袋准备 3 张以上；背包仅留 1 个空位；使用能源结晶 | 只复原 1 张，剩余卡留在消耗口袋；核对日志报告剩余数量。 |
| `tt-crystal` 空消耗口袋 | 消耗口袋为空；使用能源结晶 | 提示无需复原，道具不消耗。 |

## 迁移时需要保持的观察项

- 用同一份旧档卡牌快照复跑，确认按 `id` 补齐结构化规则后效果与背包去向不变。
- 将以上道具的描述改写但保留结构化规则后复跑；治疗值和复原上限应来自规则数据，而 UI 描述仍照常展示。
- 若建立自动化入口，应断言 `game.heal` 调用量、道具 uid 移除、`usedPocket`/`ownedCards` 变化、背包满格和日志，而不只检查描述解析结果。
