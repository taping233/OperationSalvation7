# Vite 内置浏览器性能基线 · 2026-09-28

测量范围：Codex 内置浏览器当前窗口的 Vite dev 页面，URL 带 perfProbe 参数；项目包版本 0.60.0。隔离工作树基线 HEAD 为 2cef754，本轮代码仍未提交，远端实时状态未 fetch。只测第一层入口附近地图和角色“无”的战斗帧；研究所第二地图暂缓。

## 方法与条件

窗口 1280×720，画布 CSS 区域约 1280×599.3、后备缓冲 1600×749，devicePixelRatio 1.25，页面保持 visible。开发探针只在 Vite DEV 且带 perfProbe 参数时动态加载，按按钮每次采 6 秒；三轮取中位数。静止场景不输入；受控平移场景由探针在原地图位置附近周期改变镜头并显式失效，结束后恢复镜头。探针短时包裹 Renderer.draw 统计同步 JS/Canvas 调用耗时，另记 rAF 间隔与 Long Task；结束恢复原 draw，测量结果一次性显示并写日志。

这是同一当前窗口的前后比较。rAF 回调频率不等于显示硬件实际呈现率；受控平移走静态地图的逐帧失效路径，不是游戏“moving”状态下的 120 FPS 调度。Renderer.draw 耗时也不包含 GPU 合成/DWM 等待。此次物理画布不是既有 1920×1080 Electron 基准，不能套用该发布门槛。

同一标签页、未清缓存的三次 Vite dev 重载：FCP 为 280/240/264 ms，中位 264 ms；DOMContentLoaded 为 467.8/423.1/428.0 ms，中位 428 ms；loadEvent 为 499/442/443.1 ms，中位 443.1 ms。三轮均是暖缓存或部分缓存条件，不能称为冷启动基线；资源传输量在 79–836 KiB 间波动，未据此判定预热优化收益。

## 战斗帧加载切片

从当前存档恢复同一名角色“无”的普通战斗，每次页面重载会重新建立 Pixi 纹理集；角色帧集实际 12 张，候选探测名 31 个。原实现逐个等待 Assets.load 和 alpha 包围盒；本轮改为每批最多 3 个候选并发、按原候选顺序写入 set/seqs，保留单角色缓存和卸载策略。

| 同窗口三次重载 | 帧集 ready 耗时 | 中位数 |
| --- | --- | ---: |
| 修改前 | 550.9 / 1225.2 / 649.7 ms | 649.7 ms |
| 三并发后 | 434.3 / 853.3 / 412.2 ms | 434.3 ms |

本样本中位数下降 215.4 ms，约 33%；两组范围都较宽，且浏览器缓存与系统负载未独立控制，不能把此百分比当成跨设备的稳定收益。六次均记录到 12 帧 ready。既有 battle-frames-lifecycle 用例及新增“三个 Assets.load 并发上限”和“加载中 hide 后重入必须等待卸载”用例定向 7/7 通过；当前窗口实际进入战斗并显示敌人/手牌，浏览器 warn/error 列表为空。并发上限仅约束 Pixi Assets.load，同时启动的 fetch/createImageBitmap 与 GPU 纹理峰值未测，不能据此声称内存峰值不变。战斗模块导入曾记录 136.2 ms，但选角页会提前预取，不能当作首战额外等待直接相加。

## 后续测量：战斗帧加载分段（2026-09-28 约 23:24 +08:00）

在同一 Codex 内置浏览器当前窗口、1280×720、DPR 1.25、visible 状态，反复重载并恢复档位 01 的同一名角色“无”的同一场普通战斗。新增的 `?perfProbe` 开发日志只计时，不改变帧序、并发上限或包围盒算法。每轮均有 31 个候选名、12 张实际帧，浏览器 warn/error 列表为空。

本组 ready 中位数 552.8 ms，波动明显；与上节的 434.3 ms 不能直接解释为回归，因为采样时点、后台负载和代码状态不同。`Assets.load` 与 alpha 获取/解码并行，表中的逐帧 p95 不可相加；批次按最多三候选顺序推进，所以批次墙钟合计接近整套 ready。alpha 像素扫描的 p95 仅 0.8–1.8 ms，本样本不支持重写包围盒算法。19/31 个候选名不存在，仍会走探测请求；下一优化候选是利用已有生成资产清单减少无效探测，但必须先保证开发时新增帧可见，再做同条件对照。此处只完成定位，没有宣称新优化收益。

## 如何复测与未覆盖项

在隔离 Vite dev 页面使用 Codex 内置浏览器，带 perfProbe 参数进入普通远征地图，等资源和转场稳定后分别点“测静止地图”“测受控平移”，每种三轮。点“读加载”查看当前页面的导航、paint 和 battle load mark；战斗帧加载结果也作为 vite-perf-frames 日志输出。记录日期、HEAD/工作区状态、当前窗口、DPR、缓存条件、游戏档位与角色，再对照同条件结果。普通启动不带参数，探针不显示。

未测：冷缓存首次进入、其他角色帧集、长局内存、真实指针拖拽与 zoom、战斗画面持续帧率、不同窗口/DPI。120 FPS 仍为努力目标；此记录不宣称整游戏已达到它。旧 Electron 基准留在[性能主记录](performance.md)，不能与本页数字混用。

三并发改动后的独立生产构建输出至新目录 desktop-app/game-perf-20260928，退出码 0；983 个模块转换，首屏 JS gzip 300.8/310 KiB、包 85.52 MiB，现有预算 PASS。产物 JS 中没有开发探针标题或 vite-perf-frames 标记；构建没有把带参数的开发探针带进普通生产入口。随后仅补了探针异常清理和上述定向测试，未再次构建，故最终工作树的完整产物仍以该次构建时点为准。

这组实页数字来自隔离工作树基线 2cef754 加本轮未提交改动。改动移入主工作区 HEAD 7c2b6e7 后仅做了定向代码检查；主工作区有其他会话的 CSS 在途，没有在那里重测实页或重新构建。后续对比应固定同一窗口与工作树状态，不能把这组结果自动移植为新 HEAD 的性能结论。
