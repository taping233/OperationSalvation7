## 问题与改法

原本本地 pre-commit 只要暂存 game/src、game/data 或 tests 就运行完整串行 Vitest；最近历史记录约需 5–6 分钟。两条 CI workflow 对相关变更还会各跑一次全量测试。

本轮新增 scripts/acceptance-gate.mjs：按暂存路径给出 skip、quick 或 full 计划；quick 先编译剧情，检查语法、数据、七套类型配置、lint，再运行直接或近邻测试及源码架构哨兵。数据、测试工具/配置、公共状态/启动/存储/迁移、未知测试归属等回退 full。高扇出而有直接测试时，按老板确认的效率取舍，本地只跑直接测试和架构哨兵，CI 与阶段收尾承担完整覆盖。暂存路径与未暂存的相关代码混合时阻断，避免验证了工作树却提交另一份内容。纯 CSS/图片仍须按项目约定看真实页面或图片。

新增按文件运行的 test:target 入口；没传测试文件会失败，不会意外跑全量。pre-commit 默认调用新门，FORCE_FULL_TESTS 保留强制完整套件。CI 统一 Node 22：ci.yml 做静态检查及一次带 pretest 的完整测试，vite-quality.yml 做构建/预算，避免重复的全量 Vitest。安装脚本拒绝从附属 worktree 改写共享 hooksPath。
