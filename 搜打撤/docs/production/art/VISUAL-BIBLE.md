## 页面执行规范：冬日界面体系

统一的是信息层级、控件语义和留白节奏，不把不同用途页面做成相同密度。本规范是新增/改造界面的执行标准；当前接入营火决策/结果、撤离复原说明，祭坛激活/回赠和入城补给说明、远征背包/安全格/消耗区，其他页面不能据此宣称已经统一。完整接入边界见[页面覆盖矩阵](UI-PAGE-COVERAGE.md)，实页状态按矩阵登记。原 `2026-10-17-ui-design-system` 首批实施报告及证据目录缺失；当前实现可查[营火呈现](../../../game/src/ui/fire-rest-view.js)与[结构契约测试](../../../tests/ui-design-system.test.js)，这些来源不能证明历史实页通过。

### 同一家族的四类页面

| 页面族 | 空间与信息 | 必须保留的差异 |
| --- | --- | --- |
| 地图事件 | 场景/地点与操作区分开；操作面板依内容高度，内边距32、组间24，叙事只留一句气氛/事实 | 不用全屏文字框盖住插画；营火决策用收益→容量→一次性风险→主动作→说明 |
| 战斗二级层 | 在真实战场上使用透明遮罩和紧凑内容面板，材料/候选列表独立滚动，底部确认/取消常驻 | 沿用注能compact基线；保HUD、手牌背景、同一场景节点，不通过全局CSS改战斗点击范围、层级或牌大小 |
| 卡片浏览/储物 | 筛选工具、卡片网格、容量与操作区分层；完整卡面是主对象，组间24–32 | 不靠缩小全部卡牌获得留白；长清单滚动，原职业框、等级色、选中和放大身份连续 |
| 结算/撤离 | 结果标题、实际去向/数量、容量及下一动作优先；明细在侧栏折叠 | 沿用extraction-quiet骨架和卡宽；剩余未入库的永久放弃风险始终在底栏，待复原不能冒充已入库 |

### 可执行 token 与组件

当前可复用实现：[ui-design-system.css](../../../game/css/ui-design-system.css)、[说明组件](../../../game/src/ui/ui-disclosure.js)和[事实/选项组件](../../../game/src/ui/ui-decision.js)。只有显式 `.ui-design-system`、`.exr-page` 与显式使用这些组件的营火/节点页使用新tokens；不得新增全局 `button`、`details`、`.hs-card` 或战斗通配覆盖。继续使用既有字体和图标系统，不引入新字体、材质或动画依赖。

- 色彩：纸白 `#eef1ed` 主文；冷灰蓝 `#b6cbd7` 主行动/选中；辅文 `#b9c9d2`；冷蓝黑 `#15212cef` 文字面。暖金 `#c6b487` 限价值/焦点，危险用浅暖红并配明确文字。稀有度/伤害/治疗语义保持原系统。
- 间距：4/8用于同组紧邻信息，12/16用于控件内距，24为信息组间距，32为事件面板内距。边界优先单根1px分隔线，圆角3px；不再一层层嵌套描边/发光。
- 字号：按项目1920设计画布，页面标题36、对象/关键数26、正文与操作22、标签/辅文18，正文行高1.45–1.55；结算主结果可沿用60的展示标题，不能每页都使用该字号。实际窗口经 `ui-scale` 缩放，需看最终屏幕文字，不能把设计px当屏幕px；既有卡面独立字号体系不在本轮重置。
- 按钮：主动作一个，冷灰蓝实底；次动作深底细边。高度60、横内距24；原生button与可见focus轮廓，禁用仍可读并在附近提供原因。复用既有返回图标和输入语义，不增加新的“X/返回/退出”图标家族。
- 说明：`uiDisclosure` 输出原生details/summary，默认收起；仅放规则解释、来源、历史、逐条名单。标题须指出内容（“休整说明”“复原说明”），不能用含糊“更多”替代。
- 不可折叠：支付成本、真实容量、当前可执行数量、永久放弃/一次性消耗、无法获得的奖励、关键禁用原因。关键数值与动作相邻，避免在标题、正文、按钮重复三次；概率是决策收益时也需常显。
- 图标：使用现有语义图标，装饰图标不代替文字；有文字的箭头仅装饰并设aria-hidden。道具/卡牌图仍承担识别，不能用统一图标替换。

### 页面改造验收门

先检查空池、满容、同名叠放、正常数量、结果页；核对长文展开后主动作仍可达，取消/返回与再进入不消费/不重复授予。结构测试覆盖事实是否位于折叠外、动作标识不变和CSS作用域；视觉通过必须由当前窗口内置浏览器截图与真实输入另外证实。禁止把静态旧截图或jsdom测试记成新页面视觉通过。

## 五图观察与一张实施规则表

本轮观察：无以银白高马尾、青蓝眼、黑灰短裙和蓝缎带形成对比；常无欲紫内衬/金缘、黑雾与橙火；白塔绿灰裙、白衬衣、坐椅吃蛋糕与浮书；黑像冷灰甲/巨剑与橙围巾；星月白金裙、深绿披肩、灯与长辫。现有图使用可见笔触与明暗块面，作为各自身份和构图参考。

当前五张运行立绘均为 1024×1536 竖版；四位同伴的替换与独立 3072×1728 白边横版见[重绘记录](../../evidence/2026-10-13-roster-redraw/README.md)。按实际源图和容器处理裁切，白底不作为 UI 背景要求，白塔坐姿按选定参考保留。

| 规则 | 整备 | 普通战斗 | 领取 / 结果 |
| --- | --- | --- | --- |
| 分区 / 主动作 | 当前角色与身份、可带卡列表、容量成本、稳定出发区 | 上区敌我对象，下区手牌操作带；意图与状态贴目标，结束回合固定可见 | 先结果与保留/损失，再来源分组；已有与待领分区，一个显著继续/领取动作 |
| 文字 | 名称与对象邻接，成本靠修改项 | 敌名/意图不可逐字断行，费用/规则不可被插画遮盖 | 合计与实际去向突出，长清单滚动不挤走动作 |
| 字号角色（样板起点） | 使用下方页面执行规范的设计画布token；实际窗口检查正文/数值可读性，长文先留空间再换行，不缩整页 | 同左；小牌保留费用/名称，详情完整规则 | 同左；胜负标题与合计形成两级，来源标签退后 |
| 色彩语义 | 冷灰深底/浅灰正文；金琥珀仅主动作与价值；角色身份色局部 | 红危险、绿治疗、紫诅咒、灰白格挡；附字/图标；选中轮廓与稀有度分开 | 保留/丢失同时有文字与数量，不能仅靠红绿 |
| 边框 / 材质 | 平静不透明文字面、细边、短接触阴影，纹理在背景层 | 场景退后，HUD低纹理；不把金属球或满框外光当共同标准 | 信息面安静，装饰只在边缘，不穿正文 |
| 卡牌层级 | 费用→名称/类型→图像→规则；普通/职业/高阶保持同家族 | 同对象裁切与身份连续；选中不覆盖等级，详情不换统一金框 | 同卡在清单/详情/结果中名称、图像、等级一致 |
| 动效顺序 | 选中→详情/容量变化→可出发状态 | 选牌→目标→结算→数值反馈→恢复操作；持续HUD与短效层分离 | 结果事实先可读→物品去向反馈→恢复操作；不得延长规则锁 |

字号等数值用于当前窗口样板起点，调整时核对实际背景上的可读性。参考分析中的目标/操作分层、人物/文字避让、整备成本与结果来源、已有/待领分区是布局依据；具体样板结果保存在任务证据。

## 卡面与出图参考

### 卡面用途与构图

- 背景默认采用单一纯色或多种纯色交替的大色块，组成抽象背景。
- 风、水、火等元素仅作为意象出现，不绘成河岸、山谷、建筑等实体环境。
- 每张卡面依据卡名设计独特的动作、构图与分镜，避免重复套用同一角色站姿。
- 发束与衣料按[默认画法及双图](ART-STYLE-V1.md)保留有结构的块面笔触，具体密度结合卡图显示尺度处理；完整轮廓与主要明暗组须可读，不把旧任务的草稿线或未填满边缘推广为全局标准。
- 图稿审阅方式按老板在对应任务中的指令执行；工程接入与文档检查按[质量门](../../quality-gates.md)选择范围。旧卡面任务的操作约定保留在[整理前原文](../../archive/WF-art-doc-context-1009/originals/docs/production/art/VISUAL-BIBLE.md)。

### 本地 NAI 工具参考

下面记录已有 NAI 工具的组成与参数，按使用该工具的任务查阅。当前方向不依赖某个模型、画师串或固定参数；其他生成工具使用当次能力和记录。

1. **画法与工具配方**：游戏默认采用[双图块面厚涂](ART-STYLE-V1.md)；工具配方以实际 `tools/nai_style.py` 与[NAI 工具入口](../../../tools/NAI-PROMPTS.md)为准，工具配方更新不自动改变游戏默认画风。后续使用 NAI 时须先核对实际配方与项目默认的差异，不把冲突风格词叠加。
2. **身份 / 主体**：人设页现行锚点，或明确非人物主体；无沿现图裙长，常无欲无杖，白塔坐姿。动作改变不等于身份改变。
3. **用途**：立绘完整轮廓；卡图单一焦点且不含规则文字；场景环境后退并留 HUD 低纹理区域；小图标优先现有 SVG，位图小样在真实尺寸验轮廓。
4. **构图**：由实际容器确定比例、焦点、脸/武器安全区及文字禁入区；白底全身规则只用于相应立绘，不套卡面、场景或图标。`build_asset_prompt` 分开用途/构图/光色；旧 `build_prompt` 两参数与兼容薄壳继续可用。
5. **光色 / 材质 / 排除**：统一方向光与克制身份色，明确布/皮/金属区别；特效服务主体，禁文字/水印/UI烘焙；角色专属排除单独追加。
6. **技术**：本地 NAI 客户端现默认 `nai-diffusion-4-5-full`，V5 必须显式 `model='nai-diffusion-5-full'`；28 steps、scale 6.5、cfg_rescale 0、k_euler_ancestral、karras、variety_plus。此为本地代码事实，不保证远端模型/参数能力。每次记录渠道、实际模型、配方版本、五图参考 SHA256、完整正负词、seed、宽高、原稿/alpha/裁切衍生/运行图路径、真实显示尺寸、编码体积与解码证据；不盲改 nai_gen 默认。

工具能力以当次接口为准。配方文本、参考图、候选输出和已接入素材分别记录；新增规格经对应样板确认后维护。生成轮次、旧参数与原方案从任务证据或[整理前原文](../../archive/WF-art-doc-context-1009/originals/docs/production/art/VISUAL-BIBLE.md)查阅。

## 视觉锚点

| 层面 | 当前基准 | 实施规则 |
|---|---|---|
| 外层背景 | 深色空间、桌面/深底层，背景退后 | 背景纹理与光效不能削弱主对象和文字；用面板层级表达区域，而非堆叠描边 |
| 面板与控件 | 石墨或主题色面板，细边，近直角 | 同一页面的同类面板、按钮和弹窗保持边线、内边距、阴影一致；沿用页面已有圆角 token |
| 强调 | 金/琥珀承载确认、稀有价值或焦点；红、绿、紫等保留状态语义 | 强调色只给重要信息和交互反馈，不将所有标题与边框都染金 |
| 插画与角色 | 认可五图为锚点，其他实装图逐类待审 | 身份优先于装饰；裁切、遮挡、比例不得让脸、武器、职业标识不可读 |
| 场景变化 | 战斗、基地、收藏等可以有各自主题 | 通过颜色、纹理和道具建立场景身份，同时沿用一致的控件行为、文字层级和反馈语义 |

## 信息层级

战斗布局由 `game/css/battle-stage.css` 统一维护：角色贴地站位，血条与意图贴在角色上方，职业技能位于人物旁，能量和结束回合分居底部两侧。手牌保持统一阅读尺寸，通过叠放适应数量；消耗后当前栏靠拢，分组、卡牌身份和快捷键映射保留，悬停/焦点抬牌、点选/拖拽出牌及详情沿共用 `cardHTML` 和 `card-layout-selected.css`。战斗中只常驻回合与决策信息，熟练度、重复操作教程及装饰粒子已移除。当前窗口试玩与验证范围见[三版整改记录](../../evidence/2026-10-16-WF-battle-play-rewrite/README.md)，旧设计稿不代表现行正式页。

从高到低安排视觉权重：

1. **当前决策/结果**：胜负、撤离风险、选择结果、主要行动按钮；使用最清楚的对比和位置。
2. **对象身份**：角色、卡牌/装备名称、敌人或地点名称；与图像或对象框紧邻。
3. **关键数值与状态**：生命、费用、稀有度、增益/负面效果、锁定/可用状态；使用固定语义色并配文字或图标。
4. **解释与次要信息**：规则描述、来源、辅助标签；清楚可读但降低亮度或字号。
5. **装饰**：纹理、微光、刻纹只填补空白，不穿过正文，也不抢在关键对象之前被看到。

每屏先确定一个首要焦点。文字超出空间时先调整换行和布局，不得用过度缩小字号或低对比阴影来塞入内容。

## 字体与颜色语义

- **已定事实**：全局 UI 字体栈以 HarmonyOS Sans SC / Noto Sans SC / Microsoft YaHei 等无衬线回退为主；`--font-display` 当前指向同一 UI 字体栈。不得假设某台设备必然装有首选字体。卡牌库可有页面级暖纸风格覆盖。
- 正文、按钮、数字应优先使用易读的 UI 字体；标题以字号、字重、间距建立层级。只有页面已经明确采用特殊展示字体时才沿用，不新增字体依赖作为统一化手段。
- **已定事实**：`base.css` 具有底色/面板/文字/金色/琥珀/红/绿/紫等基础 token；战斗反馈语义包括普通伤害、强受击、暴击、命中、治疗、格挡、诅咒。新增全局视觉应先复用这些 token。
- 金色/琥珀用于强调与价值，红色用于伤害/危险，绿色用于治疗/正向，紫色用于诅咒/异能，灰白用于格挡/免伤。功能状态应同时有文字、形状或图标区别，不能只靠色相传达。
- 页面专属调色板可以局部覆盖，但应以 CSS 变量表达并限定作用域；避免引入新的全局裸色和与既有状态语义冲突的颜色。
- **建议**：验收时直接看实际背景上的小字号文字和次要文字；如需提高可读性，先提升明度差、字重或留白，再减少背景装饰。

## 动效语义

- **已定事实**：基础样式提供入场、弹出、弹簧、飞行、飘字五类缓动 token（`--ease-entrance`、`--ease-pop`、`--ease-spring`、`--ease-fly`、`--ease-float`）。新增动效优先选匹配语义的现有 token，避免每处随意发明曲线。
- 入场/弹出用于界面层出现；弹簧只用于明确可交互或获得反馈的对象；飞行用于有起点终点的对象移动；飘字用于短暂战斗反馈。
- 动效应能说明状态变化，不能遮住文字、延迟关键输入或使状态只有动画结束后才可辨认。静态状态仍须完整表达结果。
- 项目支持减少动态效果的场景应尊重系统偏好；若目标页面未实现此项，登记为后续改进，不假称已支持。

## 组件状态约定

对按钮、卡牌、角色项、装备项和可选节点，按组件适用性明确以下状态：

| 状态 | 表现要求 |
|---|---|
| 默认 | 可识别的边界、名称和基础信息；不要误显为禁用 |
| 悬停 | 轻微亮度/边框/抬升反馈，避免布局跳动；触屏或无悬停设备仍可操作 |
| 键盘焦点 | 有可见焦点环/轮廓，不能被裁切或与选中混淆 |
| 选中 | 使用稳定轮廓、底色或标记；多选时也能逐个识别，不覆盖稀有度身份 |
| 禁用/不可用 | 降低权重并说明原因或条件；保留足够文字对比 |
| 危险/损失 | 使用红系等风险语义，并给出明确文字或图标；确认操作不可只靠闪烁 |
| 加载/失败 | 反馈当前进度或恢复方式，不用缺图/空白冒充正常素材 |

同一对象在列表、详情、预览、弹窗中应维持名称、等级、稀有度、状态色和图像身份。选中态与稀有度色分别表达，不能用统一选中色覆盖等级差异。

## 角色、卡牌与素材接入

1. 角色名称、职业、id 与引用查 `game/src/core/characters.js`；外观先看认可五图与[角色索引](../../character-bible/README.md)的现行段。`ref-images/` 同图参考，不另复制权威；代码加载路径仍需核对。
2. 五位角色已确认的人设细节必须保持；条目标“待定稿”的背景/性格内容不得补写推断。角色卡和其他素材应继承可识别的脸、发色、职业道具、主题色锚点，同时服从素材用途与当前页面画风。
3. 卡牌等级、类型、费用、名称、规则正文和局内状态都要有稳定位置。稀有度不能只靠名字颜色辨认；框体家族和必要的差异要与当前卡面体系一致。避免缩小正文来换取装饰空间。
4. 新素材应记录用途、来源/授权、实际引用位置及必要的生成来源。先核对 `game/data/art-mapping.json`、加载代码与 `game/assets/asset-manifest.json`；清单有条目或磁盘存在都不能单独证明素材当前被引用。
5. 图片按真实显示用途准备清晰度和裁切；透明图保持真实 alpha；缩略图和大图的对象身份一致。不要将历史预览或角色快照误当运行时资源。

## 一页式验收

在当前运行页面中检查改动所影响的实际入口和状态（本规范不要求新增多尺寸矩阵）：

- 关键资源、字体和图标已从预期路径加载；角色或卡牌身份与权威数据/人设一致。
- 首要行动和对象一眼可辨；标题、名称、正文、数字和次要信息层级清楚，正文没有裁切、遮挡或被纹理穿过。
- 页面主题与邻接流程相容；同类面板、按钮、选中/禁用状态的边框、圆角、阴影和间距一致。
- 伤害/治疗/格挡/诅咒等语义未被重新赋予；状态不只靠颜色或动效表达；悬停、焦点、选中和禁用状态按组件适用性实际可辨。
- 静止画面仍能理解动效带来的状态变化；无多余强闪、长时间遮挡或持续抢焦点的装饰。
- 对新增或替换素材，核对运行引用、来源/授权记录及最终页面显示；文件生成成功本身不算画面验收。

视觉规则若缺少依据，先在实现记录中写明“建议”及验证结果；只有改变产品基调、品牌/人设锚点或状态含义时，列为待老板裁决。
