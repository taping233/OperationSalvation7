# 项目章程

本文维护 Vite 项目的已确认目标、范围与取舍；玩家规则见[规则页](../../rules.md)，任务状态见[状态入口](../../STATUS.md)。

## 项目目的

《搜打撤·代号7》是爱好作品，不以盈利为目标。项目围绕单机搜打撤游戏持续改善可玩的体验，同时把 Agent 接口与实验能力作为同等重要的工程目标。用户已确认两项目标并重。

## 目标与范围

| 目标 | 当前工作含义 | 主要依据 |
| --- | --- | --- |
| 游戏体验 | 让玩家能理解并享受探索、战斗、资源管理、深入或撤离的取舍；视觉依据按[现行视觉规范](../art/VISUAL-BIBLE.md)执行。 | [GDD](../design/GDD.md)、[现行规则](../../rules.md)、[人设库](../../character-bible/README.md) |
| Agent 工程 | 维护可观察、可执行、可复现实验的结构化 Agent 能力，让策略迭代能基于跑局证据。 | [Agent 接口协议](../../agent-protocol.md)、[策略迭代手册](../../agent-iteration-playbook.md) |

开发范围与冻结线由根 AGENTS.md 维护；包版本从项目 README 与 `game/version.json` 查询，实现状态和验证证据从[项目状态入口](../../STATUS.md)查询。

## 已确认方向

工程方向是夯实底层、改善性能和可修改性，并完善供人和 Agent 使用的制作文档。具体在途任务及完成状态查任务记录。

长期方向仍是游戏体验与 Agent 工程并重。完整版本范围已确定为四层主地图：首脑胜利后经终局撤离进入清晰通关结算与简短收束；研究所第二地图当前阶段暂缓，不纳入本轮规划与完整版本验收。

性能以 120 FPS 为努力目标。先测当前 Vite 实页基线并记录回归，设备和可接受的回归幅度按具体测量任务确认；方法见[性能文档](../../performance.md)。

## 取舍原则

1. 长期保持玩家体验与 Agent 工程并重；每轮明确一个可观察的主问题与完成标准。
2. 保持 Vite 为唯一当前开发主线，冻结线不因目录整理而重启。
3. 视觉权威与认可范围以[现行视觉规范](../art/VISUAL-BIBLE.md)为准。角色外观锚点查[人设库](../../character-bible/README.md)；未定的人物背景保持待定。
4. 玩法改动先核对现行规则及源码；未明确的玩法决策标注 TBD，交由老板决定。
5. 用与改动相称的证据说明状态。历史记录、版本号、构建产物或 Agent 跑分不能单独证明当前实页体验或完整验收。
6. 文件归属、移动删除和提交操作遵守根 AGENTS.md。

## 成功信号

- 玩家主循环清楚呈现“搜集—战斗—决定深入或撤离”，背包与风险选择能被玩家理解。
- 视觉遵从[现行视觉规范](../art/VISUAL-BIBLE.md)；角色锚点未被未经确认的设定覆盖。
- Agent 可通过结构化观察与动作接口驱动流程，并按现行实验手册留下可复核的策略比较证据。
- 四层主地图能够形成有明确结局的完整版本体验；研究所第二地图不纳入本轮规划与完整版本验收。
- 代码便于修改；制作者能从文档定位行为、数据来源和验证方法；性能改动有同条件的前后证据。

上述信号用于制定完成标准，实际结果保存到对应任务证据。
