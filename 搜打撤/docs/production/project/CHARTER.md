# 项目章程

> 文档范围：搜打撤 Vite 项目。整理时间：2026-09-28。本文记录已确认的目标和工作边界；不替代规则、源码或阶段计划。

## 项目目的

《搜打撤·代号7》是爱好作品，不以盈利为目标。项目围绕单机搜打撤游戏持续改善可玩的体验，同时把 Agent 接口与实验能力作为同等重要的工程目标。用户已确认两项目标并重。

## 目标与范围

| 目标 | 当前工作含义 | 主要依据 |
| --- | --- | --- |
| 游戏体验 | 让玩家能理解并享受探索、战斗、资源管理、深入或撤离的取舍；基于当前 Vite 实页与已定角色图延续视觉。 | [GDD](../design/GDD.md)、[现行规则](../../rules.md)、[人设库](../../character-bible/README.md) |
| Agent 工程 | 维护可观察、可执行、可复现实验的结构化 Agent 能力，让策略迭代能基于跑局证据。 | [Agent 接口协议](../../agent-protocol.md)、[策略迭代手册](../../agent-iteration-playbook.md) |

当前项目边界是 `搜打撤` 下的 Vite 网页版。Godot、Unity 与桌面 EXE 线冻结。当前包版本记录为 v0.60.0；版本号不代表发布状态或完整验收。实现状态与验证边界以[项目状态入口](../../STATUS.md)及实时工作区为准。

本轮文档治理只增加生产文档入口和管理文档，不移动现有源码、素材或文档，不重排既有路径。玩法机制与数值仍以[现行规则](../../rules.md)和对应代码真源为准；本章程不重新定义规则。

## 当前阶段

**阶段：准备以代码为核心的下一轮工程完善。**下一轮目标是夯实底层、达到足够好的性能，并让后续修改更容易；同时为后续制作者（人和 Agent）补齐详细、明确的制作文档。120 FPS 是努力目标；采样设备与可接受的回归幅度待建立当前 Vite 实页基线后确认，不设未经证实的硬门槛。

长期方向仍是游戏体验与 Agent 工程并重。完整版本范围已确定为四层主地图：首脑胜利后经终局撤离进入清晰通关结算与简短收束；研究所第二地图当前阶段暂缓，不纳入本轮规划与完整版本验收。

性能以 120 FPS 为努力目标。先测当前 Vite 实页基线并记录回归；此目标不构成未经验证的硬门槛，也不据此臆定目标设备或验收阈值。

## 取舍原则

1. 长期保持玩家体验与 Agent 工程并重；当前下一轮优先夯实代码基础、性能和可修改性，并完善给人和 Agent 使用的制作文档。
2. 保持 Vite 为唯一当前开发主线，冻结线不因目录整理而重启。
3. 以当前 Vite 实页和已定角色图作为视觉参照。角色外观锚点查[人设库](../../character-bible/README.md)；未定的人物背景保持待定。
4. 玩法改动先核对现行规则及源码；未明确的玩法决策标注 TBD，交由老板决定。
5. 用与改动相称的证据说明状态。历史记录、版本号、构建产物或 Agent 跑分不能单独证明当前实页体验或完整验收。
6. 保持现有路径和资产的归属；整理目录不构成移动、删除、回滚或覆盖授权。

## 成功信号

- 玩家主循环清楚呈现“搜集—战斗—决定深入或撤离”，背包与风险选择能被玩家理解。
- 视觉延续当前实页和已定角色图；角色锚点未被未经确认的设定覆盖。
- Agent 可通过结构化观察与动作接口驱动流程，并按现行实验手册留下可复核的策略比较证据。
- 四层主地图能够形成有明确结局的完整版本体验；研究所第二地图不纳入本轮规划与完整版本验收。
- 代码结构便于后续修改，相关制作文档对人和 Agent 都足够详细明确；测量当前 Vite 实页的性能基线并检查回归，以 120 FPS 为努力目标，不设未证实的硬门槛。

这些是方向信号，不是已达成声明或量化门槛。实际交付情况须查实时状态、代码和证据。
