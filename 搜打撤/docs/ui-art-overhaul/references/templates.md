# 直接使用的任务、派工与交接模板

下面方括号是让执行者填写的字段，不是让执行者先停下来向用户逐项询问。能从现有会话和项目查清的自行补全；没有参考图、没有预算、没有指定配色本身不构成阻塞。

## 1. 用户最短启动语句

有图：

```text
使用 $ui-art-overhaul，对【目标界面/项目】做完整美术整改，参考这张图。
先发现问题和制定计划，再实现、生成所需素材并持续复核修改到达标。
保持现有功能与已明确的特色，兼顾字体清晰度、连续观看体验和性能。
```

无图：

```text
使用 $ui-art-overhaul，彻底整改【目标界面/项目】的美术与UI。
没有参考图，请依据产品题材和现有成熟页面建立统一标准。
先诊断再按切片实现，必要时生成素材，持续检查到满足标准。
```

用户自己验收：

```text
使用 $ui-art-overhaul，完成【目标界面】的美术整改。
我来验收，不要操作我的页面或运行验收流程；实现后列出改动与待验收项。
```

这些句子不能赋予当前模型没有的文件、生成或浏览器能力。工具缺失时报告实际缺口，完成能独立完成的部分，不宣称已交付真实页面。

## 2. 给执行型小模型的完整指令

```text
你的任务是完成指定界面的实际美术整改，而不是只给建议或计划。

目标：处理【目标界面】的清晰度、满足感与统一性；范围内包括字体排版、
色彩、材质、光影、按钮/筛选、等级表达、动态和页面衔接。
输入：用户参考图可选；没有则从现有产品提炼基准。
权限与约束：沿用最新用户指示和项目规则。禁止改无关玩法、数据或其他页面。

开始前读取 ui-art-overhaul/SKILL.md，并按任务阶段读取它链接的说明。
先建立约束表和问题表，每个问题要有位置、症状、改法、通过条件。
不要把“高级感”当成唯一标准，不要只换颜色、加阴影就报告完成。

先做一条完整的代表性操作链，再扩展其他档位与控件。
保留用户要求的图形元素和语义颜色。跨列表/预览/大图共享对象身份。
素材必须保存进项目并接入真实组件；生成成功不算接入成功。
检查字体实际生效值，不让主题覆盖、纹理、缩放和小字破坏清晰度。
保留原有缩略图、懒加载、分批和局部更新，不以全墙动态特效代替工艺。

执行循环：最高优先级问题→实现→必要证据→失败则修正→通过则下一项。
同一办法两轮没改善就重新诊断，不重复堆叠覆盖规则或生成相似失败图。
不用每完成一个小步骤就问是否继续；授权范围内继续直到标准满足。
用户接管验收就停止自动检查，明确“已实现、待用户验收”；用户叫停立即停。
无法继续时，记录真实阻塞和最小缺失输入，同时处理不依赖阻塞的工作。

交付时只报告主要变化、证据、未完成项和文件位置。不能用单元测试数量
证明美术合格，不能用“肉眼顺畅”证明性能无回退，不能承诺会话结束后自动运行。
```

## 3. 约束/问题/证据表

```markdown
# 本轮界面整改

目标与范围：
输入参考及设计假设：
最新用户决定：
可写文件及负责人：
不可修改模块：
验收方式：代理 / 用户 / 分工
运行入口及服务方式：

| 约束 | 来源/时间 | 适用对象 | 不应扩大的含义 |
|---|---|---|---|
| 保留夹子，允许等级色 | 用户本轮 | 照片夹 | 不改成皇冠，不取消所有颜色 |

| ID | 位置与证据 | 问题/影响 | 优先级 | 改法 | 通过条件 | 文件/负责人 | 状态 |
|---|---|---|---|---|---|---|---|
| A01 | 原生尺寸截图/节点 | 具体可见症状 | P1 | 有限改动 | 可观察结果 | 路径/名称 | 待处理 |

| 证据ID | 时间/版本 | 尺寸/缩放/内容状态 | 操作/采样 | 结果 | 限制 | 对应问题 |
|---|---|---|---|---|---|---|
| E01 | 本轮 | 如实填写 | 实际做过的动作 | 通过/失败/未测 | 不覆盖什么 | A01 |

素材：路径、用途、来源/生成通道、提示词、引用位置、切片/透明区域、体积。
性能：设备/工具/视口/DPR/冷热/前后台/时长/轮数/样本数/比较结果。
未完成及下一动作：
```

## 4. 子代理工作单

仅在用户/规则允许代理且确有独立并行任务时使用。

```text
目标：完成问题【ID】，产生【具体用户可见结果】。
先读：【少量目标文件或定位符】及【相关规则】。
允许写：【精确文件/目录】。
只读：【共享依赖】。
禁止碰：【其他代理文件、玩法、存档、全局样式、入口等】。
输入：参考图/设计约定/真实数据例子。
必须保留：【已有语义色、交互、尺寸、加载机制】。
实现规格：【材质/布局/映射/状态细则】。
完成条件：【可观察结果，不只“代码已写”】。
允许验证：【明确是否可运行测试/浏览器/生成；不准构建则写清】。
交付：改动路径、实现结果、实际做过的检查、未检查项和问题。
不要顺手重构或创建全局规范；遇到职责交叉先报告主代理。
```

示例：资产代理只写两张框；布局代理只改指定组件；主代理负责 CSS、接入、最终状态和用户反馈。不要给三个人同一份 CSS。

## 6. 中断、压缩上下文或换模型前的交接

```text
用户最终目标：
最新修正（覆盖了哪些旧决定）：
已完成且有证据的项目：
已实现但未检查的项目：
当前失败/阻塞及证据：
剩余优先级：
文件所有权与并行任务：
当前服务/端口/进程和日志位置（带时间）：
用户正在操作的页面/应保留的场景：
相关文件与定位符：
下一条具体动作：
禁止再做的事：
```

接手后只刷新容易变化的状态（工作区、服务、文件归属、最新用户要求）。不要从第一阶段重做已经有证据的工作，也不能盲信旧 PID、旧通过数量和旧截图。

## 7. 交付模板

```text
已完成：[少量用户可见变化]。
验证：[实际视觉/交互/性能检查及必要条件]。
未完成/未覆盖：[明确范围]。
资源与记录：[可点击路径]。
```

用户验收模式：`已实现……；按你的要求未操作页面/运行验收，以下项待你检查……`。

## 8. 用这些案例检查执行者是否真正理解规则

以下是指南的桌面推演案例，不是产品已通过的测试结果。

| 情况 | 正确下一动作 | 错误行为 |
|---|---|---|
| 没参考图，但项目可访问 | 找内部成熟页面，建立可逆基准并开始 | 停下反复要求用户提供图片 |
| “馆名白字；夹子按稀有度变色” | 只改馆名文字，保留夹子语义色 | 所有文字/夹子统一变白 |
| 稀有度仅颜色不同，用户要求夹子保留 | 在边框工艺上做等级；夹子形状保持 | 自作主张改成皇冠与盾牌 |
| 生成框中心是黑底 | 修透明规格后重新生成/按允许方式处理 | 直接接入，然后声称完成 |
| 39项测试通过，画面仍丑 | 继续视觉问题清单，测试只证明相应逻辑 | 报告美术验收通过 |
| 性能脚本退出0但无样本 | 标记采样无效，查生命周期与工具边界 | 当成零慢帧、零错误 |
| 页面全部图片失效、端口拒绝连接 | 恢复服务，再确认资源响应 | 重画全部图片、修改全局清单 |
| 用户叫停验收 | 停止浏览器和被禁止的测试，交付待验收 | 以指南要求为由继续截图 |
| 两轮加阴影仍显平 | 检查结构、材质底与缩略角件尺度 | 第三轮继续把阴影加黑 |
| 用户要求只统一退出键 | 读源按钮和目标样式，做局部修改 | 从头启动整页大改和性能审计 |
