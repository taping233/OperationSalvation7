# 诊断与美术原则

## 1. 正确理解参考图

先写清“看见什么”，再写“推断什么”，最后写“准备借鉴什么”。三者不能混为事实。

例如：一张炉石收藏截图展示许多金色卡，可以看到实体卡框、嵌入式图画、卷轴名称、明暗层级；不能据此断言其每个稀有度都采用独立框，也不能把视频字幕、鼠标、输入法或桌面悬浮宠物当成游戏设计。

按照下面六项拆图：

| 项目 | 具体观察 | 应形成的结论 |
|---|---|---|
| 构图 | 第一眼看哪里；功能区如何分组；密集/安静区域 | 主内容、辅助信息、工具的顺序与面积关系 |
| 层级 | 哪个对象最亮、最大、最高对比；背景如何退让 | 明度、尺寸、空间层级，而非盲目抄颜色 |
| 材质 | 木、纸、皮、金属各出现在哪些结构 | 材质对应部件功能，不随意混搭 |
| 结构 | 框、角、边、衔接、扣件、标签如何组成物件 | 哪些细节承担固定、分隔、保护或承托作用 |
| 字体 | 标题/名字/正文/数字的区别和承托方式 | 字体角色、最小可读尺寸、行长与间距 |
| 状态 | 截图能证实哪些选中、锁定、未拥有、禁用状态 | 只记录可见状态；动态与不可见页面列为未知 |

对目标界面使用相同的六项观察后再比较，避免把不同任务、不同缩放、不同内容密度硬比较。

没有参考图时：找到产品内最成熟、与目标功能接近的一页作为锚点，观察题材、既有色系、插画笔触、按钮语言和字体。写出简短设计约定后推进，不强迫用户补图。若项目没有任何可用方向，可以提出一个可逆的合理方向；涉及品牌、人设或玩法含义时才询问关键决策。

## 2. 三个主要视角

### 清晰度：能否快速看懂、找到、操作

- 首眼能否辨识页面用途和主要对象？背景/装饰是否抢走注意力？
- 卡名、图像、等级、费用、类型是否各有稳定位置？是否同一信息重复出现三次？
- 筛选是否靠近被筛选内容？搜索、类别、排序是一个逻辑区域还是散在四角？
- 激活/悬停/禁用/未拥有是否容易区分？“被选中”不能被误认成“高稀有度”。
- 文字在原生显示尺寸下是否发虚、过细、低对比、断字或溢出？小字体不能依赖重阴影补救。

### 满足感：对象是否值得观看和收藏

- 照片是否有纸边、纸层、接触阴影，而不只是白色矩形？
- 高等级是否有更精细的工艺、边框结构、角件和材料层次？普通等级也应完成，不能故意做廉价。
- 点开时是否像同一个对象被拿近？关闭是否返回合理来源？切换是否保持秩序？
- 大图有无足够画幅与清晰原图？边框是否侵占主体？图被裁切是否损害脸部或关键物件？
- 收藏编号、名字、备注是否有合适承托，而不是无目的增加标签？

### 统一性：是否属于同一个产品和空间

- 页面外壳、筛选器、按钮、相片、信息栏的线宽、圆角、材质、字体、光向是否协调？
- 同一对象在列表、预览、大图是否保持同一等级、框式、颜色与身份？
- 相邻页面的退出键、返回键、输入框是否来自同一套规范？不仅比图标，还要比按钮盒、留白和响应式缩放。
- UI 的写实程度是否与插画相差过大？发现来源插画不一致时单独列项，不用加滤镜掩盖。

## 3. 逐层检查，不漏“整体细节”

| 层 | 需要查的问题 | 合理的修正方向 | 常见错误 |
|---|---|---|---|
| 页面骨架 | 主次不清、区块断裂、边缘悬空 | 调整比例、对齐、节奏与连接关系 | 每个面板各设计一套风格 |
| 材质承托 | 平涂塑料感、物件没有厚度 | 真实的内外边、压边、接缝、纸纹、接触阴影 | 只加大外发光 |
| 光影 | 每块光向不同、漂浮、整体发灰 | 统一主光与遮挡关系；暗部仍有信息 | 全页蒙雾或强渐变 |
| 字体排版 | 字体跳变、宋体细笔画消失、行距拥挤 | 标题/名牌用适合题材的展示字体，正文用易读字体 | 所有文字都装饰化；缩小字号硬塞 |
| 色彩 | 所有元素争抢、等级颜色丢失 | 分配背景/正文/强调/状态角色，保留语义色 | 全部染成金色或全部变成白字 |
| 控件 | 无选中反馈、默认表单感、位置别扭 | 成组布置、边缘工艺统一、反馈明确 | 为了美术隐藏标签/焦点/禁用状态 |
| 图像 | 模糊、裁脸、主体比例不统一 | 选择合适分辨率、焦点、画幅；局部逐张校准 | 列表直接全量加载原图 |
| 稀有度 | 仅字色不同、豪华程度失序 | 框厚、框层、雕花、材质、局部镶嵌构成分级 | 更改夹子形状或添加皇冠却未尊重用户要求 |
| 动态 | 突然闪现、关闭无过渡、对象跳位 | 建立来源位置，进退成对，处理中断与缺失来源 | 无限粒子、全墙扫描光 |

## 4. 字体与颜色的具体决策

1. 先确定角色：馆名/页面标题、对象名、正文、字段标签、次要编号，限制主字体家族数量。
2. 查字体是否真实存在/加载成功；`font-family` 写了衬线不等于实际渲染使用该字体。
3. 查看最终计算样式、继承和加载顺序。旧主题的 `!important` 可能覆盖新样式。
4. 在原生 100% 页面显示下判断锐度；被 iframe 或截图工具缩小的整页图只适合看构图，不能证明小字锐利。
5. 正文、名称优先足够字号、字重和对比；不默认用透明填字、发光或描边。用户明确保留的等级渐变仍须保留，调整其明度与范围。
6. 纹理放在文字/图像背后的材质层；不要把噪声、滤镜、低透明度蒙层压到文字上。
7. 对比度需要测最终前景与实际背景。项目没有规范时，可把普通正文约 4.5:1 当初始可读性目标；它不能代替实际字体清晰度，更不能据此宣称完整无障碍合规。
8. 颜色特例保持范围精确：例如馆名纯白、职业红、传说金、棱彩渐变可以同时成立。

## 5. 稀有度设计：先结构，再局部色彩

制作同图对照板：所有等级用同一原图、同一画幅、同一显示尺寸，外部标真实等级名。可以增加只用于验收的去色/隐藏名称开关。

| 工艺层级示例 | 框层/材质示例 | 克制原则 |
|---|---|---|
| 基础 | 纸包边、细线或简单护角 | 完整且清楚，不故意降低图片质量 |
| 中等 | 双框、金属压边、明确护角 | 增加结构，不只替换颜色 |
| 高等 | 凹槽、雕花、金属/木质层次 | 细节集中角落与边缘，文字区域安静 |
| 最高/特殊 | 浮雕、镶嵌、切面、局部干涉色 | 保持边框家族关系，不变成另一个游戏 |

该表不是所有游戏的固定等级表。职业、衍生、任务物品可能只是分类，不应该凭空排成比传说更高的等级。

用户要保留夹子时，保留夹子形状；允许按等级变色时只调整其金属色。不要把“增加等级差异”自动解释为“移除原本喜欢的特色”。

## 6. 问题必须写成可修复的条目

差：`缺乏高级感，需要更好看。`

好：`A03：索引栏和照片底纸同样明亮，且索引纸纹比正文笔画更强，导致首眼先看到噪声。将索引底色压暗一档、纹理移到低对比背景层，保持正文实色。通过条件：原生尺寸可完整读出四个字段，纸纹不穿过字形，第一视觉仍是照片。`

优先级：P0 功能/资源失效、严重遮挡或不可读；P1 主次、布局、身份连续性和关键字色；P2 材质、等级工艺、按钮家族、光影；P3 微小刻纹等装饰。用户特别点名的要求优先兑现，不能埋进长期清单。

先说明会造成什么用户问题，再给改法；不要仅以审美形容词评价。装饰数量、图片文件数量和 CSS 行数都不是完成度指标。
