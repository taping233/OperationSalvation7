## FSA-01 · P2：同一局不同事件节点会重复抽到已遇事件

- 现行来源：`../搜打撤/game/src/run/game.run.events.js:85` 起用 `nodeRewards`、`eventLog` 排除已抽事件；空池显示“此处已无新的见闻”。既有节点恢复时仍使用原绑定。
- Unity：`Assets/Scripts/Sdt.Run/GameRuntime.cs:1033` 的 `RunEventDeck` 从全部事件牌抽取，`1047` 直接 `TriggerEventCard(Pick(deck),false)`，没有本局历史过滤。
- 最小玩家条件：同局先后到达两个不同事件节点，前一事件已遇见；后节点仍可能抽到同牌。
- 本次独立复现：通过公开域接口进入当前生成地图的事件节点并执行 `ResolveCell`。第一次 seed `148989015`，`0,4` / `2,2` 均为 `ev19-classchest`；最终有效复跑 seed `149119325`，`0,2` / `1,8` 均为 `ev19-arrows`。`SaveCurrent` 后 `LoadRun` 成功，重复历史仍为 2 条。未以重置同一节点或修改事件池制造条件。
- 影响：事件多样性与本局唯一事件约束改变，玩家可重复获得本应本局不再出现的事件收益。
- 修正建议：沿现有节点收据与事件历史过滤候选；保留已绑定节点恢复；处理全池耗尽返回地图。复验需覆盖不同节点去重、读档保持绑定及空池。

## FSA-02 · P2：永久收藏缺少独立浏览入口，最后一张转化后从收藏页消失

- 现行来源：`../搜打撤/game/src/hub/hub.collection-v4.js:12` 的 `ownedReader` 读取永久 `collection` 字典，并用卡库或仓库快照解析展示；`34` 的画廊候选来自 `Object.keys(base.data.collection)`，不要求仍有库存。

- 最小玩家路径：带回某职业/能力卡 → 收藏室转化最后一张 → 图鉴仍显示已收录，但收藏页不再提供此卡的查看/详情。也不能在收藏页浏览已登记的非职业收藏品。
- 本次独立复现：隔离新档放入 `tt3-flame-storm` ×1，调用正式 `TryConvertCollection(id,1)` 成功；之后 `collection[id]` 为 true、仓库该卡为 0、收藏 UI 当前枚举条件得到 0 行。重进该档后注册仍为 true、仓库仍为 0。UI 行数为源码谓词核对，没有声称运行了原生界面。
- 影响：永久收藏记录被保存，却无法在收藏室继续阅读该卡；玩家完成培养后丢失现行 Web 已提供的收藏浏览体验。
- 修正建议：复用现有卡库和 `Base.collection` 建立永久已收藏列表与详情入口；库存培养、保护与图鉴浏览按各自真源读取。最后一张转化/出售/出征后及读档后，已收录卡仍应可浏览。
